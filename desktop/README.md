# TomBot 桌面客户端

基于 Electron、React 和 TypeScript 的独立桌面工程。布局参考提供的 Grok Bot 截图，默认窗口为 1073 × 780，使用原生 macOS 窗口控制、浅灰分组侧栏、猫咪卡通头像、黑白消息气泡和底部输入栏。按原始参考图在该窗口下的比例设置：侧栏宽 300 像素，列表头像为 34 像素，置顶头像为 56 像素，消息正文为 15 像素，消息气泡最大宽度为内容区的 76%；工具栏、输入栏和弹窗使用同一尺寸基准。

## 启动

需要 Node.js 22.12 或更高版本。所有命令均在 `desktop` 目录执行。

```bash
npm ci
npm run setup
npm run dev
```

`setup` 使用 Electron 官方安装器下载对应平台的运行时；Electron 45 不再随依赖安装自动下载运行时，需要首次安装后执行。开发模式支持界面热更新。

构建并打开生产资源：

```bash
npm run build
npm start
```

当前交付包含可运行工程及生产资源构建，不包含安装包签名、自动更新或应用商店分发。

## 已实现功能

- 分组助手列表、默认助手置顶、会话切换；拖动侧栏右侧边界调整宽度，展开范围为 240～400 像素，低于 240 像素自动收缩为 88 像素头像栏，向右拖动可重新展开。分隔线也支持方向键和 Home / End。
- 助手支持右键菜单与键盘 `Shift+F10` 打开：置顶/取消置顶、移至分组、标为未读/已读、内联重命名、复制对话 ID、从侧边栏隐藏和删除。`移至 → 创建分组`会立即新建分组、移入当前猫咪，并把分组标题切换为可编辑输入框；重命名猫咪时直接在侧栏原位置修改名称。菜单按光标位置自动避让窗口边缘，支持方向键、分组子菜单及 `Escape` 关闭；默认猫咪固定置顶且不可隐藏或删除，隐藏的助手可在“我的工作空间”恢复。
- 招聘猫咪弹窗宽 480 像素，提供 8 款可区分的猫咪头像、分组与模型选择、名称及容量校验。头像使用随应用打包的 256 像素透明 PNG 帧，深浅主题不反色、不从网络加载。列表 34 像素、置顶 56 像素、会话标题 22 像素。静息时呼吸、轻摆，并按各自的节奏眨眼；指针悬停在侧栏（含 88 像素头像栏和置顶）时耳朵竖起并抽一下进场那一侧，头部按弹簧转向指针，进入时轻弹，按下时压扁；工作中保持竖耳、点头，角落显示输入点。帧要先解码完才切换，失败时停在睁眼原图。保存草稿不会进入工作中。系统开启减弱动效时只显示静止原图。详见 [猫咪头像](src/renderer/src/assets/cats/README.md)。
- 主题、语言、模型供应商、分组与招聘模型统一使用自绘选择器；支持方向键、首尾跳转、输入名称前缀定位、回车确认、Esc 取消、Tab 离开及外部点击关闭。菜单以弹出层展示，根据窗口空间向上或向下展开，适配深浅主题，不依赖系统原生下拉菜单。
- 搜索助手资料、本地消息和设置选项，支持 `⌘K` / `Ctrl+K`、方向键选择、回车打开及 `⌘1–9` / `Ctrl+1–9` 快速选择；`Escape` 关闭弹窗。
- 点击“我的工作空间”查看助手和草稿概况。按钮上是一张静止的原创橘虎斑猫头像，裁在圆框里，不跟随助手的眨眼和悬停动画。右侧齿轮与这个圆框同尺寸，独立打开双栏设置页；通用栏目提供主题与语言选项，模型栏目提供供应商、API 地址、模型名称、温度、Top P、输出长度及流式响应表单。
- 浅色、深色主题即时切换并保存；选择“跟随系统”后实时响应系统外观变化。消息、侧栏、所有弹窗和表单统一适配。
- 聊天顶部使用渐变与背景模糊，滚动内容自然淡出；滚动条仅在鼠标悬浮于对应滚动区域时显示。表单聚焦不出现额外外框。
- 每个助手独立保存消息和输入草稿；重新打开客户端可恢复。
- `Enter` 保存本地草稿，`Shift+Enter` 换行；中文输入法选字不会触发保存。
- 消息气泡可右键或悬停操作：快捷表情、更多表情、回复、复制和删除；只有消息带请求标识时才出现“复制请求 ID”。未发送和发送失败不再把时间和按钮放在气泡下面，只在朝向会话中央的一侧显示红色感叹号。未配置模型时消息保持未发送，重试会说明需要先填写 API 地址和模型名称；模型调用失败才标为发送失败。回复先在输入框上方给出可取消的引用，发出后在气泡里保留摘要，点击可滚回原消息。悬停快捷按钮平时只显示图标，指针停在单个按钮上才出现浅灰圆角底。表情显示在气泡内部、正文下方的小胶囊里，数量大于 1 才显示计数，再次点同一个表情会取消。会话第一条，或与上一条间隔超过 5 分钟，会在消息前居中显示时间：今天为 `HH:mm`，昨天为“昨天 HH:mm”，一周内为“星期X HH:mm”，更早为“YYYY年M月D日 HH:mm”。输入框的加号或拖放可以上传图片和文件。聊天页不再显示分享或侧栏收缩按钮。
- 存储异常提示、保留未落盘的内存内容、重试保存、损坏内容防覆盖。
- 最小 860 × 640 窗口适配、键盘焦点、原生模态框与减弱动画设置。

首次打开先填写远端服务地址，确认后再初始化或验证密码。没有已保存地址时不会猜测本机端口，也不会停在「正在连接服务」。地址保存在本机用户目录，下次打开直接连接；连不上时可以修改地址再试。助手、消息、草稿、资料库、电脑地址和模型设置保存在服务端；没有配置模型时，消息保持未发送，不会伪装成已发送，也不会编造回复。配置了 API 地址和模型名称后，发送会请求兼容 OpenAI 的接口。头像与初始使用指南仍是本地资源。语音仍不可用。图片和文件会上传到服务端，供 agent 读取。

主题真实生效并独立保存在本机。语言和模型设置保存到服务；界面语言仍是简体中文。API 密钥只提交给服务，不写入本地存储，响应里也只说明是否已经保存。参数范围仍按表单校验。

招聘时的模型列表仅来自“设置 → 模型设置”中填写的模型名称，不添加内置模型。未配置时显示空状态并禁用招聘。招聘成功后，猫咪详情里的模型仍是目录中的默认项，可再在详情里更换；这个选择会随工作空间保存。选项逻辑在 `features/models/modelOptions.ts`。

## 工程结构

```text
desktop/
  src/main/                      Electron 生命周期、窗口及安全边界
  src/preload/                   仅暴露平台标识的隔离桥接
  src/renderer/src/
    assets/cats/                 猫咪帧 PNG 与生成说明
    components/                  头像、模态框与内联名称输入
    features/avatars/            预设、原图、姿态与活动状态
    features/models/             招聘模型预览选项
    features/workspace/          助手领域规则、本地存储、侧栏及弹窗
    features/chat/               会话、消息与输入区
    features/search/             搜索列表与键盘导航
    features/settings/           主题偏好、系统监听、预览表单与校验
    styles/                      通用弹窗、搜索与设置样式
    styles.css                   主界面样式
  tests/e2e/                     真实 Electron 窗口测试
```

## 检查

```bash
npm run check       # 格式、静态检查、类型检查、领域与组件测试
npm run test:e2e    # 生产构建、真实 Electron 窗口测试及截图
```

端到端测试使用独立临时用户目录，不会修改日常工作空间；截图按 CSS 像素输出到 `test-results`，标准窗口截图为 1073 × 780，避免 Retina 倍率影响尺寸核对。需要当前系统支持启动图形界面。Linux 的无显示器环境需要配置虚拟显示器。

依赖版本通过 `package-lock.json` 锁定。`minimatch` 固定到 11.0.5，修复静态检查工具间接引入的拒绝服务公告，完整静态检查用于验证该依赖覆盖。

## 状态与后续服务端接入

工作空间的权威副本在服务端 `desktop_state`。客户端仍能读取旧的 `tombot.workspace.v5`（以及更早版本）：服务端还是预设、没有用户改动时导入一次，损坏的旧档会阻止继续编辑且不覆盖原文。导入之后不再把工作空间写回 localStorage。头像使用 `avatar` 预设标识。可选模型集中在 `features/models/catalog.ts`。消息含角色、发送状态、可选请求标识、回复摘要和表情。限制为 64 位助手、全局 500 条消息、单条 10000 字、序列化内容 4 MiB，避免无界加载。服务地址由用户填写，和设备凭据一起放在用户目录的 `desktop-session.json`（权限 0600）。开发时 `TOMBOT_SERVER_URL` 只预填连接页，未设置时不会连接本机端口。换服务地址会清掉旧凭据。设备凭据只放在主进程。

分组不单独存储：侧栏分组由助手的 `group` 字段汇总，不保留空分组。创建分组必须同时移入当前猫咪；重命名分组会同步组内全部助手，并拒绝空白、超长或与已有分组重名。

主题偏好单独保存在 `tombot.theme.v1`，仅包含 `system`、`light` 或 `dark`。写入失败会提示并保留当前外观，重新选择可重试；无效偏好不会自动覆盖原值。它不修改工作空间结构，无需迁移；回滚界面改动时可以保留该独立偏好，旧版本不会读取它。侧栏宽度保留在当前窗口内存中，刷新后恢复 300 像素。

侧栏展示偏好单独保存在 `tombot.sidebar.v1`，只记录置顶、未读和隐藏的助手标识，不修改工作空间结构与会话内容。写入前完整校验并清理已删除助手，失败时提示且不应用本次展示变更；内容损坏时保留原文并暂时显示全部助手。删除助手会同时清理三类标识，隐藏项可在“我的工作空间”逐项恢复；旧版本不会读取该键，回滚界面时可保留或删除它。

同一应用只允许一个实例。保存失败会保留内存内容并显示持续提示。读取到损坏的旧档时拒绝覆盖。已发送的消息再次投递不会重复调用模型。没有配置模型时不会自动补发，也不会把未发送改成已发送。

启动方式和本阶段没有接上的能力见仓库 `server/MIGRATION.md`。

猫咪姿态只在 `features/avatars/pose.ts` 解析，取值为 `idle`（静息）、`working`（工作中）和 `hover`（悬停）。画面用 `assets/cats/frames` 里的 256 像素帧：睁眼原图、半闭和闭合的眼部叠层，以及预渲染的竖耳和抽耳整帧。22、34、56 像素即使按 3 倍屏也不超过 168 像素，所以不再打包 1254 像素原图。帧在切换前一次性解码；失败会记错误并停在睁眼原图，不会闪出缺图。眨眼和抽耳共用一个时钟，页面隐藏时暂停，恢复后不补做错过的动作。不同猫咪的第一下眨眼错开。系统开启减弱动效时一律停在静止睁眼原图。否则工作中优先于悬停，悬停优先于静息。悬停只发生在侧栏：展开列表、88 像素头像栏和置顶区都会跟着指针。会话标题、搜索和资料卡只反映静息或工作中。目标视线由 `features/avatars/spring.ts` 逐帧平滑成实际倾斜，只有当前这一只猫在跑倾斜弹簧；呼吸、弹入、压扁和工作中的点头都是 CSS 变换，不改变布局盒。换帧是立刻替换，不做交叉淡化。工作中的输入点画在头像角落，不盖住脸。

工作中不写入工作空间，保存「未发送」草稿也不会进入工作中，因此不会看起来像助手已经开始回复。传输层接入后，在同一渲染进程调用 `setAgentActivity(agentId, 'working')` 表示该助手的请求已经开始，在完成、失败、超时或不再处理时写回 `'idle'`；整路断开调用 `clearAgentActivities()`。也可以派发事件，而不扩展预加载脚本：

```js
window.dispatchEvent(
  new CustomEvent('tombot:agent-activity', {
    detail: { agentId, activity: 'working' },
  }),
)
```

助手标识必须去掉首尾空白、不含控制字符，最长 80。活动只能是 `idle` 或 `working`。同时处于工作中的助手不超过 64 只。非法事件会留下警告，并且不会把状态改成成功。活动只存在当前窗口的内存里，刷新后全部回到静息；重新打开后，传输层应按仍在进行的请求再报一次。这不修改 `tombot.workspace.v5`，没有数据库迁移。回滚界面改动时可以保留现有工作空间数据。

点击会话顶部的猫咪，会在聊天右侧滑出面板，再点一次、按 Esc 或点关闭按钮都会收起。关闭按钮与侧栏搜索、创建按钮共用圆形样式。名称旁的箭头朝右，默认不显示，悬停或键盘焦点时才出现，占位不变所以宽度不跳动。页签是详情、资料库和电脑。详情展示名称、介绍、分组，并用目录里的模型做下拉选择，选择会写进该猫咪的 `modelId`。资料库按今天、本周、更早列出该猫咪的产物，每组先显示 5 条；没有产物时是空状态，应用不会编造文件。电脑没有远端桌面服务，只保存这只猫咪自己的地址：空地址显示未连接，填入 HTTP(S) 地址后在沙箱 iframe 里嵌出画面。模型名单只有 `features/models/catalog.ts` 这一处。v4 升到 v5 时补上空的产物列表和空地址，v4 原文保留。

猫咪头像迁移仍由未改动的 `features/workspace/migrations/v2-cat-avatars.ts` 完成：它把 v1 颜色映射成猫咪标识，得到 v2 结构。消息回复、表情和发送状态仍由未改动的 `v3-message-interactions.ts` 补上。当前存储层把这两步的结果再交给 `v4-cat-model.ts`，然后由 `v5-cat-surfaces.ts` 补上产物和远端电脑地址，写入 v5。v1 到 v4 的原文都保留。迁移读取、校验或写入失败会显示错误并禁止编辑，避免覆盖原内容。这是一次本地线性遍历，不锁表，也不访问网络。

接入模型时，送出的对话要经过 `toModelTranscript`。回复会附上被引用的原文，说明文字用英文，因为那是给模型的上下文；界面只显示中文摘要。原文还在就用全文，已被删除才退回摘要。

回滚前应导出迁移后新增的消息和草稿，并在客户端关闭后备份用户目录。旧代码可读保留的低版本备份，但不会读取更高版本里的新字段。重新使用新版时优先读取 v5，缺失时再逐级升级。未来更改持久化结构需新增更高版本迁移，不能修改既有迁移文件。

Electron 窗口启用沙盒、上下文隔离和 Web 安全，禁用 Node.js 集成、外部导航、新窗口及页面权限；预加载不暴露文件系统或通用 IPC。参考 [Electron 官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。
