# TomBot 桌面客户端

左下角显示当前登录用户的昵称和自定义头像，未设置头像时使用默认图片。客户端启动、重新联网及窗口重新获得焦点时通过主进程读取本人资料，因此在网页修改昵称或头像后切回客户端即可更新；请求串行合并，读取失败保留上次成功资料并提示错误，不影响聊天。长昵称在侧栏内省略显示，悬停可查看完整昵称。

用户资料依赖 `GET /api/v2/auth/profile`，需先更新服务端，再构建并重启客户端；接口只接受当前桌面会话身份，不接受指定其他用户。头像按已有 2 MiB 上限内嵌返回，只在上述时机读取，不随十秒连接探测重复下载。无数据库迁移，回滚时还原服务端与客户端版本即可，已保存的个人资料不受影响。

### 聊天布局、侧栏摘要与关于

消息正文中的 `@名称` 保留，气泡不再重复展示一行提及标签；成员标识仍按原协议提交。完成提及后继续输入正文会关闭候选菜单，光标在布局阶段恢复，避免延迟定位打断快速输入。群聊助手气泡显示发言者头像和名称。机器人私聊沿用 Markdown 的正常空白规则，不再保留排版节点之间的多余换行。

返回最新消息按钮位于输入框上方中央；按下时保持定位变换，避免全局缩放把按钮移出指针导致点击丢失；点击后终止平滑定位并在下一帧复核底部，布局变化继续跟随，主动滚轮或触屏阅读可中断跟随。输入区移除顶部实色背景和额外顶边距。资料库文件以紧凑单行展示，使用已有 Lucide 图标区分文件类型；悬浮或键盘聚焦时展示文件名称、大小、时间及更多按钮，菜单集中提供预览、下载、重命名和删除。触屏保留更多入口。

群聊默认进入“未分组”，与机器人共用分类。可直接拖动机器人或群聊到目标分组，整个分组高亮并显示头像拖拽预览；默认主猫仍固定置顶。拖拽预览固定原始比例，不继承按下压缩、指针倾斜或动画姿态。机器人分类按原服务端保存流程提交，群聊分类沿用本机侧栏偏好，重开客户端仍保留。此前没有主动指定分类的群聊会自然进入“未分组”，无数据迁移。

启动后通过 `POST /api/v2/conversations/previews` 批量读取已加载目录中每个会话的最后一条摘要，之后在消息事件、窗口焦点恢复和十秒核对时刷新。每批最多一百个身份，服务端校验所属用户并利用现有会话消息序号索引一次查询，正文摘要最多八十个字符；空会话返回空摘要。请求串行合并，旧目录回包丢弃，低序号快照不覆盖新摘要；读取失败保留上次摘要并提示。草稿和未发送消息继续优先显示。

设置的“通用”下方新增“关于”，展示 Electron 应用版本、当前连接地址与公共只读接口 `GET /api/v2/version` 返回的服务端版本；读取失败显示原因并提供重试。正式发布脚本将清单版本写入程序，直接从 Git 构建则显示内置提交号（未提交构建附加 `-dirty`）；没有版本元数据时明确报错，不显示虚构版本。版本查询不携带会话凭据，不公开路径、环境变量或依赖信息。设置页所有错误集中显示在当前标题下方，多项错误同时保留；版本重试按钮位于对应提示右侧。

这次需先更新服务端，再重建并重启客户端，以启用批量摘要接口。没有数据库结构、索引或数据变更，无需新增迁移。回滚时恢复对应服务端和客户端构建即可，聊天记录与既有分类字段不受影响；旧客户端会恢复原来的群聊默认分组和布局。验证入口为 `npm run check`、`npm run test:e2e -- tests/e2e/chat-layout.spec.ts` 和服务端 `make lint check test`。

### 消息回复

回复预览与消息内引用使用统一的圆角灰阶卡片。预览标明回复对象，发送后的引用最多显示两行，可点击定位已加载的原消息。单聊通过 `reply_to_id` 提交原消息的服务端标识；回执或推送确认本地消息后，编辑中的引用和待发回复同步更新标识。发送失败重试仍使用相同幂等键及引用目标。

服务端历史直接返回 `reply_to: {message_id, excerpt}`，所以刷新、重开客户端或原消息不在当前分页中时仍显示摘要。模型上下文由服务端解析完整原文，客户端不拼接原文作为发送正文。服务端校验引用属于当前用户和当前会话，引用不递归展开，原文占用上下文预算。

需先通过 `tomd upgrade` 应用新增的 `0066_message_replies.sql` 并更新服务端，再构建和重启客户端。已丢失的旧回复没有服务端记录，无法自动补回；升级后的新回复会持久保存。迁移锁表、性能和回滚要求见[回复存储说明](../server/internal/execution/README.md#消息回复)。

### 表情与错误提示

单聊表情经主进程提交到服务端，确认后更新气泡；刷新、重开和其他设备同步均以服务端为准。添加、取消都会携带原消息上下文触发猫咪回应；已有任务进行时在下一次模型调用前读取。连续点击串行处理，网络失败保留原请求键供再次点击重试，服务端版本防止旧历史快照覆盖新标记。表情失败不进入草稿保存队列，不会阻止关闭客户端；重复请求及目标状态未变不会重复触发模型。可选表情来自服务端同一份 `reaction_emojis.json`，客户端构建需要完整仓库。

错误提示使用灰阶圆角卡片，文字可换行，只有提示图标保留警示色。回复预览与错误卡片均放在输入区，左右边缘与输入框对齐，相邻卡片及输入框之间保持 6 像素间距；多行输入、侧栏调整和资料栏展开时一同适应当前聊天宽度。关闭会清除实际显示的错误来源；已关闭的资料读取错误不会因同一故障的焦点刷新或迟到回包立即弹回，成功恢复后再发生故障仍提示。未保存草稿的错误保留“重试保存”，避免将丢失数据风险静默隐藏。

需先通过 `tomd upgrade` 应用 `0067_message_reactions.sql` 并更新服务端，再构建和重启客户端。表情交互会计入正常模型额度；迁移与整体回滚要求见[服务端表情说明](../server/internal/execution/README.md#消息表情)。旧版本仅在本地保存的表情不自动补发。

### 单聊消息稳定性

发送后立即追加本地消息并清空输入框，发送状态按每条消息独立展示；发送失败保留气泡并用原请求标识重试。服务端历史返回 `client_request_id`，客户端使用它关联本地消息与服务端消息 ID，因此推送先于发送回执到达也只更新同一个气泡。历史按服务端序号排序，尚未确认的消息保留本地发送顺序；无变化的快照保留原消息对象。

工作状态与消息列表独立：任务开始和进度事件只更新动画及摘要，消息创建、任务结束和重连时核对历史，每十秒核对一次以恢复遗漏事件。历史请求期间收到更晚的任务事件时，旧活动快照不覆盖新状态。工作状态区域预留高度，避免动画出现挤压历史；位于底部的读者跟随新内容，上翻阅读时保持位置，主动发送才回到底部，前插历史时补偿滚动高度。

此次需要先更新服务端，再构建并重启客户端。消息查询增加 `client_request_id` 字段，来自既有 `turns` 和 `run_inputs` 记录，单页至多一百条，使用现有用户、回合、消息索引；没有数据库结构或数据迁移。回滚时同时回滚服务端与客户端代码并重新构建，无需还原数据库。验证入口是 `npm run check` 和服务端的 `TestDesktopBrowserLogin` 浏览器联合测试；后者检查真实发送、推送、回执期间历史气泡与新气泡的 DOM 身份和消息区域高度。

## 持久单聊恢复与补充消息

进入会话立即加载最新 80 条消息和当前运行摘要，支持加载更早记录。事件触发快照刷新，断线时每 10 秒核对当前会话，连续订阅失败会显示提示；切换会话保留草稿。收到服务器确认后按消息标识合并，不把执行失败当成发送失败。每条消息的 ULID 同时作为稳定幂等键，重试沿用原键。

工作状态位于输入框左上，复用猫咪动画并显示模型报告的活动摘要。任务执行中仍可发送，服务端在模型调用边界读取补充消息，收尾期间到达的消息自动进入后续运行。需要 `0064` 迁移及配套服务端，升级和回滚遵循[执行模块说明](../server/internal/execution/README.md#执行中的补充消息与状态)。

基于 Electron、React 和 TypeScript 的独立桌面工程。布局参考提供的 Grok Bot 截图，默认窗口为 1073 × 780，使用原生 macOS 窗口控制、浅灰分组侧栏、猫咪卡通头像、黑白消息气泡和底部输入栏。按原始参考图在该窗口下的比例设置：侧栏宽 300 像素，列表头像为 34 像素，置顶头像为 56 像素，消息正文为 15 像素，消息气泡最大宽度为内容区的 76%；工具栏、输入栏和弹窗使用同一尺寸基准。

## 启动

需要 Node.js 22.12 或更高版本。所有命令均在 `desktop` 目录执行。

```bash
npm ci
npm run setup
npm run dev
```

`setup` 使用 Electron 官方安装器下载对应平台的运行时；Electron 45 不再随依赖安装自动下载运行时，需要首次安装后执行。开发模式支持界面热更新。

本机服务准备托管浏览器时使用仓库 `server/browser/` 里随 Git LFS 提供的官方离线 zip，不在引导过程中下载浏览器。需要先安装 Git LFS（macOS 为 `brew install git-lfs`），再在仓库根目录执行 `git lfs install` 和 `git lfs pull`。文件名和其他系统的安装方式见 `server/README.md`。

构建并打开生产资源：

```bash
npm run build
npm start
```

当前交付包含可运行工程及生产资源构建，不包含安装包签名、自动更新或应用商店分发。

## 招聘与消息发送

侧栏与搜索共用消息摘要规则：草稿优先；已发送消息和收到的 bot 回复只显示正文，本地未发送消息标注“未发送：”，发送失败标注“发送失败：”，私聊通知保留正文。发送回执确认后即时移除待发送标记。原侧栏无条件给普通消息加“未发送”前缀，已按实际发送状态修复；此问题仅影响摘要显示，无需修改或重新发送服务端消息。该修复及重命名样式只需重建客户端，无数据迁移，回滚客户端会恢复原来的展示问题。

招聘通过 `POST /api/v2/bots` 在服务端创建机器人和单聊会话；请求使用 ULID 幂等键，实际机器人与会话 ID 均取服务端回执。等待期间禁止重复提交或关闭弹窗，失败保留资料；同一表单重试复用请求标识。自定义头像通过独立头像接口保存，读取时每批最多四项，单个响应限制为 72 KiB。

创建后刷新工作空间修订号，再保存当前选择；消息发送到新机器人的服务端会话。客户端不填写模型或密钥，继续使用管理员分配的模型策略。新猫咪默认授权终端工具和标准审批模式，可使用支持工具调用的纯文本模型。

此次只需重建并重启客户端，不修改服务端接口和数据库。旧客户端仅在内存中添加、未成功注册的猫咪需要在新版重新招聘；已经注册的猫咪会从服务端恢复。回滚可恢复上一版桌面构建，服务端记录无需删除，但旧版的招聘缺陷也会恢复。

消息受理后，即使后续运行失败、取消或结果未知，客户端也会读回服务端已持久化的消息并显示失败原因，不再将已接收的消息标成“未发送”。服务端模型记账权限修复及 `0062` 迁移的升级、回滚说明见[执行模块](../server/internal/execution/README.md#一键安装身份下的模型用量校验)。该客户端调整不改变接口或本地存储；重建并重启生效，回滚客户端会恢复原先的失败展示行为。

验证包含客户端检查和真实 Electron、Chromium、PostgreSQL 联调：登录、招聘、刷新恢复、消息及运行记录入库。联调用例不连接外部模型或生产电脑节点；模型成功回复路径由独立接口回归覆盖。

## 已实现功能

- 分组助手列表、默认助手置顶、会话切换；拖动侧栏右侧边界调整宽度，展开范围为 240～400 像素，低于 240 像素自动收缩为 88 像素头像栏，向右拖动可重新展开。分隔线也支持方向键和 Home / End。
- 助手支持右键菜单与键盘 `Shift+F10` 打开：置顶/取消置顶、移至分组、标为未读/已读、内联重命名、复制对话 ID、从侧边栏隐藏和删除。`移至 → 创建分组`会立即新建分组、移入当前猫咪，并把分组标题切换为可编辑输入框；重命名猫咪时直接在侧栏原位置修改名称，输入框使用主题浅边框、圆角与柔和聚焦光圈，保留回车提交、失焦提交和 Esc 取消。菜单按光标位置自动避让窗口边缘，支持方向键、分组子菜单及 `Escape` 关闭；默认猫咪固定置顶且不可隐藏或删除，隐藏的助手可在“我的工作空间”恢复。
- 招聘猫咪弹窗宽 480 像素，提供 8 款可区分的猫咪头像、分组选择、名称及容量校验。头像使用随应用打包的 256 像素透明 PNG 帧，深浅主题不反色、不从网络加载。列表 34 像素、置顶 56 像素、会话标题 22 像素。静息时呼吸、轻摆，并按各自的节奏眨眼；指针悬停在侧栏（含 88 像素头像栏和置顶）时耳朵竖起并抽一下进场那一侧，头部按弹簧转向指针，进入时轻弹，按下时压扁；工作中保持竖耳、点头，角落显示输入点。帧要先解码完才切换，失败时停在睁眼原图。保存草稿不会进入工作中。系统开启减弱动效时只显示静止原图。详见 [猫咪头像](src/renderer/src/assets/cats/README.md)。
- 主题、语言与分组统一使用自绘选择器；支持方向键、首尾跳转、输入名称前缀定位、回车确认、Esc 取消、Tab 离开及外部点击关闭。菜单以弹出层展示，根据窗口空间向上或向下展开，适配深浅主题，不依赖系统原生下拉菜单。
- 搜索助手资料、本地消息和设置选项，支持 `⌘K` / `Ctrl+K`、方向键选择、回车打开及 `⌘1–9` / `Ctrl+1–9` 快速选择；`Escape` 关闭弹窗。
- 点击“我的工作空间”查看助手和草稿概况。按钮上是一张静止的原创橘虎斑猫头像，裁在圆框里，不跟随助手的眨眼和悬停动画。右侧齿轮与这个圆框同尺寸，独立打开双栏设置页；通用栏目顶部展示当前登录用户的头像、昵称和用户名，账号卡片只提供退出登录，下面保留主题与语言选项。设置、搜索和猫咪详情均不展示模型策略。
- 浅色、深色主题即时切换并保存；选择“跟随系统”后实时响应系统外观变化。消息、侧栏、所有弹窗和表单统一适配。
- 聊天顶部使用渐变与背景模糊，滚动内容自然淡出；滚动条仅在鼠标悬浮于对应滚动区域时显示。表单聚焦不出现额外外框。
- 每个助手独立保存消息和输入草稿；重新打开客户端可恢复。
- 猫咪生成回复正文时，输入框上方显示“正在输入…”，完整回复确认成功后才整条显示；生成失败、超长截断或取消均不显示未发送的正文。继续思考或调用工作工具时切回工作状态，群聊发言参数生成时也显示输入状态。重开聊天从服务端恢复活动和完整历史。回复沿用品种语气，以自然聊天汇报为默认，仍保留任务需要的证据、技术细节和指定格式。
- 群成员面板显示当前用户自己的头像，未设置时使用工作空间默认头像；群主和猫咪头像、姓名分别对齐，“群主”标签靠右。
- `Enter` 保存本地草稿，`Shift+Enter` 换行；中文输入法选字不会触发保存。
- 消息气泡可右键或悬停操作：快捷表情、更多表情、回复、复制和删除；只有消息带请求标识时才出现“复制请求 ID”。未发送和发送失败不再把时间和按钮放在气泡下面，只在朝向会话中央的一侧显示红色感叹号。服务端模型策略不可用时消息保持未发送，并提示联系管理员检查配置；模型调用失败才标为发送失败。回复先在输入框上方给出可取消的引用，发出后在气泡里保留摘要，点击可滚回原消息。悬停快捷按钮平时只显示图标，指针停在单个按钮上才出现浅灰圆角底。表情显示在气泡内部、正文下方的小胶囊里，数量大于 1 才显示计数，再次点同一个表情会取消。会话第一条，或与上一条间隔超过 5 分钟，会在消息前居中显示时间：今天为 `HH:mm`，昨天为“昨天 HH:mm”，一周内为“星期X HH:mm”，更早为“YYYY年M月D日 HH:mm”。输入框的加号或拖放可以上传图片和文件。聊天页不再显示分享或侧栏收缩按钮。
- 存储异常提示、保留未落盘的内存内容、重试保存、损坏内容防覆盖。
- 最小 860 × 640 窗口适配、键盘焦点、原生模态框与减弱动画设置。

未登录时先填写或确认远端服务地址，确认后点击“在浏览器中登录”，使用已激活的普通用户账号及密码登录，完成后自动回到客户端。没有已保存地址时不会猜测本机端口，也不会停在「正在连接服务」。地址保存在本机用户目录；下次打开若未登录则预填并等待确认，已有有效会话时自动恢复。登录页始终显示当前服务地址并提供“修改地址”，授权进行中暂时禁止切换；换到另一台服务会清除上一台的本地登录凭据。连不上时可以修改地址再试。模型及凭据在管理平台统一配置，客户端登录后直接打开工作空间，空工作空间直接进入招聘。发送时由服务端解析分配的模型策略；策略不可用时报告错误，不显示供应商、API 密钥或默认模型初始化表单。头像与初始使用指南仍是本地资源。语音仍不可用。图片和文件会上传到服务端，供 agent 读取。

地址确认交互只需更新并重启客户端，无数据库或服务端接口变更；回滚客户端不会更改已保存的地址格式。真实窗口回归可在 `desktop` 目录执行 `npm run build` 和 `npx playwright test tests/e2e/server-address.spec.ts`，覆盖首次指定、修改、重启预填，以及深浅主题与长地址显示。

整条回复和输入状态需配套构建、更新服务端与客户端，使用已有运行摘要和事件字段，无新增数据库迁移或节点协议变化。状态只在生成阶段变化时入库、推送，不随正文片段重复写入。回滚此项时恢复匹配的应用构建；同批私信协作涉及的 `0071` 迁移须按[私信协作说明](../server/docs/messaging.md)单独处理。单元与执行器回归覆盖完整发送、失败、截断、取消和重开状态恢复；浏览器联合测试验证群主头像及深浅主题、窄窗口对齐。

### 自签名 HTTPS 证书

`tomd install` 签发的自签名证书首次使用时会显示“证书尚未受信任”。请由管理员在服务器执行 `tomd status`，把“证书 SHA-256 指纹”提供给用户；在客户端粘贴该指纹，点击“验证并信任证书”，再继续浏览器登录。客户端只在指纹、主机名、有效期均符合时保存公共证书；验证前的 TLS 握手不发送 HTTP 请求或登录凭据。

信任按完整服务源站（协议、主机、端口）保存在 Electron 用户目录 `server-trust/`，记录权限为 0600，采用临时文件与原子重命名发布；失败保留原记录。证书不自动扩展到其他端口或主机，请求不跟随重定向。登录、续期、事件流、上传与下载共用同一连接层，继续检查证书链、有效期、主机名及固定指纹；证书换新后必须重新核对。验证期间禁止切换服务和并发发起登录。系统浏览器的证书信任独立管理，不修改系统全局证书库。

此次只需更新依赖、构建并重启客户端，无服务端或数据库变更。回滚客户端和依赖锁文件即可，公共证书记录可保留；旧客户端不读取该目录，自签名服务仍需其原有系统信任。删除对应信任记录后重启客户端可撤销本地信任，不影响账户和服务端数据。

### 浏览器登录修复与升级

发起浏览器授权与交换授权码使用公开认证接口，不检查或刷新旧会话、不携带旧访问凭据；业务请求仍需要有效会话。系统浏览器打开服务端 `/authorize`，提交用户口令后回调本机随机回环端口，再通过一次性授权码与 S256 校验串换取会话。失败不自动重发，完成或失败均释放回环监听及超时定时器。会话保留服务端返回的用户名，供本机草稿隔离使用。

升级需重新构建并重启桌面客户端，同时替换已补齐 `/authorize` 路由及挑战校验的 `tomd`。现有账户、密码、数据库结构及授权记录格式不变，无需重新激活或迁移数据；升级时正在进行的登录可从客户端重新发起。回滚应同时恢复匹配的客户端和服务端构建；旧版首次浏览器登录仍存在已知故障，不能仅回滚其中一端。

真实登录验收使用独立 PostgreSQL、HTTPS 应用、Electron 和 Chromium，先执行 `npm run build`，再从 `server` 目录运行：

```bash
TOM_TEST_PLAYWRIGHT_MODULE="$PWD/../desktop/node_modules/playwright/index.mjs" \
TOM_TEST_DESKTOP_DIRECTORY="$PWD/../desktop" \
go test -race -tags=browserintegration ./internal/serverapp -run TestDesktopBrowserLogin -count=1
```

PostgreSQL 工具未在 PATH 中时需设置 `TOM_TEST_POSTGRES_BIN`。该验收不读取或修改日常用户目录，登录材料经标准输入传入测试进程，不写入命令参数或日志。

该联合测试覆盖普通用户网页登录、个人信息、复用网页会话授权、授权结果页深浅主题与窄屏显示，以及真正退出并重启客户端后的历史恢复。测试不连接外部模型，明确核对任务失败时已发送消息仍保留、提示可关闭且不触发未保存退出警告；执行中补充消息与模型工具边界由执行模块的 PostgreSQL 回归覆盖。

主题和语言偏好保存在本机；界面语言仍是简体中文。语言使用独立的 `tombot.language.v1` 键，损坏或保存失败会明确提示。模型、凭据和参数均由管理平台维护。

招聘和猫咪详情不再提供模型选择器，设置和搜索也不提供模型策略入口；旧模型配置页面、拉取供应商接口以及提交密钥的 IPC 通道已删除。招聘的预设与自定义类型使用 34 像素高、按内容宽度排列的紧凑切换控件。

设置中的账号信息与侧栏共用本人资料，缺少昵称时显示用户名，读取失败明确提示。退出登录期间禁用重复提交，通过现有注销接口撤销会话并清理本地凭据，再按实际会话状态返回登录或连接页；失败不会伪装成功。此次界面调整只需重建并重启客户端，无接口、存储和数据库迁移；回滚桌面构建即可恢复原界面，已注销的会话仍需重新登录。

本次需重建并重启客户端；浏览器登录页样式还需重建并升级 `tomd`。无需数据库迁移或重新激活账号。语言偏好默认跟随系统，可在本机重新选择；不读取旧模型设置接口。回滚可替换原客户端及服务端二进制，不修改账户和模型策略记录；旧客户端会重新出现原有的模型初始化问题。

## 状态与后续服务端接入

工作空间的权威副本在服务端 `desktop_state`。客户端仍能读取旧的 `tombot.workspace.v5`（以及更早版本）：服务端还是预设、没有用户改动时导入一次，损坏的旧档会阻止继续编辑且不覆盖原文。导入之后不再把工作空间写回 localStorage。头像使用 `avatar` 预设标识。可选模型集中在 `features/models/catalog.ts`。消息含角色、发送状态、可选请求标识、回复摘要和表情。限制为 64 位助手、全局 500 条消息、单条 10000 字、序列化内容 4 MiB，避免无界加载。服务地址由用户填写，和设备凭据一起放在用户目录的 `desktop-session.json`（权限 0600）。开发时 `TOMBOT_SERVER_URL` 只预填连接页，未设置时不会连接本机端口。换服务地址会清掉旧凭据。设备凭据只放在主进程。

分组不单独存储：侧栏分组由助手的 `group` 字段汇总，不保留空分组。创建分组必须同时移入当前猫咪；重命名分组会同步组内全部助手，并拒绝空白、超长或与已有分组重名。

主题偏好单独保存在 `tombot.theme.v1`，仅包含 `system`、`light` 或 `dark`。写入失败会提示并保留当前外观，重新选择可重试；无效偏好不会自动覆盖原值。它不修改工作空间结构，无需迁移；回滚界面改动时可以保留该独立偏好，旧版本不会读取它。侧栏宽度保留在当前窗口内存中，刷新后恢复 300 像素。 助手列表在滚动条两侧保留对称空间，选中背景左右留白一致。助手和群聊分组标题的箭头位于右侧，平时隐藏；鼠标悬停或键盘聚焦时显示箭头与圆角背景，点击、回车及空格均可切换折叠状态。分组标题与头像共用左右内边距，窄窗口下也保持左对齐；标题与条目、相邻条目及相邻分组均使用 5 像素间距。分组收起时右侧显示实际收起的猫咪数量，已置顶或隐藏的猫咪不重复计入；群聊分组显示群聊数量。

侧栏展示偏好单独保存在 `tombot.sidebar.v1`，只记录置顶、未读和隐藏的助手标识，不修改工作空间结构与会话内容。写入前完整校验并清理已删除助手，失败时提示且不应用本次展示变更；内容损坏时保留原文并暂时显示全部助手。删除助手会同时清理三类标识，隐藏项可在“我的工作空间”逐项恢复；旧版本不会读取该键，回滚界面时可保留或删除它。

同一应用只允许一个实例。保存失败会保留内存内容并显示持续提示。读取到损坏的旧档时拒绝覆盖。已发送的消息再次投递不会重复调用模型。没有配置模型时不会自动补发，也不会把未发送改成已发送。

启动方式和本阶段没有接上的能力见仓库 `server/MIGRATION.md`。

猫咪姿态只在 `features/avatars/pose.ts` 解析，取值为 `idle`（静息）、`working`（工作中）和 `hover`（悬停）。画面用 `assets/cats/frames` 里的 256 像素帧：睁眼原图、半闭和闭合的眼部叠层，以及预渲染的竖耳和抽耳整帧。22、34、56 像素即使按 3 倍屏也不超过 168 像素，所以不再打包 1254 像素原图。帧在切换前一次性解码；失败会记错误并停在睁眼原图，不会闪出缺图。眨眼和抽耳共用一个时钟，页面隐藏时暂停，恢复后不补做错过的动作。不同猫咪的第一下眨眼错开。系统开启减弱动效时一律停在静止睁眼原图。否则工作中优先于悬停，悬停优先于静息。悬停只发生在侧栏：展开列表、88 像素头像栏和置顶区都会跟着指针。会话标题、搜索和资料卡只反映静息或工作中。目标视线由 `features/avatars/spring.ts` 逐帧平滑成实际倾斜，只有当前这一只猫在跑倾斜弹簧；呼吸、弹入、压扁和工作中的点头都是 CSS 变换，不改变布局盒。换帧是立刻替换，不做交叉淡化。工作中的输入点画在头像角落，不盖住脸。

工作中不写入工作空间，保存「未发送」草稿也不会进入工作中，因此不会看起来像助手已经开始回复。传输层接入后，在同一渲染进程调用 `setAgentActivity(agentId, 'working')` 表示该助手的请求已经开始，在完成、失败、超时或不再处理时写回 `'idle'`；整路断开调用 `clearAgentActivities()`。也可以派发事件，而不扩展预加载脚本：

```js
window.dispatchEvent(
  new CustomEvent('tombot:agent-activity', {
    detail: { agentId, activity: 'working' },
  }),
)
```

助手标识必须去掉首尾空白、不含控制字符，最长 80。活动只能是 `idle` 或 `working`。同时处于工作中的助手不超过 64 只。非法事件会留下警告，并且不会把状态改成成功。活动只存在当前窗口的内存里，刷新后全部回到静息；重新打开后，传输层应按仍在进行的请求再报一次。这不修改 `tombot.workspace.v5`，没有数据库迁移。回滚界面改动时可以保留现有工作空间数据。

点击会话顶部的猫咪，会在聊天右侧滑出面板，再点一次、按 Esc 或点关闭按钮都会收起。关闭按钮复用侧栏圆形样式。页签仅保留“动态”和“资料库”；动态展示电脑与任务，不展示名称、分组、介绍或模型策略。电脑卡片左侧为猫咪名称和连接状态，右侧为灰色缩略图；默认收起连接配置，点击后可准备、连接、填写地址或查看已有画面。未配置地址显示“未连接”，不推断服务端是否休眠；已有地址显示“已连接”，画面使用原沙箱 iframe，断开只清空这只猫咪的地址。任务通过对话创建和修改，卡片提供启停开关及更多/右键删除菜单，显示下次时间、时区、执行结果和等待投递状态；读取、操作失败明确显示错误。任务变更事件即时刷新列表，断线由有界分页和轮询补足。资料库按今天、本周、更早列出产物，每组先显示 5 条。

任务功能需配套升级客户端和服务端，应用新增 `0069_scheduled_tasks.sql`。任务按时进入独立后台会话和桌面执行，聊天忙碌不跳过；只有完成结果等待当前对话结束再写入聊天。停用或删除停止后续计划，已受理运行继续。升级、资源边界、重启恢复与回滚见[持久任务说明](../server/internal/scheduledtasks/README.md)。介绍组件及其客户端 IPC 已移除，不再轮询介绍。

猫咪头像迁移仍由未改动的 `features/workspace/migrations/v2-cat-avatars.ts` 完成：它把 v1 颜色映射成猫咪标识，得到 v2 结构。消息回复、表情和发送状态仍由未改动的 `v3-message-interactions.ts` 补上。当前存储层把这两步的结果再交给 `v4-cat-model.ts`，然后由 `v5-cat-surfaces.ts` 补上产物和远端电脑地址，写入 v5。v1 到 v4 的原文都保留。迁移读取、校验或写入失败会显示错误并禁止编辑，避免覆盖原内容。这是一次本地线性遍历，不锁表，也不访问网络。

在线单聊的模型上下文由服务端 `messageForModel` 统一组装。引用说明使用英文，界面显示中文标题与原文摘要；客户端的 `toModelTranscript` 仅用于本地消息转换，不参与在线执行。

回滚前应导出迁移后新增的消息和草稿，并在客户端关闭后备份用户目录。旧代码可读保留的低版本备份，但不会读取更高版本里的新字段。重新使用新版时优先读取 v5，缺失时再逐级升级。未来更改持久化结构需新增更高版本迁移，不能修改既有迁移文件。

Electron 窗口启用沙盒、上下文隔离和 Web 安全，禁用 Node.js 集成、外部导航、新窗口及页面权限；预加载不暴露文件系统或通用 IPC。参考 [Electron 官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。

### 聊天体验与运行状态

创建群聊沿用招聘表单的宽度、输入框和按钮，成员按头像卡片选择；名称空白或没有成员时禁止创建，保存期间防止重复提交。搜索在没有关键词时也列出招聘、创建群聊和通用设置；输入关键词后仍按匹配结果过滤。

侧栏服务地址前的圆点来自真实会话探测：正常为绿色，连接或鉴权异常为红色。每次探测结束后等待 10 秒再探测，窗口重新获得焦点或网络恢复时提前探测；同一窗口不叠加探测，关闭后清理计时器。探测复用主进程已有的请求超时，不会因为模型上游失败把正常的应用服务标为断开。

招聘成功后进入服务端创建的空会话，由用户发送第一条消息。当前 v2 接口不创建独立的欢迎回合；普通消息通过会话接口受理为运行，结束后读取服务端消息列表。

模型通过运行时提供的 `report_progress` 工具提交一句不超过 60 字的中文工作摘要。`run.progress` 事件包含 `run_id`、`turn_id`、`bot_id` 和 `text`；桌面事件流把当前回合及其子任务的公开摘要转为 `process`，并携带运行和猫咪标识，不转发原始思考内容。工作动画由实际执行事件驱动：发送者交出任务后恢复空闲，接收者开始执行时显示自己的动态头像和摘要；发送者收到回执并继续处理时才恢复动画，不增加等待回复状态。实际执行期间尚未收到摘要时显示“正在思考…”，完成和失败时清除；减少动态效果偏好会让头像静止。群聊只显示实际工作的成员头像，最多展示三只，其余显示数量。等待区复用已有的点头、眨眼和抽耳动画，不新增动画计时器，也不反向修改全局活动状态。不同请求的 IPC 流使用独立请求标识过滤，切换猫咪不会把状态混入另一段聊天。模型需支持并调用工具才能产生专用摘要；直接回答和等待首段输出时使用通用等待文案。进度工具随正常模型回合执行，不另起摘要模型请求，但会占用工具输出 token 和运行步骤。

聊天顶部胶囊平时不为箭头或箭头间距留位，悬停和键盘聚焦时展开，离开后收回。定时任务和资料库共用虚线圆角空状态样式；读取失败显示错误，不展示为空列表。

招聘只填写名称并选择品种和分组，不再预先填写一句话介绍。当前 v2 执行器在具备工具能力的私人单聊中提供长期记忆：模型根据用户明确表达的偏好、习惯、工作方法和持续项目事实，先检索再按版本更新，并绑定当前回合的用户原话来源。每只猫咪独立保存在服务端，重新打开聊天或原始聊天超出上下文后仍能使用摘要和检索；可以通过对话查看、纠正或遗忘。不会批量推断旧聊天，不另起后台总结请求。具体额度、模型能力边界、迁移与回退见 [新版长期记忆说明](../server/docs/bot-memory.md)。

八种猫咪的默认语言风格在服务端运行时注入，界面不展示风格配置。运行时复用读取身份时的头像品种字段，不额外查询、不重写历史身份，现有猫咪的后续运行也会生效；用户明确要求的语言、语气和输出格式优先。此项不改变接口或数据库结构，只增加少量上下文文字。回滚服务端即可恢复原语气与记忆指引，已保存的记忆仍可读取，无需删除或转换数据。

助手正文和私信使用 `react-markdown` 与 `remark-gfm` 渲染标题、列表、强调、引用、代码块和表格，原文仍保留用于复制、搜索和持久化。原始 HTML 不执行，图片仅显示替代文本，附件继续走原有预览通道。

前述欢迎、Markdown 和等待动画不修改数据库结构；群聊及展示介绍的迁移说明见下文。部署时先更新服务端，再重新安装锁定依赖并构建桌面端；新桌面端与服务端需要配套升级。回滚时一起恢复桌面端、服务端和依赖锁文件；已保存的模型欢迎回复仍是普通消息，系统欢迎触发在新版中只作为模型上下文；旧服务端回滚后可能把该系统文本显示为气泡，应优先回滚桌面样式并保留新版服务端的系统消息过滤，或在完整回滚前备份并恢复升级前数据库。新增进度事件不改变消息存储格式，无需数据回滚。

### 群资料与后台记忆

右栏分割线与左侧共用 `--sidebar-border`；顶部胶囊左右各留 14 像素。助手分组和群聊分组可分别折叠，状态保存在当前设备 `tombot.collapsed-groups.v1`，不修改工作空间数据。写入失败保留原状态，损坏内容保留原文并提示。

群头像由当前成员的猫咪头像组合。侧栏群聊与猫咪共用右键菜单，群聊使用“重命名聊天”，猫咪使用“重命名猫咪”；群右栏仅保留“成员”“资料库”，成员在前。群消息切换到 v2 持久接口，受理后可以继续发言，引用和提及重开后保留；运行状态仅显示当前群成员在该群的活动。普通发言广播，@ 或回复指定猫咪时定向通知，bot 可继续转交或 @ 用户。群附件与资料库暂未接入 v2，会明确提示不可用。接口、并发与 `0070` 的部署回滚见[群聊说明](../server/docs/groups.md)。

前端不再提供记忆入口或介绍栏，当前长期记忆通过对话工具维护，详见 [新版长期记忆说明](../server/docs/bot-memory.md)。下面记录旧版迁移历史，介绍缓存不再被客户端请求。

新增 `0026_bot_introductions.sql` 保存独立介绍缓存，同时把旧桌面猫咪从介绍派生的岗位改为通用“助手”；非桌面 Bot 的岗位不变。此迁移新建空表并更新桌面猫咪（最多 64 位），持有短暂写锁。新增 `0027_equal_group_members.sql` 实施平等群成员与提及可见范围，涉及旧群配置列删除和快照回填，需要维护窗口。历史迁移均未修改。升级需先备份、停活动回合，服务端和桌面端配套更新；完整回滚必须恢复升级前完整数据与工作区及匹配旧版本，升级后新增内容应先另行保全。不能让旧客户端直接使用新群接口，也不能修改历史迁移撤销升级。

本轮新增自定义猫咪（头像上传与初始介绍）、文件粘贴、私聊直接交付用户和消息顺序修复。桌面与服务端需要配套升级到数据库版本 28；数据契约、限制、验证与回滚见[自定义猫咪与直接交付](../server/docs/custom-cats-and-delivery.md)。

v2 私聊展示、直接交付用户及跨会话工作状态已接入；需要与数据库迁移 `0073` 的服务端配套更新。消息契约、失败与恢复、升级和回滚见[私信协作说明](../server/docs/messaging.md#直接交付用户与桌面展示0073)。
