# 客户端与管理平台共享组件和样式

`theme.css` 保存从客户端提取的浅色和深色语义变量；`controls.css` 保存主次按钮、表单反馈、输入控件和模态框外观。两端直接导入同一份文件，避免主题和基础组件样式各自演化。

`Select.tsx` 与 `select.css` 提供两端唯一的自绘单选菜单实现，支持方向键、首尾定位、按名称定位、Enter/Space 确认、Escape 取消、Tab/外部点击关闭，以及禁用项和读屏标签。菜单使用浏览器 Popover 顶层，随滚动和窗口变化重新定位，不会被模态框或列表滚动区域裁剪。

管理平台的 `src/components/Select.tsx` 只增加表单适配：保留 FormData 值、必填检查与错误焦点；隐藏的文本控件承接原生约束校验，页面没有原生下拉菜单。桌面原路径已删除，所有使用方直接引用共享组件。两端构建通过 `resolve.dedupe` 使用自身 React 和图标依赖，TypeScript 路径与之对应；管理端静态检查同时覆盖共享源文件。

共享控件不包含 Electron 窗口拖拽、IPC、品牌动画或业务状态。网页与桌面可以用组件尺寸变量调整弹窗宽度和内边距；浏览器专用布局放在独立 CSS 文件中，平台特有行为保留在各自目录。

修改后执行 `admin` 的 `npm run check` 与 `desktop` 的 `npm run check`、`npm run build`，并检查对应主题下的实际界面。管理平台浏览器检查入口为 `admin` 中的 `npm run test:e2e`。

浏览器登录页的布局使用 `browser-login.css`；管理平台构建时将它与同一份主题和控件样式输出为 `assets/login.css`，同时打包共用的猫咪头像。登录页保持无脚本，深浅主题跟随浏览器系统偏好。两项固定路径资源随 `tomd` 内嵌发布，无额外部署文件。

普通用户登录、授权确认和桌面回调结果复用 `browser-login.css`。回调页将样式及头像内联到本地响应，不依赖服务端静态资源；样式和清理一次性地址参数的脚本使用内容哈希 CSP。只有授权交换与客户端会话保存都成功时才显示“授权成功”。

`user-platform.css` 提供普通用户平台的两栏布局，沿用管理端的侧栏尺寸、账户入口和主题变量；构建时与 `theme.css` 一同输出 `assets/user-platform.css` 并内嵌到 `tomd`。桌面宽度下账户信息固定在左下，窄屏压缩为可访问的图标导航，账户菜单使用原生键盘可操作的折叠控件。个人信息由服务端模板自动转义，昵称与头像由服务端保存。`user-profile.js` 管理昵称原位编辑和头像裁剪，`avatar-crop.js` 在解码前检查原图大小与格式并计算有界裁剪区域。点击原头像选择 PNG/JPEG，支持拖动、方向键和缩放；点击“确认更换”生成 512×512 PNG 并立即保存，成功后同步更新资料区和侧栏头像。上传中禁止重复确认或取消，失败保留裁剪供重试。昵称按 Enter 或焦点离开编辑区时直接保存，Esc 和取消按钮恢复原值。`profile-save.js` 按字段发送带 CSRF 的同源请求，设置 15 秒时限，不自动重试；失败保留编辑并提示，未知结果不默认成功。取消或离开页面释放位图，原图不上传。`user-platform.js` 负责菜单关闭与主题切换，独立记住用户平台的浅色、深色或跟随系统偏好，存储失败时显示提示；管理构建将脚本内嵌到 `tomd`，静态检查和类型检查覆盖这些脚本。该样式仅由用户平台加载，不改变管理端或桌面端布局。
