# 受保护节点 API

本模块提供 API/Worker 到受信 Docker 节点的通信边界。API 与节点可以分处不同主机：跨主机访问使用 HTTPS 与双向证书，默认只放行私网地址，公网监听必须由部署显式声明。`Client` 实现电脑生命周期、执行会话、终端、图形状态和 Bot Agent 以及控制心跳接口，可分别传给开户服务、电脑控制服务、执行 Worker 和电脑工具。应用服务以专用非 root UID/GID 运行，不持有 Docker socket；节点执行固定业务操作，不开放通用宿主命令。

协议与监听器已实现并通过真实 TLS 握手验证。`tomd` 已通过 [serverapp](../serverapp/README.md) 接入本客户端；[独立节点服务](../nodeapp/README.md)已组合基础探针，完整能力发布与真实节点部署尚未验收。

## 端点及身份

节点在 `listen` 指定的 TCP 地址上终止 TLS 1.3，并要求客户端出示证书。`ParseFingerprints` 只接受规范小写十六进制；`ServerTLS` 与 `ClientTLS` 各自固定对方叶证书的 SHA-256，信任来自配置而不是证书链，因此不需要维护 CA。指纹固定替代链校验，所以回调里同时补做有效期检查——否则过期证书仍然可用。

`Listen` 默认只接受回环与私网地址；公网暴露必须由部署在配置中显式允许，因为节点持有 root 与 Docker 权限。拒绝原因不回给调用方，避免暴露内部判定顺序。

连接数显式限定为 1–1024。HTTP 请求体上限 128 KiB，超出立即拒绝；取消后停止接受新请求并在退出预算内等待在途请求结束，超时返回 `ErrUnfinishedOperations`，进程入口必须退出，不能继续对外宣称就绪。

## 固定动作和消息边界

复用 [agentchannel](../agentchannel/README.md) 的规范 JSON 编解码做内容校验，动作以 `POST /v2/actions` 提交，响应体为 `response`。未知字段、重复键、大小写别名、额外对象、错误节点或错误请求标识均拒绝。请求与响应都携带 `request_id`，客户端据此拒绝串话。

| 能力             | 固定动作                                                 | 权限依据                                               |
| ---------------- | -------------------------------------------------------- | ------------------------------------------------------ |
| 控制心跳 | `heartbeat` | 固定节点、受保护进程实例、持久代次及序号，不授予 ready |
| 首次开户生命周期 | `inspect`、`ensure`、`remove`                            | 固定节点、资源规格、实例代次、操作标识、租约和控制代次 |
| 执行会话         | `open`、`renew`、`close`                                 | 完整桌面身份、运行、版本及绝对租约                     |
| 终端             | `start`、`read`、`write`、`resize`                       | 当前会话及操作 ID，不接收宿主设备或 PID                |
| 图形状态         | `desktop_start`、`desktop_status`                        | 当前会话及固定桌面尺寸                                 |
| 画面与输入       | `desktop_capture`、`desktop_image_read`、`desktop_input` | 当前会话、截图或输入持久递增序号、分块边界及完整手势       |
| Bot Agent        | `agent_start`、`agent_write`、`agent_read`               | 当前会话、固定程序、有界字节块及连续偏移               |

客户端与节点共用类型、字段、归属和结果校验。收到 `ready` 还必须具备全部真实能力探针标志，不能用连接可达替代就绪。响应核对请求 ID、节点、动作、业务身份、状态及游标；既有节点和容器代理仍逐动作执行持久授权检查。

新增画面通道仍使用现有 128 KiB 控制帧，不传输任意桌面连接地址。PNG 分块最多 32 KiB，元数据固定 1280×800 并携带 SHA-256；输入最多 512 个有界事件，必须在同批次释放按钮与按键。`sent` 仅表示完整写入桌面连接，`uncertain` 必须按未知副作用处理，不能自动重发。详细序号与缓存规则见[电脑代理](../computeragent/README.md#桌面截图与完整输入手势)。模型截图与输入工具已使用这些接口，公开用户网关仍待接入，不能把本机协议通过当作完整产品桌面已交付。

## 跨进程期限和错误

客户端和节点调用期限配置为 1–60 秒；较短的上游上下文仍优先生效，客户端配置不能大于节点配置。单次 RPC 期限在发送前转换为内核绝对单调时钟，节点核对同一时间命名空间并保守换成本地期限，排队、连接和传输均计入。该协议只用于同一 Linux 内核，不是跨节点网络协议。

调用期限以剩余毫秒传递（`remaining_ms`），不再是绝对单调时钟：两台机器的时钟不必一致，节点按收包时刻重建期限，传输与排队只会让到期更早。`open` 和 `renew` 另携带 `lease_remaining_ms`，节点通过 `computer.WithLeaseDeadline` 传给执行控制器，实际期限取本地租期与已接收期限的较早者；持久命令和版本保持不变。重复版本仍沿用原节点授权，不能用重新连接或新的传输时间延长租约。取消请求不等于执行会话已清理，关闭与看门狗继续独立工作。

传输层不重发请求。已知节点失败仅传递固定分类与是否永久失败，原始 Docker 错误、命令和输出不进入日志或错误回包；其他错误标为结果未知。响应丢失、超时、取消或校验失败都不能解释为动作未执行。开户服务按已有身份对账，执行 Worker 保留未知操作并清理所属运行，不新建操作 ID 补发。

## 验证和发布

常规测试覆盖全部 19 个动作的类型与节点归属、错误结果、配置、能力状态和期限。`nodeintegration` 验收启动真实 TLS 服务与客户端，覆盖完整接口、32 KiB 二进制传输、未登记证书在握手期被拒绝、畸形请求、伪造响应、失联、容量、取消和剩余期限传递。Docker 节点与代理的持久状态测试另核对接收期限确实传递到实际节点租约与代理授权。

测试后端使用受控业务实现，验证真实通信和身份边界；不证明实际 Docker 开户、磁盘配额、网络出站隔离或生产 cgroup 清理已完成。正式组合仍必须使用 `dockernode.Runtime` 和 `SessionController`，不得把测试探针或空能力实现放入入口。

无数据库结构变更，历史迁移不修改。节点、应用服务和部署端点配置须成套发布；账户工作者的节点调用时限要与本协议上限一致。旧的本机 socket 协议不保留兼容分支，升级必须成套切换两个二进制与证书。回滚先停单排空，保留电脑、桌面代次和关闭屏障，不删除未知业务记录，不切回让应用进程直连 Docker 或执行宿主命令的方式。
