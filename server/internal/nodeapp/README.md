# 受信宿主节点入口

`tomnode` 将固定容量磁盘后端、Docker 生命周期、基础能力复验、进程资源组、执行会话监督、出网监督和受保护节点 API 组合为独立 Linux root 进程。不持有业务数据库或模型凭据。配置来自唯一的 `TOM_NODE_CONFIG` 文件，不接受命令行参数。API 与 Worker 仍使用非 root 账户，只有本服务持有通用宿主权限。

## 配置与启动

[部署示例](../../deploy/node.example.json)展示完整版本 2 配置。示例身份和资源预算只供说明；部署生成文件时，`node_id` 必须与节点登记一致，`client_uid`/`client_gid` 必须是实际 `tombot-api` 身份，`socket` 必须与 API 配置及登记端点一致。全部容量、并发和时限根据节点资源明确提供，不从客户端或任务参数读取。API 身份不是容器内 Bot 的 UID。

配置最多 16 KiB，要求 root 所有、普通文件、0600，父目录均受 root 保护；拒绝符号链接、硬链接、重复键、大小写别名、未知字段、null、整数溢出和尾随内容。复用各组件的权威校验，并检查跨组件调用/退出预算、目录不重叠、控制 socket 不在用户存储或私有记录目录中。毫秒值先检查范围再转换，不能通过溢出绕过时限。未提供的必需参数不会补默认值。

版本 2 配置还必填 `agent_startup`：总预算 `timeout_ms`、单次预算 `call_timeout_ms`、初始退避 `retry_delay_ms` 和 `maximum_attempts`。部署示例分别为 5000、1000、100、8；API 调用预算必须覆盖代理等待、浏览器调用与探针调用之和。该等待只检查代理控制入口，不重试任何有副作用操作，不把控制可用当作电脑就绪。生成器使用同一示例与校验规则；旧配置缺少该部分时明确拒绝。

`browser.limits.dialog_timeout_ms` 必填，限定一个浏览器动作累计等待页面对话框的时间，范围 1000–600000，示例为 300000。等待期间暂停该动作的实际执行预算，答复后恢复剩余额度；此预算不是单次节点 RPC 的等待时长。取消会话立即终止等待，停服不会等待全部对话框预算耗尽。旧配置与旧浏览器授权缺少该字段时直接拒绝，须按[发布说明](../../deploy/RELEASE.md)成套切换。

启动顺序为：检查磁盘工具和受保护目录 → 打开节点生命周期独占锁并回收遗留探针与共享浏览器 → 打开执行服务锁并回收旧会话 → 恢复电脑出网 → 创建受保护的 Unix 顺序包监听器 → 启动三项监督。恢复或任一组件构造失败时不开放控制入口。不能因为恢复记录损坏而删除、忽略或重新初始化它。

`dockernode.New(ctx, options, storage, logger)` 内部创建真实基础能力检查器，生产入口不接受注入任意“全部成功”探针。检查器要求本次探针已持久关闭，资源及租约匹配，Docker 实例和实际父资源组未变化，容器看到的 ext4 容量与宿主当前挂载的实际容量一致；规格磁盘容量不能替代 ext4 的实际可用文件系统大小。基础终端、文件、回收、配额与无直连网络证据通过后，浏览器能力仍为 false，电脑不能成为 ready。共享 Chrome、窗口归属、沙箱及代理访问的联合验证在下一阶段接通。

## 系统服务

[节点单元](../../deploy/systemd/tombot-node.service)依赖 Docker 自动安装引导和固定镜像准备；[API 单元](../../deploy/tomd.service)用 `Wants` 和 `After` 拉起节点，避免节点维护连带关闭登录及历史查询。数据库迁移、首位管理员与节点目录登记仍按对应部署命令执行，不由 root 节点访问数据库。

[安装引导](../dockerbootstrap/README.md)会按受保护清单安装并核验宿主 `e2fsprogs`、`util-linux`、`mount`，即使 Docker 已存在也检查。安装引导与节点共用六项磁盘工具路径契约；工具运行成功不能代替真实 loop 挂载、实际容量和内核配额验收。升级必须同步提供新增三个宿主包版本字段，缺失不使用默认版本。

节点以 `Type=notify` 运行，只有完成恢复和监听创建才发送 `READY=1`，`STATUS` 明确说明用户电脑仍需完整检查。此通知表示控制服务启动，不写入目录健康状态、不激活账户。前台运行未配置 `NOTIFY_SOCKET` 时不发送通知；配置了端点而通知失败则停止并返回非零。通知使用有时限的 Unix datagram，遵循 [systemd 通知协议](https://raw.githubusercontent.com/systemd/systemd/main/man/sd_notify.xml)。

单元通过 `RuntimeDirectory` 创建 root 所有的 `/run/tombot`（0711，允许 API 穿越目录但不能列出），实际 socket 为 root:控制组、0660；每次调用仍核对内核对端身份。三种状态目录为 0700。节点不启用 `PrivateTmp`、`ProtectSystem`、`ProtectHome` 等会建立私有挂载命名空间的选项，因为 loop 文件系统挂载必须能被宿主 Docker 看到；不能仅检查程序启动成功就忽略挂载传播。有关命名空间行为见 [systemd 执行环境](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.exec.xml)。

配置启动预算不超过 5 分钟，统一退出预算不超过 10 分钟；单元启动 16 分钟上限覆盖“构造失败后再清理”，停止上限 11 分钟覆盖正常退出。预算包括等待锁；网络、命令、会话和代理各自仍有更短的有限时限。不提供重试业务动作的自动成功分支。`Restart=on-failure` 重建服务后重新对账持久状态，不重放未知命令。

## 监督、恢复和回滚

节点 API、执行租约监督、出网监督任一意外退出，都会取消所有监督并停止接单。只有确认全部服务及 API 在途动作退出后，才按会话 → 容器与出网 → 存储记录 → 控制端点的顺序释放资源；控制端点锁最后释放。API 不能确认在途操作结束时返回 `ErrUnfinishedOperations`，应用返回要求进程退出的错误，保留依赖和恢复记录。任何清理失败或超时均停止释放后续依赖，错误退出由系统服务监督，不伪装为正常退出。

新增 `node-runtime.json` 保存节点进程实例与跨启动代次，控制心跳序号在同一实例内递增；API 通过数据库 `0045` 的[控制租约](../../docs/node-health.md)使过期节点停止接纳新电脑。节点不转换旧记录，也不凭心跳宣称能力就绪。发布须同时部署 `tomnode`、配套 API、容器代理/镜像、受保护配置和系统服务。停止接单并排空后再升级；保留用户卷、节点代次、生命周期、探针、浏览器和会话屏障。回滚也只能使用理解相同记录/协议的成套版本，不能删除关闭屏障、跳过目录检查或切回宿主任务执行器。改变镜像或容器配置按新代次部署，不原地改写既有实例身份。

## 验证边界

常规测试覆盖配置与预算、嵌套 JSON 歧义、启动通知、三个组件的退出、取消、未确认在途动作、清理失败/超时和重复运行。基础能力测试覆盖旧证据、未关闭记录、身份或父组变化、实际文件系统容量不符及取消；未接通浏览器时不可能完整就绪。

`linux && nodeintegration && !cgo` 的专用容器测试通过真实组件构造器、受保护文件、文件锁、Unix API、降权客户端和正式 `tomnode` 子进程检查启动、通知、SIGTERM、重复启动、正常重启及损坏记录阻断。Docker 返回“资源不存在”的部分是明确替身，未创建用户容器、写 cgroup 或挂载磁盘。环境变量 `TOM_NODE_ENTRY_TEST=1` 和 `TOM_NODE_BINARY` 指向本次构建入口；不能在生产节点运行这组测试。

首次 Ubuntu systemd 安装、实际 loop 挂载与配额、真实任务入组和强制回收、共享浏览器联合检查、节点健康发布及整个开户链路仍待生产环境验收。当前控制服务可启动不代表这些工作已完成，公开远程电脑交互继续暂缓。

共享浏览器已接入宿主生命周期，见[节点浏览器监督](../dockernode/README.md#宿主共享浏览器生命周期)。配置版本 2 必填 `browser` 的调用、单实例回收、整节点退出和窗口预算；退出总预算还须包含浏览器回收，不能混用旧节点配置。用户生命周期记录升级为版本 4，防止旧节点忽略新浏览器屏障；存储版本 3、代理配置版本 4 和桌面记录版本 2 不变。当前控制入口就绪仍不开放账户，窗口客户端与浏览器联合能力探针未完成。
