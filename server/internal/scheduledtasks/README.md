# 猫咪持久任务

每只猫咪独立管理自己的计划、执行记录和结果。用户在聊天中要求提醒或安排工作时，助手通过 `task_list`、`task_create`、`task_update`、`task_delete` 操作真实存储；右侧“动态”提供任务列表、启停和删除。名称、分组及介绍不再占用动态面板。

## 时间与授权

- 支持明确 IANA 时区的五段 cron 重复任务，或未来 RFC3339 时间的一次性任务。默认建议上海时区，助手应向用户说明保存后的时间；含糊时间先澄清。
- 同一猫咪最多 100 个未删除任务。HTTP 每页 20 个，模型工具每页 1 个以控制上下文；修改携带当前修订号，冲突必须重新读取，不自动覆盖。
- 工具的猫咪和用户来自持久运行身份；变更必须引用模型已读的当前回合用户消息 ID 和原文证据。引用、工具结果、定时调用不能授权新增或修改计划。后台任务仅获得长期记忆检索工具，不能把执行结果写成用户偏好或自行生成计划。
- 停用、删除只影响未来触发；已受理任务和结果继续处理。一次性任务受理后自动停用，已过去的时间不能直接重新启用。归档猫咪或不可用用户的到期计划停止，并留下失败记录。

## 独立执行与延迟结果

调度器每秒读取至多 100 个到期索引，受理锁、任务行锁、执行记录、推进时间及事件在同一事务提交。每次触发新建隐藏任务会话，使用同一猫咪的配置、长期记忆、模型路由和工具权限；后台按需分配独立任务桌面，模型和电脑操作不会等待前台聊天结束。客户端关闭也不影响服务端调度。

聊天与任务各有一条猫咪执行通道；同一猫咪的多个后台任务按队列执行，避免并发操作同一任务桌面。用户总模型、桌面配额及全局工作线程上限继续生效，资源不足仍需排队，因此不承诺硬实时。聊天和后台的图形身份独立，同一用户业务目录共享，涉及同一文件的任务仍应避免相互覆盖。后台不读取正在变化的主聊天记录，任务描述需包含独立执行所需的工作内容。

后台运行结束时，结果正文与投递意图在同一事务持久化。投递器仅在主聊天没有排队、运行或取消中的回合时写入结果；与聊天受理共用短事务锁，避免结果插进正在生成的回复。前台继续输入会延后投递。主聊天不可用时保留结果，每分钟重新检查，避免占满批次阻塞其他猫咪。任务卡片显示“结果已就绪，将在本轮对话结束后发送”。失败结果也有明确通知，不伪装成功。

结果消息以带标记的系统来源普通消息保存；进入模型时是参考内容，不提升为系统指令，也不会触发新的模型运行。用户可以引用或标记已投递结果的表情，反馈沿正常聊天链路进入模型；隐藏任务输入不能直接参与这些操作。后台事件使用 `task.run.*`，不会提前结束或覆盖前台工作状态。

## 一致性、恢复与边界

数据库以用户、任务和计划时间唯一标识一次触发，以运行 ID 唯一标识一次结果。重启后到期计划补跑一次，并把重复计划推进到当前时间之后，避免长时间离线产生无限积压。队列容量不足时整次受理回滚，保留原到期索引供下一轮处理，不因聊天忙碌跳过任务。

任务工具修改与成功回执共同提交。恢复执行重放已持久的工具回执；外部副作用仍遵循原有租约、操作账本和“不确定结果不重复执行”规则。投递消息、投递状态、出队及事件也共同提交；失败后重试仅投递已保存的结果，不再次执行任务。并发投递器最终只产生一条结果消息，已投递历史可重新打开查看。

跨用户调度连接只能读取无正文的到期与结果索引。定义、运行正文及结果表使用强制租户 RLS；读取、变更均验证猫咪归属。查询有上限并使用任务时间、猫咪分页、运行 ID 索引。执行记录和已删除定义保留审计；当前没有自动清理策略，长期容量规划需包含这些新增记录。

## 升级与回滚

配套升级桌面客户端与服务端，按正常 `tomd upgrade` 应用新增 `0069_scheduled_tasks.sql`。不修改历史迁移，不重建用户和猫咪；已有桌面继续作为聊天桌面，任务桌面首次使用时分配。执行仍使用既有按桌面隔离的节点协议，无新增镜像命令。

迁移新增任务定义、到期索引、执行记录、结果投递索引及 RLS；扩展会话类型、桌面用途、队列执行类型，并替换猫咪执行互斥索引。迁移会锁定会话、桌面及任务队列表，校验现有数据并重建相关索引，耗时取决于现有记录规模。应停止服务、等待运行收尾，在维护窗口完整备份数据库后执行；锁等待及语句时限沿用迁移器配置，失败整次回滚。

应用不兼容旧客户端任务接口，旧服务端也会拒绝更高数据库版本。回滚须停止服务、保全升级后的计划与消息，然后恢复升级前完整数据库备份和配套客户端、服务端；不能直接降低版本账本或只替换旧二进制。

## 验证

真实 PostgreSQL 回归覆盖对话工具增删改、证据和修订校验、容量及分页、跨用户与调度权限、到期并发受理、重启补跑、一次性任务、归档停止、事件失败回滚、聊天运行期间后台完成、两个独立桌面及结果延迟/唯一投递。桌面测试覆盖任务卡片、错误、事件刷新、禁用和键盘删除。Electron 联合测试覆盖真实 HTTP 任务列表与启停、重开恢复、删除，以及深浅主题布局。

模型与节点在这些回归中使用受控测试实现；真实外部模型、Linux 容器中的并发桌面运行仍需部署环境验收。
