# 用户机器人与协作目录

本模块直接读写 PostgreSQL，管理登录用户的机器人、群组、所属会话目录、工作空间选择及自定义头像。一个机器人只有一个业务 ID，创建时原子登记稳定桌面身份并建立唯一用户单聊；不保存客户端模型选择、品牌身份映射、工作目录或模型凭据。

当前已经提供领域服务和 [v2 用户 HTTP 接口](../userapi/README.md)，并通过真实 PostgreSQL 与 HTTPS 联合测试。会话目前包含目录、所属关系和序号字段，消息、运行、私信投递、群组调度及主动发消息执行仍需接入；不能据此视为完整聊天链路已切换。

## 数据与身份边界

`New` 只接受租户数据库连接。每次业务操作先在同一租户事务中调用 `identity.CheckTenantSession`，复核用户启用状态、设备、会话、有效期与权限版本；用户身份由认证入口解析，不能从正文或查询参数覆盖。管理 Cookie 不用于用户资源接口，管理员管理角色不能直接查询这里的内容表。

机器人、群组、会话、成员和头像均带 `user_id`。会话和头像的复合外键限制资源属于同一用户，新表强制 RLS。其他用户的资源与不存在的资源均返回不存在。业务事务中的身份读取是本次操作的接纳点，后续撤销不回滚已经接纳的短事务；新请求会立即重新验证。

会话区分 `direct`、`group`、`bot_dm`。单聊按用户与机器人唯一，群聊按用户与群组唯一，机器人私信使用排序后的两个不同 Bot ID 唯一定位，数据库拒绝跨用户或无效参与方。本模块只创建单聊与群聊目录，私信会话的创建及投递由后续消息领域负责。

## 创建与修改

- 创建机器人和群组必须携带 `client_request_id`。幂等范围分别为当前用户的机器人创建、群组创建；同键同规范化配置返回同一资源的当前版本，不重复创建或发事件。同键不同配置明确冲突。没有客户端请求的受信内部创建可以不携带此列，但必须同时省略摘要。
- 机器人响应包含服务端生成的 `desktop_id`，归档、恢复及电脑实例重建后保持不变。机器人和[桌面登记](../computerdesktop/README.md)必须同事务提交，内部创建也遵守此约束；客户端不能传入桌面 ID 或运行身份。桌面编号上限为 4095，部署的 `MaxBots` 不能超过该上限，归档仍占用身份。
- 名称与文本规范化为 NFC，去除首尾空白，并限制长度和控制字符。活动机器人、活动群组分别在用户内名称唯一；用户之间可以同名。客户端展示资产只保存不解释业务含义的 `avatar_ref`，不读取该值指向的 URL 或文件。
- 工具许可来自构造时注入的实际工具名称集合，未知和重复名称被拒绝。工具集合、审批模式及私信、主动发言、群邀请配置持久保存；运行执行器还必须按当前配置执行权限校验。
- 更新完整替换单个资源配置，并要求 `expected_revision`；数据库事务取得当前用户工作空间行锁，防止本模块中的并发变更相互覆盖。目录操作低频且有事务及锁等待时限，不使用进程内锁。运行和电脑执行不能借用这个目录锁实现调度。
- 群成员为 1–32 个不同的本用户机器人，通过一次有界查询验证。新增成员必须未归档且接受邀请；已加入的成员可以保留历史身份。配置与成员集合一起更新，失败不留下部分成员。
- 归档保留历史，清除失效的工作空间选择并同步所属会话目录。恢复受活动名称唯一约束保护。后续运行领域需把取消排队及活动任务接入同一生命周期；目前没有物理删除接口。
- 部署明确限制每用户机器人和群组总数，归档记录也计入容量，避免以归档绕过存储限制。群组预算为空表示没有群组额外金额上限，后续运行仍受平台和用户额度限制，未知费用不能当作零。

首次创建机器人时自动补全空的主机器人及当前选择。工作空间只保存选择与修订，修改不会整体覆盖机器人、群组或消息。空工作空间读取返回修订 1 的默认值，第一次写入在事务内建立持久记录。

目录分页按 ID 降序，页大小为 1–100；头像正文不混入列表。工作空间快照在同一只读一致性事务中读取有限目录首页及用户事件水位，超出首页时返回明确的 `has_more`。实时订阅仍需由事件接口实现绑定用户的可验证游标及撤销复核。

业务修改与用户事件同事务提交，事件只包含资源标识与修订，不包含提示词、头像或聊天正文。事件写入失败会回滚业务修改。

## 自定义头像

保留当前客户端的小尺寸自定义 PNG 能力。输入最多 72 KiB，尺寸不超过 128 × 128；解码后重新编码，剥离元数据与尾随内容，拒绝 SVG、远程地址和其他格式。规范 PNG 存入用户隔离的 `bot_avatars`，读取时核对内容摘要。头像修改和删除都要求机器人修订，更新目录事件。

这是小型用户配置资产的明确存储例外：头像保存在 PostgreSQL，不挂载进共享电脑，避免任务覆盖展示资产；普通业务文件仍按方案存入用户卷。列表只返回是否存在自定义头像，正文经专用授权接口读取。

## 数据版本与恢复

`0035_bot_collaboration_catalog.sql` 新增会话与头像表，补充机器人和群组的目录字段及创建幂等约束；`0036_group_active_names.sql` 前向建立群组活动名称唯一索引。`0001`–`0034` 保持不变，不读取、转换或导入 SQLite 数据。

`0041_bot_desktop_identities.sql` 新增机器人必需的桌面归属及延迟复合外键，仅接受空机器人目录，不为中间模型已有机器人自动分配身份。该版本发布及回滚要求见[桌面身份说明](../computerdesktop/README.md)。

迁移在受限事务中执行，修改目录表及建立唯一索引会取得结构锁并检查现有记录。当前新系统目录数量受限；上线前仍应核对锁等待、表大小及是否存在活动重名。冲突时整个迁移失败，不自动改名或删除资源。已应用迁移不能修改，修正需新增更高版本。

应用回滚前停止目录写入并排空短事务；旧二进制不能继续修改它不理解的新目录。保留新表、头像和幂等记录，通过匹配版本恢复服务，禁止回填 SQLite 或删除历史迁移。当前 `tomd` 已使用本模块，并完成组合入口的两用户归属检查；真实节点与完整客户端尚未完成，不将该检查当作全产品可部署的证据。

## 验证

真实 PostgreSQL 测试覆盖两用户同名与隔离、复合外键和 RLS、创建幂等、修订竞争、目录分页、群成员邀请、归档恢复冲突、容量限制、工作空间选择、头像规范化与损坏、会话过期、设备撤销、用户禁用，以及事件失败的完整回滚。

```sh
go test -race ./internal/bots ./internal/userapi ./internal/store/postgres
```

测试通过 `TOM_TEST_POSTGRES_BIN` 定位 PostgreSQL 程序，建立私有 Unix 套接字临时集群，不连接已有业务数据库。HTTP 联合测试实际执行两用户的激活、登录、资源操作与退出，传输使用本地 TLS。
