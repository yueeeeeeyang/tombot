# 容器内任务引导

`computer-task` 是用户电脑镜像内的单用途受信程序。它在同一进程中完成参数核验、进入会话 cgroup、关闭控制描述符、清除权限及 `exec`，成功时被用户程序原位替换。[代理入口与会话控制](../computeragent/README.md)、[描述符通道](../agentchannel/README.md)及节点绑定已实现；生产运行目录准备、终端和图形会话启动仍待接通。

按照[改造方案](../../docs/multi-user-refactor.md)，同用户 Bot 使用稳定的独立 UID 与公共 GID，直接共享业务文件和已安装工具。私有目录仅保护桌面认证、画面、输入及会话控制，不对业务文件强制实施 Bot 隔离。

## 调用协议

普通任务入口不接收命令行参数，不读取部署环境中的凭据。仅固定共享浏览器使用下文的 `--browser` 模式；其他参数或附加参数均拒绝。容器代理通过 `exec.Cmd.ExtraFiles` 传入三个描述符：

| 描述符 | 内容 | 约束 |
| --- | --- | --- |
| 0、1、2 | 当前终端或命令的输入、输出、错误输出 | 由代理创建并绑定当前操作，不作为控制协议 |
| 3 | `Seal(Request)` 返回的匿名 memfd | 由 root 代理拥有，禁止写入、扩展、截断和移除封存标记 |
| 4 | 节点授权后由代理复制的 `cgroup.procs` | 仅允许当前固定会话的 `shell` 或 `browser` 叶组，不接收任意 PID |
| 5 | 当前会话匿名撤销管道的只读端 | root 代理独占写端；到期或关闭先关闭写端，引导在执行用户代码前复验 |

`Request` 使用版本 **2**，包含完整电脑实例与桌面执行身份、操作 ID、资源组角色、规范绝对工作目录、绝对程序路径、参数和显式环境。UID、公共 GID 和显示编号仅从已授权的 `Group.Session.DesktopIdentity` 获取，不再接收重复的顶层 UID/GID。输入采用唯一规范 JSON 编码，拒绝旧版本、重复键、未知字段、别名、额外对象及超限内容。业务接口不得直接接受这份结构；代理必须从已授权的运行与操作记录构造它。

封存确保检查之后内容不能变化，它不证明请求仍有执行权。节点必须在每次发放描述符前检查当前租约；代理到期先关闭撤销写端，再发送整组终止信号；节点最终移除资源组，令旧入组描述符失效。生产代理及完整到期回收机制接通前，禁止启用完整链路。

## 固定执行顺序

1. 验证纯 Go 构建、root 身份、Docker 规定的最小 capability 集、`no_new_privs`、seccomp 过滤和正常的权限继承状态。需要 `CGO_ENABLED=0`，不对未知本地线程执行部分降权。
2. 读取有界且完整封存的请求，随后关闭内容描述符；验证撤销管道仍有效，以 `openat2` 检查私有桌面运行目录的身份、权限和链接边界。此时不以 root 打开业务工作目录。
3. 验证入组描述符的内核文件系统、权限和固定会话路径；要求调用进程位于容器私有 cgroup 命名空间根，写入 `0` 迁移自身，并复验目标叶组。此时尚未执行用户代码。[Linux cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)
4. 关闭入组描述符，将其他非标准描述符设为执行时关闭；禁用内存转储，设置 `umask 0007`，使普通新文件默认为所属 Bot 和公共组可读写。
5. 对全部 Go 线程设置不可提权状态，清除附加组并切换真实、有效、保存和文件系统身份；复验 UID/GID、附加组及有效、允许、继承、环境 capability 均已清除。随后检查撤销管道，在降权后的身份下进入工作目录，构造环境并再次检查撤销，才执行用户程序；撤销读端在 `exec` 时关闭。[Go 全线程系统调用说明](https://pkg.go.dev/syscall#AllThreadsSyscall)、[Linux 不可提权说明](https://docs.kernel.org/userspace-api/no_new_privs.html)

不通过宿主 `nsenter` 执行，不把可写 cgroup 目录挂入用户容器，也不退回先执行用户代码再补挂资源组。`no_new_privs` 不替代身份清理；引导保留 Docker 的 capability 上界，但用户进程的上述四种 capability 集为空，且执行文件不能增加其权限。

任何步骤失败立即退出，错误不含原始命令、环境、内容或宿主路径。引导失败使用退出码 125；用户程序也能返回相同退出码，代理不能仅凭输出或该退出码推断动作从未发生。取消、超时、失联和未知结果由节点及代理关闭整棵会话资源组，不自动重发命令。

## 目录与身份

稳定身份由[桌面登记模块](../computerdesktop/README.md)分配：UID 为 `100000 + display_number`，同用户容器的公共 GID 为 `20000`。同一 Bot 的新运行沿用 UID，使用新的执行会话目录。代理负责准备目录；引导只验证，不创建、改属主或复用旧控制材料。

```text
/workspace/                       用户共享 HOME，公共组可读写，目录使用 setgid
  tools/                          共享工具、语言包管理目录和命令入口
  .tmp/                           共享业务临时文件，允许执行编译产物
/run/bot-desktops/                root:root，0711
  <session_id>/                   当前 Bot UID:公共 GID，0700
    Xauthority、ICEauthority      当前图形会话认证
    bus、desktop.sock             私有 D-Bus 与 RFB socket
    browser.sock                  root 持有、仅当前 browser 子组可用的窗口入口
    config、cache、state、data    当前图形会话配置与状态
    passwd、group                 当前桌面的 NSS 身份映射
```

工作目录不限制在某个运行目录中；规范的绝对路径可以指向另一 Bot 的产出或普通符号链接，是否可进入由降权后的 Linux 文件权限决定。不存在强制文件发布流程。业务文件允许相互读写，因此不能承诺不同 Bot 的任意代码互不影响；并发修改须由应用或任务使用普通文件锁、版本控制等方式协调。

环境从空集合构造，终端与镜像内 XFCE 启动器使用[同一份模板](../computer/desktop-environment.json)。HOME、业务临时目录和工具安装前缀共享；DISPLAY、Xauthority、D-Bus 及 XDG 图形状态指向本会话，不能经启动请求覆盖。其他明确传入的环境只在降权后的用户程序生效，不能影响受信引导。每次调用返回独立环境映射，不继承平台环境。用户级共享浏览器服务及窗口网关由代理另行管理，窗口客户端须进入当前会话 `browser` 子组；普通 Shell 不能直接请求窗口入口。不由本模块把多个浏览器进程指向同一个 profile。

## 固定服务探针

`computer-probe` 使用独立的 `ProbeRequest` 版本 1，仅允许 `probe` 服务组及固定程序，不依赖或构造 Bot 会话。它复用封存内容、内核入组校验和全线程降权，但执行身份固定为 UID `30001`、公共 GID `20000`；请求不包含可配置命令或环境。引导和 worker 都复验原始单调期限及实际组归属。完整协议、证据边界与尚待接入的节点监督见[容器基础能力探针](../computerprobe/README.md)。原 Bot 任务请求仍为版本 2，三个描述符含义保持不变。

## 固定共享浏览器引导

`computer-task --browser` 接收独立 `BrowserRequest` 版本 1，只包含 `browser` 服务组身份和有界启动期限。描述符 3、4、5 分别为封存请求、服务入组与撤销入口，6、7 为 root 创建的两条不同匿名协议管道。Bot 任务、探针请求、过期或撤销授权、普通文件假冒的内核入口均拒绝；不接受 Chrome 参数、环境、程序或目录覆盖。

引导核验固定持久目录 `/var/lib/tombot-browser` 为 30000:20000、0700，运行根 `/run/tombot-browser` 为 root:root、0711，实例目录为 30000:20000、0700。入组后按现有全线程流程降权，设置私有文件掩码 0077，只把两条 CDP 管道映射到 Chrome 固定的 3、4 描述符；其他控制入口在执行时关闭。固定 Chrome 保留沙箱，显式使用环回代理并取消隐含的环回直连豁免，不监听调试 TCP 端口。

启动期限只限制此次入组与执行；长期监督、共享 profile 独占及最终整组回收由[代理浏览器后端](../computeragent/README.md#共享-chrome-受管进程后端)负责。持久监督与三个控制动作已接入正式代理入口，宿主服务生命周期已接入节点，窗口客户端和联合能力探针仍待组合，不能因引导程序已打包就宣布浏览器就绪。代理部署配置为版本 4，原 Bot 请求版本 2、探针版本 1 与历史 SQL 迁移均不变。

## 验证与发布

常规入口 `make lint check test` 覆盖格式、静态分析、构建、协议及状态测试。`make build` 和 `make release` 以纯 Go 构建引导程序；正式镜像使用与节点协议配套的 Linux 二进制。

Linux 专用测试还验证内核 memfd 封存、私有桌面目录链接及错误身份拒绝、真实多线程 UID/公共 GID 切换、附加组与 capability 清除、不可提权与 seccomp 保留、控制描述符不泄漏、空父环境、共享文件与工具、跨桌面目录拒绝、内存转储关闭、失败程序及伪造资源组不能执行用户代码。执行方式是在新建的临时受限容器内运行测试二进制：

```sh
# 在 server 目录执行；架构与本机 Docker Linux 引擎一致。
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go test -c -tags=taskintegration \
  -o /private/tmp/tombot-taskprocess-test ./internal/taskprocess
```

容器使用本地固定摘要专用镜像、禁用网络、只读根文件系统、默认 seccomp、`no-new-privileges` 及与生产引导一致的六项最小 capability；只读挂载测试二进制，提供空白 `/tmp`、`/workspace` 和 `/run/bot-desktops` tmpfs，设置 `TOM_TASK_ISOLATION_TEST=1`，执行 `-test.v -test.timeout=60s`。业务卷允许执行，桌面根目录为 root:root、0711。不挂载宿主资源组、既有卷、用户文件或 Docker socket。

该受限容器验收已通过，实际执行了权限清理与目录、描述符边界，并验证代理关闭写端后迟到引导不能执行用户程序。成功入组、撤销与入组的联合竞态、双重派生和整树回收仍待与节点一起在真实 cgroup 上验证。没有测试绕过开关进入正式程序，也没有因验收条件不足放宽入口校验。

本模块不改数据库结构和现有运行入口。版本 2 不兼容旧请求或私有角色目录约定；镜像、代理及节点须成套发布。升级或回滚须先停止接单、排空会话并保留操作及身份记录；不能用旧的宿主 Shell、修改历史迁移或删除会话记录作为回滚方案。共享业务卷不能交给旧私有目录程序直接复用；回滚必须使用相互匹配的程序和独立部署环境，经检查后再重新开放服务。
