# 容器基础能力探针

`computer-probe` 用于节点供给及检查用户容器时取得实际基础能力证据，不借用某个 Bot 的执行会话。它以保留 UID `30001`、用户共享 GID `20000` 运行，不能访问 Bot 的私有桌面。每次检查使用独立的[基础服务资源组](../processgroup/README.md#容器级基础服务)和唯一实例 ID。

## 启动与授权

镜像内固定程序为 `/usr/lib/tombot/computer-probe`。受信容器代理必须从节点取得探针服务授权，封存 `taskprocess.ProbeRequest`，通过三个描述符启动无参数引导：

| 描述符 | 内容 |
| --- | --- |
| 3 | root 所有、不可修改的规范 JSON memfd，版本 1 |
| 4 | 当前探针服务实例的 `cgroup.procs`，只允许自身入组 |
| 5 | 代理独占写端的撤销管道读端 |

授权包含容器完整父组身份、探针服务实例及同一 Linux 时间命名空间的绝对单调期限，剩余时间最多一分钟。不接受用户命令、执行路径、环境、目录、UID 或 Bot 身份覆盖。浏览器用途的服务组不能运行探针。

引导复用[任务进程](../taskprocess/README.md)的内核入口检查、不可改写内容、全线程降权及执行时描述符关闭：先检查最小权限、撤销和实际入组，再清除附加组及所有可用 capability，以固定非 root 身份原位执行同一个程序的内部 worker。worker 再次核对身份、服务组及原期限。不存在跳过入组的生产开关；直接执行 worker 也不能取得有效身份。其他平台明确返回不支持。

服务监督器必须先持久消费授权并关闭撤销写端，再回收整个实例组；记录和实例 ID 不可复用。worker 的上下文期限负责中止正常检查，节点的整组回收还须处理阻塞内核调用、引导与撤销竞争及异常后代。[代理探针监督](../computeragent/README.md#容器基础探针监督)已接入固定程序、持久消费、超时撤销、回收确认和 `probe` 控制协议。节点的版本账本、服务组创建、调用及最终移除仍须接通；当前不得据此发布电脑就绪。

## 实际检查与证据

所有检查完成且身份、归属和期限再次有效时，标准输出才返回一份 JSON；任一步失败不输出部分成功结果，退出码为 125。错误不包含业务文件内容或控制材料。

| 证据 | 实际检查 | 不代表 |
| --- | --- | --- |
| `terminal` | 打开 PTY，设置并复验尺寸，关闭回显及行缓冲，双向传输中文、空字节和换行 | Bot 终端协议、任务成功入组及后代回收 |
| `files` | 在 `/workspace` 新建随机私有目录和独占文件，写入、同步、回读并比较，最后回收 | 业务文件互斥或用户卷硬容量已验收 |
| `filesystem_type`、`filesystem_size` | 从实际打开的验证文件读取 `fstatfs`，检查数值与溢出 | 容器挂载身份、宿主存储账本、写满拒绝 |
| `local_network` | 唯一启用的环回接口及环回地址；其他接口须停用且无地址 | 宿主出网策略、代理可达或外部供应商连通 |
| `service_id` | 完成时仍有效的本次探针实例 | 节点已撤销授权并确认回收 |

无网络命名空间也可能存在停用、无地址的内核默认隧道接口，不能仅凭接口数量拒绝。探针仍拒绝任何启用、运行或带地址的非环回接口；节点必须另外复验 Docker `none` 网络配置和最小权限，普通进程不能修改网络配置。[Docker none 网络说明](https://docs.docker.com/engine/network/drivers/none/)

文件检查使用固定目录描述符，不遍历、覆盖或递归删除用户内容。结束时复验文件及目录身份，只移除本次文件和空目录；被替换、出现额外内容、同步或清理失败均明确失败，并保留无法确认的路径。共享业务目录允许其他 Bot 修改，检查不能承诺外部进程不改变文件系统。容量证据只能作为节点交叉核验的输入，不能将 tmpfs 测试当作持久卷配额证明。

节点最终需要组合以上证据、可信 Docker 实例身份、存储硬容量、实际服务入组及回收、代理和共享 Chrome 检查后，才决定 `computer.Capabilities` 和就绪状态。探针不返回该结构，也不自行写数据库。

## 验证

常规入口为 `make lint check test`。Linux 专用测试覆盖真实 PTY、文件同步和清理、取消与描述符错误、网络接口边界、memfd 封存及未授权执行拒绝。专用容器测试另验证 32 MiB 文件系统实际容量及真实无网络配置：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go test -c -tags=probeintegration \
  -o /private/tmp/tombot-computer-probe-linux-test ./internal/computerprobe
```

将测试程序只读挂载到新容器，使用固定镜像摘要、`--network=none --read-only --cap-drop=ALL --security-opt no-new-privileges=true --user 30001:20000`，空白 `/tmp` tmpfs 和 `/workspace:rw,nosuid,nodev,noexec,size=32m,mode=2770,uid=0,gid=20000` tmpfs；设置 `TOM_PROBE_EVIDENCE_TEST=1`，执行 `-test.v -test.timeout=60s`。测试不挂载业务卷、宿主 cgroup 或 Docker socket。它调用真实检查方法，成功结果没有服务 ID，不伪造成功入组。

`taskintegration` 测试还在六项最小 capability 的临时容器中验证伪造 cgroup 入口、撤销及过期授权被引导拒绝，并回归原有多线程降权、控制描述符关闭、共享工具及跨桌面拒绝；其中共享业务 tmpfs 必须显式带 `exec`，保持与正式可执行业务卷一致。

## 发布与回滚

本模块不增加数据库迁移，也不修改既有任务请求和代理配置版本。代理通道新增 `probe` 动作及版本 1 的独立 `probe.json` 消费记录；`make build`、`make release` 和专用镜像构建包含固定程序，镜像验收检查未授权 root 与非 root 调用均不输出成功证据。

后续接通时，节点、代理、探针及镜像必须成套发布并固定镜像摘要。停止新任务、排空 Bot 与基础服务后再更换容器；保留持久关闭记录与用户卷。同一卷不得由两个实例同时写入。回滚使用相互匹配且已验收的程序与镜像，不重开已关闭实例，不用空实现补齐探针，也不把旧镜像缺少程序视为检查成功。
