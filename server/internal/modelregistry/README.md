# 服务端模型目录与策略版本

本模块实现 PostgreSQL 模型目录、凭据生命周期、策略启用与选择，服务端是唯一配置来源。客户端和用户电脑不保存供应商凭据。管理 HTTP 由 [adminapi](../adminapi/README.md) 提供，能力验证与受限传输由 [modelgateway](../modelgateway/README.md) 实现，持久运行绑定和调用 Worker 由 [execution](../execution/README.md) 实现。主服务与管理界面已接入；执行器在固定策略版本内选择候选模型。

## 配置与启用

`New` 必须接收独立控制连接、租户连接、身份服务、部署注入的主密钥集合和能力验证器。控制角色管理模型目录；所属用户与 Bot 检查经过租户事务和 RLS，不能借控制连接读取用户聊天内容。管理读操作复验管理员身份，所有变更还要求近期二次验证。

供应商启用时禁止编辑；停用后可修改名称、协议、地址及凭据，保留供应商和模型 ID。模型停用后允许编辑键、名称、能力与规格，策略输出长度可在目录上限内调整。更换 HTTPS 主机或端口须提供新凭据，并在同一事务内撤销旧凭据；同来源不填新凭据时保留原值。协议或地址变化后，旧策略快照继续保留且不可用于新配置，需创建并启用新版本。地址只接受无用户信息、查询串和片段的 HTTPS URL。此处是结构检查，不能替代实际连接时的 IP、DNS、重定向和部署允许范围检查。

流程为 `创建策略 → 新增停用版本 → 验证能力 → 启用版本 → 分配策略`。停用版本也是不可改写的版本，修改配置应创建更高版本。每个版本保存路由方式和最多 16 个候选；各候选独立固定协议、地址、模型键、能力、长度限制、思考级别、可选价格和凭据版本引用，价格缺失保留为未知。数据库触发器拒绝编辑启用供应商或模型、改写历史策略配置、删除历史引用。

启用期间不占数据库事务调用上游。`Verifier.Verify` 必须逐一实际验证全部候选的文本及所声明的工具、视觉能力，不执行用户工具，不保存凭据，遵守调用时限。启用不自动重试探测。验证完成后重新核对管理员身份、策略及目录修订、凭据状态，再以短事务原子启用；任何竞争或审计失败都会拒绝启用。已验证版本再次启用不重复探测；每次操作都必须提供最新修订号，旧请求不能覆盖之后的选择。

生产验证器使用 `modelgateway.Gateway`，在部署允许的来源范围内真实发起文本、工具结构和视觉探测。构造器拒绝缺失验证器；本模块的测试替身只用于注入成功、失败、超时和竞争，不能在服务启动入口中作为默认实现。运行入口还需显式注入出网策略与时限，不能根据管理接口提交的地址自动扩大允许范围。

## 目录测试

模型目录的“测试模型”使用当前目录和最新有效凭据，分别发送一次随机文本挑战与一次无外部副作用的工具调用挑战；停用供应商或模型也可测试，便于启用前确认。工具测试不依赖目录的工具能力声明，不自动修改声明，也不执行模型返回的工具。未通过连通性时跳过工具测试；两项结果分别返回通过、失败或未执行、固定中文说明和耗时，不透传上游正文。

测试需要管理员近期验证及供应商、模型的期望修订号。读取目录与解密后立即结束数据库事务，网络探测共享验证总时限，不重试；完成后重新校验权限、修订及最新有效凭据，竞争或审计失败明确拒绝。探测通过和失败均记录对应审计结果，明文退出时清零。已接纳的上游调用无法撤回；测试期间发生撤权或编辑时，其结果不能作为当前配置的验证凭证。测试会产生供应商用量，界面在开始前说明；与启用探测一样，尚不纳入用户聊天额度账本。

新增 `0054_disabled_provider_editing.sql` 仅替换目录保护函数，不回填数据或扫描表；锁只覆盖迁移事务中的函数定义变更。升级前备份数据库与部署文件，启动 `tomd` 自动迁移；失败整体回滚。移除旧的空供应商替换入口，以停用编辑统一处理。建议操作顺序为停用、编辑、测试、启用，再创建并启用新策略版本。回滚须恢复升级前数据库与二进制，或通过更高版本迁移恢复编辑约束；禁止修改已应用脚本。

## 供应商规格导入

模型发现保留每个模型明确提供的上下文窗口、输出上限、工具与图像能力、输入/输出媒体类型，以及思考级别候选和默认值。未提供表示未知，界面要求补齐必填规格，不再使用统一猜测值；供应商声明的媒体范围会完整保存，但当前调用链仅支持文本/图像输入和文本输出，不接纳纯音频等非文本模型。

登记时校验有界媒体类型、候选级别和默认值，所选 `reasoning_effort` 必须属于候选列表；空值表示不发送该参数。停用模型可修正规格，新策略版本固定所选思考级别，目录测试、启用验证和运行请求均使用该值。历史模型不会自动猜测或回填能力，已有策略快照不变。

新增 `0055_model_discovery_metadata.sql` 保存 `metadata` 和 `reasoning_effort`；常量默认值避免旧行重写，新增约束需扫描模型表并短暂持有结构锁，升级前核对模型表容量及锁等待。服务端与管理静态资源需同步升级，启动自动迁移，失败整体回滚。升级前备份数据库、二进制和静态资源；降级须整体恢复该备份，或新增前向修复迁移，不能修改历史脚本。测试覆盖元数据保留、未知字段、非法级别、目录不可变、历史版本和实际协议参数编码。

## 凭据轮换与退役

`AddCredential` 创建新版本，使用 AES-256-GCM 保存密文，附加认证信息绑定供应商、凭据记录、版本及主密钥引用。管理视图只显示记录标识、版本、撤销及销毁状态，不返回前后缀、摘要、密文或明文。随机数和认证操作复用仓库已有密码模块；认证加密的附加数据语义参见 [Go AEAD 文档](https://pkg.go.dev/crypto/cipher#AEAD)。

正常轮换新增凭据并启用新策略版本，旧运行继续使用原来的版本。主密钥集合由部署外部注入，当前主密钥用于新加密，保留的历史主密钥用于旧记录；缺失时明确失败，不生成替代值。不能在仍有存活密文时移除对应主密钥。

`RevokeCredential` 阻止后续启用和调用。`DestroyCredential` 只接受已撤销、且没有启用版本引用的凭据；销毁清除数据库中的密文和随机数，保留不可恢复的墓碑与审计身份。两步均幂等。销毁不会清除历史备份中的材料，备份及主密钥的保留和最终清理仍由部署生命周期处理。

## 运行选择与停用

`Resolve` 仅供受信调度器使用，按 Bot 特例、用户策略、平台默认的顺序选定策略及当前版本。选中的策略或版本不可用时明确失败，不改选其他用户或平台策略；候选不可用时仅在本版本内按路由规则选择。管理员的分配操作检查资源所属用户，并通过期望策略标识防止覆盖并发修改。

返回的 `Selection` 由 `execution.BindModel` 在有效租约下写入持久运行记录；首次绑定后由数据库禁止改写，重启恢复仍使用原版本。它本身不是客户端授权凭证，HTTP 不能接收用户自填的 `Selection`、模型标识、供应商地址或凭据标识再直接调用 `Use`。

`Use` 只接收执行器从运行记录读取的选择，每次重新检查用户和 Bot、策略及目录启用状态、固定版本和凭据撤销状态，再把配置和短期明文交给受信回调。回调不持有数据库事务，退出后明文清零。事务内检查是本次调用的接纳点；已接纳的外部请求不能保证被事后撤销回滚。新调用仍固定原版本，不能绕过紧急撤销。

`modelgateway` 提供连接、响应、流空闲时限及受限出网，新 Worker 已组合本模块、持久运行、调用额度预留与真实用量结算。主入口已组合，在途配置停用通知和启用前探测计量仍待完成；本模块没有以估算或零用量代替这些能力。

## 数据版本与验证

新增 `0033_model_policy_versions.sql` 建立修订、当前版本引用及不可变约束；`0034_model_credential_retirement.sql` 前向增加退役状态与引用索引。历史脚本不变，不读取或转换旧 SQLite 数据。

两项迁移在有界事务内执行，新约束会扫描配置表并取得结构锁。当前小型配置表可直接执行；生产升级前仍须核对容量与锁等待。失败整体回滚，已应用脚本的修正只能新增更高版本。应用回滚不得删除版本历史或重新启用已撤销材料；已销毁的凭据不能靠替换二进制恢复。

测试使用专属 PostgreSQL 集群和真实权限角色，覆盖目录分页、两用户隔离、策略优先级、不回退、并发版本号、在途版本固定、探测期间变更和撤销、探测超时、凭据清零、密文替换拒绝、主密钥轮换、退役条件、数据库不可变约束及审计失败回滚。

```sh
TOM_TEST_POSTGRES_BIN="$TOM_TEST_POSTGRES_BIN" \
  go test -race ./internal/modelregistry ./internal/store/postgres
```

测试验证数据库和领域协议，不证明真实供应商能力、联网安全或管理页面已可用。

## 停用模型编辑与删除

`UpdateModel` 和 `DeleteModel` 都要求近期管理员验证、模型已停用及期望修订号匹配。编辑复用登记校验，允许修改模型键、显示名称、上下文及输出上限、工具及图像能力、媒体类型与思考级别；供应商归属和模型 ID 不可修改，保存后保持停用。已有策略快照不变，影响调用的参数变化需要重新测试并启用新策略版本。删除仅允许没有任何策略版本引用的模型，包含停用版本在内的引用均拒绝；不连带删除策略或供应商。

行锁覆盖状态校验、更新/删除和审计，竞争使用修订冲突明确失败。策略创建持共享模型锁，删除持独占模型锁并再次检查引用；外键及触发器共同保护跨事务引用。重复删除返回不存在，重复编辑返回修订冲突，不自动重放写入。审计失败时整体回滚。

新增 `0056_disabled_model_editing.sql` 替换目录保护函数并增加策略版本 `model_id` 引用索引，无数据回填。函数替换短暂持锁；索引扫描策略版本表且建索引时阻塞该表写入，数据量大时需维护窗口。先备份数据库、二进制及页面，再成套部署并启动自动迁移。失败事务回滚；旧程序拒绝高版本数据库，降级必须整体恢复升级前备份，或保留新版程序并新增前向迁移恢复约束，不可修改迁移账本或旧脚本。

## 多模型路由与版本启停

`CreateVersion` 仅接受 `routing_mode` 与 1–16 项 `candidates`，不再接受顶层单模型字段。候选模型 ID 不可重复，优先级与权重范围均为 1–1000。默认继承目录输出上限、思考级别及供应商最新有效凭据；输出覆盖只能降低，思考覆盖必须属于模型声明。保存时固定快照，后续目录编辑不会重写历史版本。没有有效凭据明确失败。

三种路由共用能力筛选：排除停用、撤销凭据、目录不匹配、缺少工具/图像能力或上下文容量不足的候选。`priority` 选择优先级最小者，同级按添加顺序；`weighted` 按合格候选权重随机抽取；`round_robin` 按合格候选添加顺序和持久计数分配。文本容量按 UTF-8 字节保守估算，图片沿用尺寸预算，并预留完整输出上限；这只用于准入，实际 token 和费用仍取供应商报告。保守估算可能提前排除容量接近边界的模型。

`Resolve` 固定策略版本，`Route` 根据受信执行器提交的消息需求选择模型。运行级事务锁、候选外键和一次提交的计数/选择保证同运行重入不重新抽取、不再次消耗轮询位置。轮询计数按策略版本独立持久化，多个服务实例共享。运行正常继续使用原模型；不可用或能力不再匹配时只能前向选择尚未尝试的合格候选。失败切换按优先级排列，最多遍历版本内候选一次，耗尽返回 `ErrNoCandidate`。控制连接只读取模型和路由元数据，运行归属先在租户连接验证。

`EnableVersion` 首次启用时在总验证时限内测试全部候选，全部成功并复验修订和凭据后，记录 `verified_at` 并原子启用。已验证且仍有可用候选的版本可随时重新启用，包括旧版本；同策略仅一个 `current_version`，并发修改返回冲突。`DisableVersion` 清空当前选择，停用非当前版本不影响已有选择。版本接口的 `is_enabled` 从该指针直接计算，验证时间仅代表已通过测试，不构成第三种状态。版本切换及停用只影响新任务，已有运行继续使用原版本；停用整个策略、供应商、模型或撤销凭据仍会拒绝其后续调用。

迁移 `0057_multi_model_routing.sql` 将旧版本原样转换为单候选，回填已绑定运行及既有用量的模型关联，移除旧单模型列。候选仅可在创建停用版本的同一事务内写入，之后不可修改。新外键、历史回填及索引会扫描策略、运行和用量表，并持有结构锁；升级应停止接单，排空在途操作，在维护窗口备份后成套更新服务端和管理静态资源。新增路由元数据随运行增长，单行候选历史有界为 16 项。失败迁移事务整体回滚；升级后回滚须恢复升级前数据库与程序，或通过更高版本前向修复，不能直接启动旧程序或删改迁移账本。

迁移 `0058_model_version_enable_disable.sql` 移除旧版本状态字段，将原启用过且未撤销版本的时间转为 `verified_at`，原草稿及已撤销版本转为未验证的停用版本，并清除不一致的当前指针。原已撤销版本可以重新测试并启用；候选及配置历史继续不可改写。迁移只扫描策略配置表，持短暂结构锁，不扫描运行或用量明细；需停止接单、备份后与管理端成套升级。失败整体回滚，已升级环境降级须恢复升级前数据库、二进制和页面，或新增更高版本前向修复。接口移除旧发布、激活和撤销入口，不保留兼容层。
