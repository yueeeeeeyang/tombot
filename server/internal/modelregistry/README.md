# 服务端模型目录与策略版本

本模块实现 PostgreSQL 模型目录、凭据生命周期、策略发布与选择，服务端是唯一配置来源。客户端和用户电脑不保存供应商凭据。管理 HTTP 由 [adminapi](../adminapi/README.md) 提供，能力验证与受限传输由 [modelgateway](../modelgateway/README.md) 实现，持久运行绑定和调用 Worker 由 [execution](../execution/README.md) 实现。主服务、管理界面与生产执行环境尚未接入，模型调用链切换仍未完成。

## 配置与发布

`New` 必须接收独立控制连接、租户连接、身份服务、部署注入的主密钥集合和能力验证器。控制角色管理模型目录；所属用户与 Bot 检查经过租户事务和 RLS，不能借控制连接读取用户聊天内容。管理读操作复验管理员身份，所有变更还要求近期二次验证。

供应商协议与地址、模型键与能力上限登记后保持不变。变更这些内容需要新目录项；策略输出长度可在目录上限内调整。地址只接受无用户信息、查询串和片段的 HTTPS URL。此处是结构检查，不能替代实际连接时的 IP、DNS、重定向和部署允许范围检查。

流程为 `创建策略 → 新增草稿 → 验证能力 → 发布版本 → 分配策略`。草稿也是不可改写的版本，修改配置应创建更高版本。每个版本保存协议、地址、模型键、能力、长度限制、可选价格和凭据版本引用，价格缺失保留为未知。数据库触发器拒绝原地修改配置、恢复已撤销版本、降低当前发布版本或删除历史引用。

发布期间不占数据库事务调用上游。`Verifier.Verify` 必须实际验证文本及所声明的工具、视觉能力，不执行用户工具，不保存凭据，遵守调用时限。发布不自动重试探测。验证完成后重新核对管理员身份、策略及目录修订、凭据状态，再以短事务原子发布；任何竞争或审计失败都会拒绝发布。已经发布的同一版本再次请求不会重复探测或把当前版本改回旧版本。

生产验证器使用 `modelgateway.Gateway`，在部署允许的来源范围内真实发起文本、工具结构和视觉探测。构造器拒绝缺失验证器；本模块的测试替身只用于注入成功、失败、超时和竞争，不能在服务启动入口中作为默认实现。运行入口还需显式注入出网策略与时限，不能根据管理接口提交的地址自动扩大允许范围。

## 凭据轮换与退役

`AddCredential` 创建新版本，使用 AES-256-GCM 保存密文，附加认证信息绑定供应商、凭据记录、版本及主密钥引用。管理视图只显示记录标识、版本、撤销及销毁状态，不返回前后缀、摘要、密文或明文。随机数和认证操作复用仓库已有密码模块；认证加密的附加数据语义参见 [Go AEAD 文档](https://pkg.go.dev/crypto/cipher#AEAD)。

正常轮换新增凭据并发布新策略版本，旧运行继续使用原来的版本。主密钥集合由部署外部注入，当前主密钥用于新加密，保留的历史主密钥用于旧记录；缺失时明确失败，不生成替代值。不能在仍有存活密文时移除对应主密钥。

`RevokeCredential` 阻止后续发布和调用。`DestroyCredential` 只接受已撤销、且全部策略引用均已撤销的凭据；销毁清除数据库中的密文和随机数，保留不可恢复的墓碑与审计身份。两步均幂等。销毁不会清除历史备份中的材料，备份及主密钥的保留和最终清理仍由部署生命周期处理。

## 运行选择与撤销

`Resolve` 仅供受信调度器使用，按 Bot 特例、用户策略、平台默认的顺序选定策略及当前版本。选中的策略、目录、凭据或版本不可用时明确失败，不自动改选其他项。管理员的分配操作检查资源所属用户，并通过期望策略标识防止覆盖并发修改。

返回的 `Selection` 由 `execution.BindModel` 在有效租约下写入持久运行记录；首次绑定后由数据库禁止改写，重启恢复仍使用原版本。它本身不是客户端授权凭证，HTTP 不能接收用户自填的 `Selection`、模型标识、供应商地址或凭据标识再直接调用 `Use`。

`Use` 只接收执行器从运行记录读取的选择，每次重新检查用户和 Bot、策略及目录启用状态、固定版本和凭据撤销状态，再把配置和短期明文交给受信回调。回调不持有数据库事务，退出后明文清零。事务内检查是本次调用的接纳点；已接纳的外部请求不能保证被事后撤销回滚。新调用仍固定原版本，不能绕过紧急撤销。

`modelgateway` 提供连接、响应、流空闲时限及受限出网，新 Worker 已组合本模块、持久运行、调用额度预留与真实用量结算。主入口已组合，在途配置撤销通知和能力发布探测计量仍待完成；本模块没有以估算或零用量代替这些能力。

## 数据版本与验证

新增 `0033_model_policy_versions.sql` 建立修订、当前版本引用及不可变约束；`0034_model_credential_retirement.sql` 前向增加退役状态与引用索引。历史脚本不变，不读取或转换旧 SQLite 数据。

两项迁移在有界事务内执行，新约束会扫描配置表并取得结构锁。当前小型配置表可直接执行；生产升级前仍须核对容量与锁等待。失败整体回滚，已应用脚本的修正只能新增更高版本。应用回滚不得删除版本历史或重新启用已撤销材料；已销毁的凭据不能靠替换二进制恢复。

测试使用专属 PostgreSQL 集群和真实权限角色，覆盖目录分页、两用户隔离、策略优先级、不回退、并发版本号、在途版本固定、探测期间变更和撤销、探测超时、凭据清零、密文替换拒绝、主密钥轮换、退役条件、数据库不可变约束及审计失败回滚。

```sh
TOM_TEST_POSTGRES_BIN="$TOM_TEST_POSTGRES_BIN" \

```
