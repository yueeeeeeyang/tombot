# 持久消息与运行

本模块使用 PostgreSQL 保存用户消息、回合、运行、任务租约和外部操作记录，并提供容器 Agent 调度 Worker。用户发送接口与受信 Worker 接口分开：前者必须持有有效桌面会话，后者只接受从调度连接领取的完整租约。新 [用户 API](../userapi/README.md) 已接入消息受理、查询、已读和取消；Worker 已组合 [modelusage](../modelusage/README.md) 的预留与结算，并提供[容器 Shell 与桌面工具适配](../computertools/README.md)。`tomd` 已通过 [serverapp](../serverapp/README.md) 接入；其余电脑工具、真实节点部署与客户端切换仍待完成。

## 消息与所有权

`Send` 当前处理用户与单个 Bot 的单聊，输入为会话 ID、`client_request_id` 和文本正文。正文上限 32 KiB；不接受用户覆盖、模型配置、工具调用或运行身份。群聊和 Bot 私信由各自编排器创建任务，当前单聊入口明确拒绝这两类会话。

同一事务完成消息、回合、运行、队列和用户事件写入。用户级队列头锁串行核对幂等键与排队容量，会话锁分配连续消息及回合序号，数据库唯一索引保证一个会话只有一个活动回合。相同用户、相同请求键及相同内容返回原资源；内容或目标会话改变则冲突。失败完整回滚，客户端应复用原请求键核实结果。

每个实体直接携带 `user_id`，强制 RLS 和复合外键共同约束会话、回合、Bot、运行及消息的所属关系。用户请求在业务事务内复验账户、设备与会话。调度角色只能读取任务元数据和领取顺序，不读取正文、提示词或操作结果；迁移角色不用于运行时。

`Messages` 按所属会话序号倒序分页，单页最多 100 条。`MarkRead` 只推进已读位置，拒绝未来序号，旧设备回包不能使位置倒退。消息正文不可通过租户角色原地修改或删除。

## 领取与固定配置

`Claim` 先选择最近领取时间最早且有可执行任务的用户，再领取该用户最早可执行任务。使用短事务与 `FOR UPDATE SKIP LOCKED`，锁冲突时让其他用户继续领取；它保证任务互斥，不保证外部调用恰好一次，也不承诺严格的全局 FIFO。相关数据库语义见 [PostgreSQL SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html)。

同一 Bot 最多一个已领取任务，不同 Bot 的推理任务可以并行。过期但尚未完成恢复的任务仍占用 Bot，不能仅凭时间已过再启动一个执行者。平台及用户模型调用名额、用户电脑执行权是独立资源，不能把此处的 Bot 队列锁当作电脑独占或用量限额。

领取记录包含用户、任务、运行、Bot、会话、回合、持有者、代次、尝试号和数据库时间计算的到期时间。所有 Worker 写入都锁定同一任务行并逐项校验；提交前再次检查有效期。续约与恢复同样使用数据库时钟。旧 Worker、旧代次、到期租约和取消后新操作明确失败。

机器人设定在入队时保存快照。`Start` 返回固定设定、有界消息历史与已有操作；上下文截断有明确标志，中断的 Bot 回复不进入历史。最新用户消息本身超出上下文限制时失败，不静默丢弃。

首次模型调用前，`BindModel` 从 [modelregistry](../modelregistry/README.md) 解析并持久固定策略及版本。外部解析不占数据库事务，回写时重新核对租约、运行状态及资源可用性。运行已有绑定时直接返回原版本；数据库触发器禁止改写机器人快照和已绑定版本。实际调用还必须通过 `modelregistry.Use` 逐次复核撤销，不能以固定版本为由跳过检查。

## 外部操作与恢复

Worker 在产生副作用前调用 `BeginOperation`，传入稳定步骤键、类型和规范请求摘要。只有返回 `isNew=true` 才允许执行一次；返回已有记录时复用已知结果，`started` 或 `unknown` 都不代表可以重试。单次运行同时最多一个未结算操作，操作数量有显式上限。

`RecordOperation` 在原有效租约下保存成功、失败或未知结果。结果限于有界 JSON 对象，禁止写入凭据；错误只使用固定代码。相同终态重复提交幂等，冲突终态和旧执行者写入被拒绝。数据库同时保护操作身份、请求摘要和终态。模型操作必须携带固定配置和调用硬时限，原子预留额度；记录结果时同时结算独立用量账本，缺失用量保留未知。

| 到期任务状态                   | 恢复方式                                             |
| ------------------------------ | ---------------------------------------------------- |
| 没有未结算或未知操作           | 保留已知结果，增加代次，按有上限的指数退避重新排队   |
| 有 `started` 或 `unknown` 操作 | 未结算操作标为未知，运行结束为 `unknown`，不自动重发 |
| 已请求取消                     | 保存取消终态；未结算操作仍留下未知记录               |
| 达到最大尝试次数               | 以 `RECOVERY_EXHAUSTED` 失败结束，不再领取           |

恢复每次最多扫描 100 条到期记录，再逐条锁定并核实；续约成功或已被其他恢复器处理的记录不会被重复更改。有效租约不被服务重启全局中止。已记录结果在重新领取后仍可读取，不能因为 Worker 重启就重发外部请求。

排队任务取消立即收尾；已领取任务只进入 `canceling`，保留租约等待持有者或恢复器。`Complete` 原子保存回复、运行、任务和事件，存在未结算操作时拒绝完成；成功还要求已知成功的模型操作与非空回复。失败时保留的部分回复标为 `interrupted`。

共享电脑执行权已通过 [computercontrol](../computercontrol/README.md) 接入。未释放电脑会话会同时阻止 `Complete`、`Recover` 和数据库任务换代；节点确认清理后才恢复任务。因电脑到期、失联或资源失效而结束的会话不能再报告成功。电脑动作通过节点接口执行；生产业务 cgroup 的实际入组及整树回收仍须联合验收。`AppendModelEvidence` 仅追加原调用计量，`ReconcileUsage` 独立结算迟到用量；旧 Worker 不能绕过租约直接覆盖终态。

## 模型与工具 Worker

Worker 现通过 [botagent.Dispatch](../botagent/README.md) 分发到已授权电脑，不再调用同进程模型与工具循环。每次运行包括纯文本任务都先取得容器执行权，再启动固定 Agent；电脑排队期间不预留模型调用名额。构造器必须同时接收电脑控制服务与 `computer.AgentRuntime`，没有缺省执行器或宿主回退。**`tomd` 已组合本 Worker；真实节点部署与完整电脑执行仍须联合验收。**

`workerRelay` 负责单次模型或工具调用的固定配置、请求摘要、已知结果恢复及持久记录。分发中继独立核对序号、上下文、已返回的工具调用及最终答复，拒绝容器改写提示词、工具定义、调用参数、步骤或完成内容。模型和工具操作都携带当前 Agent 会话，在登记事务内复验完整桌面身份、租约及代次；电脑操作继续保存现有会话外键，截图与操作序号由下方 `0043` 迁移追加。

`NewWorker` 显式接收持久执行服务、模型目录、受管模型调用器、工具集合、电脑控制服务、Agent 运行器、时限和并发配置。新增必填 `AgentTimeout` 限定每块电脑调用，为 200 毫秒至 10 秒且不超过运行期限。`modelgateway.Gateway` 实现模型调用接口，`modelregistry.Service` 实现固定配置的逐次验证。构造器不注册示例工具或默认供应商，未注册的 Bot 工具权限会明确阻止运行。

`Serve` 有界并发领取任务，另行恢复过期运行和对账用量。`Process` 在整个循环持续续约；续约同时检查用户及资源状态，用户取消、禁用、归档或失去租约会中止后续动作。模型并发名额不足时，只在明确尚未入账、尚未发送请求的情况下等待；等待受运行总时限约束，已发出的生成请求不会自动重试。

每一步先记录稳定操作，再调用模型或工具。模型结果和工具结果落库后才推进下一步；最终回复提交失败时，重新领取必须取得新代次电脑授权并启动新 Agent，已知模型与工具结果仍直接复用。原始工具参数以 JSON 字符串保存，避免 JSONB 规范化改变大整数、指数写法或请求摘要。模型输出、工具数量、参数、上下文增长及循环次数都有上限；超限或未知结果不能变成成功回复。完成帧还必须匹配已知模型答复、确认协议输出排空和进程退出，再进入电脑回收与最终提交。

工具只从 Bot 快照允许的显式集合产生，每次新工具动作还在事务内复验当前 Bot 权限。工具实现必须执行当前策略、资源授权和电脑控制检查，使用 `Invocation` 中的运行及操作身份，并遵守上下文。已知失败作为英文工具结果返回模型，通信失败或副作用不明则终止为未知，不能靠换操作键重试。`NewComputerShell` 提供 `computer_shell`，`NewComputerDesktop` 提供 `computer_screenshot` 和 `computer_input`；后两者明确要求模型支持视觉。`ComputerBrowser` 注册 `computer_browser` 本地工具，并要求模型支持视觉；它没有服务端执行方法。`PrepareLocal` 与 `CompleteLocal` 复用现有操作及截图事务，分别登记授权和确认结果。文件、交互终端及协作工具仍待接入。

所有运行在启动 Agent 前取得所属机器人的桌面会话，不同机器人可在用户并发额度内并行。等待时不占模型名额，也不重复模型调用，运行查询返回 `computer_wait_reason` 区分桌面占用、用户额度和启动确认。`UsesComputer` 为真的工具额外以 `computer` 类型记账并保存会话外键，服务端工具通过 `Invocation.Computer` 调用节点，本地浏览器工具则由 Agent 在当前容器执行；后续模型思考期间继续持有自身桌面并续约，不占用其他桌面的输入控制权。运行退出前先清理，清理未确认则保留恢复记录，不能提交成功回复。单聊当前每次运行尝试只使用一个电脑会话；人工接管、父子任务交接及等待时释放 Worker 名额仍待扩展。

模型用量与操作结果共同提交；写入失败时用稳定证据 ID 尝试追加计量，避免旧租约失效后丢失已收到的供应商计数。运行状态仍只能由有效租约修改。后台停止保留恢复依据，不将未确认的外部请求重新入队调用。

## 截图持久化与模型视觉

桌面工具返回有界 PNG 及图片引用。`RecordOperation` 校验操作 ID、Bot、尺寸、媒体类型、长度、摘要和实际像素，再将 `run_screenshots` 与操作成功结果放在同一事务中提交。操作 JSON、Agent 控制帧、日志只保留引用，绝不内嵌 PNG；图片是临时模型观察，用户共享业务文件仍留在电脑卷。所有引用受用户 RLS、运行和 Bot 复合外键约束。

用户级事务锁串行计算图片数量与字节总量。容量拒绝完整回滚，Worker 再保存明确失败且无图片引用的工具结果；其他存储失败保留未确认操作，不宣称图片已保存。`ImageOptions` 配置每用户字节和数量、模型上下文图片数量及保留期限：默认 256 MiB、256 张、最近 2 张、7 天；允许范围分别为 4 MiB–4 GiB、1–4096 张、1–4 张、48 小时–30 天。

模型调用前只装配当前运行已成功持久化的截图，逐项比较引用并校验所选 PNG。最近若干张附带实际像素，旧引用保留身份并明确说明没有附图。原 Agent 轨迹不修改，也不允许 Agent 直接传入像素、其他 Bot 或其他运行的引用。OpenAI 兼容协议与 Anthropic 适配器沿用各自视觉格式，不把图片地址文本当作视觉输入。当前注册桌面工具要求视觉能力，能力缺失在外部调用和用量预留之前拒绝。

Worker 定期分批删除过期且任务已结束的截图，每批最多 100 张，使用行锁跳过其他清理者；运行中或排队恢复的截图保留。清理角色只能读取身份及到期时间，不能读取像素或改写图片；操作和消息审计保留。保留时间是可回收时间，不保证精确时刻删除。图片限额独立于电脑磁盘限额，须计入 PostgreSQL 容量与备份预算。

`0043_execution_screenshots.sql` 新增截图表、RLS、外键及回收索引，并为操作增加不可改写的数据库 identity 序号。桌面使用该持久递增值，允许模型步骤、无效参数或回滚造成的空隙；旧序号拒绝，重复末次输入不重发。Agent 私有协议自身的连续帧序号和终端连续写入序号不变。

迁移在事务内执行，给已有操作填充序号可能扫描并重写表、取得排他结构锁，耗时取决于操作记录规模；上线前在副本评估表大小、锁等待及可用空间，停止领取并排空后执行。旧 `0001`–`0042` 脚本保持不可变，已应用的 `0043` 只能由更高版本前向修正。发布须匹配应用、节点、镜像与数据库账本；回滚保留截图与未知操作证据，只能使用理解新账本的版本或恢复停单时一致快照，不删除迁移记录让旧程序启动。

## 数据版本与验证

新增 `0037_durable_chat_execution.sql` 建立消息、回合、运行、队列、用户调度头和操作表，为会话追加回合序号。此前迁移保持不变，不读取或转换 SQLite。迁移在事务内完成，追加列需要会话结构锁；新表索引随建表生成。上线前核对会话规模与锁等待预算，失败整体回滚，已应用版本只允许通过更高版本修正。

应用回滚先停止接收新任务，停止领取并等待有效租约收尾或进入明确恢复状态；保留消息、配置绑定与未知操作证据。只能回到理解这些实体及状态的应用版本，不能把新数据回灌旧 SQLite 或通过清空队列重放任务。新主入口只使用 PostgreSQL；本轮没有连接或修改旧业务数据。

真实 PostgreSQL 竞态测试覆盖并发幂等、事务回滚、两用户隔离、调度权限、公平领取、任务互斥、固定配置、操作去重、旧租约、取消、未知结果、有界恢复及资源限额。Worker 测试实际运行领取、模型工具循环、计量与回复提交，验证最终提交失败后的恢复不重放、长调用续约、用户取消、权限撤销和非法输出。模型与工具回调使用可控替身，不请求公网供应商或真实电脑；生产网关、电脑及主入口组合仍需端到端验收。

```sh
TOM_TEST_POSTGRES_BIN="$TOM_TEST_POSTGRES_BIN" \
  go test -race ./internal/execution ./internal/userapi
```
