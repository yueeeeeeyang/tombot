# 节点与电脑代理控制通道

本模块提供 Linux 本机 Unix 顺序包通道，在一个有界消息中传递协议内容和受限文件描述符。它只负责传输及内核对端身份读取，业务权限由 [computeragent](../computeragent/README.md)、[dockernode](../dockernode/README.md) 和 [nodeapi](../nodeapi/README.md) 复验。应用服务只能经受保护节点端点发起固定动作，模型和业务客户端不能直接连接节点或容器控制端点。

## 消息和描述符

仅接受 `AF_UNIX` 的 `SOCK_SEQPACKET`，不回退到字节流或网络连接。每帧上限 128 KiB，最多四个描述符，包含版本、请求标识、动作、描述符数量和类型化内容。规范 JSON 校验拒绝未知字段、重复键、大小写别名、额外对象和不一致的描述符数量。传输层列出的动作不代表每个端点都接受：代理处理会话、终端、图形和 Agent 协议；节点 API 只处理 `node_control`，其子动作另行校验且不允许任何描述符。

发送通过 `SCM_RIGHTS` 复制描述符，调用方继续拥有原始描述符；接收使用 `MSG_CMSG_CLOEXEC` 在内核创建接收描述符时设置执行关闭标记。消息截断、控制数据异常、解析失败或数量不符时，关闭全部已收到的描述符和连接，不能只丢弃正文。语义依据 [Unix socket 文档](https://man7.org/linux/man-pages/man7/unix.7.html)及 [recvmsg 文档](https://man7.org/linux/man-pages/man2/recvmsg.2.html)。

构造器通过 `SO_PEERCRED` 返回内核记录的 PID、UID 和 GID，但不替调用方决定信任关系。节点必须把 root 对端 PID 重新定位到已固定的容器父资源组；容器代理只接收其私有 PID 命名空间中不可见的宿主 root 对端。生产监听器还必须位于 root 独占的目录，禁止任务替换套接字。这些身份检查不能用消息内自报的用户、PID 或目录代替。

收发分别有并发入口，排队和实际 I/O 共用本次时限。取消关闭连接，错误不包含命令或原始消息。一次动作只发送一次；连接丢失不证明动作未执行，上层必须对账，不能自动重放。

## 跨进程期限

授权携带同一 Linux 时间命名空间内的绝对 `CLOCK_MONOTONIC` 截止值和时间命名空间身份。转换沿用节点已有期限，并按保守采样顺序缩短剩余时间；接收方拒绝不同命名空间、过期或超过本次最大租期的值。排队、重新连接和重发均不能从接收时刻重新获得完整租期。

这份期限只适用于同一内核的节点与用户容器，不作为跨宿主时钟协议。非 Linux 平台明确返回不支持。

## 验证和发布边界

常规测试覆盖规范编码和输入边界。受限 Linux 容器内已实际验证顺序包通信、内核对端身份读取、描述符复制及执行关闭标记、发送方所有权、异常帧描述符回收、取消、字节流拒绝和传输后剩余期限缩短；以 `/proc/self/fd` 核对异常路径没有描述符遗留。

节点已生成独立控制目录和固定挂载，代理入口建立受保护监听，节点会话也已绑定控制请求。完整宿主到生产用户容器的连接、cgroup 入组和回收仍未联合验收；按 Bot 的多桌面路由及电脑镜像也待完成。升级须与代理、节点和任务引导协议成套发布；不提供旧协议回退，不改变数据库结构。
