# 受信 Docker 电脑节点

本模块实现电脑生命周期的 Docker 适配、持久控制记录与执行会话。它已能调用真实 Docker 创建、检查、启动、停止与删除限定资源，并实现[固定容量持久磁盘后端](storage.md)及 [Linux 进程资源组后端](../processgroup/README.md)。[受保护节点 API](../nodeapi/README.md) 已提供跨进程接口及身份校验，`tomd` 已组合节点 API 客户端，[独立节点程序](../nodeapp/README.md)已组合真实基础证据检查。共享浏览器、完整能力检查及磁盘/进程资源组的完整内核验收仍未完成，因此还不能用于正式用户开户。

最新[改造方案](../../docs/multi-user-refactor.md)要求每 Bot 独立 Linux 桌面并行运行，业务文件、工具和浏览器登录态共享。节点现已按稳定桌面分别持久化会话、控制代次、期限和关闭屏障，并允许同一用户的多个桌面调用重叠执行。容器代理的多桌面授权已接通，受管终端已接通节点与代理，图形会话启动已接通，独立 Bot Agent 分发与分块中继已接通；屏幕网关和主服务仍须组合；节点测试不能替代整条并行桌面链路验收。

`Runtime` 实现 `computer.Runtime`，只暴露 `Inspect`、`Ensure` 和 `Remove`。`New(ctx, options, storage, logger)` 限定 Linux root 系统服务，检查 root 所有的配置目录及本机 Docker socket，显式提供存储实现，内部建立真实基础能力检查器。生产入口不能注入任意成功探针；缺少浏览器证据始终不能完整就绪。API、Worker 和用户任务不持有这类通用宿主权限。

## 控制记录与并发

每个用户有独立持久记录和不可替换的锁文件。记录保存操作、用户、电脑、节点、实例代次、尝试号、控制代次、租约期限和清理阶段。资源变更前先写记录并刷盘，替换后同步目录；损坏记录或写入失败会中止操作，不当作新电脑初始化。

首次锁文件采用独占创建；已存在时打开同一文件，不删除或换 inode。打开文件使用受控目录描述符及 `O_NOFOLLOW`，拒绝符号链接、多重硬链接、非预期所有者和组或其他用户可写的记录。生命周期变更持有完整操作期间的每用户独占文件锁。桌面操作先取得同一文件的共享锁，再取得该桌面的独占锁；其他桌面可以同时调用，容器生命周期变更必须等待所有在途桌面操作结束。锁顺序固定，等待锁也消耗请求及租约时限；取消会释放已经取得的锁。

同代次只能接收完全一致的资源配置；旧控制代次被拒绝，同一控制代次不能延长租约。收到租约时将剩余期限转成单调时钟截止点，节点调用和锁等待受同一期限限制。控制服务与节点仍须保持部署时钟同步；这属于首次开户协议，长期执行会话使用下述独立的期限和控制版本。

节点重启读取已刷盘的最高代次。只有旧资源已确认全部不存在时，才允许下一实例代次和下一尝试号。新代次使用不同的实际容器、卷及后端目录名称；稳定的逻辑电脑与用户卷标识由业务层保留，初次开户重试不会复用可能仍受旧删除请求影响的物理名称。

## Docker 资源边界

客户端通过明确指定的本机 Unix socket 使用固定版本 API，不读取 Docker CLI 配置、环境代理或用户登录信息。请求有连接和响应时限，禁止重定向，响应大小有上限；错误仅保留分类，不返回原始守护进程内容。协议依据 [Docker Engine API v1.47](https://docs.docker.com/reference/api/engine/version/v1.47/)。

容器配置由节点生成，外部请求不能指定命令、挂载、端口或环境变量。资源按固定标签绑定节点、用户、电脑、操作和配置摘要。每次调用都核对实际标签、持久卷来源、容器镜像及入口、资源限制、挂载和网络状态；配置漂移、额外网络接口或可路由地址出现时拒绝变更，不自动删除冲突资源。

当前固定配置包括只读系统层、固定摘要镜像、CPU/内存/进程限制、禁用额外交换空间、独立 PID/IPC/cgroup 命名空间、禁止提权、受限临时目录及有界日志。Docker init 管理受信电脑代理入口，代理具有管理任务身份所需的六项权限；用户代码必须转换为非 root 身份后执行。`computer-agent` 已实现受保护配置、共享工作区与基础图形目录准备、监听、看门狗监督及有界退出，任务运行器和每桌面图形会话仍未接通。

节点直接嵌入[镜像 seccomp 策略](../../deploy/computer/seccomp.json)，以完整 JSON 提交给 Docker API，与镜像验收使用同一来源，不依赖宿主同名文件，也不使用 `unconfined`。`/tmp` 为 root:root、1777 的有界 tmpfs，`/run` 为 root:root、0755 的有界 tmpfs；二者保留 `nosuid,nodev,noexec`。私有桌面状态在 `/run/bot-desktops` 下另行保护，平台控制目录继续为 root 私有挂载。

`Options.RuntimeBytes` 和 `Options.SharedMemoryBytes` 为必填节点配置，分别限制 `/run` 和 `/dev/shm`；运行空间允许 16 MiB–4 GiB，共享内存允许 64 MiB–4 GiB，仍受容器总内存限制。`TemporaryBytes` 独立限制 `/tmp`。节点对账检查这些容量、目录权限和完整 seccomp 内容，发现旧配置或漂移即报错，不原地扩大资源或修复未知容器。Chrome 采用原生沙箱，无需增加 SYS_ADMIN 或关闭浏览器沙箱。

除用户工作空间外，容器只额外挂载本代次 root 私有控制目录到 `/run/tombot-control`。节点先创建目录并刷盘固定实例配置，再创建容器；对账复验目录权限、配置、挂载来源和目标，不重写漂移配置。控制目录位于节点状态目录内，与用户卷分离，各实例代次不复用；资源清理保留当前代次的控制记录，旧代次在下一代建立前按下方规则回收。

## 控制元数据保留与代次回收

周期验收使用稳定逻辑电脑，不按每轮永久增加存储记录和代理目录。磁盘控制记录采用[版本 3 每用户布局](storage.md)；用户生命周期记录采用版本 4，保留可恢复的 `control_retirement`。宿主每用户的最高生命周期、探针最高消费版本以及每桌面的关闭屏障继续保留，不清空或重新编号。

换代持有同一用户生命周期独占锁：先要求宿主执行会话均已关闭，复查旧容器、Docker 卷和磁盘实际不存在，确认探针与出网关闭；再查询实际挂载表、核验代理目录所有者与权限，并确认代理及出网锁无人占用。保存旧目录设备号、inode 及下一代不可变规格、控制版本和租约后，才删除控制文件。下一代的状态只能在回收完成、目录刷盘后提交。更高控制版本可接管同一待进入代次；旧版本、改规格、同版本换期限均拒绝。

清理仅允许平面目录内已识别的配置、代理锁、端点、探针与桌面记录和两类原子写入临时文件。每批读取 100 项，最多允许 `MaxDesktops + 64` 项；逐项复核 inode、root 所有者、0600 权限和单链接。未知内容、子目录、硬链接、符号链接、嵌套/文件挂载及仍被持有的锁会阻止换代，不使用递归删除或穿过挂载，也不处理共享业务文件。当前最高代次在 `Remove` 后继续保留目录，到下一代再回收；失败时最多保留正在回收的旧目录，不继续创建新目录。

删除部分完成后，恢复使用已保存的目录身份，配置文件已删除也能继续；同名目录被替换则失败。目录删除后、新代次提交前中断时，再次同步父目录后推进。回收中的旧代次不能恢复 `Ensure`、`Inspect` 或 `Remove`；调用者继续对账账本中的待进入代次。宿主记录写入、文件删除、目录同步或资源查询失败均向上报告，不宣告回收成功。

该变更不新增数据库迁移、不修改镜像协议。节点生命周期版本 1/2/3、原按代次分散的存储记录和锁均拒绝，不自动迁移。正式部署使用新状态；中间开发环境先由匹配旧版本停单、排空并确认资源关闭，保存备份后另建空环境。回滚只允许理解版本 4 生命周期、版本 3 存储记录和镜像布局 2的配套程序，不能通过删除最高代次屏障让旧程序重新接单。

常规回归覆盖连续换代、并发、关闭前置条件、目录边界、数量上限、损坏记录、删除中断、同名替换、接管与旧回包；Linux 受限容器验证真实文件、flock、目录同步及只读挂载表。Docker、loop 与资源组成功路径仍为明确替身，本项不代表真实电脑部署验收完成。

用户工作空间只挂载本代次存储后端返回的精确路径，Docker 卷使用本代次唯一名称。存储后端区分资源存在与挂载就绪，节点不提供无配额的生产替代实现。容器固定使用 `NetworkMode: none`，只保留环回网络，不创建用户桥接网络或发布宿主端口。节点对账要求唯一 `none` 端点且没有 IPv4/IPv6 地址及网关；禁止附加接口或改成宿主网络。电脑通过[受控出网代理](../egressproxy/README.md)访问公网，业务进程不能通过网络直接连接宿主。代理模块、容器环回转接、宿主端点管理和实际容器身份校验已接入本模块；独立节点程序已组合这些组件，完整能力探针仍待补齐浏览器联合证据。

## 创建与清理

`Ensure` 先对账，再创建缺失的存储、卷及容器，使用同一代次的固定名称。创建回包丢失后先检查原资源，不更换名称重试。实际探针必须同时通过终端、浏览器、文件、进程回收、硬磁盘配额及网络隔离，才返回 `ready`。

`Remove` 先持久记录 `removing`，封闭本代次的创建入口；然后停止容器、确认已停止、删除容器并确认不存在，再删除卷，最后清理本代次后端存储。卷删除不使用强制选项，也不随容器隐式删除；任何占用、未知响应或未确认删除都会阻止后续清理。确认全部不存在后持久记录 `absent`，之后才能进入新代次。

这组方法仅服务首次开户操作。已激活用户的删除、卷保留、重建、休眠和镜像升级必须走后续专用运维协议，不能直接复用开户补偿入口。

## 执行会话与进程回收

`SessionController` 实现 `computer.SessionRuntime`，使用用户生命周期共享锁和桌面独占锁，另持有节点级执行服务锁。同一控制目录只能运行一个执行控制器。每个桌面使用 `<user_id>.<desktop_id>.session.json` 保存版本 2 记录，独立记录用户、电脑、桌面、Bot、Linux UID、公共 GID、显示编号、节点、容器、运行、实例代次、桌面控制代次和命令版本。关闭屏障跨运行和容器代次保留，不能通过改变 Bot 或物理桌面身份重用旧桌面。不同桌面的控制代次互不比较，同一桌面的旧版本和未清理会话仍被拒绝。

`Open` 先核对已就绪电脑及实际 Docker 资源，再刷盘开启意图，定位并持久记录容器父 cgroup 的设备号和 inode，最后建立空会话子树。此时不执行用户代码。`MaximumActive` 按节点上的桌面数原子预留，包含开启中、活动、关闭中和隔离的桌面，同一用户的多个桌面各占一个名额；用户自己的并发额度由控制面另行限制。失败留下可回收记录，不用另一个会话覆盖未知结果。

`Renew` 使用收到命令时计算的本地单调时钟期限，重复同版本不延长有效期，过期或关闭会话不能重新激活。`Serve` 定期回收失去续约的会话，按配置进行有限退避；等待生命周期或桌面锁超时、记录读取失败也消耗该桌面的尝试次数，耗尽后保留隔离。控制器进程重启时先清理所有遗留会话，持久记录中的墙上时间只供审计，不能恢复旧执行权。任一旧会话无法确认清理，节点执行服务拒绝启动。

`Close` 先持久封闭新入组授权，然后回收会话子树，确认空组并移除全部受管目录，最后刷盘关闭状态。重复关闭不会再次操作资源组；迟到的旧关闭也不能命中新会话。未收到开启的先行关闭也进入回收和停服集合，未知关闭结果不能因缺少进程内记录而被遗漏。生命周期 `Remove` 在用户独占锁内逐条核对该用户的全部桌面记录，拒绝任何未关闭、损坏或旧格式记录，不能因某一个桌面已经关闭就删除整台电脑。

`Membership` 只向受信内部调用者返回活动会话的 `shell` 或 `browser` 入组描述符。`Delegate` 在同一活动身份检查后生成[代理会话授权](../computeragent/README.md)及四个限定的内核入口；`AgentRenewal` 同步现有节点期限，生成或重发消息本身不续租。期限使用共同 Linux 时间命名空间内的绝对单调时钟，防止传输延迟延长执行权。

`CheckAgentPeer` 复验 `SO_PEERCRED` 的 root 对端及其宿主 PID 对应的容器父资源组设备号、inode 和完整会话身份，不单凭 UID 信任对端。`Open`、`Renew`、`Close` 已通过 `agentLink` 自动下发[控制协议](../agentchannel/README.md)，在已有生命周期共享锁和桌面独占锁内直接核验实例，避免递归取锁。开启须收到代理确认才转为活动，续约未知则隔离；代理关闭失败时仍以独立期限尝试宿主清理，两端都确认才报告 `drained`。[容器内任务引导](../taskprocess/README.md)已实现入组、撤销检查、关闭描述符和降权原语，终端启动、输出、输入与尺寸操作已通过同一受信通道接通，图形会话启动和状态查询也已接通，屏幕网关与共享浏览器运行器仍待实现。

停服先取消 `Serve`，再调用 `Shutdown` 停止接收新命令、等待在途调用并回收本进程会话；清理失败保留执行服务锁，只有确认完成才能释放。宿主重启、容器重建或父资源组身份改变时，目前明确拒绝旧身份；自动隔离并重建电脑的恢复路径仍待实现。容器代理现已为每个桌面运行独立看门狗，实现定向撤销、终止、有限回收及容器级致命退出，不能以模块测试替代控制进程死亡验收。

## 已验证与仍缺失的证据

常规竞态测试覆盖：重复创建、八个并发请求、重启后的旧控制者拒绝、代次交接、创建回包丢失、停止或删卷结果未知、错误用户标签、宿主路径漂移、特权配置漂移、额外网络、可路由地址与网关、缺失能力、锁等待取消，以及损坏、符号链接、硬链接或可写控制记录。首次并发锁文件回归已连续执行 20 次通过。

[会话竞态测试](sessions_test.go) 额外覆盖重复开启与续约、迟到关闭、先关闭后开启、过期拒绝入组、回收及前置故障的有限重试、节点独占锁、重启强制清理、并发容量预留、实际计时到期，以及损坏记录阻止入组和生命周期删除。此组使用受控资源组替身；Linux amd64、arm64 构建通过不代表真实 cgroup 回收已经验收。

[多桌面竞态测试](desktop_sessions_test.go) 验证同一用户的开启和关闭调用被阻塞时，另一桌面仍可开启、续约和取得执行授权；同桌面互斥，生命周期删除等待在途调用。还覆盖同用户四桌面竞争两个节点名额、逐桌面释放、隔离不撤销其他桌面、各自的重试状态、稳定身份替换拒绝及重启逐桌面清理。[持久记录测试](session_journal_test.go) 验证旧名称、旧版本、错误桌面、未知字段、不安全链接和可写记录拒绝，以及先行关闭失败不能脱离停服回收集合。

本轮 `make lint check test` 全部通过，Linux amd64、arm64 构建通过。使用已构建的 arm64 专用镜像，在禁网、只读、无附加 capability 的临时容器中运行上述测试及真实 Unix 通道的节点代理绑定测试，均通过；启动方式与正式容器一致使用 Docker init。该验证使用本次编译的测试程序和受控资源组，未运行用户命令、重建镜像内代理或执行真实 cgroup 回收。

`make test-docker-node` 使用显式指定的 `TOM_TEST_DOCKER_SOCKET` 和本地固定摘要 `TOM_TEST_DOCKER_IMAGE`（Alpine）执行实际 Docker 验证。测试为自己创建空白后端卷、绑定卷及无路由网络容器，核验生产配置的 Docker 实际表示，再执行独立非 root 容器的启动、占用卷拒删、停止及删除。清理器通过测试标签和资源身份核对后回收；已验证没有测试资源遗留。

该测试没有读取或挂载开发者已有卷，也没有安装系统软件。测试专用空白卷不是生产磁盘配额实现；只检查容器资源配置不等于完成压力下的限额验收。多桌面代理的完整用户进程接入、PTY、运行 cgroup 整体回收、出网代理与节点的组合及 Linux 节点系统服务仍属于未完成项。

## 部署与恢复

图形运行配置与镜像初始化程序须成套发布。节点新增的运行空间、共享内存配置不能省略；旧容器的 tmpfs、seccomp 或容量不符合新配置时对账失败。先停止接单、排空会话、保留关闭屏障与用户卷，再建立新实例；不通过改写标签、放宽校验或递归修改旧文件权限完成升级。恢复到旧版本同样要求相互匹配的程序与独立部署环境，不直接让旧私有目录程序复用新共享卷。此项不涉及数据库迁移。

节点控制目录必须位于用户存储之外，由 root 管理。API 不得接受目录或 Docker 地址覆盖。状态文件和锁文件随节点保留，禁止为解决故障删除最高控制代次记录；恢复时先停止接单、核实旧资源和备份，再恢复一致的控制记录与存储。

本模块尚未接入现有部署，当前改动没有改变已运行服务和业务数据。上线后回滚需要成套保存节点状态与用户卷，并排空在途操作；不能只替换二进制后跳过资源对账，也不能自动清理无法确认所属关系的资源。

桌面记录不兼容原 `<user_id>.session.json` 用户级记录，也不转换版本 1 内容；恢复遇到旧名称、旧版本或错误归属时明确失败并保留原文件。该改动不涉及数据库迁移，历史 SQL 保持不变。正式部署使用全新状态和配套镜像；中间版本的测试环境先停单、确认所有旧授权及资源均已清理并保留备份，再重新建立空环境，不能直接改文件名或删记录绕过屏障。回滚只允许恢复理解桌面记录的配套版本，不能让旧节点忽略已有桌面证据。

节点目录采用每批 100 项的流式扫描，恢复和删除不加载所有记录；删除扫描耗时随节点记录数增长，受调用期限约束，超时返回失败而非跳过核对。每个桌面仍需要独立刷盘，持久存储延迟会影响调用时限。

多桌面代理配置采用版本 4，`Options.Agent.MaximumActive` 为必填容器并发上限，范围为 1–64。已有实例配置不原地覆盖；节点、代理、镜像与控制目录须按新实例代次配套部署，旧配置或旧镜像不会自动兼容。真实 Unix 联合测试已验证同一容器两个桌面同时授权、独立续约及关闭其中一个后另一个继续活动，资源组仍使用测试替身。

## 终端执行通道

`StartTerminal`、`ReadTerminal`、`WriteTerminal` 和 `ResizeTerminal` 复用 `withActiveSession` 的生命周期共享锁、桌面独占锁和完整会话检查，验证固定代理实例后转发；不接受宿主 PID、设备路径或 cgroup 覆盖。调用期限取节点调用上限与已有租约的较早值，响应到达时再次核对期限。错误归属、旧代次、未开启、隔离或过期会话均在连接代理前拒绝，调用本身不续约，也不自动重放未知结果。输入去重和有界 PTY 行为见[代理说明](../computeragent/README.md)。

节点回归测试覆盖四类正常调用、错误身份、期限继承、失联未知结果只调用一次及过期后拒绝。真实 Unix 协议与容器 PTY 另行通过代理测试；主服务工具组合和真实 cgroup 成功执行仍待联合验收。此项没有数据库迁移，部署及回滚须配套镜像并保留既有控制记录。

## 图形会话通道

`StartDesktop` 和 `InspectDesktop` 与终端共用 `withOperation` 的活动会话、桌面锁和期限检查，连接固定容器代理，不接收外部显示编号、socket 路径或启动参数。启动请求快速返回 `starting`，查询得到实际 `ready` 后才可进入图形操作；重复请求不延长授权、不重启失败进程。客户端严格验证响应完整身份及固定尺寸，节点不自动重放未知启动。真实双 XFCE 监督、握手和故障边界见[代理说明](../computeragent/README.md)。

同用户仍为一个容器；每个 Bot 的 Agent 进程运行在此容器中，节点提供下述 Agent 启动和分块中继，服务端 Worker 负责调度与授权。

`CaptureDesktop`、`ReadDesktopImage`、`InputDesktop` 已复用相同授权链，逐次核对完整会话，并在连接代理前拒绝旧代次、未开启或过期会话。截图按序号保留不可变 PNG，分块最多 32 KiB；输入以连续序号去重，未知输入不重放。节点 API 校验响应归属、序号、尺寸与分块边界，错误和未知回执不会转换成成功。实际 RFB 和缓存规则见[代理说明](../computeragent/README.md#桌面截图与完整输入手势)。

节点回归测试覆盖三种操作的正常、跨代次、授权期限和失联失败路径。受限 Linux 容器通过节点跨 UID 协议及代理双 XFCE 截图、中文输入和鼠标独立性测试；这些图形进程采用测试启动器，生产业务 cgroup、公开用户桌面接口和模型视觉工具仍须继续接入。部署、升级及回滚须成套更新节点和镜像，先排空活动会话；输入回执不跨代理重启恢复，本次没有数据库变更。

## Bot Agent 分发

`SessionController` 实现 `computer.AgentRuntime`，将 `StartAgent`、`WriteAgent` 和 `ReadAgent` 转给已验证的容器代理。每次只在所属桌面锁内处理一个有界动作，沿用当前租约期限，既不延长授权，也不建立长期占锁的通道。旧代次、错误桌面、失效授权及身份不符在连接代理前被拒绝。

启动与输入回包未知时不重试；连续偏移及末块回执由代理维护。标准流字节块限制为 32 KiB，base64 后仍低于现有 128 KiB 控制帧上限。Worker 先取得完整电脑会话，再使用本适配器分发，纯文本任务没有例外。生产节点服务入口、真实 cgroup 与完整电脑能力探针仍须完成联合接入。

## 无路由网络部署变更

用户生命周期当前使用版本 4，明确拒绝版本 1/2/3，且保留原文件和资源；桌面会话记录版本 2 不变。版本 4 阻止不理解共享浏览器持久记录的旧节点接管新状态。代理配置版本 4 包含必填的连接、空闲、总传输时限、并发和字节上限；节点、代理、环境模板和镜像必须成套发布。

中间测试环境先用原配套程序停止接单、排空并确认清理旧容器及网络，再保留备份并建立全新状态；不转换旧记录，也不通过删除屏障完成升级。回滚同样先停止新实例，恢复成套状态及对应镜像，禁止混用桥接旧节点与版本 4 代理。正式新系统不导入旧业务数据，本项没有数据库结构变更。

## 宿主出网生命周期

`New(ctx, options, storage, probe, logger)` 获取持续持有的 `lifecycle-service.lock`，初始化出网管理器。`Options.Egress` 为必填公网策略和时限，`MaximumEgressComputers` 限制节点端点数（1–10000）；策略切片在构造时复制，不能由外部后续修改。控制端点路径须满足 Unix socket 长度限制（最多 100 字节），目录继续要求 root 保护。节点不在业务 HTTP 接口接受这些配置。

启动顺序为构造 `Runtime`、构造 `NewSessions`、再开放节点 API。会话构造器先回收所有旧执行，再每批 100 条读取用户生命周期记录：运行中的有效实例恢复出网端点，删除中或已停止实例关闭遗留端点；恢复不创建容器、不延长租约、不修改实例代次，也不直接提交电脑就绪。任何旧会话回收失败都不开始出网恢复；端点恢复失败关闭已恢复服务并中止启动。

`Ensure` 启动实际容器后、调用能力探针前建立其端点，`Inspect` 复验并复用同一实例。每个端点绑定完整用户与容器身份及实际父 cgroup；每次连接复验 Docker 状态、固定配置、主进程和 root 对端的精确父组身份，拒绝任务子组或其他容器。网络处理不占用用户生命周期锁；开户请求结束不取消用户电脑的网络服务。

`Remove` 先刷盘关闭意图，再停止该实例端点并等待连接、工作者和 socket 清理完成，之后才停止 Docker 容器及删除存储。旧端点不能改绑新容器；停止超时保留记录，后续请求对账。监听路径漂移封闭该端点，活监听或未知路径不会自动被覆盖。电脑停止后仍保留稳定端点锁文件。

主程序必须监督 `Runtime.Serve` 和会话、节点 API 服务。出网服务意外退出会取消节点全部出网并报告错误，停止新接入；正常退出先停止 API 及会话，再 `Runtime.Close` 等待出网结束后释放 Docker 客户端、生命周期锁与状态目录。`Serve` 的等待超时不是已回收证据；未确认全部工作者结束时保留端点锁并返回失败，不能继续启动第二个节点实例。

出网监督使用代理配置版本 4、当前生命周期记录版本 4 及桌面记录版本 2。发布/回滚时先停单、排空会话和连接，再使用匹配的新节点配置；保留最高代次记录和稳定锁，旧实例控制目录只能按上述换代协议回收。独立节点程序和系统服务已组合，真实首次部署验收尚未完成。

常规测试覆盖请求结束保留端点、复用、容器变化拒绝、节点容量、在途创建与停服、故障封闭、删除排序，以及先清理旧会话再恢复出网。受限 Linux 测试通过真实 Unix 端点恢复、请求、私网拒绝、关闭与删除；Docker 与 cgroup 在该组合测试中使用替身，生产内核身份及网络可达性仍须联合验收。


## 宿主基础探针

`Runtime` 新增必填 `Options.Probes`：检查时限 1–60 秒、独立回收时限 1–60 秒，以及实际进程组配置；回收预算必须大于正常退出宽限与轮询间隔之和。构造时建立真实服务组后端，逐用户恢复未关闭探针，之后才允许构造会话控制器和恢复出网。完整 `Probe.Check` 增加 `computerprobe.Evidence` 参数，供后续组合硬容量、出网代理、进程回收和共享浏览器能力；基础检查成功本身不等于整台电脑就绪。

`Ensure`/`Inspect` 在已有用户生命周期独占锁内执行检查，和开户、删除串行。每次使用新的服务 ULID 与跨容器代次递增的探针版本；实际服务组位于当前容器父组之下，不借用 Bot 会话。节点先保存准备记录再创建进程组，保存已发送记录再调用代理；不自动重试未知请求。三个控制描述符通过固定受保护 socket 发送，节点保留并关闭原副本，代理管理接收副本。桌面动作与探针共用受保护 socket 连接规则，各自保留完整的对端归属检查。

探针记录为节点私有 `<user_id>.probe.json` 版本 1；代理私有 `probe.json` 与其分别承担发送和消费屏障。文件沿用原子替换、文件与目录同步、所有者/权限/链接/规范 JSON 核验，拒绝回退状态、重复版本或服务 ID。租约时间以实际到期时刻比较，不比较不可持久化的 Go 单调时钟部分；资源身份、控制版本和到期时刻均不能被改变。

调用成功也必须独立回收并移除原服务组，关闭记录刷盘且实际容器身份再次核对后，才把证据交给完整能力探针。取消、结果丢失、创建结果未知和记录失败均进入同一回收路径；回收或最终记录未确认时返回错误、不返回证据，原屏障保留并阻止下一次创建。`Remove` 在停止容器之前封闭遗留探针。恢复只处理既有实例，从不重放执行；不存在对应生命周期记录、未来代次、身份漂移或损坏入口会中止启动。

Docker 已删除整个父 cgroup 时，服务回收先对真正 cgroup v2 根内的固定路径做只读检查，确认不存在方可封闭。存在但 inode 变化、未知读取错误或取消仍失败；不能按 Docker 元数据推测旧内核入口失效。该处理只适用于基础服务，未放宽 Bot 会话回收规则。

每次检查至少产生四次持久状态写入，磁盘同步延迟计入调用时限；宿主回收另有独立预算。文件系统同步不可由 Go 上下文强制中断，阻塞时不会返回成功或释放生命周期锁；容器代理仍按原单调期限独立撤销执行。启动扫描每批 100 项，恢复耗时取决于记录数量和残留资源；超时或失败必须中止激活。

探针记录使用代理配置版本 4、当前用户生命周期记录版本 4 及桌面记录版本 2，不自动迁移旧业务数据。节点接口及必填配置须与探针监督镜像配套发布。正式部署使用全新状态；中间开发环境升级或回滚前停止接单、排空执行和探针，保存全部关闭屏障与用户卷。不能让不理解 `.probe.json` 的旧节点忽略新记录，不能删除记录重置探针版本；回滚须恢复整套匹配程序和状态。本次没有替换宿主服务或业务容器。

常规测试涵盖成功、各阶段故障、失败证据清空、回收独立于取消、未知结果只发送一次、版本递增与溢出、文件屏障保护、启动恢复及删除互斥。Linux 联合测试使用真实 Unix 通道和描述符，确认节点与代理的最终记录一致及错误容器对端拒绝；资源组和工作者仍明确使用替身。真实内核入组、执行、压力回收与完整能力检查组合仍待验收。


## 固定镜像准备与开户门禁

[镜像准备入口](../../docs/image-preparation.md)使用 root 保护清单，按明确摘要及宿主平台拉取、复验并持久记录本地可用状态。`Ensure` 在分配磁盘、卷和容器之前复验同一摘要、平台和固定代理入口；镜像缺失时失败，不从开户操作隐式拉取。删除与对账仍能处理原实例，不要求重新下载旧镜像。此项改变启动前置依赖，但不改变数据库或既有生命周期记录格式；部署、失败恢复与成套回滚要求见入口说明。

## 宿主共享浏览器生命周期

`Runtime` 已组合 `nodeBrowsers`：运行中的电脑对账先确认出网端点，再等待代理控制入口可用，然后准备共享 Chrome 并执行能力探针。已有活动实例只发送原授权的状态查询，不重新发送启动。容器停止、删除、换代回收和节点停服均先处理持久浏览器记录；节点启动在恢复旧执行与出网之前关闭遗留浏览器，不自动恢复页面或未知启动。窗口客户端及完整浏览器能力探针尚未组合，浏览器进程活动不等于电脑 ready。

控制入口等待由必填 `Options.AgentStartup` 约束：总时限 1–60 秒，单次时限 1 秒至总时限，初始间隔 10–1000 毫秒，最多 1–16 次。退避按倍数增加并封顶 1 秒，始终受上游更短期限限制。只对连接建立前的 socket 不存在或连接被拒绝等待；权限、归属、回执、连接后传输及清理错误立即失败。浏览器启动、探针和网页动作不会随之重发。

等待全程固定原 Docker ID 和内核父组，在每次检查、对端验证和成功回包后再次复验，身份变化即失败。`health` 响应必须匹配实例、配置版本和 `agent_control` 范围；不接受进程存活或任意成功响应替代。一次正常确认增加有限的 Docker 身份查询和一条本机控制往返，不新增持久记录。Linux 回归实际验证延迟监听、残留 socket、错误权限和错误对端；测试 Docker 与父组定位仍为明确替身。

每用户保存固定 `<user_id>.browser.json` 版本 1，包含完整规格、不可改绑授权、跨容器代次递增版本和 `prepared → dispatched → active → closing → closed` 状态。创建服务组前先刷盘准备意图，传递三个受限入口前先刷盘发送意图；收到活动回执后复验实际 Docker 与内核父组，再保存活动状态。未知启动只关闭原实例，不能自动重发；下一次显式对账只有在原实例确认关闭后才能分配更高版本。末次服务 ID、版本和最高容器代次不能复用或降低。

正常关闭先持久封闭宿主授权，调用代理安装同授权关闭屏障，再确认原服务组排空和移除，最后保存 `closure: agent`。代理调用失败或回包错误时，复验原容器身份后停止它，核对实际停止状态，再回收原服务组；确认后保存 `closure: isolated`，同时仍向本次调用返回异常，不能把隔离当作 Chrome 正常保存站点状态。容器或内核父组漂移、无法确认停止、回收或刷盘失败时保留未知屏障，禁止创建新实例。停止回包丢失以实际停止观测为准，但不省略原资源组核验。

生命周期操作沿用每用户独占锁，其他用户不等待同一锁；浏览器不借用任何 Bot 的资源组或执行租约。取消启动后的回收使用独立有界预算；节点停服在外层确认在途操作结束后，逐用户关闭浏览器再释放出网与节点记录。恢复按每批 100 项遍历，损坏记录、错误归属、未来代次和不支持版本均拒绝。节点恢复、关闭和磁盘刷盘仍受外层进程退出监督，超时不能释放依赖后继续接单。

旧代理目录中的 `browser.json` 现在参与严格回收：先核验格式和原代理身份，再要求宿主持久记录已关闭且消费版本覆盖该代理记录；同版本必须是完整相同授权。保留宿主最高消费版本，只回收已隔离旧容器的私有控制目录。缺失宿主屏障、授权变更和代理版本超前均失败，不以文件名白名单直接删除记录。

新增必填 `Options.Browser` 提供调用、清理、整节点浏览器退出预算、服务组参数和窗口限制；窗口限制沿用代理的同一规则，调用和退出预算不能超过代理部署上限，清理预算必须覆盖代理调用、代理回收及宿主资源组退出。节点配置为版本 2，生命周期记录为版本 4，代理配置仍为版本 4，存储记录版本 3 和桌面版本 2 不变。正式部署从全新状态开始；中间环境升级与回滚须停单、排空并保存成套状态和用户磁盘，不原地转换旧记录或混用忽略浏览器记录的节点。本轮没有 SQL 迁移。
