# 节点与镜像部署目录

本模块供受保护的本机部署入口使用，以固定 `Node.ID` 和 PostgreSQL 控制角色原子登记节点与镜像，不注册 HTTP 路由。调用与文件格式见[部署说明](../../docs/node-registration.md)。普通用户不能读取或修改目录，管理平台继续通过账户领域的分页接口查看可选元数据。

## 登记与运行状态

`Register` 校验规范 ULID、名称、1–10000 的电脑数量上限及固定 SHA-256 镜像引用。节点地址只保存在部署配置中，数据库不再包含未使用的网络端点。镜像引用与电脑规格使用同一验证方法，禁止浮动标签、凭据和控制字符。

同一短事务插入节点、镜像及对应审计；主键和唯一索引处理并发冲突。相同身份及登记字段重复提交返回现有目录，不新增重复审计；同 ID 改名称、容量或引用，或不同 ID 争用同一名称/镜像引用，均明确冲突并回滚全部写入。数据库没有连接外部 Docker 的长事务，未知结果不自动重发。

新节点固定为 `bootstrapping`，预留量为零，首次登记不写入健康时间、运行代次或 `ready`。既有节点的健康状态、预留量和代次保持不变。容量是部署声明的准入数量，不能代替宿主资源检查。

新镜像允许后续供给选用，但不据此声明已拉取、可运行或能力就绪。重复登记保持其当前启用状态，已停用版本不会重新启用。换版登记新的镜像 ID 和摘要，旧电脑继续引用原版本。节点后续必须按固定摘要拉取/核验镜像，实际电脑仍须通过全部能力探针才能完成开户。

`Get` 在同一 SQL 语句快照中读取节点与镜像，不补建缺失记录。返回目录状态只代表查询时快照。提交/输出结果未知后，用原节点配置与镜像 ID 查询，或显式重复同一登记，不换身份绕过冲突。

## 数据约束与验证

新增不可变迁移 `0044_computer_catalog_identity.sql`，移除节点 `endpoint`，在数据库保护节点 ID、镜像 ID 与固定引用不被更新，并撤销运行控制角色的删除权限。停用保留历史版本，不能删除后重建同 ID；历史迁移不修改。未来有权限的节点管理流程可以调整容量、名称或状态，本部署命令不承担这些动作。

测试使用真实独立 PostgreSQL，覆盖 16 次并发幂等、默认未就绪、既有状态保留、唯一冲突、跨记录原子回滚、审计失败、取消、错误脱敏、数据库身份保护和普通用户权限拒绝。部署组合另验证仅登记节点不能创建首位管理员、严格操作文件和迁移账本复验。

本模块已接入[控制心跳租约](../../docs/node-health.md)：并发、乱序与过期使用同一数据库规则，首次绑定、重启和失联恢复不会自动就绪。镜像准备由独立部署命令负责；[节点专用电脑验收](../../docs/node-verification.md)复用正式生命周期并在清理确认后发布有时限的镜像准入。测试中的目录登记不代表真实 Docker 供给验收。部署升级、锁影响和回滚要求见[部署说明](../../docs/node-registration.md#迁移与回滚)。

`Verifier` 已由 API 后台监督启动；`Get` 返回验收状态、错误码、已验收镜像及期限。新增迁移 `0046` 的工作流、资源开销、配置、锁顺序与回滚限制见[验收说明](../../docs/node-verification.md)。生产共享浏览器探针未接通时仍不能通过完整验收。
