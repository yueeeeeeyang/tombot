# 容器内 Bot Agent

本模块提供单个 Bot 的模型与工具循环及独立进程协议。`cmd/bot-agent` 已加入远程电脑镜像；进程不接收命令行配置、供应商凭据或数据库连接，拒绝 root 和非 Linux 运行。生产启动必须由 `computer-agent` 通过固定任务引导入组并降权，绑定当前 Bot 的桌面、运行和控制代次。

`execution.Worker` 已通过 `Dispatch` 请求所属电脑的固定独立进程，不再在服务端调用 `Run`。纯文本运行也先取得电脑执行权；`computer.AgentRuntime` 由节点与电脑代理实现，没有宿主执行回退。**新的 `tomd` 已组合这条链路；真实节点部署、业务 cgroup 入组、其余电脑工具及整个产品的端到端验收仍未完成。**

## 循环与中继

浏览器的目标执行位置是 Agent 所在的用户容器：Agent 调用本地工具操作已安装的 Chrome，服务端只登记授权操作、接收结果并提供统一模型访问。浏览器导航、键鼠、截图和对话框不再沿服务端与宿主节点逐次转发。共享浏览器仍需在容器内校验页面归属，完整共享账号不授予跨 Bot 页面操作权。

`Start.LocalTools` 指定由固定 Agent 程序注册的本地工具。`computer_browser` 已通过本地执行器接入：服务端先持久登记并返回操作授权，Agent 通过容器内 Unix 入口操作 Chrome，再回传结果。服务端确认结果后才允许下一轮模型；缓存回执直接恢复，不再次执行。断连、超时、错序、截图替换与持久确认失败均停止；Agent 完成前还须确认所有所属页面没有等待、在途或未知动作。

`Start` 只携带固定系统提示词、文本历史、已授权工具定义、本地工具名称和执行上限。`Run` 生成稳定步骤键，依次请求模型、执行模型返回的工具、加入工具结果并请求下一轮模型。单次模型最多 16 个工具，最多 64 轮；上下文最多 1 MiB，输出最多 24 KiB，实际限制由服务端启动内容决定。

`Relay` 每次只处理一个模型或工具请求。服务端负责固定策略、权限与租约复验、操作持久登记、恢复和用量记账，不能把供应商配置传给 Agent。现有 `workerRelay` 继续承担这些职责；额度预留明确未成功时可以在中继中有界等待，Agent 自身不重试。结果未知、工具中继错误或连接中断立即停止，已知工具拒绝才作为错误工具结果交给下一轮模型。

新请求的持久登记先于外部副作用，已知结果只能在步骤键与请求摘要一致时恢复。节点与代理已实现授权分块中继；Worker 在操作登记事务中再次核对 Agent 的电脑会话。具体电脑与平台业务工具适配仍待完成。标准流协议不能直接作为对外网络 API，也不接受帧内更换用户、Bot 或模型策略。

## 独立进程协议

私有标准流版本为 3，使用四字节大端长度和规范 JSON；旧版本在读取时直接拒绝，不提供兼容转换。单帧最多 2 MiB，先验证长度再分配；拒绝未知字段、协议层重复键、别名、尾随内容及非法组合。工具参数保留 JSON 原文，包含大整数和字段顺序，避免跨进程传输改变持久请求摘要。模型历史中 `ToolUse.Input` 的通用类型在解码后恢复为原始 JSON。

截图工具结果携带服务端签发的图片引用：操作 ID、Bot ID、PNG 类型、真实视口尺寸、字节数和 SHA-256；不携带路径。浏览器视口为宽 320–1280、高 240–800，完整桌面仍固定 1280×800。本地截图先以 `tool_complete` 元数据和连续 `tool_image` 块提交，单块最多 32 KiB、整图最多 4 MiB；服务端校验操作归属、偏移、PNG 实际尺寸和摘要，模型轨迹只保留引用。`Run` 将引用加入工具结果上下文，`DispatchStream` 按已返回结果核对引用，拒绝伪造或换图。实际 PNG 由服务端在工具提交事务中保存，并在模型调用前按运行归属装配，见[截图持久化](../execution/README.md#截图持久化与模型视觉)。因此私有帧和文本上下文上限保持不变；图片限额由独立配置控制。

服务端先写入序号为零的 `start`，Agent 随后按递增序号发出 `model` 或 `tool`；普通请求接收同序号、同结果类型的 `result`。本地工具先收到操作授权，然后发送递增序号的 `tool_complete` 及可选图片块；最后接收与末次报告序号一致的已持久结果。最终 `done` 携带答复及固定失败代码。错序、错误结果类型、部分写入或 EOF 都不补发，不伪造完成。`DispatchStream` 按启动快照及已持久返回的结果核对整个轨迹，拒绝改写上下文、未授权工具、修改参数、步骤跳跃和伪造答复；执行和审计共用消息构造规则。收到完成帧后继续确认没有额外输出，并等待程序退出，不能仅凭一条完成文本提交成功。

节点协议以 32 KiB 字节块传输，每块重新验证完整电脑会话，调用有显式超时。代理每个方向只保存上一块，管道提供背压，不缓存整个模型上下文。输入采用连续偏移与内容摘要，同一块只复用已知回执；部分写入或超时留下不可继续写入的状态，分发器不会重发。读取允许复查上一块，确认推进后不保留更早内容。每次最多等待输出 100 毫秒，避免持续占有桌面锁而阻碍续约。

程序标准输出仅用于协议，诊断写入标准错误且不包含业务正文。Linux 入口将继承的私有管道或套接字复制为可轮询描述符，拒绝普通文件和终端；取消会关闭流并唤醒阻塞读写。直接使用阻塞 `os.Stdin` 曾在真实容器测试中无法及时响应终止信号，修正后的专项回归覆盖这一分支。

## 验证与发布

普通测试覆盖循环、工具结果上下文、参数原文、大整数、未知工具、重复调用标识、额度边界、两步之间取消、错误回包、帧长、部分写入和停止语义。既有真实 PostgreSQL Worker 测试继续验证模型用量、已知操作恢复与未知操作不重放。

`linux && botagentintegration && !cgo` 验收在专用容器中调用镜像内真实二进制：两个独立非 root UID/PID 并行运行，一个中继中断后另一个继续完成模型—工具—模型循环；同时验证 root/命令行拒绝和终止信号打断读取。电脑代理的 `agentintegration` 测试另验证 70 KiB 上下文分块、真实进程监督、Unix 控制协议及伪造入组拒绝。测试中继返回固定结果，没有调用真实模型供应商；成功进程由测试启动器直接降权，没有证明生产 cgroup 成功入组。

图片引用新增对应的服务端迁移 `0043`，此前历史迁移保持不变。Agent 二进制、镜像、协议调用方须按版本成套发布，不在旧活动连接上混用新字段；升级或回滚均需停止接单、排空会话并保留控制代次及未知操作记录。不能回退到宿主执行循环，也不能对旧连接中结果未知的请求重新发送。
