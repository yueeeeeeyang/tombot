# 共享电脑内的桌面执行权

本模块按机器人桌面管理申请、独占、续约及回收确认，并限制同一用户同时占用的桌面数。不同机器人在同一台用户电脑内可以并行取得各自桌面控制权；同一桌面仍只允许一个控制者。已接入 [执行 Worker](../execution/README.md)，通过新增 `0042` 迁移替换电脑级独占约束，历史脚本保持不变。

节点协议见 [computer/session.go](../computer/session.go)。节点与容器代理均已按桌面独立管理持久记录、授权和回收；主入口已组合授权控制与 Shell 工具；图形输入、共享浏览器、交互终端和文件工具仍未完成生产组合。控制面并行测试使用受控节点，节点与代理的真实 Unix 联合测试使用受控资源组，不代表整条真实电脑链路已经支持多桌面运行。

## 所有权与调度

`RunReference` 由受信 Worker 根据已领取任务构造，包含用户、任务、运行、Bot、持有者、任务代次及尝试号。业务请求和模型输出不能直接构造该身份。每次申请与续约都在短事务内核实任务、用户、机器人和会话仍可执行；数据库时间决定到期。

事务依次锁任务、用户准入行及所属桌面代次行，再更新会话。用户准入行仅用于短事务内的票号分配与额度检查，不跨节点调用持有，也不串行化工具执行。`desktop_execution_heads` 为每个桌面独立递增控制代次；部分唯一索引保证同一桌面最多一个尚未收尾的控制者。

用户额度来自 `user_limits.concurrent_desktops`，由开户配置显式提供，允许 1–64。`starting`、`active`、`draining` 和 `quarantined` 都计入额度；节点未确认清理的桌面不能因超时腾出名额。数据库准入触发器再次校验容量，拒绝绕过服务端的超额状态变更。额度调整对后续准入使用读取时的已提交快照；降低额度不强制终止已经受理的会话，名额回落前禁止新准入。

可执行桌面按票号竞争空闲额度，同一桌面按票号等待。被占用桌面的队列、已取消或已失效任务、旧容器实例的等待记录不预占其他空闲桌面的名额。`MaxWaiting` 限制真正留下的等待记录，能够立即准入的桌面不会因其他桌面的等待队列已满而被拒绝。等待有固定时限，同一申请重试不重复排队或开启节点会话。

`WaitError` 保持 `errors.Is(err, ErrWaiting)` 语义，并提供 `desktop_busy`、`user_capacity` 或 `starting_desktop` 原因。持久等待原因随用户事件返回，重复轮询相同原因不重复写事件；运行查询的 `computer_wait_reason` 显示最近一次调度观测，准入或释放后清空。

| 状态          | 含义与下一步                                                   |
| ------------- | -------------------------------------------------------------- |
| `waiting`     | 已入队，尚未向节点发出开启命令；可以直接取消                   |
| `starting`    | 所属桌面与用户名额已保留，节点开启尚未确认；不能再次盲目开启                 |
| `active`      | 当前节点已确认同一实例、会话、代次及控制版本，可以调用电脑工具 |
| `draining`    | 已封闭控制面的新操作，等待节点回收确认；继续占用所属桌面及用户名额           |
| `quarantined` | 节点动作或清理结果不确定；继续占用所属桌面及用户名额，禁止交接               |
| `released`    | 未曾开启的排队项已结束，或节点已确认全部回收；状态不可重新打开 |

桌面会话跨多个工具调用及中间的模型思考持有，其他机器人可同时使用各自桌面。`Renew` 只续约已经激活的会话，不延长固定的最大持有期限；过期会话不能通过续约复活。等待电脑不占模型调用名额，也不重复模型请求。

## 节点确认与异常

`ExecutionSession` 包含完整 `DesktopIdentity`（用户、电脑、Bot、桌面 ID、Linux UID、公共 GID、显示编号），以及节点、容器 ID、实例代次、会话、运行和桌面控制代次。身份从数据库登记读取，复合外键防止替换；同一桌面跨容器重建仍保持逻辑身份，实例代次与桌面代次分别检查。每个控制命令另有递增版本及有界期限。节点必须持久拒绝旧命令；有效期限使用节点本地单调时钟，失联后封闭输入并回收进程。

- `Open` 只建立受管执行环境，不执行用户动作。开启回包丢失后隔离并走清理，不能重复启动任务动作。
- `Renew` 只能更新同一活动会话，不能重新打开已关闭或过期会话。
- `Close` 是持久终止屏障。只有封闭旧输入、回收所属运行的任务进程、浏览器窗口及端口并确认资源为空后才能返回 `drained`。调用重复仍返回同一会话的清理结果；旧清理不能作用于下一代会话，也不能终止其他桌面或用户级共享浏览器服务。

节点调用不占数据库事务，调用与回写各有时限。回写重新锁任务和电脑头，核对控制版本、任务有效性和占用时限。错误实例、错误代次、迟到版本或缺少状态均不能构成释放证据。清理已在节点完成但数据库提交失败时仍保留占用，后续用幂等清理重新确认。

`Reconcile` 每次最多检查 100 条记录，按最近检查时间轮转。单个用户失败不阻止其他用户收尾。清理采用有上限的指数退避及次数限制；耗尽后保留隔离，不默认成功。自动停止旧容器、重建及重新核对资源的生命周期升级路径尚待实际节点实现，当前不提供人工改状态或清空记录的恢复入口。

数据库到期、用户禁用、任务取消和节点失联都不能直接释放桌面或用户名额。首次停止原因保留到最终状态，后续清理错误不能抹掉到期或失效原因。控制面记录用户事件与会话状态使用同一事务。

## Worker 与操作账本

工具通过 `UsesComputer` 声明是否操作电脑。远端文件、终端和浏览器操作必须声明需要电脑；独立存储的附件等不依赖活动环境的读取可以不申请桌面会话。业务文件和安装工具继续在用户电脑内共享，不按会话建立文件访问壁垒。构造 Worker 时，注册电脑工具却缺少本模块会明确失败。

电脑工具执行前先取得会话，再以 `computer` 类型记录操作；记录绑定当前会话、原任务代次与尝试号，并复验当前工具权限、完整桌面身份、实例代次、桌面控制代次及期限。节点命令使用 `Invocation.Computer` 与稳定操作 ID，不从模型参数选择电脑身份。

Worker 正常完成、失败或取消时都先调用 `Release`。`Complete` 和 `Recover` 在任务锁内检查未释放会话；数据库触发器也禁止未清理任务完成或换代。因电脑失效结束的会话不能在最终回复竞态中被报告成功，也不能由恢复器重新排队执行。只有普通收尾的回包或最终提交失败，且外部操作结果已知，才允许清理确认后恢复并复用原结果。

当前集成处理单聊 Bot 运行与不同 Bot 的并发桌面申请，每次运行尝试至多一条电脑会话。人工接管、多阶段释放后重新申请、父子任务交接，以及等待电脑时释放 Worker 执行名额仍需接入相应编排；这些是最终共享电脑能力的未完成部分，不以当前单聊实现替代。

## 结构变更与回滚

`0040_computer_execution_sessions.sql` 保留历史不变。新增 `0042_desktop_execution_control.sql`，移除整台电脑的独占索引与用户级控制代次，建立桌面独占索引、桌面代次表、稳定身份绑定、等待原因和用户并发额度。原任务释放保护与操作归属约束继续有效。

按全新目标模型初始化，`0042` 只接受空电脑会话和用户限额记录，不推断旧会话所属桌面、不补造默认额度，也不删除原记录。存在旧中间模型数据时明确失败并整体回滚；正式运行从全新空 PostgreSQL 数据库建立所有记录。

迁移在事务中执行，桌面表追加唯一约束、会话字段与索引替换、用户限额字段及外键校验会取得结构锁。发布前评估桌面目录规模、锁等待与维护窗口；本次测试只验证隔离测试库，不能作为生产执行时长证据。失败整体回滚，已应用脚本只能通过新增版本前向修正。

会话协议增加必需桌面身份，开户配置增加 `DesktopConcurrency`，节点、代理和镜像内二进制必须成套更新，不能复用此前构建的旧代理来验证新协议。应用回滚必须停止新领取并完成或隔离已有桌面会话，保留队列、桌面代次和操作证据；只允许退回理解该协议及数据库保护的版本。不能通过删除会话、放宽触发器、重置代次或把隔离状态改为已释放来回滚。

## 验证

[computer_test.go](../execution/computer_test.go) 使用真实 PostgreSQL 与故障注入节点，验证用户额度限制及跨用户并行、并发申请去重、排队和容量、权限与复合绑定、开启回包丢失、错误清理证据、事务回滚、有限清理重试、等待取消及超时、固定占用上限、旧清理拒绝、Worker 清理失败恢复，以及电脑到期与最终回复竞争。[desktop_test.go](../execution/desktop_test.go) 进一步验证同用户双桌面同时准入、独立代次、单桌面清理失败不阻止另一桌面续约、并发额度竞争、取消队首、等待原因与事件去重、工具身份替换拒绝，以及数据库同桌面唯一约束和容量兜底。协议身份与期限另有单元测试。

这些测试不启动真实用户命令，也不证明 Linux cgroup、浏览器沙箱、磁盘配额或完整图形输入授权已完成。真实节点、人工控制、生产启动组合和前端仍须独立验收。
