# 账户与会话模块

该模块是新多用户运行链路的身份边界，使用 PostgreSQL 身份角色连接。`tomd` 已使用新的 [应用组合](../serverapp/README.md)，整体重构仍未完成；不能仅依据身份和入口测试通过就发布完整多用户产品。

## 调用顺序

1. 控制服务同步供给用户电脑，提交 `pending_activation` 用户及一次性激活记录。激活值由控制服务生成，数据库只存摘要；本模块不创建用户或 Docker 资源。
2. 普通用户调用 `Activate` 设置口令。管理员先调用 `BeginAdminEnrollment` 取得供验证器登记的材料，再带动态验证码激活；激活材料只通过专用认证响应短暂展示，不进入日志或 URL。
3. `Login` 提交规范化账户名、口令、设备名称、平台与会话范围。管理员账户在桌面和管理平台登录时均要求动态验证。普通用户不能取得管理会话。
4. 每个普通请求调用 `Authenticate` 验证访问凭据及期望范围，构造 `Principal`。业务层只能使用该身份进入租户事务，不能采纳请求体里的用户、角色或会话字段。
5. 客户端串行调用 `Refresh`，成功后原子替换两份凭据。旧访问凭据立即失效；旧续期值再次使用会撤销整条会话。续期响应丢失时重新登录，禁止自动重试旧值。
6. 管理操作调用 `RequireAdmin`；敏感操作要求近期验证。验证窗口到期后调用 `Reauthenticate`。控制服务的管理员修改还须在事务中取得 `tombot.active_administrators` 对应的咨询锁，与数据库保护规则一致。
7. 长连接定期调用 `Revalidate` 并结合撤销事件停止推送与控制。访问凭据到期策略由通道入口执行；本方法核验会话状态，不延长访问凭据有效期。HTTP、SSE、WebSocket 和电脑网关尚待新入口统一接入。

## 并发与存储约束

- 账户、设备、会话、激活、验证时间步均在 PostgreSQL 中维护，重启或运行多个 API 实例不会清空限流和重放记录。
- 口令计算前按账户主题和可信来源地址分别限流；限流按固定时间窗口原子预占，成功或失败都计入，不在成功后清零。`Attempt.Source` 必须从传输层或受信代理配置解析，不能直接信任用户提交的转发头。
- 口令计算受有界信号量限制，并在数据库事务之外执行。提交前再次核对账户状态、口令摘要和认证版本，防止验证期间发生禁用或改密。
- 涉及身份变更时先锁用户，再锁设备、会话或激活记录。刷新、退出、设备撤销和改密使用相同锁顺序。重复续期的撤销必须提交后再返回拒绝，不能随业务错误回滚。
- `ChangePassword` 原子替换派生值、增加认证版本并撤销全部设备和会话；调用成功后需要重新登录。普通退出不取消已提交的机器人后台工作。
- 访问、续期和激活值只保存 SHA-256 摘要。管理员验证材料使用带记录标识的 AES-GCM 密文，动态码已消费的时间步在数据库中更新。
- 口令使用带算法和成本标识的 Argon2id 编码；当前成本为 64 MiB、三轮和两个执行通道，保留既有计算成本。未知算法或损坏编码明确失败，不读取旧单用户认证文件。以后调整成本需增加明确的验证及更新流程，不能把未知格式当成登录失败而掩盖数据损坏。[Argon2 文档](https://pkg.go.dev/golang.org/x/crypto/argon2)
- 动态验证采用 30 秒时间步，允许前后各一个时间步，禁止再次使用已消费或更早时间步。算法依据 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)，测试覆盖其公开向量、过期及重放。

## 配置与边界

`Options` 的访问、会话、二次验证、限流窗口、来源和账户次数、口令计算并发、设备上限及加密主密钥全部由部署配置传入。模块校验上下界；不提供内置生产凭据或隐式无限值。`RequestID` 必须由服务端生成，原始口令、验证码、激活材料、会话值和连接串不能写入审计或日志。

`identity` 连接可以处理认证数据、激活用户以及增加认证版本，不能创建账户、修改角色、停用用户或访问机器人内容。管理员控制连接不具有口令与动态验证材料读取权限。数据库还约束首次激活必须有就绪电脑、验证材料不能跨账户关联，以及不得降权、停用或删除最后一名有效管理员。

[新认证 HTTP 模块](../authapi/README.md) 已实现管理端安全 Cookie、绑定续期会话的 CSRF 校验及桌面独立凭据通道，并完成协议与真实数据库联合测试。它尚未接入运行入口。后续仍需完成桌面主进程凭据保管、主动撤销通知、认证数据有界清理和管理员恢复流程。已消费续期摘要至少保留到其会话过期，不能为清理记录破坏重放检测。控制服务创建、禁用、角色修改和电脑补偿不属于本模块。

## 验证与升级

真实 PostgreSQL 测试覆盖激活失败回滚和并发消费、过期激活、两用户设备隔离、会话范围、轮换重放、并发续期、到期和禁用、改密、设备上限、管理员登记与二次验证、跨连接限流、审计失败回滚、损坏凭据及数据库权限边界。最后管理员保护使用两条真实数据库连接并发验证。

结构通过新增 `0030_identity_lifecycle.sql` 和 `0031_identity_integrity.sql` 实施；`0029` 及历史 SQLite 脚本不变。初始化或升级由独立迁移角色执行，失败事务整体回滚。已经提交的结构修正只能新增版本；应用回退仅限与当前新 schema 兼容的版本，不回退到旧单用户数据库。
