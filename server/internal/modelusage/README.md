# 模型额度与真实用量

本模块为新 PostgreSQL 运行提供用户并发名额、月度 token 预留、供应商用量证据和结算。它与 [execution](../execution/README.md) 的模型操作共用事务，独立于待删除的旧 SQLite 用量代码。不会把缺失计数、缺失价格或失联请求当作零用量。

## 调用前预留

`Reserve` 只能在有效运行租约及模型操作插入事务中调用。配置来自该运行固定版本的 `modelregistry.Use`；数据库进一步用复合外键和触发器核对运行、操作尝试、策略版本、预留上限、价格及缓存语义，传入另一个版本或更低额度会使整笔操作回滚。

同一用户的计量账户行串行执行接纳与结算，不跨用户加锁。先检查尚未释放的调用名额，再检查当月已知用量、未结算预留与本次预留是否超过用户限制。并发限制与月度额度分别生效，月度额度为空不等于并发无限。额度不足或名额已满时，模型操作和预留均不会落库。

每次保守预留固定版本的 `ContextLimit + OutputLimit`，这只是接纳上限，不作为实际 token 数展示。它避免用字符估算充当精确 tokenizer，但会使接近月度限额的用户提前遇到额度不足。收到最终计数后按实际用量结算并释放差额；供应商报告超过预留的真实计数也会保存，不截断为预留值，后续调用按实际余额拒绝。

月份按数据库 UTC 时间、调用开始时确定。跨月完成和迟到证据结算回原月份；旧月份仍未知的预留保留原归属，不移到新月份或被自动清零。账本不实现支付或扣款。

## 计数与价格

计数来自 `provider.ReportedUsage`，每个缺失字段保留为空。兼容协议的输入已包含缓存读取，不能再把缓存加到总输入；Anthropic 的普通输入、缓存读取和缓存写入分别计数。总 token 所需字段不齐全时，仅保留已知下界，结算仍为未知。

价格来自不可变策略，单位是每百万 token 的微美元。普通输入、输出、缓存读取、缓存写入分别计价，整数中间量防溢出，最后对单次调用总额四舍五入。需要的价格或缓存拆分缺失时费用为空；已知 token 仍可结算。明确报告总 token 为零时费用才可确定为零。新增缓存写入价格是可选配置，已有版本不改写。

原始计数、是否最终、计量结果和摘要作为不可变 `model_usage` 证据保存。`usage_reservations` 是当前结算投影，`usage_periods` 保存月度已知计数及保留额度。未知费用可以由一致的补充证据补齐；已经确定的 token 和费用不能覆盖。不同证据的最终计数相互冲突、或最终总量低于已知下界时明确拒绝，不选取对余额更有利的数值。

## 结束与迟到结果

有效 Worker 的 `RecordOperation` 同时提交操作结果、用量证据、额度变化和事件。任一步失败整笔回滚。相同结果和证据 ID 重试不重复计费或重复产生用量事件。

请求在本地结束但计量不完整时，释放调用名额、保留 token 额度。已知部分计数超过原预留时，提高保留额度以覆盖已知下界。运行租约过期不能证明模型请求已经结束：失联调用只有超过单独的调用硬时限后，才能释放本地调用名额；此时仍不能释放未知 token 预留。硬时限不代表远端供应商一定已经停止处理。

`AppendModelEvidence` 是受信 Worker 的受限入口，用原用户、运行、操作、尝试号及代次验证归属，只追加计量证据，不修改运行、回复或操作终态。相同证据 ID 必须保持内容一致，每次调用最多 16 份证据。对账器在用户计量锁下核实并应用；即使迟到结果已确定用量，已结束的 `unknown` 运行也不会被旧 Worker 改成成功。

`Reconcile` 通过受限调度连接每次发现最多 100 条待处理记录，再切入各用户事务核实。调度角色没有消息、提示词、价格或供应商计数读取权。管理员只能读取计量记录及汇总，不能通过计量接口读取会话正文。所有新表强制 RLS，已知计量、关联身份和策略绑定由数据库约束保护。

## 接入与验证

Worker 已组合运行模型调用、原子预留、真实计数结算、迟到证据及后台对账。管理端用量查询、限额编辑与界面，能力发布探测的计量，仍需完成；`tomd` 已接入运行 Worker，不能把当前运行账本覆盖范围扩大为所有模型流量都已入账。

纯计算测试覆盖缓存语义、缺失与零值、费用舍入、缺失价格及溢出。真实 PostgreSQL 竞态测试覆盖并发争抢月度额度、用户并发名额隔离、重试去重、固定配置拒绝、未知预留、硬时限对账、迟到证据、原运行终态保护、费用补齐、部分计数下界及事件故障共同回滚。运行集成测试通过可控模型回调注入实际计数字段，不向公网供应商发请求。

## 数据版本与恢复

`0038_model_usage_reservations.sql` 新建计量账户、月份、预留和证据表；`0039_model_usage_integrity.sql` 前向增加运行与尝试的复合关联、配置核对及费用补齐约束。此前版本保持不变，不导入旧账本。新索引、外键和唯一约束需要结构锁及已有运行表扫描；部署前核对表规模和锁等待预算，迁移在有界事务内执行，失败整体回滚。

应用回滚须先停止接纳和领取，记录在途请求并等待可确认结果，保留所有预留和证据。不能回滚到跳过计量接纳的 Worker，不能删除未知记录以恢复余额，也不能自动重发未知模型调用。若要修正结构或计量规则，继续新增版本并验证投影与证据的一致性。
