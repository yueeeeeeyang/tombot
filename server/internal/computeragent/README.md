# 用户电脑代理会话控制

本模块实现用户容器内的受信会话控制、持久关闭屏障、有限失联回收、节点控制协议及 `computer-agent` 入口。它与 [agentchannel](../agentchannel/README.md)、[节点会话](../dockernode/README.md)、[进程资源组](../processgroup/README.md)及 [computer-task](../taskprocess/README.md) 共同构成电脑执行基础。专用镜像、稳定桌面身份、私有会话目录、受管终端和图形会话启动已接入代理及节点协议；独立 Bot Agent 启动、监督与分块中继已接通；屏幕输入网关及主服务仍待组合，不能把终端模块测试等同于电脑已就绪。

`Controller` 现已按稳定桌面管理多个独立授权、撤销管道和看门狗，并接入正式代理入口与节点协议。最新[改造方案](../../docs/multi-user-refactor.md)要求的文件能力、浏览器自动化及完整能力探针仍须继续接通；原生应用的远程桌面另行设计，本模块的多授权不代表整台远程电脑已完成联合验收。

## 身份和执行权

每个代理固定用户、电脑、节点和容器代次，Bot 操作须携带一致的完整执行会话身份，容器基础探针使用下述独立服务授权。容器级目录校验桌面、Bot、Linux UID、公共 GID 和显示编号的稳定绑定，拒绝两个桌面占用同一显示身份或 Bot。每个桌面持有自己的守卫、控制代次和命令版本；不同桌面可以同时开启。同桌面新会话必须等待上一会话关闭；重复版本不能更换期限或延长授权，已关闭或过期的会话不能重新开启。

`MaximumActive` 为容器级活动桌面上限，显式配置为 1–64，在接管资源组前原子预留。开启中、活动及清理未确认的桌面均占一个名额；确认整组回收且关闭记录已持久化后才释放。它与控制面的用户额度、节点总额度共同限制并发，部署时须配套规划。稳定身份目录最多登记 4095 个桌面，关闭后保留归属与代次，不复用编号。

全局锁只保护身份目录、容量及接单状态，不覆盖文件读写、任务回调或整组清理。每个桌面的初始化通过独立完成屏障汇合，同一桌面的操作由自己的守卫串行；其他桌面的开启、续约和任务启动不等待其耗时操作。初始化未产生执行授权时，读取失败可由下一次显式请求重新核验，不能跳过损坏记录或撤销其他桌面的有效授权。

开启接收四个限定的 cgroup 文件描述符：Shell 入组、浏览器入组、当前会话整组终止，以及只读存活状态。Linux 后端核对文件系统类型、所有者、访问模式和完整会话路径，且只接管初始空组；用户任务只临时获得自身角色的入组入口，不接收终止入口或目录写权限。

代理先持久保存开启意图，再保存活动状态；只在本地授权仍有效时确认成功。续约、关闭均先在内存保留最高受理版本，随后保存记录。即使 `rename` 已完成但回包失败，也不能用旧关闭请求覆盖可能已经提交的新版本。保存失败返回未知结果并撤销执行权，不能恢复为默认成功。

`FileStore` 使用 root 私有目录、固定独占锁、受限文件、无符号链接打开、临时文件刷盘、原子替换及目录同步；拒绝硬链接和损坏记录。每个桌面保存版本 2 的 `<desktop_id>.session.json`，文件名与内容必须同属该桌面；独立记录可并发刷盘，关闭目录仍等待所有文件操作结束。启动按每批 100 项遍历记录，检查全部归属和冲突后才开放控制服务。

代理重启不恢复单调时钟租约：同代次任一桌面仍有未关闭记录时拒绝启动，须由节点隔离实例。只有节点已确认旧实例隔离后的更高容器代次，才允许封闭旧记录；不得删除状态文件绕过屏障。恢复耗时随记录数量增长，受启动调用期限限制；超时明确失败，不跳过剩余桌面。

## 启动时准备运行空间

入口先核验容器权限、取得控制目录独占锁并读取部署配置，再运行镜像内固定的 `prepare.py`。初始化子进程保持 root UID、切换为用户公共 GID 20000、清空附加组和继承环境；父代理身份不改变，不增加 FSETID capability。子进程具有明确时限，失败诊断有长度上限并携带用户、电脑与实例代次；准备失败时不建立控制监听。

共享卷只接受空白 root 所有的挂载，或已经符合约定的共享卷；ext4 的 `lost+found` 保留。初始化设置 `/workspace`、`tools`、`tools/bin`、`.tmp` 为 root:20000、2770，同时建立 root:root、0711 的 `/run/bot-desktops` 和 root:root、1777 的 X11/ICE socket 目录。所有路径通过无链接目录描述符核验与授权，不递归访问或更改业务文件。已有符号链接、其他身份、异常权限或非空旧目录均拒绝，只有创建中断遗留的空目录可继续完成授权；Linux 自动继承的 setgid 位也明确核验。

这一步准备共享业务目录与图形基础目录。接管一个初始空资源组时，代理为该执行会话创建 UID/公共 GID 所有、0700 的私有目录以及 0600 的 NSS 身份文件；XDG 子目录也为 0700。重复会话目录、错误根身份、链接和权限漂移均拒绝。XFCE 只读取代理已准备的身份文件，不再与终端分别创建或覆盖它们。关闭时先确认整组为空并等待直接引导进程结束，再按已登记目录 inode 清理图形状态；目录内指向共享卷的链接不会递归到业务文件。目录准备成功不能代替开户能力探针或真实进程回收验收。

## 迟到启动和独立回收

每个桌面的活动会话有一根独立匿名撤销管道。代理持有唯一写端，任务引导只借用只读端；管道写端关闭后不能再次激活。`WithTask` 按完整身份定位桌面，串行检查该会话并借出对应入组入口及撤销读端，回调只能启动受信 `computer-task`，不能直接执行用户程序或保留描述符。

到期及主动关闭遵循同一顺序：

1. 关闭撤销写端，阻止迟到引导执行用户代码。
2. 独立向 `cgroup.kill` 发送整组终止信号，不等待业务锁或状态文件刷盘。
3. 持久记录关闭意图，等待 `cgroup.events` 确认子树为空，关闭控制描述符并保存关闭屏障。
4. 节点继续执行资源组排空和目录移除，完成宿主交接后才能将该桌面交给下一会话；其他桌面的租约保持有效。

任务引导在入组、降权后且执行用户程序前再次检查撤销读端。若它在回收后才入组，管道已关闭，必须退出；若它在撤销之前已通过最后检查，则已经在被终止的资源组内。代理返回的 `closed` 不是节点的 `drained`，不能跳过节点移除资源组的交接步骤。[Linux cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)

计时器与独立终止信号不等待启动回调或业务状态锁，每个桌面的看门狗独立处理到期及有限清理重试。单次关闭失败保留该桌面占用，其他桌面仍可续约；独立终止失败、不可取消的回收阻塞或清理重试耗尽意味着无法确认旧任务已停止，会升级为容器级致命故障，立即拒绝所有新操作。`computer-agent` 独立等待看门狗结果，致命故障立即退出，不等待阻塞的 RPC 或状态刷盘；正常停服先封闭接单并等待在途调用，再有界并行回收全部桌面，确认完成后才释放持久锁。PID 命名空间的 init 退出会终止其中进程，正式容器使用 Docker init 承接入口退出；完整故障验收仍须包含真实用户进程。[Linux PID 命名空间说明](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html)

## 控制协议

`health` 是无副作用的控制入口检查：只接受当前用户、电脑、节点和容器代次，不接收描述符；响应明确限定为 `agent_control` 并带当前代理配置版本。它经过正常接单门禁，停服或致命故障后拒绝，不创建桌面、浏览器或探针，不写入就绪状态，也不延长任何授权。宿主仅用它跨越 Docker 已启动而代理尚未监听的间隙，完整能力仍由专用探针核验。

`Client` 每次请求建立一条独立本机连接，验证内核对端身份，单次发送并核对响应的请求标识、完整会话、版本和状态。`Server` 限制并发连接及请求时限，处理 `open`、`renew`、`close`、终端 `start`、`read`、`write`、`resize` 、图形 `desktop_start`、`desktop_status`、`desktop_capture`、`desktop_image_read`、`desktop_input`、Agent `agent_start`、`agent_write`、`agent_read`、固定基础探针 `probe` 及共享浏览器 `browser_start`、`browser_status`、`browser_close`。基础探针证据或浏览器进程活动均不代表完整电脑已就绪。

开启与续约携带节点已有的绝对单调时钟期限，传输耗时不延长授权。节点 `SessionController` 已通过 `agentLink` 自动下发开启、续约和关闭，并在用户生命周期共享锁和所属桌面独占锁内核验实际容器及内核对端。关闭时仍验证固定容器身份，不因活动租约结束而放弃对端校验。代理关闭未确认时节点仍尝试宿主清理，但不能报告交接完成。

服务监听器必须位于本代次 root 私有的控制目录，该目录不能属于任务可写的工作空间。取消 RPC 服务会封闭接入并等待在途请求；这不是看门狗的退出边界，入口仍须独立处理致命故障和有界停服。

## 容器基础探针监督

`ProbeController` 已接入正式入口和本机 `probe` 协议。探针使用独立服务组及固定非 root 程序，具体检查见[基础能力探针](../computerprobe/README.md)。同容器只执行一个探针，各 Bot 的桌面锁和会话容量不被探针占用；检查可与 Bot 任务并行，失败可能因共享文件被同时修改而明确返回，不能伪造成功。

`ProbeGrant` 包含完整用户、电脑、节点、代次、正整数 `revision` 及固定探针请求。节点须在该电脑全部容器代次中持久递增版本，每次使用唯一服务实例，不复用旧实例。请求携带三个受限描述符：服务入组、整组终止、只读存活事件。代理验证内核类型、权限、用途和完整路径，拒绝非空组，再持久保存版本 1 的 `probe.json` 为 `consumed`，随后才能启动。重复版本、较低版本或复用末次实例都不能再次执行；未知回包不自动重发。

记录只保存最后一次消费屏障，以固定单文件限制空间和启动开销；使用现有私有控制目录、原子替换、文件和目录刷盘。同代次重启发现 `consumed` 时，入口在建立监听前失败并记录业务标识，交由宿主隔离原容器。只有节点确认替换为更高容器代次后，才能封闭旧记录，且保留最高消费版本；损坏、跨用户、跨节点或未来代次记录均不接受。

探针使用不晚于节点原期限、RPC 期限及部署调用上限的有效期限。独立撤销计时器不等待启动或刷盘，期限结束、取消或停服都关闭撤销管道并发出服务组终止信号。固定程序只能通过封存授权启动；标准输出和错误输出各保留最多 4096 字节，超限继续排空并报错，日志不输出原文。

无论检查成功或失败，代理都先撤销，再等待固定子进程结束、确认整组为空、关闭控制入口并持久保存 `closed`。只有完整且归属匹配的证据与回收确认一起返回，客户端拒绝部分成功、混合错误、错误版本或实例响应。关闭未知、刷盘未知或取消后超过清理期限仍未结束，会封闭探针并通知既有容器看门狗退出，不能释放持久锁后继续接单。宿主节点仍须持久封闭其自身授权并移除服务组，代理的空组观测不代替宿主交接完成。

已通过持久往返和权限/链接拒绝、并发重复请求只执行一次、独立 Bot 授权、取消与停服、错误证据及各阶段失败、持久写入阻塞时独立撤销、失控通知和重启边界测试。真实 Linux Unix 通道验证描述符副本、成功回收确认、重放拒绝和伪造响应拒绝。受限镜像实际入口验证旧探针恢复拒绝，固定运行器实际拒绝伪造 cgroup 入口。协议成功测试的服务组是明确替身，尚不证明真实业务 cgroup 的成功入组、后代回收或完整节点 `Probe.Check` 已完成。

探针没有新增数据库迁移，当前部署配置为版本 4、Bot 任务仍为版本 2；新增控制动作和独立消费记录要求节点、代理、固定程序与镜像成套发布。升级或回滚先停止接单，排空 Bot、探针与共享浏览器并确认宿主回收，再切换匹配版本。保留全部控制记录和用户卷，不能删除 `probe.json`、`browser.json`、降低版本或回到忽略未关闭服务的旧代理后继续使用原实例。

## 受管终端

节点与代理的每一次终端调用都检查完整用户、电脑、容器代次、Bot、桌面、运行和控制代次，复用既有桌面锁及单调时钟租约；读写不续约。代理分配独立 PTY，把从端设置为当前 Bot UID、公共 GID 和 0600，仅启动固定的 `computer-task`。命令及环境通过封存描述符传递，另借出 Shell 入组入口与只读撤销管道；不把用户命令作为宿主 Shell 参数执行。成功启动响应只表示引导已发起，程序退出及失败通过终端输出与退出码报告。

启动操作标识在当前会话内去重；同一标识更换参数会被拒绝，失败与已退出记录保留到会话关闭，不重新执行未知动作。每个执行会话最多保留 16 次启动，每个终端保留 256 KiB 尾部输出。输出使用 UTF-8 字节游标，缓冲覆盖时明确标记缺口；单个传输分片最多 16 KiB，预留控制字符 JSON 转义的帧空间。读取不消费其他观察者的游标，也不等待新输出。

输入最多 16 KiB，序号从 1 连续增长。最近一次相同序号和摘要返回原回执；更换内容、跳号、旧序号均拒绝。写入最多等待 2 秒且响应包含实际写入字节数；部分写入标记 `terminal_write_incomplete`，重复调用不重发。窗口尺寸限制为 2–500 列、2–300 行。传输失联返回未知结果，客户端与 Worker 不能把重发输入当作错误恢复。

请求结束不停止终端。直接程序退出后最多给尾部输出 1 秒排空时间，随后关闭该 PTY；不向其他终端或整个桌面发信号。脱离该终端的后代仍由会话 cgroup 管理，直接程序退出不等于执行会话排空。关闭会话必须撤销授权、确认 cgroup 为空，并在有界期限内等待直接引导和输出协程结束；失败保留关闭屏障，不删除图形目录后假报回收成功。

## 图形会话启动与监督

`StartDesktop` 在已授权桌面内按需发起唯一 XFCE 会话；固定 `computer-task` 使用本 Bot UID、公共 GID、私有运行目录及 `shell` 入组入口。图形启动只依赖真实 XFCE 与 RFB，不启动自研浏览器客户端。传输断连不重启进程，同一执行会话的重复启动返回原状态；失败记录保留到会话关闭。返回 `starting` 只说明已发起，调用者使用 `InspectDesktop` 查询 `ready`，不能把请求成功视为桌面就绪。

就绪文件先写完整私有临时文件，再原子发布。代理检查文件身份、权限、尺寸与显示编号；只有标记就绪后才连接固定私有 socket，检查 socket UID/GID、0600 权限、内核 `SO_PEERCRED` 及对端进程的当前执行资源组。之后实际完成 RFB 3.8 握手，核验 1280×800、32 位像素/24 位色深、真彩色格式和 Bot 名称。检查使用共享连接标记，不断开已有观察者；帧长度有界，不发送鼠标键盘或暴露原始连接。[RFB 握手与初始化定义](https://www.rfc-editor.org/rfc/rfc6143.html#section-7.3.2)

图形启动总期限为 45 秒、每次连接检查最多 2 秒；探测与进程等待在独立协程中进行，不持有桌面操作锁等待 XFCE 启动。总期限无论在轮询之间还是握手中耗尽，都报告启动超时。核心进程退出、就绪校验失败或超时立即撤销本桌面的授权，日志携带用户、电脑、Bot 桌面、会话和固定错误代码。正常回收先标记停止，避免把主动停止再次报告为故障；整组回收及进程、探测等待完成后才删除私有目录。其他桌面继续使用各自授权。

当前 `computer-agent` 是用户容器的受信基础设施监督器，**不是每个 Bot 的 Agent 主循环**。用户已明确要求每个 Bot 的独立 Agent 进程也运行在此共享容器中；该进程、模型/持久操作中继及 Worker 分发已实现，见下述 Bot Agent 章节；完整电脑工具和节点能力验收仍待完成。

## 原生应用与远程桌面边界

用户要求远程访问真实 Linux 桌面并直接操作 Google Chrome、XFCE 终端和 Thunar。自研 GTK 浏览器窗口客户端已移除，镜像不再安装其 Python 包、Pillow 或额外 PyGObject 依赖，桌面健康检查不再等待该客户端。Chrome 自动化服务与原生桌面的呈现分别验收；现有共享浏览器仍使用无头模式，不能据此宣称原生 Chrome 的多桌面展示已经完成。

## 桌面截图与完整输入手势

`CaptureDesktop`、`ReadDesktopImage`、`InputDesktop` 已从节点接通到实际 X11 桌面。每次调用重新验证完整执行会话、当前租约及控制代次；只连接授权会话目录中的私有 RFB socket。连接复用健康检查的文件权限、内核 UID/GID 与实际 Shell cgroup 校验，调用者不能指定显示号、连接路径或其他 Bot 的窗口。

截图使用 [RFB 3.8](https://www.rfc-editor.org/rfc/rfc6143.html) 的原始像素更新，显式请求全画面并统一像素字节序。只有完整覆盖 1280×800 才生成 PNG；缺块、越界、未知编码、过量更新和取消均失败。一次操作最多五秒，仍受上游更短期限和会话撤销约束；编码最多 5 MiB，每次读取最多 32 KiB，携带完整身份、序号、总长度与 SHA-256。接收方组装后须验证摘要。每桌面只保留最后一张不可变画面，新的截图使旧分块明确失效，避免将两个时刻的画面拼接为成功结果。

截图与输入分别核对会话内严格递增的持久操作序号，允许模型调用或拒绝参数造成的空隙。重复截图只返回同一张已缓存画面，失败尝试也占用序号；需要新画面时提交更大的序号。输入最多 512 个键盘或鼠标事件，包含 X11 keysym、中文 Unicode keysym、按钮和画面内坐标，整批必须释放全部按键与按钮。允许点击、滚动、拖动、文字和组合键；不提供跨请求保持按住的输入流，也不传输剪贴板内容。

输入在连接前记录尝试，相同末次序号及内容仅返回原回执；旧序号及更换内容均拒绝。`sent` 只证明完整写入桌面连接，不证明应用已经处理；后续应重新观察画面。任何连接、短写、关闭、期限或撤销异常产生 `uncertain`，同序号不会再次发送，后续输入被阻止直到结束当前执行会话。上层必须保留未知结果并回收所属运行，不能新建操作绕过此状态。截图和输入内容不写入日志。

每个桌面的锁、画面缓存及撤销上下文独立；一个桌面阻塞或撤销不占用其他桌面的操作锁。撤销立即取消传输，确认关闭后释放截图和输入缓存。最坏每个活动桌面保留 5 MiB PNG，另有固定尺寸解码缓冲，节点资源档位须计入并发桌面数量。回执不跨代理重启恢复，沿用已有关闭屏障禁止旧输入重新执行。

真实受限 Linux 验收已通过：同一容器内两个非 root XFCE 桌面并行中文输入和鼠标操作，截图分别显示各自窗口，跨桌面请求被拒绝，撤销一个桌面后另一桌面仍可截图。Unix 顺序包协议和节点身份链另行验证。图形测试进程由专用测试启动器降权，使用测试容器根 cgroup，不代表生产业务 cgroup 入组、完整能力探针或客户端桌面界面已完成。模型工具和临时截图存储现已接通，见[容器工具](../computertools/README.md)。

## 独立 Bot Agent 监督

`StartAgent` 只允许固定 `/usr/lib/tombot/bot-agent`，以当前会话作为启动标识，通过 `computer-task` 入组并降权，不接受程序、命令行、用户身份或环境覆盖。同一会话只保存一次启动尝试；重复请求复用已知记录，启动失败或退出不重新发起。Agent 与终端使用同一所属桌面 Shell 资源组，控制面回收时先封闭私有标准流，再终止资源组并确认排空。

每次 `agent_write` / `agent_read` 都由 `withScope` 核对完整会话与有效许可。二进制块最多 32 KiB，输入偏移连续，相同末块仅复用已知回执；部分写入后禁止继续。输出保留上一块用于确认，错误游标被拒绝；读等待最多 100 毫秒，不持续占有桌面锁。特权代理只缓存两端上一块，内核管道负责背压。程序退出后先排空输出，再报告实际退出状态，不能把领导进程退出当成整个资源组已清理。

资源撤销时即使关闭标准流报错，仍会发送整组终止指令。`Close` 依然要求已确认排空，随后等待 Agent 退出并清理该桌面私有目录，不清理共享业务文件。Agent 回执只存在于当前代理内存；重启沿用持久关闭屏障，不能恢复旧输入或自动重放程序。

受限 Linux 验收使用两个真实非 root Agent，验证 70 KiB 上下文经过分块中继、模型—工具循环、大整数参数、实际 Unix 协议、独立 PID 与旧代次拒绝；伪造 cgroup 入组被固定引导拒绝。成功进程由测试启动器直接降权，这些证据仍不替代真实业务 cgroup 成功入组及整组回收验收。节点、代理、Worker 和镜像须成套发布，排空旧会话后切换，不增加数据库迁移。

## 容器环回出网

入口同时监督控制 RPC 与 [出网转接](../egressproxy/README.md)：转接仅监听环境模板定义的 `127.0.0.1:3128`，每条连接只连接控制目录下固定的 `egress.sock`。端点必须为 root 所有、0600、单链接 Unix socket；通过已打开目录描述符定位，随后验证宿主 root 的内核对端身份（容器私有 PID 命名空间中 PID 为 0）。同容器 root 不能冒充宿主代理。

部署配置显式提供 `egress_connect_timeout_ms`、`egress_idle_timeout_ms`、`egress_lifetime_ms`、`egress_maximum_connections` 和 `egress_maximum_transfer_bytes`，没有隐式无界默认值。毫秒原值在转为时长前校验以防溢出；传输按方向限流量、限制连接数和总时长。宿主端点缺失时返回 502，不尝试直连；任何监听异常触发代理退出，正常停服关闭隧道并等待转接工作者结束。

统一桌面环境包含大小写 HTTP/HTTPS 代理变量及环回 `NO_PROXY`，终端、Bot Agent 与 XFCE 继承同一模板。不遵循代理的程序在无路由网络中无法直接出网。浏览器服务仍须显式使用此代理；单靠环境变量不能宣称 Chrome 联网已完成。

Linux 入口验收新增缺少宿主端点时明确失败、SIGTERM 后环回端口释放；真实宿主与容器跨命名空间的端点组合及公网能力探针仍待节点服务接入。

## 共享 Chrome 受管进程后端

`BrowserFactory.OpenBrowser` 复验独立服务组的真实内核入口、启动期限和退出预算，然后取得 root 运行根下的稳定独占锁，为此次实例建立私有运行目录。Chrome 无权删除锁文件；目录已存在、身份漂移、链接或另一个持有者均拒绝。持久 profile 不参与临时目录回收，所有 Bot 继续使用同一份站点状态。

`BrowserScope.Start` 只消费一次完全相同的封存授权，通过固定 `computer-task --browser` 入组并以 UID 30000 启动 Chrome。代理只持有私有 CDP 管道，不暴露调试端口；Chrome 原始诊断可能含页面内容，因此不进入业务日志。协议初始化成功后才返回服务，取消、进程提前退出和协议失联均撤销启动权，通知监督者并终止该服务组。

正常 `Drain` 先禁止迟到启动，给予 Chrome 有界退出时间，再检查并回收整个服务组。超时、强制终止及异常退出不会报告为已干净保存账号状态。`Close` 必须等实际启动流程、直接进程和整组后代都结束，才清理原 inode 对应的运行目录并释放 profile 独占锁；不能把单个 Bot 的窗口关闭当作整个用户浏览器关闭。

后端已通过下述 `BrowserController` 接入正式 `computer-agent.Run` 和受保护控制协议。宿主持久版本及服务组生命周期已接入节点，每会话窗口网关也已接入资源回收；桌面客户端、文件交互和联合能力探针仍待组合。代理不会在缺少宿主授权时自行启动 Chrome，账户与浏览器就绪门禁保持关闭；公开远程电脑交互继续暂缓。

受限 Linux 回归使用真实 Chrome 验证固定代理、两 Bot 共享账号、独立窗口、单会话回收与正常重启保留账号；成功 Chrome 进程由明确的测试启动器降权。正式引导另行验证伪造内核入口、撤销、过期、管道和目录错误的拒绝路径，仍不等于生产 cgroup 正向入组验收。新增运行目录由镜像入口准备，镜像与代理须成套更新；升级或回滚先停止接单并排空共享进程，保留持久 profile 和控制记录，不允许两个实例同时写同一份 profile。本轮没有数据库迁移。

## 共享浏览器监督与控制协议

`BrowserController` 在正式入口监听前恢复版本 1 的私有 `browser.json`，同一用户只持有一个共享 Chrome。三个控制动作分别启动、查询和关闭固定服务；只接受与代理一致的用户、电脑、节点及容器代次、正递增 `revision`、唯一服务实例、原始启动期限和显式窗口与时间预算。启动接管三个受限资源组入口，不接受任意程序、参数或 profile 路径。窗口预算复用共享浏览器的同一校验规则，调用与退出预算不能超过代理部署限制。

启动先持久保存 `consumed`，再启动受管 Chrome，协议初始化成功后持久保存 `active`。原子替换及文件和目录刷盘沿用私有文件存储；相同或较低版本、末次实例复用和已有未关闭实例均拒绝。查询、关闭核对完整原授权，包括原期限和预算；允许引用已到期的启动期限，但不恢复或延长执行。客户端验证完整回执，缺失回执、错误归属、错误阶段或混合成功与错误均拒绝。

关闭可以先于同授权启动抵达：代理持久记录 `closed`，迟到启动随后被拒绝。活动服务关闭时先禁止新授权，等待受管后端确认直接进程、整组后代和运行目录完成回收，再保存 `closed`；已关闭的同授权可重复确认，旧授权不能关闭新服务。代理的 `closed` 仍不替代宿主服务组移除和宿主持久交接。

取消和停服通过独立回调撤销服务，不等待状态刷盘。意外进程退出、协议失联、清理失败或持久化结果未知会通知容器看门狗退出；超过清理预算仍未完成时不释放控制目录锁。同代次启动发现 `consumed` 或 `active` 记录，在开放监听前失败并记录业务标识。只有宿主已隔离旧容器后的更高代次才能封闭旧记录，最高消费版本继续保留；损坏、错误归属、未来代次均拒绝，不自动重放启动或网页动作。

服务生命周期使用独立门禁，Chrome 启停不长期占用 Bot 桌面锁。每次窗口授权复验实际容器及桌面会话，正式窗口网关按下述流程在会话撤销后调用 `ReleaseSession`。正常停服先并行等待探针与桌面控制器回收，再关闭共享 Chrome，全部结束后才关闭持久目录；依赖回收失败时保留共享服务与记录，交由容器退出完成隔离，不报告正常保存账号状态。

单元和竞态测试覆盖并发启动、先关闭后启动、全部持久阶段及回收失败、取消、意外退出、重启和并发停服；真实 Unix 测试覆盖三个动作、描述符所有权及伪造回执。实际镜像入口验证旧配置与同代次未关闭浏览器记录不能建立监听。协议测试的资源组为明确替身，真实 Chrome 成功进程使用测试启动器，不代替宿主真实入组、回收和完整开户验收。

部署使用配置版本 4，必须成套更新节点、代理、固定程序与镜像；代理接线未改 SQL 迁移；宿主接线现采用生命周期版本 4，存储版本 3 和桌面版本 2 不变。回滚先停单排空并保存匹配的全部状态和用户磁盘，不能将新控制目录交给忽略 `browser.json` 的旧代理。宿主旧控制目录回收现在核验原代理身份及已关闭的最高浏览器消费版本；缺失宿主屏障或授权不一致仍拒绝，不以删记录代替恢复。

## 会话窗口入口与回收

正式资源工厂在创建私有桌面目录后、发放执行授权前建立 `/run/bot-desktops/<session_id>/browser.sock`。入口属于 root:20000、0660，父目录属于本桌面 UID、0700；通过固定目录描述符创建并保存实际 socket 身份。重复入口、错误目录身份或共享 Chrome 尚未活动均拒绝创建会话，不建立无浏览器的默认成功分支。

窗口入口固定完整执行会话及原 Chrome 实例，仅接受本会话 Agent 所在 `shell` 子组中具有正确 UID/GID 的真实对端。每次 HTTP 请求重新检查内核进程组、租约及原共享实例；同 UID 的旧运行、其他 Bot 和其他资源组均不能访问。当前运行的 Agent 与其工具进程共用该会话页面能力。停止、失控或替换 Chrome 后，旧入口不会重定向到新服务；页面和 Cookie 仍由用户级同一 Chrome 上下文管理。

窗口额度、画面尺寸复用共享浏览器授权。每个窗口最多计入画面与动作两条连接，单入口封顶 16 条；调用时限沿用浏览器预算且至少 1 秒，退出等待受代理清理预算约束。多个桌面的监听器及请求取消互相独立，窗口动作仍使用共享浏览器原有的窗口级门禁，不持有全容器启停锁。

租约撤销立即取消所属网关，并独立等待在途请求退出、在原 Chrome 上执行 `ReleaseSession`，不等待任务进程回收或桌面状态刷盘。页面脚本不能因为输入连接已断开而被遗留运行；独立看门狗在清理预算耗尽时通知容器退出，即使内部调用阻塞也不等待业务锁。会话资源组确认为空后，还须确认页面回收成功并按原 socket 身份清理入口，才能确认会话回收与释放桌面。关闭只消费一次；未知页面回收、入口被替换、超时或清理失败保留错误与文件证据，不重发关闭请求或删除替换文件。其他 Bot 页面、共享 Chrome 及持久账号目录不因正常回收一个会话而关闭。

退出总预算至少为 `call_timeout_ms + 2 × cleanup_timeout_ms`，分别覆盖在途操作、桌面/探针回收和最后的共享 Chrome 回收。新入口不改变持久记录或 SQL 格式；升级须排空旧会话并成套部署节点、代理、镜像与满足预算的配置，回滚同样保留原代次和关闭屏障，不原地接管旧进程。

测试覆盖绑定原实例、错误身份与进程组、重复入口、跨 UID 请求、取消在途动作、单 Bot 回收、页面关闭失败、入口替换和退出顺序。真实 Chrome 组合验证两个入口只返回各自页面、关闭甲后乙仍可截图、账号共享及正常重启保留。成功入组仍使用明确夹具；上传下载与联合能力探针尚未交付，原生桌面呈现也未验收，不能据此开放完整就绪。

## 代理内部的直接浏览器调用

`Controller` 新增所属页面列表、创建、动作、截图、对话框回复与关闭的 Go 调用入口，通过 `WindowSession.UseBrowser` 使用已绑定的原共享 Chrome。调用方仍须提供完整执行会话；窗口 ID 和动作序号由共享浏览器校验，不接受调试地址或 Chrome 实例选择。原有桌面私有 socket 不作为此入口的传输路径，也不需要自研浏览器界面。

桌面锁只用于取得当前会话的绑定，网页动作在锁外执行，允许租约检查、续约和对话框回复并行。调用前后均验证完整会话和原实例；动作开始前的拒绝不会进入 Chrome，动作期间撤销、超时或回执时失去授权统一报告结果未知，并丢弃页面和截图结果，不能重放副作用。

直接调用与网关共享会话撤销信号。页面回收必须先等待两类在途调用退出；调用忽略取消或超过清理期限时，独立看门狗报告容器致命故障，不把页面标为已释放。实例失效后不重新绑定新 Chrome。

这些只是代理内部 Go 入口。最新执行方向是容器内 Agent 通过本地接口操作 Chrome，不再把它们扩展为 root 控制协议或节点逐动作 API。Agent 本地调用、执行登记和结果确认已通过协议 3 接通；浏览器工具区分对话框等待与完成，并在任务结束前检查未完成动作。原生应用的远程展示及生产宿主组合仍须独立验收。

本次不修改 SQL、持久记录或线上协议格式。发布时仍须排空会话、保留用户磁盘和控制代次，成套更新节点、代理及镜像；回滚也必须恢复匹配集合，不能在活动会话中替换原实例。镜像与 Agent 必须使用匹配源码重新构建；旧开发发布包尚未更新，不能与最新协议混用。


启动取消与完成清理存在竞争时，`cancelScope` 仍必须执行撤销：停止尚未调度的取消通知后再次检查上下文，已取消则同步撤销原服务组。确定性延迟通知测试与实际取消回归覆盖此分支；不能依赖后台回调一定先于启动返回执行。
