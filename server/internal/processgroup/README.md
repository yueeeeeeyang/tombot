# Linux 电脑进程资源组

本模块为同一用户电脑内的执行会话与容器级基础服务建立独立 cgroup v2 子树，并提供入组描述符与整树回收能力。会话部分由[受信节点会话控制器](../dockernode/README.md)调用；用户、模型和业务 API 不能直接传入宿主路径、PID 或资源组身份。当前已完成资源组实现、身份与解析测试及 Linux 交叉构建，基础服务监督器接入与真实内核执行验收仍待完成。

## 资源身份与边界

构造器只允许 Linux root 节点，固定访问 `/sys/fs/cgroup`，验证 cgroup v2 文件系统、root 所有权及禁止组和其他用户写入的权限。非 Linux 平台明确返回不支持，不提供普通进程组或宿主 Shell 替代实现。

`Locate` 根据节点已经核实的 Docker 容器主进程读取归属，要求路径末端精确匹配完整容器 ID，记录父目录的设备号和 inode。后续调用重新核对该身份；路径缺失、替换或所有者异常均返回错误，不能凭同名路径接管另一实例。

`LocateContainer` 为出网等容器级基础设施提供相同的父组定位；它返回 `ContainerReference`，不需要构造 Bot 会话。`Locate` 复用此实现，读取 cgroup 目录身份后再次核对进程归属；拒绝不匹配的容器 ID、任务子组、路径变化或取消。节点出网将容器主进程与连接对端的完整引用比较，不能只比较同名目录或 root UID。

每个会话使用包含不可复用会话 ID 和控制代次的目录，下面固定建立 `shell`、`browser` 两个叶组。Docker 祖先组继续约束整台用户电脑的 CPU、内存和进程数量，本模块不修改其控制器配置或扩大限制。开启时检查新组为空，且 `cgroup.kill` 可写；能力缺失即拒绝开启。

## 容器级基础服务

`ServiceGroups` 使用 `ServiceReference` 绑定同一容器父组、规范大写 ULID 实例与固定用途，只支持 `probe`、`browser`。服务目录为 `tombot-service-<用途>-<实例>`，与 `tombot-session-<会话>-f<代次>` 同级，服务不借用 Bot、桌面或运行身份。探针结束或单 Bot 取消只能回收自己的组，不能把用户共享 Chrome 放入任一 Bot 的会话子树。

服务只发放三个描述符：当前服务 `cgroup.procs`、`cgroup.kill` 和只读 `cgroup.events`。`ValidateServiceControls` 在接收端重新检查数量、顺序、内核文件类型、权限、root 归属与完整实例路径，拒绝普通文件、任务入口及另一服务的入口。该验证与会话四入口共用内核校验实现；调用方保留描述符所有权并负责关闭，不能把控制入口传给用户程序。

`Contains` 检查宿主 PID 是否属于当前服务精确路径；目标组或进程缺失返回不属于，父组身份漂移、解析失败及取消返回错误。它只提供内核归属证据，实际对端授权还必须核验 UID/GID、有效服务实例及连接生命周期。

受信监督器必须在创建前持久化实例，关闭前封闭新授权，重启后先对账旧实例；服务 ID 不能复用。资源组库本身不代替这套持久状态机，不能独立对外提供创建接口。当前新增的是生产探针及共享 Chrome 所需的资源管理层，尚未接入节点启动、容器代理或共享浏览器进程，不能据此将电脑标记就绪。

## 用户进程入组

`Membership` 只打开上述叶组的 `cgroup.procs` 写入描述符。完整执行链必须满足以下顺序：

1. 节点会话控制器验证当前会话身份、活动状态和有效期限，发放受限描述符。
2. 容器内受信引导程序在执行用户代码之前向描述符写入 `0`，将自身放入指定组。
3. 引导程序关闭全部控制描述符，清理继承权限，降为任务非 root 身份后执行用户程序。

`Controls` 一次打开当前会话的两个叶组入组入口、会话 `cgroup.kill` 和只读 `cgroup.events`，只授予固定文件的访问能力，不授予目录写入权。`ValidateControls` 在容器代理中复验四个描述符的顺序、访问模式、root 所有权、cgroup 文件系统及完整实例路径；租约与业务身份仍由上层单独核验。

描述符不能交给用户代码，不能接受用户选择的 PID，也不能用宿主命令执行代替容器执行。[容器内任务引导](../taskprocess/README.md)、[描述符通道](../agentchannel/README.md)、[代理入口与看门狗](../computeragent/README.md)及节点绑定已实现。现有会话内 `browser` 叶组不能承载共享 Chrome；后续每桌面的窗口客户端仍随自身 Bot 回收，共享内核由上述容器级服务单独管理，生产组合仍待接入。

## 回收与交接

节点先封闭会话的新入组授权，再调用 `Drain`。本模块枚举受管组内有限数量的进程，通过 pidfd 固定进程身份并复查归属，发送正常退出信号；有限宽限内仍未退出时，终止完整会话子树并等待空组。内核接口的语义依据 [Linux cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)：`cgroup.kill` 覆盖子树，`cgroup.events` 的 `populated` 反映子树是否仍有活进程。

确认空组后还必须移除两个叶组及会话父组，才允许节点返回 `drained`。这一步封闭此前发放但尚未写入的描述符；仅检查一次空组不足以避免迟到进程重新进入。目录仍忙、出现未知子组、身份漂移或任何操作失败时保留清理失败，不递归删除未知资源。

基础服务复用同一回收实现，但仅操作自己的单叶组；删除前仍须确认真实空组。服务路径、会话路径与父目录核验的权威逻辑共用，不能为探针另开普通 `kill` 或宽泛目录清理后门。

同一已核实父组下，会话目录已不存在可视为此前完成删除；父组自身缺失或更换不能据此判定旧实例已经退出。容器重建和宿主重启需要节点生命周期提供独立的隔离与恢复证据，目前没有自动放行路径。

## 验证与部署条件

[单元测试](group_test.go) 覆盖完整身份、容器路径、目录逃逸、统一层级记录、存活状态及进程列表边界；节点会话测试使用可控资源组替身验证协议竞态。真实 Linux 验收必须另行覆盖入组前无用户代码、双重派生、脱离会话、并发 fork、到期清理、迟到描述符及无关容器保持运行。当前未执行这组内核验收，不能以编译和替身测试代替。

新增服务测试覆盖固定用途、非规范实例、路径注入、父身份绑定、持久字段、取消和普通文件控制替身拒绝。[真实内核测试](service_integration_linux_test.go) 另外覆盖实际入组、错误父 inode、跨服务/会话入口拒绝、忽略正常退出信号后的强制回收、Bot 与探针关闭时共享服务继续运行，以及保留旧描述符后的迟到入组拒绝。该测试使用真实 cgroup v2，缺少条件直接失败，不跳过或模拟成功。

内核测试应在专用 Linux root 测试节点上执行，先创建仅供验收的 Docker 容器，设置 `TOM_TEST_CGROUP_KERNEL=1`、`TOM_TEST_CGROUP_CONTAINER_ID`（完整 ID）及 `TOM_TEST_CGROUP_CONTAINER_PID`（宿主可见实际主进程），然后执行 `make test-process-groups`。它只创建新的随机服务/会话子组及固定测试子进程，不执行用户命令；需要真实可写的宿主 cgroup 管理入口。当前环境仅完成测试编译与受限 Linux 身份拒绝测试，未运行这条需要宿主资源组写权限的命令。

节点部署需要受信 root 服务和可写的宿主 cgroup v2 管理入口，用户电脑不挂载宿主 cgroup 管理目录。生产镜像、任务身份降权、Chromium 沙箱、描述符通道和看门狗组合验收完成前，不启用用户命令执行。

本模块不新增数据库结构，也没有在开发机创建或修改宿主资源组；现有会话路径及四入口契约保持不变，尚未发布服务实例控制协议。未来服务组合上线时应成套部署节点与容器代理。升级或回滚前先停止接单、排空会话并关闭全部基础服务，保留节点持久记录；不得让不识别服务记录的旧程序接管仍运行的实例，不得删除控制记录、放宽身份校验或切换普通进程组以绕过回收失败。
