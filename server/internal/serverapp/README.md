# 多用户应用组合与运行入口

`cmd/tomd` 使用本模块组合 PostgreSQL、身份认证、机器人目录、管理平台、模型网关、开户工作池和执行 Worker。API 使用专用非 root 身份，通过 HTTPS 与证书指纹固定的节点控制端口调度电脑，因此服务端不再要求 Linux；Bot Agent 的模型与工具循环仍在所属用户容器内执行。本模块没有宿主 Shell 或旧运行时回退。

本阶段完成入口组合，不表示部署引导与全部产品能力已完成。[首位管理员本机部署入口](../../docs/admin-bootstrap.md)与[节点及镜像目录登记](../../docs/node-registration.md)已接通，节点首次启动通过一次性凭据登记，后续使用已绑定证书身份；多节点共享 API 客户端证书并各自独立监督。目录登记只创建 `bootstrapping` 节点，不发布就绪。独立节点程序、镜像准备和[控制心跳租约](../../docs/node-health.md)已接通，[独立验收与镜像准入](../../docs/node-verification.md)已接通；共享浏览器、真实生产部署验收、客户端切换及备份恢复仍待完成。远程电脑用户交互按最新范围暂缓。不得手工把未验收的电脑标为就绪来绕过前提。

## 配置与秘密文件

普通首次部署使用[服务端一键安装](../../deploy/SERVER.md)，无需逐项准备下述文件。`tomd install` 负责安装，`tomd upgrade` 负责备份和更新，`tomd status` 检查状态；应用运行入口仍使用非 root 账户及显式配置。

`TOM_SERVER_CONFIG` 必须指向规范绝对路径的 JSON 文件。未知字段、尾随内容及无效参数会阻止启动。省略运行限额时使用 `DefaultConfig`；时间均使用 `5s`、`2m` 等带单位字符串。监听地址、管理来源、文件路径、节点身份、验收镜像 ID 必须显式提供。

首次部署可使用[配置生成程序](../../deploy/CONFIGURE.md)绑定节点、镜像及实际 API 身份，并生成配套文件。服务配置解析阶段复用模型网关的网络和预算校验，不读取信任文件或连接外部服务；不再等到加载凭据、打开数据库后才发现这些参数无效。TLS、附加信任文件及数据库实际状态仍在启动时核验。

以下是字段示意，示例路径不指向现有数据，节点标识须由部署登记产生。它不是可直接上线的部署文件。

```json
{
  "address": "127.0.0.1:8443",
  "admin_origin": "https://admin.example.test",
  "tls_certificate_file": "/etc/tombot/tls/certificate.pem",
  "tls_private_key_file": "/etc/tombot/private/tls.key",
  "identity_key_file": "/etc/tombot/private/identity.key",
  "csrf_key_file": "/etc/tombot/private/csrf.key",
  "active_model_key": "current",
  "model_key_files": {"current": "/etc/tombot/private/model.key"},
  "database": {
    "migration_dsn_file": "/etc/tombot/private/migration.connection",
    "dsn_files": {
      "tombot_identity": "/etc/tombot/private/identity.connection",
      "tombot_control": "/etc/tombot/private/control.connection",
      "tombot_tenant": "/etc/tombot/private/tenant.connection",
      "tombot_dispatch": "/etc/tombot/private/dispatch.connection"
    }
  },
  "node": {
    "certificate_file": "/etc/tombot/tls/api-certificate.pem",
    "private_key_file": "/etc/tombot/private/api.key",
    "heartbeat_interval": "10s",
    "control_lifetime": "2m",
    "maximum_nodes": 128
  },
  "models": {"concurrency": 16}
}
```

配置文件和证书必须为 root 或服务身份拥有的普通文件，不允许组或其他用户写入。DSN、TLS 私钥及三种用途的加密文件要求只对所有者开放；通常部署为服务身份拥有的 `0600` 文件。拒绝最终路径符号链接、硬链接、目录、管道、空文件及超限内容。路径和父目录由受信部署维护，API 不接受客户端传入文件路径。机密内容与系统原始文件错误不会写入日志。

身份加密、CSRF 和各模型密钥文件分别存放 32 字节随机原始内容，不使用文本编码或换行。模型密钥轮换保留仍用于解密历史凭据的旧版本文件，活动版本通过 `active_model_key` 选择。文件内容由部署机密渠道产生并保管，不放入仓库或命令参数。TLS 证书必须匹配 `admin_origin` 的主机且在有效期内，最低 TLS 1.3；载入后续期或轮换需要停单排空并重启。

`database.migration_dsn_file` 为必填的独立迁移连接文件；四个 `dsn_files` 则分别使用只继承对应权限组的业务登录身份。五个连接的主机、端口和库名必须一致，不接受多地址故障转移或不同别名拼接；独立 TLS 配置及登录凭据可以不同。远程连接遵守存储模块的 TLS 限制。业务连接仍拒绝迁移角色、超级用户及混合权限组。

`tomd` 每次启动先通过迁移连接核对嵌入程序的 SQL 与完整版本账本，仅执行尚未应用的脚本；空库自动初始化，已就绪库只校验。全部待执行脚本与账本写入处于同一个事务，使用事务级咨询锁串行化同库并发启动。连接建立最多 10 秒、迁移总时限 1 分钟、锁等待 10 秒、每次语句调用 45 秒；超时、取消、权限不足、未知非空库、历史摘要不符或数据库版本高于程序均阻止启动，不监听业务端口。失败事务回滚，下次启动重新校验实际账本，不跳过失败脚本。

迁移完成即关闭专用连接，再建立四个最小权限业务连接池。迁移凭据不得复用为业务凭据；迁移身份应拥有目标结构的建表、修改和授权权限，首次部署还须预先准备四个 `NOLOGIN` 权限组及其独立登录身份。自动迁移意味着 API 系统身份可以读取迁移凭据，关闭连接不会撤销它对凭据文件的访问能力；该文件须纳入服务机密管理。启动日志只记录阶段和节点标识，不记录连接内容。

`trusted_proxies` 只用于部署明确的代理网段，不能允许所有来源；代理必须覆盖单一客户端地址与 HTTPS 协议信息。模型 HTTPS 出口不再使用域名或公网 IP 白名单，支持内网和代理 Fake-IP，升级须删除旧 `origins` 字段；本机、链路本地与云元数据等禁止地址仍受拦截，额外排除地址使用 `denied_networks`，额外信任根使用 `root_ca_file`。这些网络策略不会由管理端模型表单覆盖，详见[模型网关](../modelgateway/README.md)。

## 启动及进程生命周期

1. 用受信部署准备空 PostgreSQL、四个最小权限组及其独立登录角色、迁移身份、五份连接文件和包含管理平台的 `tomd`；不创建演示账号。
2. Docker 安装与节点运行分别由受限部署组件负责。节点监听地址、证书与客户端指纹遵守[节点 API](../nodeapi/README.md)。API 不能加入 Docker 组。

   API 与节点跨主机时，节点必须只放行 API 的出口地址；仅靠证书认证不足以防住对 root 端口的资源耗尽。
3. `tomd` 校验非 root 身份、配置、TLS、私有文件及数据库归属，自动迁移后关闭迁移连接，再核对四个业务连接的权限及版本并构造服务。任何失败释放已经打开的数据库连接且不监听业务端口。
4. HTTPS、节点控制观察、独立电脑验收、开户工作池和执行 Worker 使用同一进程监督。任一组件提前退出即停止接单并取消其他组件；正常退出信号不作为故障。Worker 在自己的有界收尾上下文中保存恢复证据和清理所属会话。
5. 所有后台退出后才允许关闭连接池。退出超过 `http.shutdown_timeout` 时明确返回错误，保留“仍在停止”的状态并结束进程，不能假装资源已经释放。进程重启仍须按持久租约和关闭屏障恢复，未知外部动作不重发。

默认 HTTP 请求时限为 60 秒，开户请求等待 30 秒、模型验证 45 秒，写入时限不低于请求时限。部署节点调用总时限必须覆盖开户、桌面及 Agent 的单次调用时限；收尾时间必须落在退出总时限内。各领域构造函数继续核对自己的上限与并发约束。工具注册集合同时生成 Bot 可用工具名称，当前为 `computer_shell`、`computer_screenshot` 和 `computer_input`。

桌面启动等待由 `computer.desktop_start_timeout` 控制，默认 `45s`。临时截图配置位于 `runs.images`，默认 `max_user_bytes=268435456`、`max_user_images=256`、`context_images=2`、`retention="168h"`；范围和清理语义见[执行模块](../execution/README.md#截图持久化与模型视觉)。模型请求默认上限由 2 MiB 调整为 16 MiB，启动检查其足以承载配置张数的最大 PNG base64 加文本预留空间；配置更多图片时必须相应提高 `models.max_request_bytes`。模型自身也必须声明并验证视觉能力，客户端无须配置模型。

## 路由和健康语义

| 路径 | 行为 |
| --- | --- |
| `/admin/` | 内置管理平台，沿用同源 CSP；运行时无需外部前端目录 |
| `/activate` | 公开用户激活页面，输入激活码并设置密码；无需管理会话 |
| `/` | 普通用户平台首页，左侧用量管理占位导航及账户菜单；未登录转到 `/login` |
| `/login` | 独立普通用户登录页，不要求客户端授权参数 |
| `/account` | 用户平台中的个人信息页，复用已登录网页会话 |
| `/authorize` | 桌面授权页，校验登记的授权请求并复用网页登录状态 |
| `/api/v2/web/auth/` | 普通用户网页 Cookie 登录与退出 |
| `/api/v2/auth/` | 桌面激活、登录、续期、会话与退出 |
| `/api/v2/admin/auth/` | 管理平台 Cookie 认证 |
| `/api/v2/admin/` | 管理操作，受管理身份、来源及 CSRF 保护 |
| `/api/v2/` | 当前用户资源及持久运行接口，受桌面身份保护 |
| `/health/live` | API 进程可以响应 |
| `/health/ready` | 应用正在运行且四个数据库连接可用，返回 `scope: api` |

API 就绪探针不连接 Docker 或模型供应商，也不声明用户电脑已就绪。电脑故障通过其所属开户或运行流程报告；新 Worker 仍要求每次运行先取得电脑授权，纯文本任务同样遵循。旧 `/api/v1` 和旧命令不再注册。

## 变更、恢复与验证边界

自动迁移仅调整执行入口，没有新增或修改 SQL 脚本，也不保留独立 `tomdb` 命令。升级部署先停单并排空所有旧实例，保存数据库与关联资源的一致备份；增加 `database.migration_dsn_file` 并准备对应私有文件，再部署同一版本程序。咨询锁只协调迁移实例，不能保护仍在运行的旧版本业务代码；涉及表锁或大量数据的迁移仍需维护窗口，实际耗时取决于待执行 SQL 和数据规模。

若启动失败且迁移事务未提交，修正原因后可重新启动；迁移已提交但后续服务组装失败时，已提交版本不会自动撤回。仅回滚本次入口改动、且 SQL 版本相同时，可恢复原二进制和原配置，按原发布流程执行独立迁移；若数据库已升级到旧程序不支持的版本，必须前向修复或恢复升级前一致备份，不能降账本、删除已应用迁移或让旧程序忽略版本检查。

当前迁移链执行至 `0052`，包含节点能力验收、桌面授权、事件保留、管理员身份拆分与直接创建、供应商删除约束；历史迁移不变。`tomd` 从单用户入口整体切换，旧环境变量、初始化码、宿主浏览器安装、SQLite 归档及恢复命令已移除。相应旧命令测试随功能退役，由新入口的配置、TLS、数据库权限与版本、生命周期及组合路由测试替代；旧领域测试继续保留，未关闭检查规则。

正式部署从新库和新卷开始，不把旧单用户数据转换为新数据。切换前停止接单并排空，保存 PostgreSQL、加密文件、用户卷、节点代次与关闭屏障的一致恢复点。回滚使用配套的新架构版本与资源；不能让旧 `tomd` 读取新库、复用新卷或忽略未知执行证据。需要保留旧产品时只能在独立环境恢复旧版本及其原数据，不与新服务混接。新的全链路备份恢复尚未验收，当前不能按完整生产交付切流。

测试使用真实临时 PostgreSQL、独立 TLS 证书和正式服务组合，覆盖空库和已有库自动迁移、并发与重复启动、历史摘要与版本拒绝、迁移权限不足、取消和锁等待超时、迁移连接释放，以及两用户激活登录、独立机器人桌面登记、跨用户拒绝、管理通道拒绝、退出撤销、数据库失联、启动失败连接释放、工作者异常、取消竞争及退出超时。测试中的电脑目录为明确的数据库夹具，不启动真实 Docker，不调用公网模型；该范围不能替代节点或电脑端到端验收。

## 内置管理平台部署

`tomd` 在编译时嵌入管理页面，由入口将已校验的处理器注入应用。构建使用 `make build`，自动按锁文件安装前端依赖、构建页面再编译 Go；直接编译前须先运行 `make admin-build`。发布包格式 7 不再包含独立 `admin/` 目录，部署不需要 Node.js 或单独前端进程。`tomnode` 不依赖内置资源包。

升级前备份程序、配置及原前端目录，从配置移除 `admin_directory`，替换新版 `tomd` 并重启。旧字段会作为未知配置拒绝，不提供外部目录兼容入口。本次无数据库迁移，页面更新与 API 由同一二进制原子切换；回滚到外置资源旧版须成套恢复原二进制、原配置和前端目录。访问地址和 `admin_origin` 不变，深层页面刷新仍由正式路由处理。
