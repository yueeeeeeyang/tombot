# 新认证 HTTP 接口

本模块提供多用户认证传输协议，使用 `identity.Service` 完成身份规则。已通过真实 PostgreSQL 与 HTTPS 联合测试，并挂接到新的 `tomd` [应用组合](../serverapp/README.md)；完整节点与客户端部署仍待验收。

## 入口与响应

桌面认证前缀为 `/api/v2/auth`，管理平台认证前缀为 `/api/v2/admin/auth`。

| 方法与后缀                   | 用途及输入                                                    |
| ---------------------------- | ------------------------------------------------------------- |
| `POST /login`                | 用户名、口令、动态验证码、设备名；桌面端还提供平台            |
| `POST /refresh`              | 桌面提交续期值；管理端提交空 JSON 对象，续期值来自安全 Cookie |
| `GET /session`               | 当前 Principal；管理端同时返回当前 CSRF、访问与会话到期时间                |
| `POST /logout`               | 提交空 JSON 对象，撤销当前会话                                |
| `POST /password`             | 当前口令、新口令及管理员动态验证码；成功后全部会话失效        |
| `POST /verify`               | 口令和动态验证码，用于刷新敏感管理操作的验证窗口              |
| `GET /devices`               | 当前用户有效设备；`before` 游标及 `limit` 有界分页            |
| `DELETE /devices/{deviceID}` | 撤销当前用户指定设备；不能通过用户标识切换操作对象            |

普通用户激活入口为 `POST /api/v2/auth/activate`，输入 `activation_token`、`password`，仅作用于用户表；管理员在创建时直接设定口令并登记验证器，没有激活流程。

`tomd` 同源公开页面 `/activate` 提供激活码、密码及确认密码表单。管理平台签发材料后同时展示该页面链接；链接不携带激活码，页面不恢复管理会话、不附带管理 Cookie，成功后可直接进入 `/login` 登录用户平台，也可从客户端发起登录。部署与回滚说明见[普通用户激活](../../../admin/README.md#普通用户激活)。

首位管理员入口为 `GET` 与 `POST /api/v2/auth/admin-setup`。`GET` 只返回 `required`，供登录页判断是否展示创建按钮；`POST` 接受 `username`、`display_name`、`password`，仅在平台没有任何管理员时成功，并一次性返回动态验证器密钥。两者均不接受 URL 中的凭据，也不需要会话。

客户端提交 JSON 对象，最大 16 KiB；未知字段、多个对象、无效 UTF-8 及其他内容类型会被拒绝。会话范围由路由决定，不能提交 `scope`、`role` 或 `user_id` 覆盖身份。身份由访问凭据解析，其他业务路由也必须沿用相同 Principal 契约。

业务 HTTP 模块通过 `Protect` 复用相同安全边界，回调接收已验证的 Principal 与服务端生成的请求标识。范围由服务入口固定，管理处理器只能挂接 `/api/v2/admin/` 命名空间，不能借路由别名跳过来源或 CSRF。领域层仍须执行当前管理员权限、二次验证及资源所属校验。

所有认证响应设置 `Cache-Control: no-store`，包含服务端生成的请求标识。错误响应固定为 `code`、`message` 和 `request_id`，不传递数据库错误内容、原始请求或凭据。参数错误、认证失效、权限拒绝、限流和服务不可用分别使用明确 HTTP 状态；审计或数据库错误不转换为登录成功。

## 桌面与管理平台

桌面浏览器登录通过公开 `POST /api/v2/auth/browser/start` 登记本机随机回环地址、状态与 S256 挑战，系统浏览器打开同源 `/authorize`。表单使用 `strict-origin` 保留同源 POST 的来源校验，同时不向 Referer 暴露授权查询参数；CSP 仅额外允许本次登记的回环来源及端口，以便批准后的重定向返回客户端。错误口令页沿用相同策略并清空输入。完成后由桌面主进程调用公开 `POST /api/v2/auth/browser/exchange`，校验授权码、状态与挑战摘要后签发会话；无效、过期及重复交换统一返回 `400 AUTHORIZATION_INVALID`。这些公开请求不附带或刷新旧会话，业务接口的认证要求不变。

此修复无数据库迁移，需同步更新客户端和 `tomd`，升级或回滚后重新发起尚未完成的登录。完整 Electron、Chromium 与真实数据库联合验证命令见[客户端说明](../../../desktop/README.md#浏览器登录修复与升级)。

桌面登录及续期返回访问值、续期值、过期时间和 Principal，不设置管理 Cookie。后续请求使用 `Authorization: Bearer …`，不从查询参数或 Cookie 读取身份。桌面主进程保存凭据、串行续期及向渲染层提供受限 IPC 的接入仍待客户端阶段完成。

管理平台登录及续期仅把两份会话值写入 `__Host-` Cookie，设置 `Secure`、`HttpOnly`、`SameSite=Strict`、根路径及绝对过期时间，不设置 `Domain`。JSON 仅返回 Principal、过期时间和 CSRF 校验值，不把会话值交给页面脚本。退出、改密及撤销当前设备后清除两份 Cookie。

管理写请求必须同时满足：

1. `Origin` 与部署配置的管理站点完全一致；拒绝跨站和同站其他来源的 Fetch Metadata。
2. 已登录操作的 `X-CSRF-Token` 与服务端计算结果一致。计算采用独立密钥的 HMAC-SHA-256，并绑定当前 HttpOnly 续期 Cookie。旧会话或其他会话的校验值不能用于当前请求；重复头和重复 Cookie 被拒绝。
3. 校验完成后才调用身份服务。管理续期也遵守此顺序，不能在 CSRF 验证之前轮换或撤销会话。

CSRF 值在登录、续期或查询当前会话后从 JSON 读取，页面只需保存在内存中。刷新页面后可查询当前会话重新取得；续期成功后使用新值，不自动重发已可能提交的敏感请求。实现采用绑定会话的签名校验及来源核验，依据 [OWASP CSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 部署约束

所有认证接口要求 HTTPS。直连连接使用实际 TLS 状态和对端地址，不信任任意转发头；只有外部配置明确列出的代理网段可以覆盖来源。受信代理必须覆盖而不是追加 `X-Forwarded-For`，只转发一个合法客户端 IP，并设置 `X-Forwarded-Proto: https`；不明确的代理链直接拒绝。

`Options.AdminOrigin`、`TrustedProxies`、`CSRFKey` 和 `RequestTimeout` 由部署配置提供。CSRF 密钥与模型、MFA 加密材料分开管理，不向浏览器、用户容器或日志暴露。此模块的请求上下文超时不能代替 HTTP Server 的读取、写入与空闲超时，运行入口须同时配置传输层时限。

## 验证范围

协议测试覆盖安全 Cookie、CSRF 在业务操作之前执行、续期后校验值变化、跨会话和重复值拒绝、来源及代理伪造、JSON 限制、身份参数注入、凭据通道隔离、错误脱敏和真实 HTTPS Cookie 往返。独立联合测试使用真实临时 PostgreSQL 与 HTTPS 服务执行两用户激活、登录、设备隔离、续期及重放撤销。

联合测试中的电脑记录仅作为身份前置条件夹具，不创建真实 Docker 电脑，也不代替同步开户与容器验收。完整运行入口、管理页面、桌面凭据保管以及长连接撤销尚在后续实施范围。

## 管理会话恢复

新增管理专属 `GET /api/v2/admin/auth/refresh-context`，使用 HttpOnly 续期 Cookie，只返回 `csrf_token`，不轮换 Cookie、不返回 Principal 或凭据。该只读操作由身份服务查询续期摘要，要求未消费、未到期，且账户、设备、权限版本和会话仍有效；旧值校验失败不会触发重放撤销。拒绝外部 Origin、跨站及同站其他来源的 Fetch Metadata、重复 Cookie、认证头和查询参数。随后 `POST /refresh` 仍完整检查 Origin、CSRF 并原子轮换，旧值重放撤销规则保持不变。

管理 `GET /session` 返回数据库中的 `access_expires_at` 和 `expires_at`，页面刷新后可恢复续期时钟。访问 Cookie 已失效时，页面在 Web Locks 独占锁内先读取上述续期校验接口，再发起一次续期；业务请求使用共享锁，防止在途访问凭据被其他标签页轮换。响应丢失时先只读核实当前 Cookie，不自动重发已消费值。

无结构迁移；必须成套发布或回滚服务端二进制和管理静态产物，重启后生效。会话绝对有效期及撤销策略不变，写请求多一次当前会话查询，查询复用凭据摘要索引。

管理会话的 Principal 还返回当前 `username` 和 `display_name`，供侧栏账户菜单展示；登录、续期和会话恢复均来自数据库。页面不从用户名输入或管理员列表猜测身份，不缓存账户信息。此字段补充要求管理前端与服务端同步发布。

## 浏览器登录样式

`/login` 和登录失败、链接失效页面使用与客户端和管理平台相同的猫咪头像、主题变量及表单控件。样式和头像通过 `/admin/assets/login.css`、`/admin/assets/login-logo.png` 同源加载，由管理平台构建并嵌入 `tomd`。页面无脚本；CSP 只允许同源样式及图片，表单仍仅允许本站和已登记的精确回环来源。密码不回填，授权信息不进入资源请求的 Referer。

先完成管理平台构建，再升级服务端二进制。联合浏览器验收覆盖浅深主题、375 像素窄屏、错误密码重试、个人信息以及复用网页会话完成客户端授权。

## 普通用户网页与客户端授权

普通用户可独立访问 `/login`，无需客户端或授权参数。根路径 `/` 是用户平台首页，未登录时转到 `/login`，登录后返回首页。平台沿用管理端的左侧栏和右侧内容布局，导航暂时只有“用量管理”占位页，不显示模拟用量。左侧底部展示当前用户名和显示名称，账户菜单提供个人信息、修改密码、主题切换及退出登录；`/account` 可编辑昵称和头像，`/account/password` 可修改密码，用户名、账号类型和状态只读。刷新和直接访问各页面均重新核验网页会话；管理入口仍为 `/admin`，不复用管理 Cookie。

桌面端打开的 `/authorize?authorization=…` 在已有网页会话时只显示当前账号和设备，点击“授权客户端”即可完成授权，无需重复输入密码。未登录时验证密码后同时建立网页会话并批准本次客户端授权。`/login` 不再解析桌面授权参数，旧授权链接需在客户端重新发起。

本次平台布局和路由拆分不新增数据库迁移，复用已存在的 `0063` 网页会话能力。构建管理资源后更新包含 `assets/user-platform.css` 的 `tomd`；反向代理须将 `/`、`/login`、`/account`、`/authorize`、`/api/v2/web/auth/` 和 `/admin/assets/` 转发到同一服务。客户端按认证接口返回的地址打开授权，无需新增客户端配置。回滚本次页面调整可恢复支持同一迁移版本的上一版 `tomd`，已建立的会话及账户保留，未完成的授权需重新发起。页面按请求渲染有界身份资料，不新增后台轮询或用量查询。

网页使用独立 `web` 作用域和 `__Host-tombot-user` Cookie，设置 Secure、HttpOnly、SameSite=Lax 和根路径；Lax 支持桌面端打开顶层网页时携带登录状态。绝对有效期沿用 `identity.session_lifetime`，没有续期材料和自动重发。网页和桌面设备均计入既有设备上限。网页凭据不能用于桌面业务 API 或管理 API；网页退出仅撤销网页会话。禁用、改密、设备撤销和会话到期会在访问个人信息及批准授权时重新验证。

登录表单通过 HttpOnly 随机 Cookie 与 HMAC 绑定浏览器；批准与退出表单绑定当前网页会话，批准另绑定授权编号和状态。所有表单写入验证精确同源 Origin 和 Fetch Metadata；跨会话、跨操作与重复字段拒绝。批准授权在事务内再次锁定当前用户、会话及设备，防止撤销竞争。一次性授权码继续通过 PKCE 交换为独立桌面会话。

升级新增迁移 `0063_user_web_sessions.sql`，仅扩展用户会话作用域约束，不修改历史迁移或现有账号。替换约束需要短暂独占锁并扫描会话表，使用既有迁移超时与事务整体提交；大库应在维护窗口升级。先备份数据库，构建管理资源并升级 `tomd`，再更新客户端以启用新版回调页。回滚时停服务、恢复升级前数据库和对应二进制；不要删迁移记录或直接降级约束。旧客户端应同步更新，避免继续使用旧回调页。

## 用户资料、密码与主题

`POST /api/v2/web/auth/profile` 接收 multipart 表单 `csrf`，以及至少一项变更：`display_name` 或 `avatar`。成功返回 HTTP 200 和 JSON `{display_name}`，失败返回结构化 JSON 错误，不再重定向页面。未提供的字段保留数据库当前值，独立保存头像不会以旧页面中的昵称覆盖当前值。昵称经 NFC 规范化和去首尾空白，限 1–120 个字符并拒绝控制字符。图片只支持 PNG/JPEG，最多 2 MiB、512×512 像素，服务端先校验尺寸再解码并转成 PNG，剥离元数据和尾随内容。一次请求中的修改在同一事务保存，头像校验失败不改昵称。`GET /api/v2/web/auth/avatar` 只读取当前网页会话用户，未设置头像时跳转默认图片，响应禁止缓存。每次读取均重新鉴权，不接受指定其他用户的标识。

`POST /api/v2/web/auth/password` 接收当前密码、新密码与确认密码。复用身份服务的最少 12 字符、最多 1024 字节限制、当前密码校验、尝试限流与原子撤销机制；成功清除网页 Cookie 并返回登录页，全部网页和客户端会话立即失效。失败不回填密码。两项写入均检查同源 Origin、唯一字段以及绑定当前会话和操作的 CSRF，不自动重试。

`user-platform.js` 负责主题与菜单交互，不读取身份或凭据。个人信息页加载独立的 `user-profile.js` 和 `avatar-crop.js`：点击原头像选择不超过 8 MiB、宽高不超过 4096 像素的 PNG/JPEG 原图，浏览器内拖动或缩放裁剪，点击“确认更换”生成 512×512 PNG 并直接上传，成功后同步显示资料区与侧栏头像；页面没有统一保存按钮。请求中禁止重复提交和取消，失败保留当前裁剪供重试。取消不会替换已保存的头像，原图解码前检查尺寸，取消和离开页面时释放位图。昵称旁的铅笔按钮切换为原位输入框，Enter 或焦点离开编辑区时保存，Escape 或取消按钮恢复原值；成功后展示服务端返回的规范昵称并更新侧栏。`profile-save.js` 按字段发出同源请求，设置 15 秒时限，不自动重试，网络中断或异常响应明确提示结果未确认。四份脚本与模板、JSON 接口须随同一个 `tomd` 发布，CSP 只新增同源连接许可；本次不新增迁移，回滚须整体恢复支持同一迁移版本的应用与资源。主题独立保存在 `tombot-user-theme`，支持跟随系统、浅色、深色；系统变化即时更新，浏览器拒绝存储时明确提示。平台 CSP 允许同源脚本，登录页仍不执行脚本。菜单支持 Escape 和外部点击关闭。

部署前停单并排空旧实例、备份数据库；构建管理端资源并发布包含资源的 `tomd`，启动时自动执行新增迁移 `0065_user_profile_avatars.sql`。迁移创建空的头像表及身份角色权限，无数据回填，不扫描用户表，只有短暂元数据锁，失败由迁移事务整体回滚；图片存储上限为每用户 2 MiB。代理须转发 `/account/password` 和上述接口。数据库更新沿用用户→设备→会话的锁顺序，串行化资料更新与改密、撤销；局部更新不写入未修改字段；同一字段的多个保存按事务提交顺序生效，响应在事务提交后返回规范昵称。审计只记录用户、会话、操作和请求编号。数据库版本检查禁止旧程序连接已升级数据库；迁移提交后优先发布前向修复。如必须降级，停服务并同时恢复升级前一致备份和对应二进制，升级后的资料变更需先另行备份。不删除迁移记录、不改写历史脚本；需要移除头像存储或权限时另增更高版本迁移。
