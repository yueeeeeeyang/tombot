# Tom

Tom（汤姆猫，取自 Tom the cat）是单用户持久化云电脑与 Bot 团队客户端。服务端为无 CGO 的 Go 二进制，客户端使用同一套 Flutter 代码。

本次交付覆盖 M1–M8，客户端聚焦 macOS 与 Android。逐项验收及外部环境边界见[实施进度](docs/progress.md)。可运行链路包括依赖引导、初始化与设备授权、模型供应商配置、Bot 管理、单聊流式执行、文件工作区与六项文件工具、Shell 执行、持久终端、审批决策、可选独立模型审查，以及带模型审批、实时画面和用户接管的持久浏览器。Flutter 电脑分区已整合浏览器、终端与文件；原生浏览器下载已接入工作区，截图可保存到本机；群组创建、平等成员并行回复、提及隔离、群发言工具、Bot 私信与任务委派已接入。

系统链接支持直接打开单聊、群组、Bot 私信，或扫码预填服务器地址。各平台的协议注册、移动关联域名构建与复验步骤见[系统链接与部署](docs/deep-links.md)。

## 构建与启动

私有记忆已接入 Markdown 文件、双 FTS 检索、模型工具与审批、运行时索引，以及客户端的搜索和编辑。格式、接口、容量、故障恢复和回滚约定见 [私有记忆](docs/memory.md)。

例程支持 Bot／群组目标、时区 cron、配置审批、错过补跑、重叠跳过或排队、独立或固定会话和运行历史。客户端关闭后继续由服务端调度，详见 [例程调度与恢复](docs/routines.md)。升级需执行新增迁移 0012，审批与会话索引的锁影响、接口变化和回滚要求已在文档中说明。

客户端支持独立密钥管理、按 Bot／模型／UTC 日期查看用量，以及月度预算和阈值提醒。超限可拒绝新任务或仅告警，已接受任务继续结算。新增迁移 0013 的接口、费用口径与升级回滚见 [密钥、用量与月度预算](docs/secrets-usage.md)。

工作台在打开或切回时同步待审批事项，可在设备页开启原生审批与任务完成提醒。权限、隐私、去重和迁移 0015、0016 见[工作台本地通知](docs/notifications.md)。

Bot 可检索自己参与的会话、读取公开转录，并通过待办向用户提问。支持选项、自由回答和群组问题排队；人工等待释放执行名额，回答后继续。权限、问题接口、迁移 0014 和升级回滚见 [会话检索与用户提问](docs/conversation-tools.md)。

构建环境使用 Go 1.26.5+、Flutter 3.44.8 / Dart 3.12.2+。macOS 客户端最低系统版本为 12，iOS 为 15。Xcode 27 系列的当前工具链将新构建的 iOS 应用最低目标限定为 15。安装到设备前需用自己的开发团队签名；回退可重新分发此前已签名且支持目标系统的客户端。

```sh
make build
./bin/tomd
```

默认监听 `:8787`，数据和工作区位于二进制旁的 `data/`、`workspace/`。Linux 首次启动会安装系统运行库与中文字体，需要 root 或免密 sudo 权限。所有阻塞检查完成后才允许初始化与登录；健康页为 `/health`，引导进度为 `/api/v1/bootstrap/status`。

准备托管浏览器时使用仓库自带的官方离线 zip，不从网络下载。四个平台的 Chrome for Testing 157.0.8103.38 包放在 `server/browser/`，用 Git LFS 保存（每个约 190–200MB，超过普通 Git 的单文件上限）：

| 平台 | 文件 |
| --- | --- |
| linux/amd64 | `server/browser/chrome-linux64.zip` |
| linux/arm64 | `server/browser/chrome-linux-arm64.zip` |
| darwin/amd64 | `server/browser/chrome-mac-x64.zip` |
| darwin/arm64 | `server/browser/chrome-mac-arm64.zip` |

使用这些包必须先安装 Git LFS。没安装时 `git lfs` 不是 git 子命令。macOS 执行 `brew install git-lfs`；Debian/Ubuntu 执行 `sudo apt-get install git-lfs`；Fedora 执行 `sudo dnf install git-lfs`；也可以按 [Git LFS](https://git-lfs.com) 的说明安装。装好后在仓库根目录执行 `git lfs install`，再执行 `git lfs pull`。克隆后如果这些文件只有几行指针文本，引导会读取仓库里已有的 Git LFS 对象，不会把指针当成 zip 做摘要校验，也不会因此去浏览器分发地址下载。本地还没有对象、或系统没有 `git-lfs` 时，引导会先说明需要安装，再给出上述步骤。在 `server/` 下执行 `./bin/tomd` 时，引导会找到上一级 `server/browser/` 里的当前平台包；`TOM_DATA_DIR` 设为 `server/data` 时，这个目录正好是数据目录的同级 `browser/`。引导会复制、核对 SHA-256 并解压，不会跳过安装。把服务装到仓库以外时，从 `server/browser/` 复制当前平台的包到数据目录同级的 `browser/`，不必再访问官方分发地址。`TOM_BROWSER_ARCHIVE` 只用于改路径。摘要不匹配或文件缺失时，引导失败并写出应放置的路径。

引导失败时，在连接页选择“重新体检与修复”。已登录设备也可从“已授权设备 → 服务器环境与修复”查看进度。“重置引导记录”会清除环境检测结果并重新执行全部检查，保留业务数据。环境修复使用 `POST /api/v1/bootstrap/repair`，重置使用 `POST /api/v1/bootstrap/reset`，二者在后台执行。接受后返回 202，同时发起的维护返回 409。首次初始化前需提供初始化码，之后需提供有效设备授权。`GET /api/v1/bootstrap/status` 返回的 `cursor` 可直接用于订阅 `/api/v1/bootstrap/events?after=…`。引导检查期间，新业务请求返回 503，例程调度在每轮领取前等待就绪。已经接受的任务继续执行，环境维护宜安排在活动任务结束后。

在客户端填写服务器地址、一次性初始化码和管理员密码。初始化请求体只接受 `password`，初始化码通过 `X-Tom-Setup-Code` 请求头传递。请仅在本机终端查看初始化码，不将控制台输出上传到公共日志。生产环境可通过 HTTPS 反向代理或配置证书后直连；客户端仅对环回地址允许 HTTP。

```sh
cd client
flutter pub get
flutter run -d macos
```

在 `client/` 下运行 `flutter build macos --release`，即可打开 `build/macos/Build/Products/Release/tom.app`。同一台 Mac 上的服务可直接填写 `http://127.0.0.1:8787`。

Android 本机联调使用以下命令。连接一台已启用 USB 调试的设备或启动一台模拟器后，端口转发让客户端以同一环回地址访问开发机服务。连接已部署的实例时，直接填写其 HTTPS 地址即可。

```sh
cd client
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb reverse tcp:8787 tcp:8787
```

在 Android 上直接试用可选择体积较小的优化包。在 `client/` 运行 `flutter build apk --release`，再用 `adb install -r build/app/outputs/flutter-apk/app-release.apk` 安装。当前构建使用本机调试签名，最低 API 24，包含 ARM64、ARMv7 与 x86_64。运行过集成测试后应使用这条完整构建命令，让 Flutter 按发布模式重新生成原生插件清单。对外分发时需配置自己的发布签名。

连接就绪后，客户端从原生应用包读取发布版本，与 `GET /api/v1/auth/status` 新增的 `server_version` 比较主、次、补丁版本。两端不一致、服务端缺少版本或本机读取失败时会显示可关闭的提示。开发后缀和构建编号不影响这一检查。升级后可直接重连；需要回滚时，恢复配套版本的服务端和客户端。

客户端设备授权仅保存在系统安全存储。macOS 使用普通系统钥匙串，不启用跨应用钥匙串共享，因此本地构建不需要共享组的开发签名。iOS 发布仍需配置自己的签名团队。

在“已授权设备 → 审计记录”查看初始化、设备登录、撤销以及业务操作。可按页查看详情，也可导出脱敏后的全部记录。接口、保存位置与初始化故障恢复见[鉴权与审计](docs/audit.md)。

登录后进入“设置 → 模型”，添加 DeepSeek 提供商并填写 API 密钥，保存时自动验证并获取支持的模型。首次配置会为默认助手 Tom 选择默认模型，也可继续创建 Bot。提供商同步、应用运行限额和部署说明见[模型接入](docs/provider-connect.md)。价格可留空，此时按零计费并标注估算；实际费用仍以供应商账单为准。单聊支持流式文本、Markdown、取消、断线续传与历史分页。每个 Bot 的执行互斥，全局超过并发上限后排队；服务重启会将未完成运行标记中断，不重放动作。

点击侧栏搜索按钮或按 `⌘K` / `Ctrl+K`，可搜索 Bot、群组与例程会话、历史聊天正文及设置入口。消息命中会打开相邻上下文，关闭后保留聊天草稿。范围、分页和部署说明见[全局搜索](docs/search.md)。

单聊顶部悬浮显示 Bot 头像和名称，点击打开详情；执行期间可从输入框停止，群组按成员显示等待回答或审批。展开工具卡片可以查看调用参数、结果与耗时，重新进入会话也能找到正在等待的调用。状态字段与本地真实模型复验步骤见[会话执行状态](docs/conversation-activity.md)。

会话内可按 Esc 或点击停止按钮。界面立即显示“正在停止…”，服务确认回合结束后恢复发送。中文输入法正在组词时，Esc 留给输入法处理。全局事件流还会推送浏览器、终端、记忆和例程的更新摘要，让其他已登录设备按需刷新对应面板。

文件工具需要在 Bot 设置中勾选。默认标准审批下，读取和 `out/` 内普通写入可直接执行，其他写入进入“审批待办”；严格模式会询问所有操作。待办可批准或拒绝，并选择仅本次、当前 Bot 或全部 Bot 的相同操作与目标。规则命中优先于严格度；取消执行或审批过期不会执行待批动作。调用、决策和写前旧内容摘要均持久记录，完整工具输出保存于该 Bot 的 `.tom/tmp/`。

`computer_shell` 同样需要加入 Bot 工具白名单。普通命令在标准模式下需要审批；密钥环境注入提升为高风险；命中系统修改、格式化磁盘、提权等危险模式时默认拒绝，只有显式策略规则允许才执行。审批展示命令、工作目录及变量名，规则记忆绑定命令、归一化工作目录、时限和密钥引用的共同摘要。Shell 是当前服务用户权限下的真实主机命令，路径校验只限制起始工作目录，不能替代操作系统隔离。部署应使用专用主机或容器。

Shell 默认时限 120 秒，可指定 1–600 秒；取消先终止整个进程组，5 秒后仍未退出则强制回收。仅继承 `PATH/LANG/LC_ALL/TERM`，主目录和临时目录指向 Bot 工作区。密钥通过 `env_secrets: [{name, secret_id}]` 注入，禁止覆盖进程控制环境变量，注入值在输出分片合并后先脱敏再保存。结果保留退出码和有界尾部；超过 32 KiB 的结果保存到 `.tom/tmp/out-<run>-<step>-<call>.log`。达到 16 MiB 输出上限会停止命令、保存已接收部分并返回 `TOOL_OUTPUT_LIMIT`；二进制日志保留原始字节并明确标注，文本读取接口会拒绝二进制文件。停用 Shell 前先取消活跃回合，再从白名单移除。

## Bot 工作台

桌面端首次启动且没有窗口记录时，默认窗口为 1280×800 逻辑像素；已有用户继续恢复上次保存的尺寸与位置，并按当前显示器的可用区域收敛。界面主文字为 14 逻辑像素，辅助文字为 13，标题保留字号与字重层级。

桌面和平板侧栏默认宽度为 300，展开范围为 240–400 逻辑像素，可收缩到 100（红绿灯左右各留 20 像素），仅通过拖动右边缘调整。以 170 为收缩阈值：低于阈值吸附到 100，否则至少展开到 240；跨阈值时使用 220 毫秒宽度动画，展开区拖动直接跟手，减少动态模式下立即切换。松手后才保存，取消拖动不写入。侧栏与右侧内容使用不同背景，分割线贯穿窗口顶部。搜索和新增按钮带圆形背景；非全屏 macOS 将二者放在左侧局部工具条，圆形顶部距窗口 13 像素，与红绿灯顶部齐平。右侧 Bot 头像名称浮层从顶部 13 像素开始，不保留全宽标题条；收缩侧栏时搜索按钮从侧栏边界外 16 像素开始，右侧标题为局部工具条预留 112 像素横向空间。其他平台和全屏时保留原有页面布局。新增弹窗可选择“新增 Bot”或“新增群组”；底部同一行显示不含协议的主机与端口、带圆形背景的设置按钮。地址保留域名，IPv6 使用方括号包围主机部分。会话行使用圆头像、名称与最新消息预览，预览随实时摘要更新；收缩后以头像和悬停提示定位会话。

服务端内置默认助手 Tom；没有已保存会话或外部会话链接时，客户端优先进入它的对话。Tom 的常规直接会话在侧栏与搜索结果中置顶，例程会话保持原有状态排序，搜索仍先匹配标题和预览。未上传头像时使用随客户端分发的默认图片，上传头像优先；身份按稳定 Bot 标识识别，改名后保留，同名普通 Bot 不受影响。Tom 可以像其他 Bot 一样编辑、归档或删除，服务重启不会重新创建。没有模型时可从对话进入设置；创建 Tom 时绑定已有默认模型，后续设置默认模型时只为尚未配置模型的 Tom 自动绑定，不覆盖用户已选模型。

新建 Bot 默认自动分配身份色，优先选择与现有同事区分较大的色相，也可以在表单手动选择。会话列表、Bot 详情和消息作者显示已上传的头像。要暂停使用一位 Bot，在会话菜单或 Bot 设置中选择“归档”。从“设置 → 已归档 Bot”可以阅读历史或恢复原会话。客户端按服务器地址在本机保存上次会话、详情分区、展开状态和宽度。宽屏右栏默认宽 400，平板使用 360 宽抽屉，手机使用独立详情页。

桌面侧栏不再放置例程和待办入口。例程从 Bot 的“详情 → 管理例程”进入；待办可通过聊天输入框的 `/approvals`、例程页的“审批待办”或手机底部“待办”打开。手机底部的待办数字合计排队或执行中的回合、可处理的审批以及未读产物。打开待办可以跳回对应会话；阅读会话后，已读产物从数字中扣除。群聊在桌面右栏、平板抽屉或手机独立页编辑同一组设置。聊天输入框还支持 `/attach` 和 `/stop`；在 macOS 也可以把文件拖入输入区，确认发送前会以附件显示。

## 文件工作区

在 Bot 会话的“电脑 → 文件”浏览自己的目录与共享目录；主侧栏不再提供资源快捷入口，终端与浏览器从 Bot 的电脑进入。目录按修改时间排序；文件支持 Markdown、代码、图片预览，以及文本编辑和下载。桌面可从文件进入电脑终端并打开所在目录，收起宽屏详情栏会保留预览与未保存草稿。文本保存使用读取时的 SHA-256 校验；遇到其他操作修改时返回冲突并保留本地草稿。文件工具、用户编辑和上传的持久事件会触发目录刷新，直接在 Shell 中修改的任意文件仍需手动刷新。

上传使用系统选择器，单个文件最多 32 MiB，流式写入 `inbox/<唯一标识>/<原文件名>`。完整接收并校验 multipart 后才发布，异常时清理临时文件。上传与编辑期间删除对应 Bot 会返回冲突。文本预览与编辑最多 1 MiB。图片预览最多 16 MiB、1600 万像素，解码时保持原比例，最长边限 2048 像素。桌面下载先选择父目录，再分块写入独立的 `tom-download-*/<原文件名>`，完成后显示完整路径。移动端通过系统保存插件交付完整字节，单次上限 64 MiB。服务端支持流式传输、HEAD 和 Range。

接口均需设备鉴权：`GET /api/v1/fs/file?bot_id=&scope=bot|shared&path=` 返回原始 `{path,content,bytes,sha256}`，不添加行号；`PUT /api/v1/fs/file` 接受 `{bot_id,scope,path,content,expected_sha256}`。提供摘要时要求目标已存在且未被修改，否则返回 409；缺省摘要表示明确的无条件写入。`POST /api/v1/fs/upload?bot_id=` 上传到指定 Bot 的收件目录，`POST /api/v1/fs/upload?scope=shared` 上传到共享收件目录；两者都只接收一个名为 `file` 的 multipart 文件；`GET/HEAD /api/v1/fs/download` 使用与读取相同的路径参数。传输限时 2 分钟，客户端另设 30 秒无数据超时；写请求不会自动重试。若提示文件已保存但完成记录失败，应先刷新确认，避免重复上传。

聊天输入框悬浮在消息流中，两端与消息气泡对齐。点击框内左侧加号选择附件，附件显示在边框内顶部；可只发文件，也可同时输入问题。单聊使用 Bot 收件目录，群聊和 Bot 私信使用共享收件目录。短文本可以直接进入模型上下文，启用视觉能力的模型可以读取 PNG、JPEG 和浏览器工具的截图。发送失败会保留草稿与已上传附件。容量、历史引用与降级方式见[聊天附件与视觉输入](docs/attachments.md)。

浏览器故障时，工作台会隐藏浏览器入口，电脑面板仍可使用终端。若自动重试已耗尽，从“已授权设备 → 服务器环境与修复”点击“恢复浏览器”，恢复成功后即可重新打开页面。详见[浏览器状态与恢复](docs/browser.md)。

## 工具动作审查

在“模型 → 审查设置”启用并选择审查模型，默认关闭。自动选择会优先使用已启用、`model_key` 与执行模型不同的模型；没有不同模型可用或手动选择相同模型键时，审批明确标注“由执行模型自查”，使用弱化提示。不同供应商配置中相同的模型键也视为自查；无法根据模型别名保证底层权重不同。显式配置的审查模型不可删除，需先在设置中更换或清空。

工具白名单、参数与路径校验、显式允许／拒绝规则优先。其余动作在严格度判断前审查，使低风险动作也能被提升并触发审批。审查接收当前 Run 的用户意图、工具参数和目标，不提供工具能力；不会降低静态风险，意图不一致提升为高风险。调用限时 30 秒，输入 JSON 最多 64 KiB，输出最多 8 KiB／1024 token，并按模型容量保守检查上下文；不会截断参数后宣称已完整审查。调用失败、截断、无效 JSON 或模型不可用会将风险提升一档并要求人工确认，包括宽松模式。

审查与执行、摘要使用同一费用账本，并计入 Run／Turn 总费用。上游中断或取消也保存已确认用量；审查结束和审批后执行前重新检查预算。预算限制后续调用和副作用，不能撤销已经发生的上游费用，单次调用或同时进行的摘要可能使结算总额超过预算。费用或审计持久化失败会停止动作。审查审计只保存运行、模型、工具调用标识、风险与结果状态，不保存参数或审查正文；审批保存面向用户的审查说明。

配置接口为已鉴权的 `GET/PATCH /api/v1/settings`，形如 `{"reviewer":{"enabled":true,"model_id":null}}`。`model_id: null` 表示自动选择，PATCH 可只提供一个子字段；未知字段、空补丁及空启用状态被拒绝。设置按每次新工具调用读取，已经创建的审批保留当时的审查结果。

## 持久终端

终端入口位于 Bot 会话的“电脑 → 终端”，也可从同一电脑内的文件页打开所在目录。桌面支持输入、调整尺寸、接管和交还 Bot；手机只读。离开面板不结束进程，关闭会话会终止其交互式 Shell 和同一会话中的前后台作业。输入不会自动重发：断线时若仍有输入未确认，客户端暂停键盘，检查输出后可恢复。主动使用 `setsid` 脱离会话的程序不在回收范围内，不应用终端启动此类守护进程。

`terminal_session` 提供 `list/open/write/read/resize/close`；`list` 返回当前 Bot 最近 50 条会话，便于发现用户分配给它的终端。模型输入为高风险操作，宽松模式也会询问，危险模式仍默认拒绝。审批绑定当前输入版本；用户接管、交还或其他输入都会使旧审批失效。用户可创建关联 Bot 的终端并交还控制，模型不能访问其他 Bot 的会话。Bot 最近使用它的 Run 结束后保留 30 分钟，每分钟扫描清理；用户接管后改为手动关闭。服务重启只保留中断标记和元数据，不恢复进程或输出。

终端总上限 32 个、每归属上限 8 个、每会话输出环形缓存 1 MiB、单次输入 16 KiB、全局 WebSocket 连接上限 128。模型增量读取游标保存于数据库，客户端游标独立；缓存缺口明确提示并重新显示保留内容。输入输出不保存为终端日志，审计只记录身份、操作类型、字节数和尺寸；模型主动读取的输出仍进入工具结果及聊天记录。不要在模型输入中放置凭据。终端不继承服务端机密环境变量，不自动加载 Shell 启动文件，不写命令历史文件。

终端接口均要求设备凭据请求头：`GET/POST /api/v1/terminals`、`GET/DELETE /api/v1/terminals/{id}`、`POST /api/v1/terminals/{id}/control {controller: "user"|"bot"}`。同一 GET 地址可升级为 WebSocket，`after` 是输出字节游标，`readonly=1` 禁止输入和尺寸变更；不支持查询参数凭据。服务端定时及每次输入前复查授权。协议在设计中的输入、尺寸、输出、退出帧上增加 `ready/state/ack/error`，输入可带 `seq`，输出带 `cursor/reset`；反向代理需支持 WebSocket 升级和长连接。

群组协作使用方式、接口、费用边界和迁移 0010 的升级／回滚方案见 [群组协作与恢复约定](docs/groups.md)。

Bot 私信、委派、旁观／介入、调用链护栏、父子费用和迁移 0011 的升级／回滚方案见 [Bot 私信与任务委派](docs/messaging.md)。

## 迁移与回滚

侧栏调整仅需更新客户端，不改变服务接口或数据库。新版宽度按服务器保存到 `workbench.sidebar.v3.*`，只接受 100 或 240–400；旧 `workbench.sidebar.v1.*`、`workbench.sidebar.v2.*` 不读取、不覆盖。本次宽度规则升级将侧栏偏好重置一次为默认 300，包括此前收缩或自定义展开的宽度；会话与详情分区仍使用原 `workbench.v1.*`，不受影响。之后恢复合法 v3 宽度。拖动和动画期间只做本地预览，每次完成调整才串行写入一次，失败在工作台提示重试。回滚旧客户端时仍读取其原版本侧栏记录，v3 选择不回写旧版。尺寸、视觉基线与回归命令见[工作台视觉验收](docs/client-visual.md)。

回退到旧 v2 客户端时，保留的旧 v2 记录决定宽度；本次 v3 的收缩 100 或展开宽度不会影响旧版。若旧记录本身超出该客户端的上限，按旧版提示重置布局。

工作台布局与引导维护共用原有数据库版本 0014，直接部署匹配的服务和客户端。重置操作在一个短写事务内清除能力记录、登记审计并发布新一轮检测事件，之后逐步写入各项结果。回滚时先等待维护结束，再恢复此前支持 0014 的程序和客户端。新安装的系统依赖由主机包管理器管理。如需恢复维护前完整的运行环境，使用维护前主机快照。

数据库迁移由二进制内嵌，只新增版本；启动验证历史脚本摘要，并拒绝旧程序打开更高版本数据库。迁移在单个 SQLite 写事务中执行，初始数据库为空，首次建立表与 FTS 索引的锁定时间取决于消息数量。`0002` 会索引已有消息，大数据库升级前应停机备份并预留维护窗口。`0004`–`0006` 增加配置引用约束、估算价格标记和活跃回合唯一索引；升级需扫描相关配置与执行表，在同一写事务内建立索引。大库应在维护窗口升级，若原有活跃回合违反唯一约束，迁移会明确失败。数据目录持有进程排他锁，防止两个实例同时修改认证和引导状态。

`0017_default_tom.sql` 仅写入一次性种子；认证提交后，服务在同一写事务内依次准备工作目录、创建默认助手 `tom` 和常规会话 `tom-direct`，再消费种子。失败明确返回并保留种子，后续启动或登录可重试；已有同名 Bot 和工作区文件保留。完成后归档或删除不会被启动过程撤销。升级前停机备份数据库、认证文件与工作区；回滚需恢复升级前成套快照及匹配版本，不能只替换旧二进制。事务、恢复和模型绑定约定见[默认助手 Tom](docs/default-assistant.md)。

`0007_terminal_sessions.sql` 新建终端元数据表及索引，不重写已有业务表，无历史数据回填；执行时间主要是 SQLite 模式写锁，升级仍应停机备份。服务启动将旧终端标记为中断，不重放命令。旧二进制不能打开版本 7 数据库，回滚必须同时恢复升级前数据与二进制。文件工具、Shell 与审批继续使用既有表；规则只匹配归一化的精确目标，Bot 规则先于全局规则。

本次审查功能沿用既有 `settings`、`approvals`、`usage_events` 和审计表，无新增结构迁移或数据回填，也未修改历史迁移。升级服务与客户端后默认关闭审查，可在设置页启用；启用后每次未命中显式规则的工具调用增加一次模型调用，调用上限为 30 秒。回滚时先停止活动任务并停机，恢复升级前的数据／工作区快照与匹配二进制、客户端；旧程序不会执行新审查设置，不能在启用审查的实例上仅替换成旧二进制。

文件传输功能无数据库迁移。`GET /fs/file` 从带行号的窗口结果改为完整原文，旧 `start_line/limit` 参数直接拒绝，服务端和客户端必须同步升级；模型 `file_read` 的窗口协议保持独立。反向代理需允许至少 32 MiB 加 64 KiB 的上传体，并为传输保留 2 分钟时限。macOS 客户端增加用户所选文件的读写沙箱授权，用于系统保存对话框。回滚前停止传输并备份工作区，恢复匹配的旧服务与客户端；已经上传的文件是普通工作区文件，无自动删除或反向迁移。

浏览器服务新增 `0008_browser_tabs.sql`，创建空标签表、归属索引和 Bot 删除保护外键，无既有业务数据回填；短暂占用 SQLite 写锁，执行时长主要取决于存储同步。升级前停止活动任务、正常关闭服务并备份数据目录和工作区。新版本在引导完成后启动单一 Chromium，profile 位于数据目录的 `browser-profile/`，需一并备份。回滚必须恢复版本 8 迁移之前的完整快照及匹配的旧二进制，旧程序会拒绝打开版本 8 数据库；不要删除表或篡改迁移账本。容量、锁顺序、操作超时和恢复约定详见浏览器文档。

浏览器审批新增 `0009_browser_navigation_permissions.sql`，建立标签来源许可表并增加被阻断导航字段；无历史许可回填，标签检查受 32 条容量上限约束。已有 Bot 标签升级后需通过明确审批或用户交接获得来源许可。回退此增量须停机恢复迁移 0009 之前的完整快照、profile 与匹配二进制，不能只替换二进制或删表。浏览器审批使用新的动作分类和单次决策约束，服务与客户端应同步升级。

升级前停止服务并执行 `tomd backup -o <归档路径>`。使用 `tomd restore --input <归档路径> --target <新目录>` 一次恢复数据与工作区。文件主密钥随归档保存，环境主密钥需在还原时重新注入原值。完整操作、容量和回滚方案，以及非 root systemd 与 Caddy 部署示例见[备份、还原与 Linux 部署](docs/backup.md)。

浏览器画面增量没有新增迁移，继续使用数据库版本 9。新增 WebSocket、用户坐标／焦点输入和截图来源响应头，服务端与客户端须同步升级；反向代理须支持 WebSocket 与约 11 MiB 的最大画面消息。固定视口 1280×720，默认最多 5 FPS、全局最多 8 路连接，实际吞吐受浏览器与网络资源限制。回滚时停止活动操作、备份数据并恢复匹配的旧服务与客户端，数据库无需反向修改；详情见浏览器文档。

原生下载复用数据库版本 9，无新增迁移。仅显式下载动作临时开启 Chromium 下载接收，完成或失败后关闭；标签和页面版本、来源拒绝规则、超限取消及原子文件发布共同约束执行。下载期间浏览器命令串行，客户端会暂停对旧画面的输入；具体限制、临时文件恢复和回滚办法见 [浏览器接口与恢复约定](docs/browser.md)。
