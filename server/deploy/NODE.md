# 节点离线镜像安装

完整解压对应架构的安装包到受保护目录（例如 `/root/tombot/`），在该目录执行：

```sh
sudo ./tomnode install
```

粘贴管理平台“电脑节点 → 生成接入凭据”中新生成的接入码，再确认服务端可访问的节点地址。默认无需准备 `node-install.json`，无需填写服务地址、证书指纹、镜像摘要或软件包版本。

安装包包含 `tomnode`、`computer-image.tar`、`node-release.json`、可选参数示例、安装说明及 `SHA256SUMS`。电脑镜像离线随包交付，安装器校验后自动导入 Docker；**Docker 与宿主依赖仍从官方软件源安装，需要联网**。节点还需访问服务端。镜像不依赖远程仓库，不在离线导入失败时回退到联网拉取。

适用 Ubuntu 24.04、systemd、cgroup v2；必须使用与宿主架构一致的包。当前提供的宿主软件清单为 amd64，其他架构须提供对应受测清单后发布。文件和整个父目录链须由 root 或此次 sudo 调用者持有，不得组写、其他用户写入、含符号链接或硬链接。不要从公共 `/tmp/` 目录直接安装。

## 自动填写与可选参数

接入码封装服务端 HTTPS 来源、固定证书指纹与一次性授权。安装器先核对证书，再通过已鉴权接口取得 API 客户端证书指纹和验收资源预算，不使用首次连接返回的证书建立信任。服务端 `admin_origin` 必须是节点实际可达的 HTTPS 来源，不能配置为远程节点无法访问的本机回环地址。

节点名称默认取主机名加唯一后缀；容量按 CPU、内存、可用磁盘及独立验收预算计算，最多 7 台业务电脑。容量只是安装建议，实际就绪状态仍由服务端能力验收决定。单网卡自动选择监听地址；多网卡或 NAT 场景由安装者确认本机监听地址及服务端可达地址。默认控制端口为 9443，请只向 API 来源放行。

需要覆盖时才生成可选参数：

```sh
./tomnode template > node-install.json
```

初始内容为 `{}`，仅支持以下四项；不需要全部填写：

| 字段 | 用途 |
| --- | --- |
| `node_name` | 自定义唯一节点名称 |
| `computer_capacity` | 降低建议容量，不得超过资源计算结果 |
| `listen` | 本机监听的 `IP:端口`，IPv6 使用方括号；通配地址需显式指定 |
| `node_url` | 服务端可访问的节点 HTTPS 来源；NAT 或端口映射时填写实际地址 |

显式使用参数文件：

```sh
sudo ./tomnode install /绝对路径/node-install.json
```

不传路径时不会自动读取当前目录的同名文件。参数文件拒绝未知字段、重复字段、空值、尾随对象及超过 16 KiB 的内容。接入码输入不回显；Ctrl+C、终端关闭或五分钟超时会取消。不要把接入码写入 JSON、命令行、环境变量或日志。

## 运行与接入

安装命令自动创建身份和证书、保存配置和归档、安装程序及 systemd 单元、设置开机启动，并等待控制服务启动和自动接入。多个节点分别使用独立接入码，管理平台无需手动登记。

```sh
sudo systemctl status tombot-node
sudo systemctl restart tombot-node
sudo journalctl -u tombot-node -f
```

| 位置 | 内容与权限 |
| --- | --- |
| `/usr/lib/tombot/tomnode` | 节点程序，root 0755 |
| `/etc/systemd/system/tombot-node.service` | 内置服务单元，root 0644 |
| `/etc/tombot/node/` | root 0700；内含三份运行配置、证书、私钥、`enrollment.token`、`computer-image.tar` 及安装记录，均为 root 0600 |

原始授权值由程序私有保存，完整接入码不落入安装配置。离线归档保留用于本机镜像丢失后的恢复，安装及重试会校验 SHA-256，导入后还会核对固定镜像摘要、平台和电脑入口约定。需为安装包、归档副本和 Docker 镜像存储预留空间。

服务执行 `tomnode start`，按配置检查、宿主软件准备、固定镜像准备、节点恢复、自动接入顺序运行。宿主安装与镜像准备各最多一小时，服务启动上限 140 分钟，安装器最多等待 141 分钟。取消安装等待不保证已启动的 systemd 作业停止，先查看状态再用原命令重试。高级诊断见 `tomnode help` 与 `tomnode check`。

`state: control_started` 只表示控制服务已启动。共享浏览器完整能力探针目前尚未接通，完整电脑就绪验收仍会阻止开户；真实 Ubuntu 首次安装、挂载配额及 cgroup 回收需实机验收。

## 重试、升级与回滚

安装锁串行保护首次安装，配置、身份和归档在私有目录写完、刷盘后原子发布。中途失败保留已发布身份；使用同一二进制和相同选项重试，复用本地安装快照，不再询问接入码或依赖原始发布清单、镜像归档。JSON 缩进与字段顺序不影响重试。快照、凭据、归档、证书、程序或单元被修改时明确失败，不覆盖或重新生成身份。

本次新增离线节点包格式 1，安装记录版本为 2，不修改数据库。旧完整安装参数和旧裸凭据不再作为首次安装输入；升级服务端和管理平台后重新生成接入码，使用配套离线包。运行中的既有节点继续使用原运行配置与服务；新版安装器不会接管旧安装记录。

安装器用于首次安装及原安装重试，不负责自动升级或证书续期。证书有效期一年，提前安排维护。维护升级前停单排空，备份程序、配置、证书、服务单元、用户磁盘及节点记录；停止服务后成套更新并检查，再由 systemd 启动。回滚恢复配套备份并重新加载 systemd，不通过删除身份或安装记录回退。已安装软件和镜像层不自动卸载。多节点接入的历史数据库迁移及回滚要求见[接入说明](../docs/node-registration.md#升级与回滚)。
