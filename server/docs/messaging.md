# Bot 私信与任务委派

## 使用方式

Bot 设置提供三项独立协作权限：接受 Bot 私信与委派、主动联系其他 Bot、接受群组邀请。默认接受私信与群邀请，默认不主动联系。主动联系还需将 `message_bot` 或 `delegate_task` 加入工具白名单，并通过当前规则、审查和审批。

工作台将 Bot 私信放在独立折叠区；出现新的未读消息时自动展开，双身份色区分参与者。打开后默认旁观，点击“介入对话”再选择一位成员发送消息。用户介入创建普通用户回合，只调用所选成员；目标必须属于该私信，且处于可执行状态。活动回合中不能另行发送，但可以停止当前回合。交接卡可以从原会话跳转到私信或委派会话。

## 工具契约

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `message_bot` | `bot_id`、`message`；可选 `reply_required`，默认 true；可选 `context_paths`、`deliver_to_user` | 会话 ID、Run ID、投递状态；等待回复时附带摘要与共享产物路径 |
| `delegate_task` | `bot_id`、`task`；可选 `context_paths` | 独立子会话、Run ID、摘要与经过存在性检查的共享产物路径 |

两项工具均为中风险，动作分别为 `message.bot` 和 `delegate.spawn`。审批绑定目标身份、模型选择、消息策略以及明确共享文件的内容摘要；等待期间这些内容发生变化，旧审批不能继续投递。目标还须配置模型，供应商须启用。拒绝、过期、取消和基础设施失败均有明确结果，不自动重放非幂等投递。

消息或任务正文上限为 32768 个 UTF-8 字节。共享上下文最多 8 个文件，正文合计最多 32768 字节；路径必须是规范的 `shared/` 普通文本文件，禁止私有目录、路径回退、重复路径和链接逃逸。文件内容在审批前读取，审批后重新校验，仅显式选择的内容随消息传递。

启用协作工具且具备主动联系权限时，模型上下文加入同事 ID、名字和职责，不加入同事的角色指令或记忆。目录最多 64 位、约 8 KiB；超出时明确提示截断，可以由用户提供目标 ID。接收方不自动取得发送方的单聊、思考或工具记录；复用私信的历史只保留公开文本。群转录、私信和委派不会自动写入长期记忆。

同一对 Bot 的普通私信复用一个 `kind=bot_dm`、`source=bot_message` 会话，方向互换也不会创建重复会话；每次委派创建新的 `source=delegation` 子会话。每次投递创建 `source=bot_message` 的 Turn，Run 的来源区分 `bot_message` 与 `delegation`，并记录父 Run、父工具调用和跳数。

委派接收方须用单个 JSON 对象结束任务，包含非空 `summary` 和 `artifacts` 路径数组；工具拒绝缺字段、额外字段、尾随内容或私有产物路径。普通私信可以直接回复文本。两者都会收集本次成功文件写入／编辑产生的共享路径；委派还支持显式列出 Shell 等工具生成的共享文件。返回前逐一检查文件存在且为普通文件，最多 32 项。格式或文件校验失败以工具错误回灌，不把不存在的产物当作成功交付；文件仍保留在工作区供用户查看。

## 并发、费用和恢复

- 最多四跳，每个 Run 最多创建 16 个子任务；不能联系当前调用链上已经出现的 Bot。运行时同时检测不同根任务之间的等待环，包含尚未等待的异步投递。
- 同一对 Bot 双向合计，五分钟内最多接受六次投递；第七次拒绝并在调用方会话保存限流交接提示。已接受但随后失败的投递也计入窗口。
- 同一普通私信只允许一个活动回合；并发第二次投递返回 `BOT_DM_BUSY`。独立委派也遵守全局模型并发上限与每 Bot 互斥。
- 同步等待让出全局模型执行槽，同时保留发送 Bot 的互斥锁；目标完成后调用方重新排队取得执行槽。只有一个槽时也能完成嵌套调用。
- `reply_required=false` 在投递完成后立即返回给调用模型。父 Run 最终完成前仍等待子任务及其后代结算，不产生父回合完成事件之后才增加的费用。异步目标失败会在调用方会话留下提示。
- 每个子任务的预算取所有祖先 Run／Turn 的最小剩余额度；后续模型调用、工具执行和审批恢复继续检查整个父链。实际费用在单一事务内增加到当前 Run 和所有祖先，以及各自去重后的 Turn；`usage_events` 只记录实际调用一次，不重复生成祖先费用事件。
- 预算为软上限：已发出的并发请求仍可能产生超额费用，照实结算；达到上限后不再发起新的调用或副作用。统计实际总支出应汇总 `usage_events`，不能将包含后代费用的父子 Run 总额直接相加。
- 子任务继承父执行的剩余墙钟时间，排队也包含在内；取消父回合会向下传播。子任务失败、取消或超时，同步调用返回 `BOT_NO_REPLY`；持久化失败向上传播，不能伪装为目标无回复。
- 重启沿用统一中断恢复，不自动重发已投递消息。父工具调用唯一索引阻止同一调用重复创建子执行。没有跨服务实例调度，数据目录仍由进程锁独占。

## HTTP 与事件

接口均需设备鉴权。会话列表支持 `GET /conversations?kind=bot_dm`，列表和快照附带双方公开成员资料、未读数与活动状态。普通用户可以查看完整私信；这是用户的工作室旁观权限，不代表其他 Bot 可以读取这些内容。

`POST /conversations/{id}/messages` 对私信增加可选 `recipient_bot_id`，省略时使用会话的 `bot_id`；显式指定时只能为双方之一。群组仍用 `mentions`，单聊和群组不接受私信收件人字段。归档或不可执行的目标明确拒绝，写入冲突不留下半条消息。

父会话保存 `handoff` 块，包含双方 ID、子会话／Run ID、交接理由和跳数；交接元数据不插入模型的工具调用／结果序列。新增 `handoff.created` 事件，消息及执行状态仍通过已有 `message.completed`、`run.status`、`turn.finished` 和 `conversation.updated` 同步。客户端重连以原子快照和事件游标恢复，不重发发送请求。

## 迁移、性能和回滚

新增 `0011_bot_messages.sql`，为 Run 增加父工具调用 ID、是否等待回复及两个索引；0001–0010 历史脚本未修改。既有 Run 的新增字段分别为空和 false，无父子费用历史回填。

迁移在 SQLite 写事务中执行，建立索引需要扫描 `runs` 并持有模式写锁，执行时间随记录数量和存储速度增长。大库应预留维护窗口。每次费用结算最多读取五级 Run 并更新五级 Run／去重 Turn；协作目录、子任务、产物、文件上下文和队列均有数量上限。私信成员资料随会话查询聚合，客户端不额外逐会话请求双方资料。

升级前停止活动执行并正常关闭服务，备份完整数据目录、浏览器 profile 与工作区，然后同步更新服务端和客户端。启动执行迁移后检查私信权限、模型和工具白名单。旧二进制会拒绝打开版本 11 数据库。

回滚须停止新服务，另外保全升级后的消息及文件，再恢复迁移 0011 前的完整快照和匹配的旧服务、客户端。不得修改迁移账本、删除新列或单独替换旧二进制；结构修复只能新增更高版本迁移。

## 验收范围

Go 竞态回归覆盖单槽嵌套、跨根任务等待环、四跳边界、祖先回环、私信复用、五分钟限流、父子费用、预算、取消、超时、目标失败、审批期间目标／文件变化、拒绝共享私有路径、无效委派结果和缺失产物。真实本地 HTTP 模型流覆盖委派 → 文件工具 → 结构化回复、独立子会话、异步投递、费用和 SSE 收尾。Flutter 覆盖三档宽度旁观／介入／停止、未读自动展开、交接跳转、失败草稿与消息策略保存。

这些证据使用可控模型上游和组件测试；外部商业模型账号、原生人工键鼠与完整视觉基线仍属后续验收。

版本 28 新增独立的 message_user 人类收件人通道，以及 message_bot 的 deliver_to_user 直接交付选项。目标执行、实时通知、幂等规则和配套升级要求见[自定义猫咪与直接交付](custom-cats-and-delivery.md)。
