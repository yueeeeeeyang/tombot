# 猫咪私信协作

本文描述 PostgreSQL v2 执行器的当前实现。私信就是委派工作的通道，只有 `send_bot_message` 一个发送动作；不会另建委派接口或要求特殊的最终回复格式。

## 目录与权限

每只猫咪的运行都有当前用户猫咪目录的第一页快照，包括标识、名称、简介、分类、工具权限、私信策略和状态。`list_bots` 提供实时查询、按标识查询、游标分页及所需工具筛选，每页最多 10 只。模型不会得到其他用户的猫咪、其他猫咪的系统提示词或独立长期记忆。目录快照固定后恢复不变，实时查询用于发送前重新判断。

所有猫咪内建这两个工具，不需加入电脑工具白名单；实际发送仍要求发送方 `can_initiate`、接收方 `accept_dm` 为真，且资源可用。桌面创建的猫咪默认开启这两项策略。接收方使用自己的模型、工具权限和审批规则，不继承发送方的权限。私信会话不提供长期记忆及任务计划修改工具，私信内容明确标记为同伴数据，不能冒充用户授权。

| 工具 | 参数 | 结果 |
| --- | --- | --- |
| `list_bots` | `after`、`bot_id`、`only_idle`、`required_tools` | `bots` 及 `next_after`；按标识查询时游标为空 |
| `send_bot_message` | `bot_id`、`message`、`required_tools` | 受理后的私信标识、接收方及异步回复说明；拒绝返回原因和候选 |

参数均须显式提供，空筛选使用空字符串或空数组。正文上限 8192 个 UTF-8 字节；不得自动附带私人聊天记录、长期记忆、凭据或系统提示词。发送方只提供完成当前工作所需的背景。候选是否符合实际工作由模型结合职责判断，服务端再次校验所需工具集合，不能为成功转交而放宽要求。

## 忙碌处理与回复

状态包括 `idle`、`busy`、`queued`、`waiting`、`unavailable`、`archived`。空闲要求没有任何聊天或后台任务正在排队、执行，也没有待返回的协作结果；不能仅根据是否持有运行租约判断。

发送与普通消息受理共享用户调度锁。即使目录刚才显示空闲，目标被其他任务占用后也会明确拒绝，不把请求排在忙碌猫咪后面。并发两个发送方选择同一空闲猫咪时，只能受理一个。拒绝会给出满足同一工具要求的空闲候选：当前猫咪选择其他合适同伴；没有合适同伴则使用自身能力完成，能力不足须说明实际限制。每次运行最多尝试三个候选，禁止轮询、等待空闲或创建重试计划。

受理后异步执行。例：用户在小黑的单聊中提问，小黑私信小黄，小黄完成后私信回复小黑，最后小黑汇总给用户。群聊发起时也只恢复原群中的发起猫咪，由它汇报。后台任务发起时，恢复该猫咪的主聊天。发起猫咪忙碌时先保存结果，待其已有聊天、后台运行和排队工作结束后恢复，不重跑协助任务。

同一对猫咪复用 `bot_dm` 会话。接收方的最终回答自动成为私信回复，不需要另发确认消息。若接收方也请求协助，当前私信先等待子回复，再恢复接收方汇总，最后逐层返回。每条协作链最多 16 次受理、最多四跳，不能发给自己或祖先猫咪；异步恢复不会重置链条上限。

私信输入只进入指定猫咪的上下文。普通单聊、群聊的消息历史均过滤这些内部输入，其他群成员不能读取或引用它们；最终群回复也不会自动引用私信原文。`private.message.received` 只发布状态标识，私信运行事件使用 `private.run.*`，避免覆盖前台单聊运行状态。

## 一致性、失败与恢复

- 私信正文、接收运行、链条关联与发送工具回执在同一事务提交。回执写入失败则全部回滚；恢复时重用已保存回执，不重复发送，旧租约不能再次写入。
- 接收方收尾时原子保存回复及投递意图。投递时原子写入指定猫咪的隐藏输入、恢复运行及已投递状态。多 Worker 并发投递和进程重启不会重复创建恢复运行。
- 发送时忙碌直接拒绝；已经完成的回复允许持久等待。容量不足或根会话暂不可用时一分钟后复核，不丢弃结果。投递每批最多 100 条，每轮有超时，错误包含用户、私信和猫咪标识。
- 模型、工具、权限撤回、取消和未知结果沿用运行器的显式终态，接收失败会作为失败消息返回发起方，不伪造成功。中间猫咪不可用时向上级返回失败，避免整条链无限等待。
- 根发起运行或当前私信的来源运行被取消后，接收方启动、续约及新操作会拒绝继续；已完成回复保留审计记录而不重新唤醒已取消聊天。已经发出的外部操作仍须按租约及节点确认收尾，取消不撤销已经发生的副作用。
- 运行超时、操作数、用户队列、模型调用并发、月度额度和电脑权限均使用原有边界。不同私信运行各自预留和结算实际模型用量，不把子调用重复算进父运行。

## 部署影响与迁移

新增 `0071_bot_private_messages.sql`，历史迁移不变。新增私信、链条运行及投递表，均强制 RLS 并使用租户复合外键。调度身份只能读无正文的投递元数据。运行表增加目录快照和候选次数，消息表增加指定猫咪可见标识，并前向收紧引用检查。历史消息保持公开可见，不回填旧协作关系。

迁移需要运行表、消息表结构锁，消息约束校验及未完成任务索引建立会扫描现有表；耗时随数据规模和锁竞争变化。新增空表和索引无历史回填。上线在维护窗口停单、等待执行收尾、备份数据库，再用 `tomd upgrade` 执行迁移；沿用升级器的锁等待、语句及迁移总时限，失败事务整体回滚。无需变更节点协议或重建电脑镜像。

目录查询有分页上限，状态子查询走用户及猫咪的待执行索引；链条按根运行和父私信索引查询，最多 16 项。内建工具、协作提示和目录会增加模型输入用量，因此所有猫咪均需可用的工具调用模型和足够的上下文预算；不足时按现有模型路由返回明确错误，不降级为假成功。目录过长时缩短当前页；单个资料超预算会明确要求查询，不静默宣称没有同伴。

回滚先停止新受理和 Worker，保全新增消息、操作及文件，恢复升级前数据库备份和匹配二进制。不能删除迁移账本、修改旧脚本或直接启动不认识 `0071` 的旧程序。前向修复必须新增更高版本迁移。

## 验证

真实 PostgreSQL 及受控模型 Worker 测试覆盖目录、权限与租户隔离、忙碌换人和自行执行、并发受理、异步回复、群聊隔离、嵌套汇总、候选与整链上限、取消、权限撤回、中间猫咪归档、事务失败、回执恢复和多 Worker 投递；前向迁移测试检查已有消息和旧程序降级拒绝。外部供应商的实际任务理解和候选判断仍取决于所配置模型，测试不会连接生产账户。
