# Tom 设计文档

> 产品名 **tom**，显示为 **Tom**，取自 Tom the cat（汤姆猫）；每个助手都是一只猫；命名空间统一为 `io.yueyang`。
>
> 产品定位：一台属于你个人的持久化云电脑，上面有若干个有岗位、有独立记忆的 Bot。它们可以单聊，也可以互相发消息、组成群组协作；关掉客户端后它们继续工作。你通过桌面端与移动端两个入口使用它们——同一份代码，两套原生外壳。
>
> 文档状态：v3.1（可进入实现）
> 目标读者：实现者（Codex）、后续维护者
> 配套文档：[implementation.md](./implementation.md)

## 1. 产品定义

### 1.1 一句话

单用户的「AI 同事团队」：拥有一台长期在线、保留登录态与文件的云电脑，在上面雇佣若干各有专长的 Bot；它们各司其职、各有记忆，也像同事一样能彼此交代事情、开小组会。

### 1.2 目标用户与场景

单用户（部署者本人）：

| 场景 | 参与者 | 需要的电脑能力 |
| --- | --- | --- |
| 每天早上汇总指定来源的资讯 | 研究员 Bot | 浏览器、定时例程、私有记忆（偏好信源） |
| 把素材整理成周报并发到内部系统 | 写作 Bot ← 研究员 Bot | 文件、浏览器登录态、私有记忆（文风与格式） |
| 一起评估一个新方案 | 群组：研究员 + 写作 + 助理 | 多 Bot 同场讨论、共享会话转录 |
| 盯着某个后台任务，失败就重试 | 运维 Bot | 终端、轮询、告警 |
| 通勤路上让某个 Bot 接着干 | 任意 Bot | 移动端同样的会话与审批 |

### 1.3 设计立场

1. **部署简单到一次上传。** 只有二进制与 `./tomd` 一条命令。运行时依赖在启动时自动检测并安装，全部完成才对外宣告就绪；不存在"启动成功但某功能一用就报错"。
2. **服务端没有前端应用。** 服务器只提供 API 与一个纯展示的 health 页面（服务与能力是否正常、CPU/内存/磁盘）。真正的产品是客户端。
3. **两个入口，一份代码。** 桌面端与移动端共享同一套 UI 与业务逻辑，只换原生外壳；不维护两个 App，也不做两套布局语义。
4. **初始化只设一个密码。** 首次启动不问模型、不问供应商、不问 Key；登录后在客户端里按需配置。
5. **电脑是持久的，会话不是。** 登录态、工作区文件、安装的 CLI 工具跨会话存活。
6. **Bot 是岗位，不是会话。** 稳定的名字、头像、职责、模型、私有记忆与工具边界。你想的是"交给谁"。
7. **Bot 之间是同事关系。** 可一对一私下传消息，也可被拉进群组共同处理一件事；协作有明确的路由与护栏。
8. **记忆私有，协作显式。** 长期记忆互不可见；跨 Bot 的信息流动只有两条路：说出口的话（私信/群组），或显式委派时的 brief。
9. **人始终在环。** 高风险动作默认需要批准，批准可按规则记忆。
10. **细节是产品力。** 简洁、现代、克制而精确；参考同类产品的形态，但不复刻其外观。

### 1.4 名称与标识

产品名 **tom**，显示为 **Tom**，取自 Tom the cat（汤姆猫）；每个助手都是一只猫。命名空间统一为 `io.yueyang`，全项目只用这一组标识，不再出现其他别名、代号或临时名。

### 1.5 明确不做

- 服务端 Web 应用（除 health 页）；
- 多用户、团队协作、分享 Bot；
- 支付渠道与账单对账（只做用量计量与预算控制）；
- 自研模型推理；
- 多机分布式调度；
- 通用工作流编排器（只有"对话驱动 + 定时触发 + 群组路由"三种入口）。

## 2. 竞品评估

### 2.1 Grok Bot

形态：xAI 的常驻 Agent 产品。每个账号的 Bot 共享**一台**持久化 Linux 云电脑，具备真实浏览器、文件系统、终端，关闭客户端后继续工作；提供技能、例程、录屏式任务教学、Bot 独立邮箱；安全上以独立审查模型加审批为抓手。计费折叠进订阅制。客户端为桌面与移动的聊天工具形态。

值得借鉴：

- **账号级共享电脑**：登录态与文件天然共享，交接零成本，是"团队感"的来源。
- **每 Bot 有独立屏幕**：共享机器、独立视图。
- **例程 + 技能**：把重复劳动沉淀成可复用能力。
- **审查 + 审批**双闸，不把安全全押在提示词上。
- **客户端即产品**：服务器藏在后面，交互在手里。

需要规避：

- 共享电脑意味着任一 Bot 读到的内容、拿到的 cookie 对其他 Bot 全部可见；一次提示注入的损失面是全账号。
- 删除 Bot 不清理其文件与登录态，残留无人负责。
- 订阅额度不透明，重度使用难以预估成本。
- 视觉与交互高度压缩在"卡片 + 头像堆"范式里，信息密度低、长时间使用疲劳。

### 2.2 同类产品

| 产品 | 形态 | 借鉴与差异 |
| --- | --- | --- |
| Manus | 单任务沙箱 Agent | 交付物意识强；缺少长期身份与记忆 |
| Devin / OpenHands | 编码 Agent 工作区 | 工具链与执行模型可参考；领域单一 |
| ChatGPT Agent | 浏览器操作型 Agent | 快照式交互范式 |
| Claude Code | 终端内 Agent | Agent 循环、记忆文件、工具审批模型直接影响本设计 |
| Slack / 飞书 | 多主体对话 | 群组的信息组织与"谁在说话"的表达 |

### 2.3 能力取舍

| 能力 | 决策 | 理由 |
| --- | --- | --- |
| 共享电脑 | 采用，单用户单机 | 与部署形态一致；风险面收敛到一个自然人 |
| 每 Bot 独立屏幕 | 采用（独立标签组/终端会话） | 共享资源不等于共享工作区 |
| 私有长期记忆 | 采用，**文件权威 + FTS 派生索引** | 可读、可 diff、可备份，用户可直接改 |
| Bot 私信 | 采用，带跳数与环路护栏 | 同事关系的最小实现 |
| 多 Bot 群组 | 采用，**协调者路由** | 比全员轮流发言更省成本、更像协作 |
| 定时例程 | 采用 | 持久化电脑的价值在"你不在时也在干活" |
| 自动安装依赖 | 采用，启动期一次性完成并验证 | 支撑"单二进制、启动即全功能" |
| 服务端 Web 应用 | **不做**，仅 health 页 | 客户端才是产品；减少一套需要维护的界面 |
| 桌面 + 移动客户端 | 采用，**一套代码两种壳** | 见 5.1，避免双份维护 |
| 自带邮箱 | 不做 | 需要域名与收发基础设施 |
| 录屏教学 | 不做 | 采集端成本高，收益可由"例程 + 会话回放"近似 |

## 3. 核心概念

```
Workspace（云电脑）
├── Bot（岗位）── 名字、头像、职责、模型、工具白名单、私有记忆
│   └── Group（群组）── 多个 Bot 的共享会话，带协调者与协作规则
├── Conversation（会话）
│   ├── direct   ── 你 ↔ 一个 Bot
│   ├── group    ── 你 + 多个 Bot
│   └── bot_dm   ── Bot ↔ Bot
├── Turn（回合）── 一条消息引发的一轮响应，可包含多个 Bot 的发言
│   └── Run（执行）── 某个 Bot 在这个回合中的一次 Agent 循环
├── Routine（例程）── cron 触发的 Run
└── 共享资源：/workspace 文件树、浏览器 profile、终端会话、Secrets
```

概念语义详见上一版设计的延续部分，要点：

- **会话三型**：`direct` / `group` / `bot_dm`。一条用户消息开启一个 Turn；群组中的 Turn 可能派生出多个 Run。
- **群组路由三策略**：`mention`（默认，只答被 @ 的）、`coordinator`（协调者先产出分工、成员执行、协调者汇总）、`all`（成员各答一次）。
- **Bot 私信**：`message_bot` 形成 `bot_dm` 会话，链路最大 4 跳，带乒乓检测。
- **委派 vs 私信 vs 群组**：委派是"交付一件事"（结构化结果 + 产物路径），私信是"问一句/通个气"，群组是"一起讨论"。三者都不自动写入任何 Bot 的长期记忆。

## 4. 关键用户旅程

### 4.1 首次部署（三分钟内完成）

1. 上传单个二进制，执行 `./tomd`。
2. 启动期自动检测环境、安装系统依赖与 CJK 字体、下载并校验内置版本锁定的浏览器、逐项自检（含中文渲染验证）。
3. 就绪后终端打印服务地址与一次性初始化码；可用任意浏览器打开 `http://<host>:8787/health` 看到服务状态与能力清单。
4. 打开桌面客户端，填服务器地址，用初始化码设置管理员密码。
5. 进入客户端，默认助手 Tom 已在左栏并打开常规对话；尚未配置模型时引导进入模型设置，后续配置全在客户端内完成。已有会话记录或外部会话链接时优先打开对应会话。

### 4.2 日常

1. 打开客户端直接回到上次的会话；左栏展示 Bot 与群组的圆头像、名称及实时更新的最新消息预览，右上角提供搜索和新增，底部显示服务器地址与设置。
2. 点开某个 Bot 直接对话；消息实时流式，工具执行以卡片呈现，需要时内联审批。
3. 关掉客户端不影响执行；重新打开从事件流续上。
4. 会话界面点"详情"展开右侧栏，在同一处查看这个 Bot 的身份与策略、管理例程，或切到"电脑"查看文件、浏览器画面与终端；收起后再打开仍是刚才的位置。待办通过聊天 `/approvals` 或例程页的"审批待办"进入。

### 4.3 通勤中的移动端

1. 手机端打开同一个 Bot，看到桌面端未完成的任务还在跑。
2. 有审批或任务完成时，本地通知提示"某 Bot 需要你确认"；切回或打开客户端即拉到最新状态，审批以全屏 sheet 呈现，一次点按即放行。
3. 手机上不展示终端与浏览器画面（屏幕太小），只保留"查看截图"与"发消息"。

> 系统推送（应用在后台时也能收到）是后续目标，不在首个交付版本内；当前版本不做后台常驻与推送网关。

### 4.4 拉群

1. 新建群组，选三个 Bot，指定协调者，写一句"这个群用来做什么"。
2. 在群里说话，协调者先给分工，相关 Bot 依次发言，结论被汇总。
3. 成员想留经验，自己在私有记忆里写；群组文件落在 `/workspace/shared/`。

## 5. 系统架构

### 5.1 部署形态与客户端形态

```
┌──────────── Flutter 客户端（一套 Dart 代码）────────────┐
│  macOS / Windows / Linux 桌面 + iOS / Android 移动      │
│  同一套 Widget 与状态层；按断点切换信息密度与导航形态    │
│  原生能力：安全存储 / 通知 / 深链 / 分享 / 文件选择      │
└──────────────────┬──────────────────────────────────────┘
                   │ HTTPS / SSE / WS
                   ▼
        ┌──────────────── 服务器（即"云电脑"）────────────────┐
        │ tomd（单二进制，无 CGO）                            │
        │  ├ 引导层：检测 → 安装 → 自检 → 就绪门禁             │
        │  ├ HTTP API + SSE + WS                              │
        │  ├ /health：纯静态状态页（唯一服务端页面）           │
        │  ├ Agent 运行时 / 群组编排器                         │
        │  ├ 工具层（文件 / shell / PTY / 浏览器 / 消息）      │
        │  ├ 调度器、密钥、用量、审批、记忆                    │
        │  └ SQLite(WAL) + /workspace                         │
        └──────────────────────────────────────────────────────┘
                   │ 出站 HTTPS
                   ▼ LLM 供应商
```

**客户端形态：Flutter 全平台，一套代码**

选型结论：**放弃 Electron**，客户端用 Flutter 一套 Dart 代码编译到 macOS / Windows / Linux / iOS / Android。这里的"一套代码"是字面意义的：UI、状态、路由、API 客户端、SSE/WS 都只有一份实现，不存在桌面与移动各写一遍的情况。

| 组成 | 桌面 | 移动 | 是否共用 |
| --- | --- | --- | --- |
| Widget 树与设计系统 | ✔ | ✔ | **同一份 Dart 源码** |
| 状态、路由、API 客户端、SSE/WS | ✔ | ✔ | **同一份源码** |
| 布局 | 左栏 + 会话 + 详情栏（可收起） | 单列 + 底部导航，详情栏为全屏页 | 同一份源码，按断点（`<720 / 720–1199 / ≥1200`）切换 |
| 原生能力 | `flutter_secure_storage`、本地通知、深链、窗口管理 | 同上 + 分享、生物识别（系统推送为后续目标） | 同一组插件，用能力探测区分可用性 |
| 终端 | `xterm.dart` 完整渲染 | 只读输出 + "在桌面端打开"提示 | 同一 Widget，移动端限制输入 |

因此 KNOW-HOW 只有一处：Flutter 的 `CustomScrollView` + 自适应断点，而不是两套工程。

选型代价（必须在实现中正视）：中文与代码高亮的排版细节要靠自建 Widget 打磨；Markdown 渲染能力弱于 Web 生态，需要选型并提供自定义组件（代码块、表格、工具卡片）；终端能力可满足使用但生态不如 xterm.js 丰富。

客户端技术栈：

- **Flutter 3.x（Dart 3）**，Material 3 仅作基础，视觉以自定义设计令牌为准；
- **状态**：`riverpod`（编译期安全、可测试）；
- **路由**：`go_router`（深链与 Web 支持，便于将来补一个轻量只读页）；
- **网络**：`http` + 手写 SSE 客户端（`http` 流式读取，断线按游标续传）；WS 用 `web_socket_channel`；
- **存储**：`flutter_secure_storage`（设备令牌、证书指纹）+ `drift` 或 `shared_preferences`（本地偏好与草稿）；
- **Markdown / 代码**：`flutter_markdown` 不足以承载工具卡片，改为自建块渲染器（见实现文档 13.5）+ `flutter_highlight` 或 `shiki` 的等价方案（内置一套 TextMate 语法的高亮器）；
- **终端**：`xterm.dart`；
- **动效**：Flutter 内建 `AnimationController` + 统一的时长/曲线令牌，`flutter_animate` 仅用于列表进出；
- **通知**：`flutter_local_notifications`，桌面与移动同一套 API，应用在前台或刚切回时提示。移动端系统推送（`firebase_messaging` 或自建网关）列为后续目标，首个版本不引入。

服务端：

- Go 单二进制、无 CGO，内嵌 SQLite；无 Caddy/Nginx 也可直连（自带可选 TLS）。
- 除 `/health` 与 API 外不提供任何 HTML 页面。

### 5.2 分层

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| `provision` | 环境探测、依赖安装、自检、就绪门禁 | 不参与业务 |
| `httpapi` | 鉴权、校验、SSE/WS、health | 不含业务规则 |
| `service` | 用例编排 | 不拼 SQL、不起进程 |
| `agent` | 上下文装配、Provider 调用、工具循环、预算 | 不知道客户端 |
| `orchestrator` | 群组路由、发言计划、汇总、消息护栏 | 不直接调模型 |
| `provider` | 协议适配 | 不含业务策略 |
| `tool` | 工具注册与实现 | 不做权限判断 |
| `policy` | 审批与审查 | 不执行工具 |
| `store` / `infra` | SQLite、配置、日志、事件总线 | 无领域概念 |

### 5.3 三条并发约束

1. 同一 Bot 同刻只跑一个 Run。
2. 全局 Run 并发上限（默认 3，超出排队）。
3. 共享资源加锁：浏览器 profile 单实例（按 Bot 标签组隔离）、文件写入串行、PTY 会话按 ID 加锁。

## 6. 关键子系统设计

### 6.1 引导与依赖自举

**目标**：`./tomd` 之后，除了"你还没配模型"这种业务前置，任何功能都不因环境缺失而报错。

```
读取配置 → 文件系统预检 → 环境探测（发行版/架构/libc/包管理器/root 能力）
  → 安装中文字体与 Chromium 运行库 → 下载并校验托管浏览器
  → 功能自检（中文渲染截图、TLS、FTS5、PTY、磁盘、时钟）
  → 写能力表 → 宣告就绪
```

- **失败即不就绪**：任一步失败则只开放 `/health` 与引导接口，页面给出可执行的中文修复建议；不存在"能用一半"的中间态。
- **幂等**：每步先检测后执行，重复启动不重复安装，中断后可续跑。
- **按发行版适配**包管理器（apt / dnf / yum / apk / zypper），只装缺的；无 root 且无免密 sudo 时明确失败并给出完整命令，绝不静默降级。
- **字体是硬需求**（缺失会导致界面与截图出现方块），作为阻断项。
- 浏览器版本与 sha256 硬编码在二进制内。四个平台的官方离线 zip 随仓库放在 `server/browser/`（Git LFS），引导直接安装，不从网络下载；`TOM_BROWSER_ARCHIVE` 可改路径。
- 提供 `tomd doctor`（只诊断不改动）与客户端的"重新体检 / 修复"操作。

**能力表**驱动 UI：某项能力为 false 时，客户端隐藏对应入口，而不是等用户点进去才报错。

### 6.2 共享云电脑

```
/workspace/
├── shared/                    # 所有 Bot 可读写
├── bots/<bot_id>/{inbox,out,notes,.tom/memory}
└── .tom/{bin,logs,tmp}
```

- 文件工具一律解析绝对路径并校验在 `/workspace` 内（含软链二次校验）。
- 单一持久浏览器 profile：你在"这台电脑的浏览器"里登录过的站点，Bot 打开即是已登录。
- 删除 Bot 时明确询问是否删除其文件与记忆；默认保留文件、移除索引，并提供"孤儿目录"清理。

### 6.3 Agent 运行时

```
1. 载入 Bot、会话、Turn；获取 Bot 锁
2. 装配上下文（身份 → 电脑环境 → 工具规则 → 记忆索引 → 会话转录 → 本回合任务）
3. 循环：流式生成 → 工具调用按策略执行 → 结果回灌
4. 落库：消息、工具调用、用量；必要时更新会话摘要
```

- 上下文预算按 token 估算分配；会话转录在 `group` 会话中含全部成员发言，`direct`/`bot_dm` 只含双方。
- 取消：中止上游 → 杀子进程组（SIGTERM→5s→SIGKILL）→ 结果标记 canceled。
- 达上限优雅收尾：写说明块，状态 `failed` + 明确错误码，客户端显示"已停止：达到上限"。

### 6.4 群组编排器

```
用户消息 → 规划（mention 直路由 / coordinator 产出结构化分工 / all 依次）
        → 护栏裁剪（发言数、重复分工、预算）
        → 成员并行执行（各自 Bot 锁、共享群转录）
        → 协调者汇总（可关）
```

护栏：单回合发言数上限（默认 3）、同 `(bot, brief)` 去重、连续空转提前收口、回合成本上限、禁止通过私信回环回到同群。

### 6.5 工具系统

| 类别 | 工具 |
| --- | --- |
| 文件 | `file_read` `file_write` `file_edit` `file_list` `file_glob` `file_search` |
| 执行 | `computer_shell` `terminal_session` |
| 浏览器 | `browser`（open/snapshot/click/type/key/scroll/screenshot/tabs/close_tab/download） |
| 协作 | `message_bot` `post_to_group` `group_members` `delegate_task` |
| 认知 | `memory_search` `memory_write` `memory_delete` `conversation_search` `conversation_read` `ask_user` |

工具名、描述、参数 schema、错误码英文（模型面向）；审批标题与客户端文案中文。单次输出上限 32KB，超出落盘并返回路径与确定性摘要。

### 6.6 浏览器 / 终端

- 托管 Chromium + CDP；每 Bot 一个标签组，Run 结束不关标签。快照交互（无障碍树 + `[ref=eN]`）为主，富交互页回退截图。
- 持久 PTY 进程内管理（`creack/pty`），不依赖 tmux；重启后终端会话不恢复（界面明示），文件与消息不受影响。你与 Bot 共用同一批会话，可随时接管。

### 6.7 记忆

- 长期记忆为 `bots/<id>/.tom/memory/*.md`，文件是权威；SQLite 只存元数据与 FTS 索引（中文 trigram、英文 porter），索引可重建。trigram 无法命中少于 3 个字符的中文查询，这类查询退化为在该 Bot 记忆目录内做 LIKE 扫描（目录规模有界）。
- 系统提示只注入 ≤2KB 的记忆索引，逼模型主动检索。
- 群组转录不会自动进入任何 Bot 的长期记忆。

### 6.8 例程、密钥、用量

- 例程：`{bot|group, cron, prompt, overlap_policy, catch_up, target_mode}`；重叠默认 `skip`，错过默认补跑一次。
- 密钥：AES-256-GCM 密文存储；模型只见名字，`computer_shell` 支持 `env_secrets` 在执行期注入；日志脱敏；客户端只提供写入与轮换。
- 用量：每次调用记录 token 与成本；Run / Turn / 月度预算；达阈值提醒、达上限按配置停止或告警。

### 6.9 安全与审批

防线：工具白名单 → 路径约束 → 审批规则（`allow/ask/deny`）→ 可选独立审查 → 协作护栏 → 全量审计。

动作类：`fs.delete` `fs.write_outside_out` `shell.exec` `shell.privileged` `net.new_domain` `browser.login` `secret.use` `delegate.spawn` `message.bot` `group.invite` `routine.create` `user.question`。

**如实记录的已知风险**

- shell 在宿主机执行，理论上可越过 workspace。单用户部署下刻意接受的取舍；缓解是审批 + 审计 + 建议以独立低权限用户运行。演进路径为工具执行下沉容器，接口不变。
- 共享浏览器 profile 意味着站点会话对所有 Bot 可见；缓解为新域名审批、外发动作强制询问、执行浏览器动作时客户端高亮当前域名。
- 群组转录对成员全量可见；群组创建页明确写出"成员之间共享本群对话"。
- 客户端持有长期凭据：必须存于系统安全存储（Keychain / Keystore / DPAPI / libsecret），不得写入日志与明文文件。

### 6.10 客户端与服务器的连接

- 首次连接：输入服务器地址（可扫码或深链带入）→ 用管理员密码登录 → 服务端下发长期设备令牌（device token）→ 客户端存安全存储。
- 传输：所有接口走 HTTPS；客户端在服务器未配置证书时提供两种模式——自签证书指纹固定（TOFU，首次确认并记录），或由用户提供反向代理域名。**不允许无声降级为明文 HTTP 跨公网**。
- 实时：SSE 负责会话事件（断线带游标续传），WS 负责终端与浏览器画面（仅桌面/平板启用）。
- 通知：桌面用原生通知；移动端首个版本只用本地通知，系统推送为后续目标（到期接入时，推送内容不含敏感正文，只含"某 Bot 需要你确认"）。设备表已预留 `push_token`，接入时无需改表。

## 9. 客户端设计方向

### 9.1 形态

**左栏是你的 Bot 与群组，中间是对话，右侧按需展开它的工作面。** 信息架构对齐 Grok 的客户端形态：一列常驻的 Bot 团队、一个以对话为主体的阅读区、一个可以随时收起的侧栏；视觉语言与信息密度另立一套（见 9.2）。

桌面端首次启动且没有窗口记录时采用 1280×800 逻辑像素；已有用户恢复上次保存的尺寸与位置。默认窗口与恢复窗口均限制在当前显示器可用区域内，适应菜单栏、任务栏与较小屏幕。非全屏 macOS 工作台使用左侧局部工具条，40 像素搜索与新增按钮上边距为 13 像素，与原生红绿灯顶部齐平；右侧会话标题和操作也从顶部 13 像素开始，不保留全宽 48 像素标题条空白。局部工具条高 61 像素、宽度至少 212，随侧栏宽度移动；收缩时右侧标题、头像和操作避开其覆盖范围。普通页面仍保留 48 像素标题条，其他平台与全屏时保留原有页面布局。

桌面端（≥1200）三栏：

```
┌───────────────┬───────────────────────────────┬───────────────────┐
│ 左栏 240–400   │ 会话主列（居中，正文 ≤680）      │ 详情栏 400（可收起） │
│               │                               │                   │
│          ⌕ ＋ │ 研究员 · 资讯汇总 · 模型 · ●    │ [详情] [电脑]        │
│               │───────────────────────────────│                   │
│               │                               │                   │
│ BOT           │ 消息流                         │ （当前分区内容）     │
│ ○ 研究员   ●   │                               │                   │
│   最新消息预览  │                               │                   │
│  写作         │                               │                   │
│  运维      ⚠   │                               │                   │
│               │                               │                   │
│ 群组           │                               │                   │
│  选题会        │                               │                   │
│               │───────────────────────────────│                   │
│ 私信（折叠）    │ 输入区                         │                   │
│               │                               │                   │
│ 主机:端口   ⚙  │                               │                   │
└───────────────┴───────────────────────────────┴───────────────────┘
```

- **左栏是会话一级导航**：Bot 与群组会话列表 → Bot 私信（默认折叠）→ 底部服务器地址与设置。默认宽度 300，展开范围 240–400，收缩为 100（红绿灯左右各留 20 像素），仅通过拖拽调整，不设置收起／展开按钮；拖动宽度低于 170 时吸附收缩，否则至少展开到 240，跨阈值使用 220 毫秒宽度动画，展开区连续拖拽直接跟手，结束时才按服务器保存。展开态使用圆头像、名称、最新消息预览与未读标记，预览随实时摘要更新；收缩态使用头像与悬停提示。侧栏与右侧内容背景区分，边界分割线贯穿标题栏。右上角并排放置带圆形背景的搜索和新增，新增弹窗选择 Bot 或群组后进入已有编辑页，保留背景会话草稿。
- **统一设置**：底部地址与带圆形背景的设置按钮位于同一行。地址仅显示主机与端口、不含协议，保留域名，IPv6 主机使用方括号；过长时省略、悬停可查看完整值，收缩后使用地址图标。设置弹窗采用左分类、右内容，集中提供模型、用量、密钥、设备及已归档 Bot 管理。
- **会话主列**：顶部是当前对话对象（Bot 或群组）与执行状态，提供记忆、Bot 设置与"详情"入口。消息流与输入区是唯一的正文区域；桌面侧栏不再放置例程和待办，例程由详情中的"管理例程"进入，待办由聊天 `/approvals`、例程页或手机底部导航进入。
- **详情栏是 Bot 的工作面**，两个分区，同一时刻显示一个，切换分区不改变会话：
  - **详情**：身份、模型、工具边界、审批严格度、记忆索引摘要、例程与下次触发时间；群组则显示群用途、路由策略、协调者与成员。
  - **电脑**：浏览器、终端与文件页签，可只读旁观，也可接管；文件支持 Bot 与共享范围，主侧栏不再单独提供这些入口。
- **详情栏默认收起**（48px 竖条，两个图标各对应一个分区）。点会话顶部的"详情"开关，或直接点收起态的任一图标，即展开到对应分区；宽度与上次分区在设备内记忆。
- **收起不打断执行**：文件预览的滚动位置、终端会话、浏览器标签在收起期间保持，展开即还原。
- **打开即回到上次的会话**；没有记录时优先进入默认助手 Tom，外部会话链接优先于本地记录。Tom 已归档或删除且没有其他目标时显示会话列表或空状态，不自动重建。左栏本身承担首页职责。

默认助手以稳定 Bot 标识 `tom` 识别，其常规直接会话为 `tom-direct`，不增加 API 标志字段。常规对话在侧栏和搜索结果中置顶，搜索先匹配标题与预览，例程及协作会话保持原有状态排序。Tom 无上传头像时使用内置图片，上传头像优先；改名不改变默认身份，同名普通 Bot 不享有此规则。Tom 的设置、归档和删除与普通 Bot 一致。认证完成后一次性创建并绑定已有默认模型；后续设定默认模型时，仅为仍未配置模型的 Tom 自动绑定，不覆盖用户选择。没有模型时在对话中提供设置入口。

中等宽度（720–1199）：左栏同样采用默认 300px、展开 240–400px、收缩 100px 的两态布局，详情栏改为覆盖式抽屉，宽度 360。
移动（<720）：单列 + 底部导航四项（会话 / Bot / 待办 / 设置）；详情栏变为全屏页 `/bots/:id/detail`，只保留文件与浏览器截图，终端只读。

侧栏宽度使用每服务器独立的 `workbench.sidebar.v3.*` 记录，只接受 100 或 240–400；旧 v1/v2 侧栏记录不读取、不改写。本次宽度规则升级一次性重置侧栏偏好为默认 300，之后恢复合法 v3 记录；主会话与详情面板布局记录不变。拖动和动画期间只预览，结束才串行保存，取消不写入，失败可见并可重试。减少动态模式下宽度立即切换。此调整无需服务端或数据库迁移；回滚旧客户端仍读取其保留的原版本侧栏记录，不消费 v3。

### 9.2 气质与差异化

**"私人工作室"，而不是"AI 控制台"。** 排版质感来自阅读与写作工具：留白充足、单一阅读列、克制颜色、精确对齐。深色沉稳如墨，浅色如纸；动效短、准、不炫技。

| 维度 | Grok Bot 的印象 | 本项目 |
| --- | --- | --- |
| 底色 | 纯黑 + 高对比白 | 墨黑带冷调 / 暖纸色浅色 |
| 主导色 | 黑白灰 | 陶土色（ember）作品牌与关键动作；Bot 各有低饱和专属色相 |
| 布局 | 左栏列表 + 中间对话 + 右侧工作面 | **同一套骨架**；但左栏以排版与状态点表达身份，不做大卡片与头像墙 |
| 右侧面板 | 单一工作视图 | 详情 / 电脑两个分区，一个面板解决，不开多窗口 |
| 消息 | 气泡感强 | Bot 回复使用左对齐圆角气泡；用户消息使用右对齐轻卡片 |
| 图标 | 线性圆润 | 1.5px 线性、端点圆、几何一致 |
| 动效 | 弹性明显 | 160–260ms 缓出，只在状态变化时出现 |

### 9.3 设计令牌（摘要，完整值见实现文档）

- **字**：UI 系统无衬线（Inter / PingFang SC / Noto Sans SC 回退链）；数字等宽且 `tabular-nums`。
- **色**：深色侧栏 `#0E0E0E`、内容区 `#121212`、消息气泡 `#1E1E1E`；浅色侧栏 `#F5F5F5`、内容区 `#FCFCFC`、消息气泡 `#EFEFEF`。侧栏选中背景分别为深色 `#202020` 和浅色 `#E4E4E4`。机器人详情面板与内容区同色，通过细分割线分隔；其他表面保持深色 `#131518`、浅色 `#FFFFFF`，描边分别为 `rgba(255,255,255,.08)`、`rgba(18,20,23,.08)`；品牌陶土 `#C4553B` / `#E0705B`；文本三档。
- **尺度**：4px 基准、8px 网格；控件圆角 10、卡片 14、抽屉 20；主文字 14、辅助文字 13，标题保留字号与字重层级；正文行高 1.65，正文列最大宽度 680 逻辑像素。
- **触控**：移动端所有可点区域 ≥44×44pt，次要操作收进长按或滑出。

### 9.4 关键界面

- **左栏（BotRail）**：Bot、群组、折叠的私信与底部同一行的主机与端口、统一设置。展开态展示圆头像、名字、最新消息预览和未读数，收缩态保留头像及提示；操作菜单提供记忆、设置、归档。搜索与新增置于右上角，和底部设置一样采用圆形背景；`⌘K` 打开会话搜索，新增先选择 Bot 或群组，再进入对应编辑页。
- **会话（Chat）**：顶部仅悬浮 Bot 头像与名称，点击打开详情；用户与 Bot 使用同色圆角气泡，输入框悬浮在消息流底部并与气泡两端对齐；工具调用是可展开的一行卡片；末尾流式光标。输入区支持 `@` 提人、拖拽/选择文件、`/` 命令。执行中显示当前步骤摘要，右侧详情栏切到"电脑"可看实时画面。
- **群组**：顶部成员色带（谁在说话就亮）；协调者的分工显示为缩进的"分工"条目；成员按完成顺序发言；右栏"详情"显示群用途、路由与协调者。
- **Bot 详情（DetailPanel · 详情）**：身份（名字、职责、色相）、模型与温度、工具白名单与消息策略、审批严格度、记忆索引前若干条、"管理例程"入口与下次触发时间。群组会话下同一分区显示群设置。
- **文件（DetailPanel · 电脑 · 文件）**：文件树按最近修改排序，本回合被写入或新建的文件在名字前显示一个 `brand` 圆点并在首次出现时短暂高亮；点开右侧转换为预览（Markdown 渲染、代码高亮、图片）；支持下载与"在终端中打开所在目录"。
- **电脑（DetailPanel · 电脑）**：浏览器画面（当前域名常显）、终端与文件页签并列，切换保留各页状态；移动端终端只读。
- **审批**：桌面为右栏之上的抽屉，移动为全屏 sheet；风险徽章 + 一句话说明 + 三键（仅此次 / 本 Bot 以后允许 / 拒绝）。可从聊天 `/approvals`、例程页"审批待办"或手机底部"待办"进入；手机待办数字汇总运行中回合、待审批事项与未读产物。
- **引导**：一列待办项，逐项从"检测中"变"已就绪"，失败项展开修复建议。
- **空状态**：所有 Bot 均被归档或删除后，左栏为空时给"创建第一个 Bot"与三个模板；会话无消息时显示首条消息引导，无模型时提供配置入口。

## 10. 非功能需求

| 维度 | 目标 |
| --- | --- |
| 首次启动 | 典型云主机 ≤5 分钟（含浏览器下载与自检）；二次启动秒级 |
| 客户端冷启动 | 桌面 <2s 到左栏与上次会话骨架；移动 <1.5s |
| 实时性 | 模型首 token 不额外增加延迟；SSE 转发 <50ms |
| 并发 | 3 Run 并行界面不卡；单 Run 工具串行 |
| 恢复 | 崩溃重启：Run 置 interrupted、消息不丢、浏览器恢复；客户端断线自动续传 |
| 数据安全 | 密钥仅密文落库；设备令牌可撤销；日志脱敏；审计可导出 |
| 备份 | `tomd backup` 产出 SQLite 快照 + workspace 归档；给出还原步骤 |
| 升级 | 迁移前向兼容；替换二进制重启即可；客户端检查版本并提示 |
| 可维护 | 单测覆盖 agent 循环、policy、编排、记忆检索、provider 适配；工具有集成测试 |

## 11. 权衡与演进

| 决策 | 代价 | 演进 |
| --- | --- | --- |
| Flutter 全平台 | 放弃 Web 生态（Markdown、代码高亮、终端需自建或换库） | 需要更强渲染时可内嵌 Markdown 预览 WebView（仅局部使用） |
| 无服务端 Web 应用 | 临时借用他人设备不方便 | 可补一个极简只读会话页，但不作为主路径 |
| 引导期装依赖 | 首次启动慢，需网络或本地归档 | 预置离线包；镜像内置依赖 |
| 单进程 + SQLite | 无法水平扩展 | store 抽接口迁 Postgres；调度加租约 |
| 宿主机直跑工具 | 隔离弱 | 工具执行下沉容器/微虚拟机，接口不变 |
| PTY 进程内 | 重启丢终端会话 | 接回 tmux 或自建会话守护 |
| 协调者路由 | 多一次规划调用 | 加轻量意图分类，简单消息跳过规划 |

## 12. 术语表

| 术语 | 含义 |
| --- | --- |
| Bot | 有岗位、模型、工具与私有记忆的长期 Agent |
| 会话 Conversation | direct / group / bot_dm 三种对话空间 |
| 回合 Turn | 一条消息引发的一轮协作，可能包含多个 Bot 的发言 |
| Run | 单个 Bot 的一次完整 Agent 执行 |
| 群组 Group | 多个 Bot 的协作单元，有协调者与路由策略 |
| 私信 bot_dm | 两个 Bot 之间的会话 |
| 例程 Routine | cron 触发的 Turn |
| 引导 Provisioning | 启动期的环境检测、依赖安装与自检 |
| 设备令牌 | 客户端登录后获得、存于系统安全存储的长期凭据 |
| 云电脑 | 承载文件、浏览器、终端、凭据的持久化服务器环境 |
