# 资料库与 Bot 电脑的文件传输

Bot 的电脑工具启用后，内建工具 `chat_file_import` 可以把当前聊天附件写入远程电脑，`chat_file_export` 可以把电脑生成的实际文件作为聊天附件交付。文档、表格、PDF、图片和视频均传输原始字节，不把二进制内容塞进模型上下文。`chat_file_create` 继续用于直接生成 UTF-8 文本。

导入文件保存到 `/workspace/Library/<操作标识>/<原文件名>`。导出仅接受 `/workspace` 内普通文件，显示名称单独校验。单文件沿用资料库的 16 MiB 上限，用户总容量和文件数量仍由资料库事务核验；超过限制明确失败。业务文件按既有电脑模型在同一用户的 Bot 之间共享，文件工具只能取得当前聊天可见的资料库附件。

## 执行和失败处理

文件工具声明需要电脑执行权。Worker 先申请所属 Bot 桌面并持久登记操作，再调用当前节点的 `file_transfer` 协议。完整身份包含用户、电脑、Bot、桌面、运行、容器实例和执行代次，不能从模型参数选择其他电脑。

节点按 32 KiB 分块传输，完整文件使用 SHA-256 校验。导入分块必须连续，重复启动、重复分块和重复提交会被拒绝。导出读取一次有界快照，文件在读取期间发生修改则拒绝交付。每个桌面最多保留 32 条操作消费记录和 64 MiB 暂存配额；结束后清除文件字节，保留操作标识直到会话回收。

容器使用固定镜像程序，以当前 Bot 的 Linux 身份打开文件。逐级目录打开禁止符号链接，拒绝路径越界、目录、管道及设备。导入先写同目录临时文件并刷盘，再原子创建最终名称，不覆盖已有内容；失败清理临时文件。文件内容不进入命令行、日志或模型工具回执。

导出附件、聊天消息、资料库事件和成功回执在同一个事务中提交。群聊沿用群消息额度及引用规则，单聊交付到对应 Bot 的用户聊天。节点结果未知时不自动重放写入或发布；运行结束仍执行原有桌面回收和隔离流程。

## 部署与回滚

文件传输不新增数据库表。需要成套更新 `tomd`、`tomnode` 和电脑镜像中的 `computer-agent`、`computer-task`、`bot-agent` 及 `files.py`。节点接口新增 `file_transfer` 动作；不支持该动作的旧节点不能提供此功能。先停止新运行领取，等待在途运行完成或按现有流程隔离，再更新节点和镜像、完成节点能力验证，最后恢复领取。

回滚同样先停止领取并收尾在途传输，再成套恢复旧程序及旧镜像。已交付附件和 `/workspace` 中的文件无需删除；操作账本、桌面代次和隔离状态必须保留。默认电脑权限的数据迁移与回滚另见 [默认电脑工具](default-computer-tools.md)。

## 验证

`computeragent/files_test.go` 覆盖分块字节完整性、摘要错误、取消、错序、重放及桌面归属；Linux Unix 协议测试覆盖完整分块和失效代次。`scripts/test_computer_files.py` 覆盖实际文件读写、空文件、二进制、链接、路径越界、覆盖拒绝、文件变化和失败清理。

`execution/library_computer_test.go` 使用真实 PostgreSQL 和 Agent 协议，替代节点字节传输，验证单聊/群聊导入交付、原始二进制完整性、损坏回包、跨会话文件及中断收尾。实际文件进程另由 Linux 文件协议和 Python 测试覆盖；有头 Chrome 集成测试验证真实下载文件与中文文件上传。远程屏幕与接管验证见 [远程电脑](remote-desktop.md)。生产 cgroup 联合部署仍需按部署流程验收。
