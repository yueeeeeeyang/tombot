# 群聊与提及

群里的猫咪是平等成员，用户是群主。普通发言通知所有当前成员；选择 `@` 或回复猫咪消息时，只通知指定成员。同时指定多个目标时取并集。所有群消息对群主和群成员公开，`@` 代表通知对象，不代表私密消息。群聊不读取猫咪的私人单聊或长期记忆。

## 客户端

群聊与猫咪共用侧栏右键菜单：置顶、移至分组、标为未读、重命名聊天、复制对话 ID、隐藏、删除。分组、置顶、未读和隐藏保存在本机；隐藏后可以从“我的工作空间”恢复。重命名与删除提交服务端并检查版本；删除归档群聊，保留历史消息。群右栏只有“成员”“资料库”两个页签，成员在前，名称通过侧栏重命名。群头像由当前成员的猫咪头像组合。

消息受理后立即清空输入，其他成员仍在回复时可以继续发言。消息按服务端序号合并，通过用户事件流通知和定时读取恢复，不依赖当前窗口的临时流式气泡。引用、作者和提及标记保存在服务端；再次打开或刷新聊天仍可显示。点击引用加载并定位原消息，单次最多补载 20 页，超过时提示继续查看更早消息。模型提及用户显示 `@你`。

当前 v2 的群附件上传与资料库尚未开放，客户端对此明确报错；本次群消息链路支持文本、引用和表情交互，不把未上传的文件假装成已发送附件。

## 投递、并发与恢复

每条用户消息创建独立群回合；不同成员可并发执行，同一猫咪的聊天任务复用已有互斥队列，忙碌时排队，不跳过或合并掉群消息。定时任务继续使用独立后台通道。群运行事件使用 `group.run.*`，不让单聊误显示群聊的忙碌状态或错误。运行开始固定触发消息及公开历史水位，恢复不会读入后来的发言。历史中其他猫咪发言作为带作者标识的引用材料，不冒充当前模型的助手输出。

模型使用 `post_to_group(message, mentions, reply_to_id)` 发言、指定成员或回复消息；成员标识来自公开名单，`user` 表示用户。也支持在最终回复中输入完整 `@成员名称` 和 `@用户`。明确提及在发言猫咪结束本轮运行后唤醒收件猫咪，只交付对应公开发言；`@用户` 不创建模型运行。工具中不等待对方，避免执行槽相互占用。普通 bot 答复不会再次广播。

同名成员需要选择标识；无效标识拒绝发送。邮箱和未知 `@` 文本是普通正文。最终答复存在歧义时保留正文并提示未转交。表情交互只唤醒被标记消息的猫咪；回复其他会话或其他用户消息一律拒绝。成员移出或群归档后不再允许该成员继续调用模型、发言或转交；取消或失败有可见通知。

用户请求通过 `client_request_id` 去重，同键异内容冲突。同一公开消息与收件猫咪组合只投递一次，成员投递与运行、任务和事件在一个事务中提交；工具发言与成功回执也原子提交，恢复读取原回执。沿用运行租约、围栏令牌、用量结算及未知外部结果的阻断机制，不盲目重试有副作用的工具。

群最多 32 位猫咪，每轮最多 64 次成员运行，转交最多延伸 4 层，每次运行最多 15 条工具发言和一条最终答复。达到转交或队列上限时显示停止通知，用户可另发消息继续；用户消息无法受理时全部回滚，不生成半条消息或只通知部分成员。用户模型调用、队列和上下文配额仍生效。群目录中的 `max_cost_micro` 原样保留，本执行器当前使用统一用户配额，不宣称实现独立群费用上限。

## v2 接口

所有路径以 `/api/v2` 开头，需要当前用户会话，不接受客户端指定发送者身份。

| 接口 | 参数与返回 |
| --- | --- |
| `GET /groups` | `before`、`limit`（最多 100），返回 `groups` |
| `POST /groups` | `client_request_id`、`name`、`purpose`、`member_ids`，返回 `group` |
| `GET /groups/{id}` | 返回 `group`，含成员、版本、会话标识 |
| `PUT /groups/{id}` | `expected_revision` 与完整群设定；增删成员保留其他字段 |
| `POST /groups/{id}/state` | `expected_revision`、`is_archived` |
| `POST /conversations/{id}/messages` | `client_request_id`、`content`，可选 `mentions: string[]`、`reply_to_id`；返回 `submission`，首次 202、重放 200 |
| `GET /conversations/{id}/messages` | `before`、`limit`，按服务端序号倒序返回；正文块含可选 `mentions: [{id,name}]`，消息含引用摘要 |
| `GET /conversations/{id}/activity` | 当前成员运行与进度 |
| `PUT /messages/{id}/reaction` | 与单聊相同的幂等表情设置接口 |
| `POST /runs/{id}/cancel` | 取消指定成员运行 |

本次移除客户端旧群聊 SSE 发送协议，群聊使用与单聊相同的持久消息接口及事件同步；不保留旧协议兼容层。

## 升级与回滚

新增 PostgreSQL 迁移 `0070_group_chat_execution.sql`，历史迁移不变。重建活动会话唯一索引，使群消息可以有多个独立回合，单聊和后台任务约束保留；新增 `group_deliveries` 表保存触发消息、深度和成员快照，采用强制 RLS、复合外键和唯一投递约束。无消息回填；索引重建扫描回合表并取得写锁，耗时取决于历史回合数量和锁竞争，应在维护窗口停止受理并等待运行收尾，先备份，再执行 `tomd upgrade`。节点协议未改变，不需重建电脑镜像。

客户端与服务端配套升级。运行时只按主键或会话序号进行有界读取，不逐条读取引用原文；投递上限限制每次事务规模。归档/成员变更与发送都通过群会话锁串行化，完成与发送再共享用户调度锁，唯一约束防止恢复重复投递。

不能直接启动不认识新迁移的旧二进制。优先用前向修复版本回滚功能，数据库修正只能新增更高版本迁移；若整体回退，停止受理并等待运行结束，保全新增群消息，再恢复升级前数据库备份和匹配程序版本。

验证覆盖提及解析、广播与定向投递、同键并发、引用和租户边界、bot 转交、用户提及、循环上限、成员移除、失败通知、新迁移及客户端接口、菜单和实时同步。`TestDesktopGroupChat` 使用真实 HTTPS 服务与隔离 Electron 验证建群、提及、引用、成员修改、重命名、置顶、重开和删除。模型是否主动使用转交工具仍取决于所选模型；运行器协议由可控模型集成测试覆盖。
