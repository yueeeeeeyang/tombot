# 群聊与提及

群里的猫咪是平等成员，用户管理群名称和成员。没有协调者、群内职责分配或自动汇总。未提及成员时，所有活跃成员各自处理用户消息；有提及时，只向指定成员投递。成员仍使用自己的模型、语言风格和私有记忆，最终发言按完成顺序排列。

## 桌面交互

点击聊天顶部的群名胶囊打开右栏，包含详情、资料库和成员三个页签。群名称默认只读，点击铅笔后编辑；成员栏点击“添加成员”打开搜索菜单，悬停或键盘聚焦成员行时显示移除按钮。群里至少保留一位成员。修改期间禁止重复提交，版本冲突保留输入并刷新版本，用户再次操作才重试。

建群时按所选成员顺序保存前四位猫咪的头像品种快照，列表、标题胶囊和右栏使用同一快照。之后增删成员、修改猫咪品种不会重置群图标。资料库只列本群已完成消息里的共享文件引用，包括附件和工具产生的文件，不合并成员的私聊资料。按消息序号每页读取 50 条含文件的消息，客户端可继续加载。

## 可见范围与连续提及

消息持久化两个独立字段：`audience_json` 为空数组表示公开，否则仅列出的成员与发送猫咪可读取；`mentions_json` 表示需要投递的对象。用户始终能查看完整群聊。客户端提交成员 ID，同时在正文显示自然的 `@名称`；服务端也识别手工输入的完整名称。重名必须通过菜单选择，未知成员或重复 ID 显式报错，不降级成全员广播。

可见范围在模型上下文、`conversation_search` 和 `conversation_read` 的 SQL 查询中执行，先过滤再分页。读取不可见消息作为锚点会返回不存在。回复、工具结果和未指定新收件人的群发言继承触发消息的可见范围。群聊不使用共用历史摘要，超出窗口时告知模型历史不完整，避免跨成员摘要泄露。

猫咪可通过 `post_to_group` 的 `mentions` 指定成员 ID 或 `user`，也可在最终回复中使用完整的 `@成员名`、`@用户`。明确提及的单条发言会在当前猫咪完成后交给收件猫咪，原始用户消息不会随之转发。提及用户不会产生新的模型调用。工具内不等待收件猫咪，避免全局执行槽相互等待。

同一消息与收件人组合只投递一次；一轮最多 64 次成员执行，提及最多延伸 4 层，达到上限保留已有回复并显示提示。运行仍受并发、队列、单次执行和回合费用上限约束。取消时等待工具和用量收尾；进程重启将未完成回合标为中断，不自动重放具有副作用的工作。

共享工作区维持原权限：上传到 `shared/` 的文件可被有共享工作区权限的猫咪读取。消息提及限制不会把共享文件转换成私有文件。

## 接口

路径前缀为 `/api/v1`，均需要已授权设备。

| 接口 | 参数与返回 |
| --- | --- |
| `GET /groups` | `cursor`、`limit`（1–200），返回含 `avatar_presets` 的分页群列表 |
| `POST /groups` | `name`、`members`，可选 `purpose`、`max_cost_micro` |
| `GET /groups/{id}` | 群名称、成员、固定头像、会话 ID、版本 |
| `PATCH /groups/{id}` | 当前 `revision`，可更新名称、用途和费用上限 |
| `POST /groups/{id}/members` | `revision`、`bot_ids`，已有成员不重复添加 |
| `DELETE /groups/{id}/members/{botId}` | 查询参数 `revision` |
| `GET /groups/{id}/artifacts` | 可选 `before` 消息序号，返回 `artifacts` 和下一页 `next`，0 表示结束 |
| `DELETE /groups/{id}` | 查询参数 `revision`，删除群记录、会话及执行，保留猫咪与共享文件 |
| `POST /conversations/{id}/messages` | `content`，可选 `mentions`、附件与回复标识；创建群回合 |
| `POST /turns/{id}/cancel` | 取消整个回合 |

服务端移除 `routing`、`coordinator_bot_id`、`max_speakers`、`auto_summary` 和 `role_notes` 契约，旧客户端必须配套更新。`turn.plan` 仅保存内部投递状态，不再插入分工卡片。流式 `delta` 增加 `message_id`、`bot_id`，桌面按消息标识累加，避免并发回复串进同一气泡。

群修改采用版本检查与事务，活动回合期间禁止改名、成员变化和删群。实际模型请求由统一队列和猫咪互斥处理，审批等待释放调度名额。费用是软上限，已经发出的并行请求仍会如实结算。

## 迁移与回滚

新增 `0027_equal_group_members.sql`，不修改历史迁移。它删除旧群路由列与职责备注，增加固定头像快照、消息可见范围、提及与执行触发消息标识。已有消息正文不变且默认保持公开；历史共用群摘要清空，下一轮从可见原始消息读取。历史群无法恢复已经移出的初始成员，因此升级时取现存成员中最早加入的四位作为固定快照。

SQLite 删除列会重写群及成员表；头像回填读取群成员，清理群摘要扫描群会话。迁移持有模式写锁，执行时长取决于群、会话及消息规模，大库需要维护窗口。消息新增列带常量默认值，不逐条重写正文，但新增约束需要校验已有行；查询复用会话序号与成员索引，读取和投递均有界。

升级前停止活动回合，备份完整数据目录与工作区，先升级服务端再配套更新桌面端。旧二进制不能打开版本 27 数据库。完整回滚需停服务，先保全升级后新增内容，再恢复升级前数据、工作区和对应二进制；不能只回滚二进制或修改迁移记录。继续使用新版时，结构修正只能新增更高版本迁移。

自动测试覆盖平等回复、指定成员与重名提及、原始消息隔离、历史搜索与锚点隔离、连续提及上限、并发、取消、用量、版本冲突、固定头像迁移和资料库分页。真实上游模型的自然回复与主动使用提及工具仍取决于所选模型；本地模型集成用例通过环境变量单独启用。
