# 群组协作与恢复约定

## 使用方式

工作台通过“创建群组”选择成员、填写用途、设置协调者与路由。群会话展示成员色带、公开发言、分工卡和执行状态；点击成员标签选择 @ 提及。群组设置支持增删成员、编辑群内职责、调整费用与人数上限、关闭自动汇总，以及删除群组。删除群组会删除其转录和执行记录，保留成员 Bot 与共享文件。

群成员最多 32 位，每回合最多 1–8 位发言，默认 3 位；默认回合预算为 6 美元。所有群设置与成员操作使用版本号，冲突时保留表单草稿并提示重新读取。活动回合期间禁止编辑群配置或修改、删除其成员 Bot，覆盖规划尚未创建 Run 的窗口。Bot 本身的消息策略仍控制是否接受群邀请。

## 路由和执行

| 路由 | 行为 |
| --- | --- |
| `mention` | 有提及时只分配给所选成员；未提及时交给协调者；无协调者时写入系统提示，不启动 Run |
| `all` | 按持久成员顺序分配，跳过归档成员，超出人数上限时裁剪 |
| `coordinator` | 使用协调者模型的独立路由提示生成 JSON；仅解析失败重试一次，仍失败时交给协调者处理用户请求，并显示 `PLAN_FALLBACK` |

路由模型只接收群用途、公开角色、最近 20 条公开转录和当前请求，不带人格或工具。规划调用也计费，保存为 `source=group`、`plan_role=coordinator` 的 Run。单步规划限时为运行时步骤上限与 30 秒的较小者；规划输出最多 32 KiB，拒绝未知字段、重复字段、越权成员与尾随内容。

成员 Run 使用 `plan_role=member`，复用全局执行队列与每 Bot 互斥。编排器不占用模型槽，避免等待自己的子任务。每个成员看到回合开始时固定序号以内的公开转录与自己的分工，不读取同时执行的其他成员输出。思考、工具参数、工具结果与私有文件内容不会自动转发；成员主动写入公开发言的内容会被其他成员看到。群转录不会自动写入长期记忆。

完成的成员发言按完成顺序排列；流式占位消息使用稳定消息 ID，完成时更新序号，因此界面可能重排正在流式生成的消息。序号允许有间隔，客户端按 ID 去重，再按最终序号排序。相似度超过 0.9 的同成员分工去重；同成员的不同分工合并成一个 Run。连续两条无工具调用且不足 40 字的成功回复触发提前收口，已经启动的并行执行正常收尾。

自动汇总在成员结束后由协调者执行一次，输入保留各成员文本、状态与失败码。汇总不调用工具，不开始新分工；只有一位成员且就是协调者时不重复汇总。模型或预算原因导致汇总失败时保留成员结果并显示提示；基础设施与持久化失败不会伪装为正常汇总降级。

## 成本、取消和恢复

单 Run 的预算取运行时预算与群回合预算的较小值；每次模型调用、工具执行与审批恢复都检查 Run 和 Turn 账本。规划、成员、审查与汇总的实际费用累加到同一 Turn。达到回合上限后不再新增分工；已经发出的并行请求可能产生超额费用，系统如实结算，不能把软预算当成预付费硬限额。剩余预算不足时不强制额外调用协调者，改为系统提示收口。

群回合整体墙钟上限沿用 `TOM_RUN_TIMEOUT`，包含排队时间。取消会传播到规划和全部成员；编排器等待子 Run、工具、审批与费用收尾后才发出唯一的 `turn.finished`。服务重启中断所有未完成群回合，包括尚未创建 Run 的 queued 回合，不自动重新规划或重放工具。数据库收尾失败会明确记录错误，回合保留活动状态，由重启恢复处理，避免无记录地继续执行。

## 工具

工具必须由 Bot 工具白名单启用，沿用精确策略、可选独立审查和严格度审批。

| 工具 | 参数与限制 | 策略动作 |
| --- | --- | --- |
| `group_members` | `group_id`；仅当前有效成员可读取群的公开角色资料 | `group.read`，低风险 |
| `post_to_group` | `group_id`、`message`；只允许当前群回合内的活动 Run，追加公开消息，不创建新回合 | `group.post`，低风险 |

追加发言最多 16384 个 UTF-8 字节，每 Run 的 Bot 公开消息总数最多 64 条（包括普通模型回复）。发言的消息 ID 绑定工具调用 ID，事务重试不能重复发布。消息、审计和事件同一事务保存，审计不写正文。工具追加消息只进入群转录；当前 Run 通过工具结果获知成功，避免破坏模型协议要求的工具调用与结果顺序。私信来源不能调用该工具返回群组。

## HTTP 与事件契约

以下路径相对于 `/api/v1`，均需要设备鉴权。

| 方法与路径 | 参数 / 返回 |
| --- | --- |
| `GET /groups` | `cursor`、`limit`（1–200）；分页配置列表，成员在详情中读取 |
| `POST /groups` | `name`、`purpose`、`members`，可选路由、协调者、人数、费用及汇总开关；返回群详情 |
| `GET /groups/{id}` | 配置、成员、会话 ID、`revision` |
| `PATCH /groups/{id}` | 必须提交 `revision`；`coordinator_bot_id=null` 清空协调者 |
| `POST /groups/{id}/members` | `revision`、`bot_ids`，可选 `role_notes`；已有成员只在显式提供时更新职责 |
| `DELETE /groups/{id}/members/{botId}` | 查询参数 `revision`；协调者须先更换或清空 |
| `DELETE /groups/{id}` | 查询参数 `revision`；返回 204 |
| `POST /conversations/{id}/messages` | `content`、可选 `mentions`（唯一的有效成员 ID）；返回 Turn 和用户消息 ID；群组提交不返回单个 Run ID |
| `POST /turns/{id}/cancel` | 取消整个群回合，最终状态以事件或快照确认 |

群配置的更新、成员变化与删除必须携带当前版本，旧版本返回 `GROUP_CHANGED`。会话列表附带公开 `members` 元数据，避免侧栏逐群查询。会话快照增加 `active_runs`（ID、成员、状态、执行角色），使重新连接后仍能展示并行状态。`turn.plan` 携带完整分工，消息历史中也保存可更新的分工卡；`run.started/run.status` 标识成员执行，`turn.finished` 只由编排器统一发送。

## 迁移、性能与回滚

新增且仅新增 `0010_group_execution.sql`。为群配置增加 `revision` 和 `auto_summary`，为回合增加预算、不可变群配置快照与历史截断序号，并建立群成员反查、群分页、回合执行状态索引。历史 0001–0009 未修改；单聊的回合预算字段为空，仍使用原有 Run 限额。

迁移在 SQLite 写事务内执行，新增索引需扫描 `groups`、`group_members`、`runs`。执行时间随现存记录数量增长，会持有模式写锁；大库应预留维护窗口。运行时配置、成员与快照读取均有数量上限，新增成员与配置写入使用事务及版本竞争检查。

升级步骤：停止活动任务和服务，备份完整数据目录及工作区，替换服务端与客户端，再启动执行迁移并运行必要自检。旧二进制会拒绝打开版本 10 数据库。回滚必须停止新服务，恢复升级前完整数据和工作区快照、匹配的旧二进制与客户端；不能只替换二进制或删除新列。升级后的新消息和文件应在恢复前另行保全，结构修复必须新增更高版本迁移。

## 验收边界

群汇总只读取本回合用户的请求，以及已完成成员的标识、显示名、状态、错误码和公开回复原文。协调者收到一条包含这些引用材料的用户消息，系统指令独立。群成员的并行执行仍使用各自的角色和私有索引。若原话与预留回复空间超出模型窗口，汇总失败并保留成员结果。此调整同步随服务升级，沿用数据库版本 0014；回滚前等待活动群回合结束，再替换为上一版服务。

真实模型验收把三份预订分别写入三个 Bot 的私有记忆，每人只持有自己的场次、时间和地点。用户要求编制日程，成员分别公开核对，协调者按场次汇总。断言逐条匹配三份原始预订、每个执行的身份与真实用量，并核对回合结束时各自私有文件的路径、数量和 SHA-256。

macOS ARM64 使用 llama.cpp b12144 与 Qwen2.5-1.5B-Instruct Q4_K_M，权重摘要为 `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`。在本地推理服务的启动参数中设置 `--ctx-size 4096 --parallel 1 --temp 0 --seed 42`。按[本地推理服务配置](conversation-activity.md)设置 `TOM_TEST_LOCAL_MODEL_URL` 和 `TOM_TEST_LOCAL_MODEL` 后运行以下命令。0.5B 模型在同一场景曾混淆时间或漏列场次；单聊算术通过不能证明模型能胜任这项汇总。[固定版本权重](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/tree/91cad51170dc346986eccefdc2dd33a9da36ead9)

```sh
go test -race -count=3 -run '^TestLocalModelGroupAssignment$' -v ./internal/httpapi
TOM_TEST_NATIVE_GROUP=1 go test -race -count=1 -run '^TestLocalModelGroupAssignment$' -v -timeout 6m ./internal/httpapi
```

回归覆盖三路由、并行与 Bot 互斥、规划重试和回退、公开上下文隔离、发言完成顺序、费用、空转、取消、无 Run 回合恢复、邀请与编辑冲突、审计回滚、工具审批及私信回群拒绝。真实本地 HTTP 模型流覆盖三个并行成员各执行一次群发言工具，再继续模型回复，并通过 SSE 和原子快照验证消息及费用。Flutter 覆盖 390／900／1440 宽度、成员身份、提及、分工卡、停止按钮、成员编辑和版本冲突。

使用上述 1.5B 权重对三组预订重复创建独立实例，连续十次完成时间与场地核对；另行从 macOS 原生工作台发起的三次复验也通过。验收只针对这个任务和模型配置。

本地可控模型协议测试不代表外部商业模型验收。后续接入的 `message_bot`、`delegate_task`、私信旁观和介入，以及跨会话跳数／频率限制见 [Bot 私信与任务委派](messaging.md)。原生人工交互与完整视觉基线继续在 M8 验收。
