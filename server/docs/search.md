# 全局搜索与消息定位

已认证设备可调用 `GET /api/v1/search?q=...&cursor=...&limit=...`。服务器就绪门禁、设备撤销与其他业务 API 一致；模型工具仍使用独立的参与者权限检索，不能借用这个管理员接口。

`q` 去除首尾空白后须为 1–128 个 Unicode 字符、最多 512 字节，不接受控制字符。查询按字面文本匹配，百分号、下划线、引号和 FTS 运算符不会扩展查询范围。`limit` 默认为 20，范围为 1–50。空查询返回 `SEARCH_QUERY_INVALID`，界面应在输入为空时显示引导。

响应为 `{items: [...], next_cursor?: "..."}`，每项字段如下：

| 字段 | 含义 |
| --- | --- |
| `kind` | `bot`、`conversation` 或 `message` |
| `id` | 对应 Bot、会话或消息的稳定标识 |
| `title` | Bot 名称或所属会话标题 |
| `preview` | Bot 职责、命中附近的公开正文片段，标题结果为空；最多 240 字符及省略号 |
| `conversation_id` | 可打开的会话 |
| `bot_id` / `group_id` | 所属 Bot / 群组，可为空或省略 |
| `conversation_kind` | `direct`、`group` 或 `bot_dm` |
| `source` | 会话来源，例如 `user`、`routine` 或 `delegation` |
| `message_id` / `seq` | 仅消息命中提供，用于精确定位 |

结果依次排列为 Bot、会话、消息；每类按不可变的创建时间、标识倒序排列。Bot 匹配名称和职责，会话匹配标题，消息检索全部已保存公开正文，包含当前聊天首屏以外的历史。归档会话与归档 Bot 条目、尚在流式输出的消息不参与搜索。同一 Bot 名称可同时命中 Bot 和其会话，客户端应按 `kind` 区分。

`next_cursor` 是绑定查询内容的游标，应原样传回，不可用于另一个查询。分页使用创建时间及标识作为边界，同毫秒记录不会重复或遗漏；分页期间新增的记录若排在当前边界前，需要重新搜索才能看到，已删除或不再匹配的记录自然消失，不保存服务端搜索快照。

索引复用 `0014_conversation_tools_and_questions.sql` 已收窄的 `messages_fts`：仅索引消息的 `text` 与 `note` 正文，不读取私有记忆、角色提示词、摘要、供应商配置、密钥、工具参数/结果或附件路径。三字及以上查询使用 trigram FTS，短词使用转义后的字面扫描；整次查询的数据库操作限定 3 秒，超时明确返回 `SEARCH_TIMEOUT`，不返回不完整结果。每页最多读取 51 条用于判断续页，不在应用层加载全量历史。短词命中很多时应增加查询字符以缩小范围。

## 命中消息上下文

`GET /api/v1/conversations/{id}/messages?around_seq={seq}&limit=50` 返回与普通消息接口相同的消息数组，按 `seq` 升序排列，保证包含锚点。最多返回 200 条，锚点前最多取 `floor(limit/2)` 条，其余向后读取；接近末尾时可以少于 `limit` 条。窗口总消息块大小不得超过 1 MiB，超过时返回 `MESSAGE_WINDOW_TOO_LARGE`，客户端可减小 `limit` 重试。

`around_seq` 必须为正整数，不可与 `before_seq` 同时使用。锚点不存在或不属于指定会话返回 `CONVERSATION_MESSAGE_NOT_FOUND`；读取同样有 3 秒超时。未提供 `around_seq` 时保持既有最近消息和 `before_seq` 分页语义。客户端可在独立上下文窗口显示命中与相邻消息，并提供打开会话入口，避免将历史片段直接混入当前实时消息列表造成中间缺口。

## 部署与回滚

本次仅新增查询及有限窗口服务，无新数据库结构、索引或迁移，不改写历史数据。现有消息写入、更新与删除的触发器继续在同一事务维护公开正文索引。部署后旧客户端仍使用已有消息分页；回滚应用版本后新增搜索与 `around_seq` 能力不可用，已保存消息无需回滚。使用新客户端时应与提供这些接口的服务端一起发布。
