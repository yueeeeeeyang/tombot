# 私有记忆

每个 Bot 的长期记忆保存在其工作区 `.tom/memory/*.md`。群聊与私信记录不会自动复制为记忆；只有显式工具调用或用户编辑会写入。记忆检索和提示索引始终使用执行 Bot 的身份，工具没有跨 Bot 参数。

## 文件格式与索引

Markdown 是权威来源，SQLite `memory_index`、`memory_fts_ascii`、`memory_fts_cjk` 都是可重建的派生数据。支持平铺的普通 `.md` 文件，不跟随符号链接，不接受特殊文件或子目录。每个 Bot 最多 512 个文件、合计 8 MiB，单文件最多 1 MiB，目录扫描最多 2048 个目录项。超过 200 行或 64 KiB 时返回 `too_long`，仍可读取和检索；超过硬容量则明确报错，不使用旧索引掩盖失败。

YAML front matter 只解释 `title`、`tags`、`importance`。缺省标题使用文件名，重要性默认为 3，合法范围为 1–5；标签最多 16 个且不重复。未知字段以原始行保存，编辑已知元数据不会解释或展开未知字段。整个头部使用 YAML flow mapping 的文件可以读取，但界面或工具修改元数据会明确拒绝，需先在工作区将头部改为块格式，避免重排未知内容。

摘要取正文首个非空行，最长 240 字符。工具或创建接口的 `summary` 不作为第四个受解释的头部字段；传入与正文首行不同的摘要时，将其作为首段写入正文。这样手工编辑、重启与全量重建得到相同摘要。记忆编辑器直接编辑正文，并提示首行用于列表摘要。

服务启动时按 Bot 分页重建索引，之后每十分钟检查。记忆工具、工作区编辑与普通文件写入工具在提交后立即校正；列表、读取、搜索和模型索引生成前也会校正，因此 Shell 或外部手工修改在下一次读取时可见。单个 Bot 的坏文件不会阻断其他 Bot 的后台校正，但该 Bot 的记忆操作和需要索引的模型调用会返回错误；后台同时发出带 Bot 标识的系统通知。

## 检索与模型

英文使用 FTS5 porter/unicode61，包含中日韩字符的查询使用 trigram；存在不足三个字符的中日韩查询词时，采用受上述容量约束的字面 `LIKE` 查询。查询最多 512 UTF-8 字节、16 个词，词之间为 AND，用户输入不作为 FTS 操作符执行。结果默认 5 条，最大 50 条，包含路径、标题、摘要、片段、SHA-256 和长度提示。

排序使用正向相关度乘以 `1 + 0.2 × importance`，再按更新时间作三十天半衰；未来时间按零年龄处理。短词字面查询使用相同的重要性和时间权重。读取和检索更新 `last_used_at`，但不因此提升更新时间权重。

运行时注入不超过 2 KiB 的私有记忆索引，包括说明和截断提示；按重要性、更新时间选择完整条目，不截断 JSON 行。需要更多内容时模型使用 `memory_search` 和已有 `file_read`。

模型工具：

| 工具 | 输入与行为 | 默认风险 |
| --- | --- | --- |
| `memory_search` | `query`、可选 `limit`，仅当前 Bot | low / `fs.read` |
| `memory_write` | `title`、`content`，可选 `summary`、`tags`、`importance`；更新还需 `path` 与 `expected_sha256` | medium / `fs.write_outside_out` |
| `memory_delete` | `path`，可选 `expected_sha256`；准备阶段读取并绑定文件摘要 | high / `fs.delete` |

工具遵循 Bot 白名单、显式规则、独立审查和审批。新 Bot 默认包含三项记忆工具，已有 Bot 的白名单不自动修改，可在设置中启用。审批期间文件变化会使旧提案失效，不能凭旧审批覆盖或删除新内容。

## 管理接口与客户端

以下接口均需设备鉴权，前缀为 `/api/v1`：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /bots/{id}/memory` | 记忆列表，不返回正文；提供 `query`、`limit` 时检索 |
| `POST /bots/{id}/memory` | 创建，接收标题、正文、标签、重要性和可选摘要，返回 201 |
| `POST /bots/{id}/memory/reindex` | 重建当前 Bot 两套 FTS，返回条目数 |
| `GET /memory/{botId}?path=…` | 读取当前正文与版本摘要 |
| `PATCH /memory/{botId}?path=…` | 全量提交已知元数据和正文，同时要求 `expected_sha256` |
| `DELETE /memory/{botId}?path=…&expected_sha256=…` | 条件删除，成功返回 204 |

创建路径从标题生成；同名文件返回冲突，不覆盖。更新必须显式指定私有路径，重要性为 1–5；SHA-256 过时返回 409。文件已变更但索引保存失败返回 `MEMORY_SAVED_INDEX_FAILED`，用户应先刷新确认实际文件状态，客户端不会自动重复写入。

Flutter 在 Bot 顶栏提供“私有记忆”，详情面板展示前三条摘要；记忆页支持搜索、创建、编辑、删除确认与重建索引。`memory.updated` 仅刷新对应 Bot；迟到的搜索结果被丢弃。编辑冲突和事件刷新不会覆盖草稿，重新读取或离开未保存编辑需确认。

## 一致性、性能与回滚

记忆操作持有服务互斥与 Bot 文件租约，防止内部并发覆盖和写入期间删除 Bot。条件写入还在工作区写锁内重新比较 SHA-256。外部进程不共享服务锁，可能在读取或校验后改变文件；返回版本用于下一次条件写入，服务不会宣称与任意外部编辑器实现跨进程事务。

文件变更前先持久审计意图，正文和未知元数据不进入审计或事件。写入采用同目录临时文件、同步及原子替换；删除同步目录。随后在单个 SQLite 事务内更新元数据、两套全文索引和通知事件。文件与 SQLite 不构成单一原子事务：后者失败时返回明确错误，文件保留，并在后续校正中恢复索引。数据库事务失败不会留下半套 FTS。

扫描、查询和写入受文件数量与容量上限约束，短词不进行无界全库扫描。读取前校验会增加最多 8 MiB 的文件 I/O；当前记忆服务串行处理索引操作，适用于单用户规模。周期任务按每页 100 个 Bot 读取，每个 Bot 校验上限 30 秒。若遇慢存储，应以实际负载评估延迟，不将当前实现宣称为多租户并行搜索服务。

本功能复用版本 11 数据库，无新增或修改迁移。YAML 解析依赖锁定为 `go.yaml.in/yaml/v3 v3.0.5`。升级前停止活动任务并备份数据目录和完整工作区，再同步升级服务与客户端；首次启动将重建派生索引，预留与记忆总量相称的 I/O 时间。回滚时停止服务，恢复升级前的完整快照以及匹配的服务、客户端，禁止手工改迁移账本。记忆文件包含用户长期内容，应随工作区加密备份。

## 验证

Go 竞态测试覆盖固定中英文语料、词干与短词、前三名排序、Bot 隔离、2 KiB 提示索引、未知元数据保留、手工编辑和重复重建、后台启动与周期校正、文件数量和容量、链接与 FIFO 拒绝、并发条件写入、审计和索引故障恢复、审批后的文件变化。真实本地 HTTP 模型上游完成写入提案、审批、检索、提示索引注入和费用结算；这不代表外部商业模型账号验收。

客户端组件测试覆盖 390／900／1440 宽度下的创建、更新、删除，编辑冲突与重新读取确认，跨 Bot 事件隔离、迟到的搜索结果、索引重建失败。原生桌面人工交互仍属于项目最终验收范围。
