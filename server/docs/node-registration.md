# 节点与镜像登记

`tomnode-register` 为部署登记本机节点与固定镜像版本。它使用与 `tomd` 相同的非 root 身份和服务配置，只写 PostgreSQL 目录与审计，不持有 Docker socket，不启动容器，不提供把节点标为就绪的参数。

登记成功后新节点为 `bootstrapping`，还不能创建账户。[镜像准备命令](image-preparation.md)及[独立节点服务](../internal/nodeapp/README.md)已接通，[控制心跳租约](node-health.md)也已接入，完整能力探针及就绪发布仍在生产部署阶段继续接入；节点控制通知不改变登记健康状态，不能手工改成 `ready` 来绕过这一边界。

## 前置与调用

先通过 `tomdb` 在全新 PostgreSQL 执行全部迁移（包含 `0045`），并按[服务配置](../internal/serverapp/README.md)准备四个用途分离的数据库连接。节点 ID 在部署时生成并保留，与 API 的 `node.id` 和后续独立节点配置一致；命令从服务配置读取该 ID，不接受操作文件覆盖。

`make build` 与 `make release` 包含此命令。安装与宿主架构匹配的二进制，使用 API 服务身份执行：

```sh
# 操作与配置文件不包含明文凭据，只引用各自受保护的文件。
TOM_SERVER_CONFIG=/etc/tombot/server.json \
TOM_NODE_REGISTRATION_REQUEST=/etc/tombot/node-registration.json \
/usr/local/bin/tomnode-register
```

不接受命令行参数，拒绝 root；命令本身不限制操作系统，宿主检查由节点程序负责。配置和操作文件必须使用规范绝对路径，由 root 或当前服务身份持有，不可被组或其他用户写入，拒绝末级链接及非普通文件。数据库连接文件另须仅所有者可读；命令校验四个连接属于同一数据库，只打开控制连接，并复验完整迁移账本。

首次并发登记使用覆盖全部唯一约束的 `ON CONFLICT DO NOTHING`，随后读取并核对节点、镜像和完整登记字段；名称或引用被其他身份占用时仍返回冲突，整个事务回滚。相同登记只创建一次资源与审计，不重试未知事务结果。[PostgreSQL INSERT 冲突范围](https://www.postgresql.org/docs/16/sql-insert.html)。

## 操作文件与回执

首次登记使用以下字段；示例中的镜像 ID 和引用须替换为实际发布值。ID 使用规范大写 ULID，镜像使用完整 `@sha256:` 摘要。不要填写认证信息，镜像仓库认证应由独立节点的受保护部署机制处理。

```json
{
  "action": "register",
  "name": "主节点",
  "capacity": 20,
  "image_id": "部署生成并保留的镜像 ULID",
  "image_reference": "实际仓库及镜像路径@sha256:实际的64位小写十六进制摘要"
}
```

`capacity` 为节点可预留的用户电脑数量，取值 1–10000，须依据宿主验收结果设定。它不是 CPU、内存或磁盘硬限制的替代；每台用户电脑还使用开户规格中的实际硬限制。

相同字段重复登记复用目录；不同字段冲突时返回非零状态，不覆盖已有节点或版本。首次创建的镜像允许后续供给选用，此状态不证明镜像已经拉取或运行成功。再次登记不会重新启用已停用镜像，不改变节点的运行状态、预留容量、控制代次或健康时间。换镜像使用新 ID 和新固定摘要，不能修改原版本引用。

查询原登记仅包含：

```json
{"action":"status","image_id":"原登记的镜像 ULID"}
```

操作文件允许缩进，拒绝未知字段、重复键、大小写别名、空值、尾随对象及混合动作。不能传入 `node_id`、`endpoint`、`status` 或 `is_enabled` 来覆盖部署身份或运行状态。

成功回执包含 `action`、`request_id` 和 `catalog`。目录内含节点的 ID、名称、状态、容量、预留量、代次和可选健康时间，以及镜像 ID、固定引用及启用状态。日志携带节点、镜像和请求 ID，不记录配置内容或数据库连接。审计与新增目录在同一事务提交；重复登记不制造重复变更审计。

进程中断、数据库失联或输出失败均不能假定没有写入。保留原配置、操作文件和身份，先查询原目录；只有同参数登记允许幂等重试。命令不自动发起第二次写入。名称、容量或版本冲突须查明原记录，不能删除记录或改用随机身份绕过。

## 迁移与回滚

`0044_computer_catalog_identity.sql` 只通过新增迁移实施变更：删除未使用的节点网络端点列，增加节点及镜像身份保护触发器，撤销控制角色对两类目录的删除权限。现有节点状态、容量、预留量、镜像引用及电脑关联保持不变。所有历史迁移不可变，不导入旧 SQLite 数据。

迁移不包含表扫描、索引构建或用户数据转换；`ALTER TABLE` 与触发器创建仍需短暂结构锁，应在停单、数据库备份完成的部署窗口执行。迁移器具有锁和语句时限，失败整体回滚，不能关掉检查强行运行。

API、部署命令与数据库迁移成套发布。旧二进制的迁移账本检查会拒绝新版本，不能只回退程序后继续接单。应用修正使用更高版本前向迁移；整套恢复须使用经过验证的配套备份，保留用户电脑、目录身份、预留量、审计及控制记录，不删除新迁移、重置账本或重新登记来掩盖未知状态。

本次没有改变本机节点通信协议或电脑镜像，没有把任何真实节点/用户电脑标为就绪。目录与开户门禁已有真实 PostgreSQL 证据，完整生产节点和首次部署仍待联调；后续步骤见[首位管理员部署](admin-bootstrap.md)及[实施进度](multi-user-progress.md)。
