# 多节点自动接入

接入码携带主服务信息，离线安装包携带固定电脑镜像及宿主软件清单。每台节点首次启动时自动登记节点、镜像和控制连接，管理平台无需手工录入目录；服务端支持多台节点同时接入，并按节点 ID 路由全部电脑、终端、桌面和 Agent 请求。

## 使用步骤

1. 启动新版 `tomd`，启动迁移会创建节点连接目录。服务配置的 `node` 仅保留共享 API 客户端证书及运行预算，`maximum_nodes` 默认 128，可配置为 1–1000。
2. 管理员打开“电脑节点 → 生成接入凭据”，完成近期身份验证后生成并复制凭据码。每个新节点使用独立的一次性凭据，有效期 24 小时。凭据码只在本次弹窗可见，关闭后不能再次查看；通过受保护渠道交付，在节点安装提示中粘贴。
3. 完整解压对应架构的离线安装包，执行 `sudo ./tomnode install`，粘贴接入码并确认节点地址。默认不需要 JSON；名称、容量、监听及可达地址可通过[可选参数](../deploy/NODE.md#自动填写与可选参数)覆盖。
4. 安装器自动校验、导入随包镜像，安装 Docker 及宿主依赖，生成并保存节点身份，打开控制监听后自动接入。管理平台刷新即可看到节点。其他节点使用各自的接入码。

接入码包含主服务 `admin_origin` 和 HTTPS 叶证书 SHA-256 指纹，来源必须是节点实际可达的 HTTPS 地址。节点先核对该指纹，再从 `GET /api/v2/node-bootstrap` 获取 API 客户端证书指纹与验收资源；两类证书用途不同，但都无需手填。节点自己的证书由安装器创建，随签名登记自动绑定到服务端。

服务端可达的节点地址与本机监听地址可以不同，NAT/端口映射须在安装时确认。HTTPS 来源不带路径、尾斜杠、查询参数或认证信息，不自动发现公网地址。电脑镜像离线交付；Docker 与宿主软件仍在线从官方源安装。

## 认证、并发和恢复

管理接口 `POST /api/v2/admin/computer-nodes/enrollment-tokens` 使用现有管理 Cookie、来源、CSRF 与近期验证。接入码只返回一次，数据库仅保存内部一次性凭据的 SHA-256 摘要。引导接口只接受未过期、未消费的凭据，读取不消费凭据，最多 16 个并发请求、每次 10 秒；客户端固定证书、15 秒超时、不重定向、不自动重试。安装器只将内部授权值保存到 root 0600 的私有文件，重试从安装快照恢复，不重复引导。节点通过 `POST /api/v2/node-enrollment` 提交 Ed25519 签名，覆盖节点 ID、名称、容量、镜像身份、连接地址、公开证书和时间；时间偏差上限为五分钟。

首次登记在同一事务中串行核对节点总量、消费凭据、创建目录及连接并写审计。并发使用同一凭据只能接入一个身份；任何部分失败全部回滚。连接地址和证书均唯一，已登记身份不能通过重试改绑。多个节点可使用相同镜像摘要，各自保留镜像 ID。

节点重启凭已绑定的证书签名确认身份，不依赖已消费或已过期的接入凭据。首次响应丢失时，重试也复用原身份。安装器始终保留首次生成的 ID 与证书；不要删除安装记录或重新生成身份来绕过冲突。运行配置检查仍要求引用文件存在且权限正确。

网络调用每次最多 10 秒，最多三轮，仅对传输失败、429 和暂时性网关/服务错误按 1、2 秒退避；首次 401 允许额外一次凭据认证挑战。禁止跟随重定向、无限重试及日志输出凭据。最终失败会使此次节点启动失败，修复网络、时间或授权后用原身份重启。

服务端按主键每页 100 条发现新节点，每个节点独立运行心跳与持久验收；一个节点断线不会阻止其他节点接受检查。连接缓存和监督器受 `maximum_nodes` 限制。节点登记仅产生 `bootstrapping` 状态，控制心跳和完整能力验收通过后才允许开户。基础能力未通过时，不得手工改写就绪状态。

## 升级与回滚

新增迁移 `0059_node_enrollment.sql` 创建连接目录与凭据摘要表，移除镜像摘要唯一约束并建立查询索引；既有节点、镜像及用户电脑数据保持原身份。旧版本迁移不修改。索引构建会扫描镜像目录，删除约束及建索引需要短暂结构锁；目录规模通常较小，仍应在维护窗口备份并执行，锁或语句超时会整批回滚。

这是部署契约变更。升级前停止新任务并备份数据库、程序、节点配置及证书。服务端删除旧 `node.id`、`node.url`、`node.server_fingerprints`、`node.verification.image_id`，保留 API 客户端证书与预算，可添加 `node.maximum_nodes`。旧单节点手动登记命令、登记文件和对应管理接口已移除，不提供兼容入口。当前完整发布包格式为 7。

已有节点升级时保留原节点 ID、镜像 ID、证书、名称、容量和摘要，在运行 `node.json` 添加 `enrollment`（其中 `server` 包含上述公开字段及受保护的 `enrollment_token_file` 运行时路径，`registration` 包含 `name`、`capacity`、`image_id`、`image_reference`），配置一份新凭据后启动新版。首次绑定清除旧健康租约，重新观察与验收后再接单；节点未绑定前服务端不会沿用旧静态地址。首次安装使用配套离线包及新版接入码，不必手写运行文件。已有安装的配置变更属于维护升级，不可作为原参数安装重试。

连接身份当前不可在线变更，地址、证书或镜像轮换需安排维护和明确的前向数据迁移，不允许通过重新登记覆盖既有绑定。节点证书有效期一年，须在到期前安排维护。

回滚必须恢复相匹配的数据库备份、配置和程序；旧程序会拒绝新迁移账本，不能只回退二进制。上线后的修正使用更高版本迁移，不能删除新脚本、复用版本号或手改目录绕过冲突。恢复时保留电脑磁盘、预留量、审计、未知操作和关闭屏障。

本次精简首次安装新增引导接口和封装接入码，没有新增数据库迁移。默认使用离线节点包，旧完整 JSON 输入和裸凭据不再支持；升级管理平台和服务端后重新签发。安装记录版本 2 不接管旧记录。已有节点保留原运行配置、私有凭据、证书和绑定身份，维护升级不重新执行安装器。首次安装工具回滚需恢复配套旧包及旧流程；已运行节点按上面的成套备份方案恢复。

## 节点详情、编辑与隔离恢复

管理平台列表显示独立的验收失败/隔离状态，节点名称进入 `/admin/computer-nodes/{id}`，详情支持直接打开和刷新。列表和详情通过同一个模态框编辑，保存后关闭弹窗并刷新所在页面，取消不写入；不再提供独立编辑页地址。详情包含连接地址、公开证书指纹、心跳时间、运行代次、镜像、验收阶段、错误分类、资源预算和已有能力证据。不返回接入授权、私钥、容器环境或任意远端错误正文。尚无探针结果显示“未确认”，不把在线或镜像就绪当作电脑就绪。

管理员可修改名称、准入容量及暂停/恢复接收新电脑，写入需要近期身份验证。名称唯一、容量为 1–10000 且不能低于已预留数。容量只影响新电脑准入，不会重新分配宿主硬件，也不会停止已有电脑。暂停撤回准入证据；恢复后重新验收。节点、镜像、地址和证书身份不可通过此页修改。节点重启签名仍验证原连接身份及固定镜像，但不再用安装时的旧名称/容量覆盖管理员配置。

编辑使用 `configuration_version` 和与容量预留一致的节点行锁；并发修改只有一个成功，重复读取再提交相同配置不递增版本。心跳不改变配置版本。读操作在一个数据库语句快照中联查目录、连接、镜像和验收，避免逐行查询；网络探针不在管理事务内运行。

隔离表示验收资源状态连续核实失败，自动重试已经停止。修复节点故障后，详情页“重新核对验收”先核对、清理原资源，原资源未确认清理前不会新建替代电脑。请求必须匹配当前验收令牌且没有有效工作租约，保留原资源身份和全部关闭屏障；不修改心跳、不跳过完整能力检查。终态失败可以提前下一轮正常验收。写操作记录管理员、请求标识、节点及变更摘要。

迁移 `0060_node_administration.sql` 仅新增配置版本和可空的节点错误分类字段，不回写业务记录或更改验收状态。常量默认值使用 PostgreSQL 元数据默认机制；新增错误码约束需扫描验收表，执行时持有短暂结构锁，应在维护窗口备份数据库并使用既有迁移超时。现有节点的配置版本从 1 开始，旧错误记录没有节点分类码时明确显示缺失。升级同时发布内嵌管理页面的新 `tomd` 与修复标签校验的 `tomnode`；不需要重建电脑镜像。

升级节点前停止接单并排空任务，保留节点状态，停止服务后用新二进制执行 `tomnode repair`。服务端执行 `tomd upgrade` 并自动应用迁移。回滚须恢复配套程序、服务配置、节点状态和迁移前数据库备份：旧迁移检查器会拒绝更高版本账本，不能仅回退服务端二进制或删除 0060。保留所有用户磁盘、未知资源和审计记录；有新业务写入后应使用后续迁移修正，不能直接恢复旧备份丢弃数据。

节点核验固定镜像的存储布局、桌面浏览器标记、受管容器及挂载身份。既有电脑需保盘换镜像。详见[升级与回滚](browser-readiness.md)。
