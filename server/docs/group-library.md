# 聊天资料库

单聊和群聊使用同一套资料库：只展示该会话中用户发送的附件和猫咪发出的文件。附件上传后先处于待发送状态，消息受理成功后才收录；取消发送的附件不显示。右栏不再提供独立上传入口，通过聊天输入框添加文件。两种聊天均支持名称搜索、游标分页、图片及文本预览、下载、重命名和删除。

## 存储与权限

文件元数据和正文分别保存在 PostgreSQL 的 `chat_files`、`chat_file_contents`，通过 `conversation_id` 绑定会话。电脑离线不影响读取；资料库文件是不可变快照，不随电脑上的工作文件变化。备份数据库必须包含文件正文。

单文件最大 16 MiB；每位用户所有单聊、群聊和待发送上传共用 256 MiB、1024 个有效文件配额。每页最多 20 条，名称查询最长 240 字节，按字面子串搜索；不会只搜索客户端已加载的历史消息。PNG、JPEG、GIF 校验可解码尺寸，单边不超过 8192 像素，总像素不超过 2000 万。文本预览最多 64 KiB；HTML/XML/SVG 以转义文本展示，其他二进制提供下载。

所有操作检查租户、会话归属及归档状态，数据库强制 RLS；私信内部会话不开放用户上传。单聊之间、单聊与群聊之间不能互相引用附件。上传以 `client_request_id` 去重；名称和内容变化必须使用新标识。修改和删除携带 `expected_revision`。发送请求的幂等摘要包含附件标识，不能用同一幂等键替换附件。已发送消息的重试不重新创建消息，也不因后来删除附件而失败。

上传配额、消息引用、收录、重命名和删除使用同一个用户锁串行化。收录标记与消息处于同一事务，成功后发布 `chat.library.changed`，携带 `conversation_id`；重复分享不重复发布收录事件。客户端只刷新对应会话，切换会话和搜索时丢弃迟到响应；重连和窗口聚焦重新读取。列表只读取元数据，索引按用户、会话、标识限制扫描范围，不逐文件读取正文。

删除原子释放正文和配额，保留墓碑及聊天快照；不能用旧上传重试复活文件。已进入模型上下文、已下载的内容不能撤回。归档会话的资料不可读取，恢复后可继续使用。

## 接口与猫咪工具

- `GET /api/v2/conversations/{conversationID}/files?before=&q=`：返回 `files`、`next` 和容量信息。
- `POST /api/v2/conversations/{conversationID}/files`：接收 `client_request_id`、`name`、`content_base64`，返回待发送的 `file`。
- `GET /api/v2/conversations/{conversationID}/files/{fileID}/content`：返回元数据和 Base64 正文，禁止缓存。
- `PUT /api/v2/conversations/{conversationID}/files/{fileID}`：接收 `expected_revision`、`name`。
- `DELETE /api/v2/conversations/{conversationID}/files/{fileID}`：接收 `expected_revision`，成功返回 204。
- 单聊和群聊的消息发送请求均接受 `file_ids`，最多四个且不能重复；只接受同会话有效文件。消息中的 `chat_file` 块保存文件快照，正文留在独立内容表。

上传和下载主进程调用超时 60 秒，其余调用 20 秒。上传允许 Base64 膨胀后的约 22 MiB 有界请求，普通接口仍限制为 1 MiB。反向代理应为新上传路由允许至少 23 MiB 请求；服务端仍限制原始文件最多 16 MiB。主进程下载校验大小和 SHA-256，再弹出保存窗口；取消不会报告成功。

猫咪通过 `chat_file_list`、`chat_file_read` 和 `chat_file_create` 操作资料库。群运行只访问当前群，单聊、私信协作及定时任务访问自己的用户单聊。创建工具一次最多生成 64 KiB UTF-8 文本，并在同一事务内发送附件、收录文件及保存工具回执；失败全部回滚，租约恢复重放回执，不重复发送。群运行仍受每轮发言上限约束。读取工具按字节分页且仅支持 UTF-8 文本，不解析 PDF、Office、图片等二进制；不能将文件内容当作指令。

## 升级与回滚

1. 备份并验证 PostgreSQL 可恢复；待当前运行结束后暂停收发，同步升级服务端和桌面客户端。旧群文件接口、消息块和工具已替换，不提供兼容层。
2. 新增迁移 `0074_chat_library.sql` 重命名文件表，将群归属映射到真实会话，新增收录标记和分页索引，并转换已有消息的附件块。历史文件正文、名称快照、摘要与删除状态保持不变；只有公开发送过的附件收录到目录，独立上传而未发送的文件不显示。
3. 迁移需扫描文件元数据及带附件的历史消息，持有文件、会话和消息表的独占锁；耗时随历史消息量增长，应在维护窗口执行并事先在备份副本验证。临时策略仅授权结构所有者进行跨租户回填，运行租户的 RLS 始终生效；事务结束前回收临时策略。迁移失败整体回滚，不修改任何历史迁移。
4. 客户端重开后从服务端读取转换后的聊天历史；升级前尚未发送的附件应重新选择，不重放旧群文件地址及旧上传幂等键。
5. 数据库版本不支持降级。优先用新迁移和修复版本前向修复；必须整体回滚时，停服、保留当前库备份，再恢复升级前数据库及配套程序。恢复备份会丢失升级后的写入，应先保存需要保留的文件。禁止删除迁移账本或修改历史脚本绕过版本检查。

附件存于数据库会增加备份和 WAL 体积，Base64 会产生有界额外内存开销。当前容量上限保持不变。
