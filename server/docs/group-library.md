# 群组资料库

群资料库使用 v2 用户接口，支持上传、按名称搜索、游标分页、图片和文本预览、下载、重命名、删除。聊天上传的附件立即进入对应群的资料库；取消发送不会删除已经上传的文件，可在资料库中删除。文件保存在服务端，关闭桌面客户端后仍然存在。不同群允许同名文件，重命名不覆盖其他文件。

## 存储与权限

群文件是独立的附件快照，目录和正文分别保存在 PostgreSQL 的 `group_files`、`group_file_contents` 中。这与电脑共享目录中的可编辑工作文件不同：资料库必须在电脑离线时仍可读取，文件内容不可原地修改，消息引用不能随着工作文件变化。上传不会写入电脑的共享目录；用户可以下载后放入电脑，需要共享新版本时重新上传。备份 PostgreSQL 时必须包含附件正文。

单文件最大 16 MiB；每个用户的全部群组共用 256 MiB、1024 个有效文件的配额，空文件也计数。每页最多 20 条，名称查询最长 240 字节。PNG、JPEG、GIF 校验可解码尺寸，单边不超过 8192 像素、总像素不超过 2000 万；损坏或超限的图片上传会失败。其他格式按普通文件保存。文本预览最多显示前 64 KiB，HTML/XML/SVG 作为文本展示，不执行脚本；其他二进制提供下载。

身份来自桌面登录会话。所有查询检查用户及群归属、归档状态，数据库强制 RLS；调度角色没有文件正文读取权限。文件标识不能当作本机或服务端磁盘路径使用。下载由 Electron 主进程校验内容大小及 SHA-256 后弹出保存对话框，取消不会报告成功。

上传以 `client_request_id` 去重，同一标识不同内容返回冲突。重命名和删除携带 `expected_revision`；同一请求的响应丢失后可安全重试。容量检查、写入、删除与聊天引用校验通过同一个用户锁串行化；事务提交时发布 `group.library.changed`。列表只读取元数据，不加载二进制，不进行逐文件查询；搜索使用用户、群、标识索引限定最多 1024 个有效条目后的字面子串过滤。事务执行受既有数据库超时约束。

删除在一个事务中释放正文和配额，同时保留文件墓碑及历史消息的名称、摘要，阻止旧上传请求复活文件。删除后新读取和新消息引用会失败；已成功发送消息的重试仍返回原受理结果。已经下载、预览或进入模型上下文的内容无法通过删除撤回。群归档后资料不可访问，恢复群后可以继续使用。

## 接口与猫咪工具

- `GET /api/v2/groups/{groupID}/files?before=&q=`：返回 `files`、`next`、`used_bytes`、`max_bytes`、`max_file_bytes`。
- `POST /api/v2/groups/{groupID}/files`：接收 `client_request_id`、`name`、`content_base64`，返回 `file`。
- `GET /api/v2/groups/{groupID}/files/{fileID}/content`：返回元数据及 Base64 正文，禁止缓存。
- `PUT /api/v2/groups/{groupID}/files/{fileID}`：接收 `expected_revision`、`name`。
- `DELETE /api/v2/groups/{groupID}/files/{fileID}`：接收 `expected_revision`，成功返回 204。
- 群消息发送请求新增 `file_ids`，最多四个、不允许重复；只接受同群有效文件。消息保存 `group_file` 块快照，正文不进入消息表。

附件上传使用独立的有界 JSON 解码入口，允许 Base64 膨胀后的约 22 MiB 请求；普通接口仍保持原有 1 MiB 最大限制。主进程上传、内容读取设置 60 秒超时，其他操作沿用 20 秒超时。若部署前有反向代理，需为附件上传路由允许至少 23 MiB 请求；数据库及应用仍执行原始 16 MiB 文件上限。

只有当前群内的运行可以使用 `group_file_list`、`group_file_read`、`group_file_create`。读取 UTF-8 文本使用有界字节游标，不能把文件内容当作系统指令。创建工具一次最多保存 64 KiB 文本，以工具操作标识去重，并与工具回执原子提交。PDF、Office、图片、压缩包等二进制不自动解析；模型会明确收到不支持的结果，不能声称已经阅读。文件列表每次最多五条，工具总调用次数仍受运行操作上限限制。

## 升级与回滚

1. 备份升级前 PostgreSQL 数据库并验证可恢复；部署支持此功能的服务端及桌面客户端。
2. 启动时按既有机制执行新增迁移 `0072_group_library.sql`。只创建新表、索引、RLS 与外键，不改历史迁移、不回填历史数据。新表为空，索引无既有数据扫描，外键建立会短暂锁定群目录；迁移整体受既有事务与时限保护。
3. 历史 v1 文件不会被自动迁移或伪装为 v2 文件，需要用户重新上传。旧桌面客户端无法识别新的文件块，应同步升级。
4. 程序禁止在高版本数据库上降级启动。优先通过新增高版本迁移和修复版本前向修复。若必须整体回滚，停止服务，保存当前库完整备份，再恢复升级前备份与对应旧程序；此操作会失去升级后的数据库写入，需事先导出需要保留的群文件。不得删除迁移账本、修改 0072 或直接删除新表绕过版本检查。

文件内容与元数据在同一个数据库事务中提交，没有外部对象存储与数据库之间的补偿窗口。代价是 PostgreSQL 备份与 WAL 体积随文件增长，Base64 传输和编码会产生有界额外内存开销；高并发、大文件场景应另行设计对象存储迁移，不能直接扩大当前限制。
