# 会话检索与用户提问

## 模型工具与权限

新增 Bot 默认启用 `conversation_search`、`conversation_read`、`ask_user`；现有 Bot 保留自己的工具白名单，需要时在设置中启用。检索和读取属于低风险 `conversation.read` 动作，遵循明确策略、独立审查和审批严格度；严格模式需要审批。提问属于 `user.question`，始终等待真实回答，不进入动作审查，也不能用回答代替其它工具的审批。明确拒绝规则与工具白名单仍然生效，允许规则不会自动生成答案。

`conversation_search` 接受 `{query,bot_id?,kind?,limit?}`，默认 10 条、最多 50 条。查询为 1–16 个字面词项、总计最多 512 UTF-8 字节，不支持 FTS 运算符。`kind` 为 `direct`、`group` 或 `bot_dm`。可见范围为调用 Bot 自己的单聊及例程会话、目前仍参与的群组、自己作为任一成员的 Bot 私信。`bot_id` 只追加参与者筛选，不能改变调用身份。返回会话标识、标题、类型、消息标识、公开片段和时间；归档不删除检索权限，退出群组则立即失去该群的读取权限。

`conversation_read` 接受 `{conversation_id,around_message_id?,limit?}`，默认 30 条、最多 100 条。无锚点返回最新窗口，有锚点返回其附近按消息序号排列的窗口，另有 `has_before/has_after`。锚点必须属于同一会话且不是流式未完成消息。使用窗口边缘消息作为下一锚点时应设置至少 3 条，才能向前或向后推进。单次公开正文合计最多 1 MiB，超过时明确返回 `CONVERSATION_TOO_LARGE`，不截断正文；通用工具输出超过 32 KiB 时按已有机制保存完整结果文件。不存在和未参与的会话统一返回 `CONVERSATION_FORBIDDEN`。

两项工具只返回 `text` 和 `note` 块。思考、工具参数、工具结果、分工等结构块不会进入索引或转录；只有私有工具结果的消息会保留消息标识和空正文。工具结果中的私有记忆、文件内容不会经共享群组检索传播，Bot 主动写进公开正文的信息仍然可见。消息历史被标注为引用资料，不能作为新的系统指令。

## 提问与待办

`ask_user` 接受 `{question,options}`。问题最多 4000 UTF-8 字节，选项为最多 8 个去除首尾空白后互异的非空字符串，每项最多 200 字节；空数组表示自由回答。工具提示禁止索取密码、凭据或敏感个人信息。

客户端“待办”中可选择一项或填写自由回答，主动点击提交才发送。回答最多 1000 UTF-8 字节；选择选项与自由文本互斥。成功返回 `{choice,text}`：正文等于某个选项时 `choice` 为该选项，否则为 `null`。取消输入、网络失败和刷新不会替用户作答，失败请求不会自动重发。跳过问题需确认，工具收到 `USER_NO_RESPONSE`，不得臆造答案。

同一 Turn 的问题按 ID 升序排队，只能回答当前最早的问题。界面提供后续问题预览；加载完整回合的问题后，可选择将同样的答案应用到全部问题。选项含义可能不同，因此每项分别判断 `choice`，正文相同。问题集合变化会取消批量勾选并保留草稿；服务端对完整 ID 集合进行事务校验，拒绝过时快照，防止回答未显示的新问题。

## 接口变化

接口均以 `/api/v1` 为前缀并要求设备授权。

- `GET /approvals` 增加 `created_at`、`turn_id`、`waiting_questions`。待处理事项按 ID 升序分页，`cursor` 表示继续读取更大的 ID；已批准、拒绝或过期历史仍按 ID 倒序分页。客户端与服务端应同步升级。
- `POST /approvals/{id}/decision`：回答使用 `{decision:"approve",note:"回答文字"}`，跳过使用 `{decision:"deny"}`。成功为 HTTP 200，返回 `{resolved:true}`。问题不接受 `remember`；普通动作审批不接受问题批量字段。
- 批量回答增加 `{apply_to_turn:true,question_ids:[完整待回答ID集合]}`，请求路径必须是最早问题。快照改变返回 409 `USER_QUESTIONS_CHANGED`；回答队列中后续项返回 409 `USER_QUESTION_QUEUED`。重复、过期与取消后的决策按原审批错误返回。

问题、审批状态和工具关联先在同一事务保存，再通知客户端。回答、结果 JSON、审计与 `approval.resolved` 原子提交；任一步失败完整回滚，竞争回答仅有一个成功。审计记录业务标识和决策，不记录问题或回答正文。正文保存在问题详情和对应工具结果中，属于用户会话数据。

## 时限、并发与恢复

问题默认有效期 24 小时。Run 原有的 30 分钟执行预算在人工等待期间暂停，回答后恢复剩余预算；普通动作审批仍受原执行时限约束。提问释放模型并发槽并保留 Bot 互斥，回答后重新排队获取槽位，不产生超额模型并发。

父任务只有在等待包含问题的子任务时才暂停；子任务提问而父任务仍执行其它工作时，父任务继续计时。祖先群组总时钟在人工等待期间暂停，群组编排名额也让出，单并发下多个成员仍可形成问题队列。非人工的子任务执行仍消耗父任务预算，现有群组空转停止规则和费用上限继续生效。

用户取消、服务停止或重启会终止等待并使待办过期，不重放提问、工具或模型请求。问题的 24 小时并不延长外层不可暂停的操作时限：经私信／委派工具发起的子任务仍受其 24 小时总调用上限约束。创建待办限时 10 秒，每次状态读取限时 5 秒，清理使用独立 5 秒上下文；清理持久化失败向上报错，不伪装成功。

全局最多 1024 个待回答问题，超过时返回 `USER_QUESTION_CAPACITY`。每回合批量集合最多 32 项，与群成员上限一致。长时间等待只保留有界任务状态和计时器，不持续占用数据库连接。

## 迁移、性能与回滚

新增迁移 `0014_conversation_tools_and_questions.sql`，0001–0013 保持不变。新增公开转录视图，重建 `messages_fts` 及触发器，只索引公开正文；给审批表添加带约束的 `answer_json` 和待回答问题部分索引。原消息块、历史审批及其 ID 不变。

升级会扫描全部历史消息并重建派生 FTS 索引，持有写事务，耗时与历史正文体量有关；大数据库应预留维护窗口和索引重建磁盘空间。历史 JSON 损坏将使整个升级回滚并明确失败，不能丢弃坏数据后继续启动；应保留快照并以新增迁移或受审计修复处理。新索引更新与消息写入处于同一事务。

检索、读取均限时 15 秒、在 SQL 中应用权限和条数上限；短于 3 个字符的词项使用字面 LIKE 辅助匹配，短词扫描和排序可能较慢。普通长词使用 trigram FTS。转录先计算选定窗口大小再读取正文，避免无界返回；批量问题计数一次聚合，回答最多处理 32 条。服务仍使用单写连接，长历史查询会与写入争用，需按实际数据量观察延迟。

升级前停止任务和服务，备份完整数据目录（含 SQLite WAL、主密钥）及工作区，再同步更新服务和客户端。旧服务拒绝打开版本 14 数据库；回滚必须停机恢复升级前完整快照及匹配的服务／客户端，不能删除迁移记录或修改历史脚本。仅停用工具时先取消活跃回合，再调整 Bot 白名单。

## 验证范围

测试覆盖中文短词、FTS 字面词、参与者筛选、跨 Bot 隔离、群成员退出、私有块排除、锚点窗口和容量、索引更新与删除、历史升级及损坏回滚；也覆盖真实回答、自由文本、跳过、到期、取消、重复与并发决策、批量快照、审计失败回滚、允许规则不代答及严格审批期间成员变化。运行时验证单并发、Bot 互斥、群组排队、父子等待和剩余计时；客户端验证三档宽度、主动提交、防重复、草稿、批量集合变化和失败不重发。外部真实模型账号与跨平台原生人工交互仍属于项目最终验收。
