# 默认助手 Tom

Tom 是服务端创建的一位普通 Bot，稳定标识为 `tom`，常规直接会话标识为 `tom-direct`。客户端据此识别默认身份，不增加 API 标志字段，也不按显示名称识别。用户可以修改名称、角色、模型、权限和头像，也可以归档或删除；完成一次初始化后，后续启动不会撤销这些操作或重新创建 Tom。

## 一次性初始化

`0017_default_tom.sql` 仅向 `system_state` 写入 `default_bot.pending` JSON 种子，不直接插入 Bot 或会话。服务只有在认证状态已经成功提交后才消费种子：已有认证的实例在启动时处理，新实例在首次设置管理员密码成功后处理，随后登录也会重试未完成的准备。

准备顺序如下：

1. 检查待处理种子，在数据库写事务内重新读取并校验种子，选定可用名称和默认模型，然后准备 `bots/tom/inbox`、`bots/tom/out`、`bots/tom/notes` 与 `bots/tom/.tom/memory`。
2. 目录准备成功后，在同一事务中创建 Bot 和常规直接会话，写入审计及会话事件，删除待处理种子，再提交。
3. 后续启动未发现种子时不再创建默认助手，即使用户已归档或删除 Tom。

新实例尚未提交认证时没有默认 Bot 业务记录，不会把正常首次初始化误判为丢失认证文件。已有业务数据而认证文件缺失时，原有的拒绝启动保护保持不变；默认助手不能绕过此检查。

已有用户创建的同名 Tom 保留，内置助手采用首个可用的 `Tom N` 名称。稳定标识与显示名称分离，改名或同名不会混淆默认身份。

## 失败与恢复

目录准备与 SQLite 事务不能组成一个原子操作。目录先准备，失败会明确返回，种子保留供后续启动或登录重试；数据库事务失败同样保留种子，不提交半个 Bot 或缺失主会话的状态。重试允许复用已创建的目录，不覆盖其中已有文件。必需目录被普通文件占用、权限不足等错误不会被当作准备成功。

若管理员密码已经设置成功，但随后默认助手准备失败，认证状态仍然有效；修复具体错误后，用已设置的密码登录重试。无需删除认证文件或重置实例。进程在建目录之后、数据库提交之前退出时，可能留下部分目录；下一次准备会补齐目录并继续消费同一个种子。数据库提交后种子已删除，不会因再次登录重复插入。

该过程只创建一位 Bot、一个常规会话和固定的工作目录，不扫描消息历史。迁移只写一条种子，消费时会检查现有 Bot 名称和默认模型；目录准备在同一写事务内部、插入 Bot 之前完成，文件系统操作计入事务持锁时间。升级应停机备份，并为数据库同步和文件系统操作预留时间。

## 模型与头像

创建 Tom 时若已有默认模型，则在创建事务中绑定；没有默认模型时 `model_id` 保持为空。后续通过模型配置设置默认模型时，在同一事务内仅为仍未配置模型的 Tom 绑定，不覆盖它已有的模型，也不改变其他 Bot 的空模型语义。未配置模型时发送仍受原有校验限制，客户端提供配置入口。

Tom 的 `avatar_path` 初始为空，客户端使用随包分发的图片作为占位；上传头像优先，远端读取失败显示默认图并提供重试。普通同名 Bot 继续使用自己的头像或首字占位。素材来源与使用限制见[默认头像说明](../client/assets/avatars/README.md)。

客户端首次没有保存会话或外部会话链接时进入 Tom。它的常规直接会话在侧栏和搜索结果中置顶，搜索先过滤不匹配项，例程与协作会话保持原有状态排序。已有会话记录、外部链接与用户返回会话列表的操作优先于默认入口。

## 升级与回滚

升级前停止服务，保存完整的数据库、认证文件和工作区备份，部署匹配的服务与客户端。目录准备失败时先修复错误并重试，不手工删除种子或向数据库补行。

旧二进制会拒绝打开已应用新迁移的数据库。回滚必须停止新服务，恢复升级前成套备份中的数据库、认证文件和工作区，并使用匹配的旧版本；不能只替换二进制、只还原数据库或修改迁移账本。具体备份与恢复命令见[备份、还原与 Linux 部署](backup.md)。
