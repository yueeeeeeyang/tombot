# 浏览器接口与恢复约定

当前实现包括鉴权 HTTP 接口、模型 `browser` 工具、画面 WebSocket 和 Flutter 浏览器面板，支持持久标签、来源许可、逐次动作审批、旁观、用户接管、原生下载与截图导出。浏览器和终端已整合到 Bot 详情的电脑分区。

## 运行与数据

引导成功后启动一个托管 Chromium，profile 位于数据目录的 `browser-profile/`，权限为 `0700`。不同 Bot 的标签共享站点登录态；标签归属只用于服务访问检查，不构成浏览器 profile 或操作系统隔离。CDP 使用进程管道，不暴露远程调试端口。

`0008_browser_tabs.sql` 持久保存标签 ID、Bot 归属、最后可恢复的 Web 地址、标题、控制者、控制版本、页面版本、操作状态和错误码。用户独立标签的 `bot_id` 为空；关联 Bot 的标签也可以由用户控制。删除 Bot 前必须关闭它的所有标签，包括失败记录。

`0009_browser_navigation_permissions.sql` 新增按标签保存的来源许可，以及被阻断导航的地址、方法、错误码。许可按协议、规范化主机和端口隔离，不扩张到子域；主机使用 IDNA 处理，默认端口、IPv6 和末尾点统一规范化。每个标签最多保存 64 个来源，弹窗只复制父标签已有许可，关闭标签时级联清理。显式拒绝规则优先于已有许可；规则之间仍遵循 Bot 专属、精确目标优先的既定顺序。

全局最多 32 条标签记录，每个 Bot 或独立用户归属最多 8 条；失败记录也占容量。列表有界加载，归属列建立索引。元数据同步与弹窗登记在同一运行时锁下完成，锁顺序为服务命令锁 → 运行时锁 → 数据库；浏览器弹窗回调只访问数据库，不反向获取服务锁。审计与状态更新在同一 SQLite 写事务中提交，事务内不等待网络或执行页面动作。

页面命令串行，含排队最多 30 秒；副作用发生后的结果保存另有独立 5 秒期限，即使客户端取消也会保存操作结果。不能自动重试输入、点击或表单提交。SSE 发布 `browser.updated`，负载仅含 `tab_id` 与 `bot_id`；空 ID 表示重新读取全部浏览器状态。事件通知可合并，数据库列表是权威状态。

## HTTP 接口

客户端以鉴权接口 `GET /api/v1/browser/status` 的 `available` 判断能否打开浏览器。`running` 和可按需启动的 `stopped` 在服务可接单时返回 true；自动恢复中的 `recovering`、重试耗尽的 `failed` 或标签状态持久化故障返回 false，持久化故障另带 `state_error`。工作台收到全局 `browser.availability` 通知会重读状态。事件只在状态变化时发布，指定会话的事件流只接收会话数据。

客户端共用一次状态读取，并在应用返回前台时重查。每次读取完成后，可用状态在 30 秒后复查，自动恢复中为 2 秒，其他故障或读取失败为 10 秒。未确认可用时隐藏操作入口，已打开的电脑面板仍可使用终端。重试耗尽后，到“已授权设备 → 服务器环境与修复”点击“恢复浏览器”；请求失败后先重读状态，由用户决定是否再次恢复。

此增量沿用数据库版本 0014。同步升级服务与客户端；旧服务缺少 `available`，新客户端会隐藏浏览器入口。回滚时先让活动浏览器操作结束、备份数据与 profile，再恢复上一版配套服务和客户端。

以下路径均以 `/api/v1` 为前缀，经过引导就绪门禁和设备认证；截图响应为 `image/jpeg`，所有响应禁止缓存。

| 方法与路径 | 用途与参数 |
| --- | --- |
| `GET /browser/status` | 进程状态、标签数、恢复失败次数；持久化失败另带 `state_error` |
| `GET /browser/tabs?bot_id=` | 列出全部标签，或按 Bot 过滤 |
| `POST /browser/tabs` | 打开 `{url, bot_id?}`，返回创建的标签；初始控制者为用户 |
| `GET /browser/tabs/{id}` | 读取持久元数据 |
| `GET /browser/tabs/{id}/snapshot` | 读取 `{tab, text, truncated}`，生成新的元素引用 |
| `GET /browser/tabs/{id}/screenshot` | 固定视口 JPEG；`X-Browser-Origin`、`X-Browser-Error` 描述对应画面 |
| `WS /browser/tabs/{id}/screen?readonly=1` | 按标签查看实时画面；只读参数可选，带设备鉴权请求头 |
| `POST /browser/tabs/{id}/actions` | 执行页面动作，必须提交当前 `revision` 与 `page_revision` |
| `POST /browser/tabs/{id}/downloads` | `{revision, page_revision, url 或 ref}`，使用网页登录态下载一个文件，返回 `{tab,file}`，成功状态为 201 |
| `POST /browser/tabs/{id}/control` | `{controller: user 或 bot, revision}`，交接控制权并递增版本 |
| `POST /browser/tabs/{id}/restore` | `{revision}`，显式重新打开失败标签的已验证地址，保留 ID 并交由用户控制 |
| `DELETE /browser/tabs/{id}?revision=` | 显式关闭标签或清理失败记录；重复关闭返回 204 |
| `POST /browser/recover` | `{}`，保存可确认状态并解除持久化失败门禁，必要时恢复浏览器进程 |

动作参数如下；不支持任意 JavaScript、文件协议或带用户凭据的 URL：

| `action` | 额外参数 |
| --- | --- |
| `navigate` | `url`，必须为 HTTP(S) |
| `click` | `ref`，来自最新快照 |
| `type` | `ref`、`text`、`clear?`；默认清空，文本最多 16 KiB |
| `key` | `key`，限定 Enter、Tab、Escape、方向键、Backspace、Delete、Home、End |
| `scroll` | `delta_x`、`delta_y`，每项绝对值最多 4096 像素 |
| `click_at` | 用户接管专用；`x`、`y` 必须在固定视口内 |
| `input` | 用户接管专用；`text` 插入当前焦点，不自动清空 |

`revision` 表示控制权版本，`page_revision` 表示页面版本。用户交接控制权、页面跳转或交互后，旧版本动作返回 `BROWSER_TAB_CHANGED`；客户端应重新查看页面，由用户决定下一步，不能自动替换版本重发。截图和快照允许旁观，输入要求先接管。快照包含版本与当前页面信息；页面在快照后发生变化时，运行时仍会在执行前再次验证。

## 实时画面与客户端

连接按标签 ID 建立，避免同一 Bot 多标签时选择不明确。服务端先发送 `ready`（含 `tab`、`readonly`），客户端在 10 秒内发送 `start`；`tab_id` 若提供必须与路径一致。随后发送 `tab_changed` 和画面：

```json
{"type":"start","tab_id":"标签ID","quality":60,"max_fps":5}
{"type":"frame","data":"JPEG 的 Base64","meta":{"w":1280,"h":720},"tab":{"id":"标签ID","revision":2,"page_revision":7}}
{"type":"click","x":120,"y":340,"seq":1,"revision":2,"page_revision":7}
{"type":"ack","seq":1,"action":"click","tab":{"id":"标签ID","revision":2,"page_revision":8}}
```

示例省略了 `tab` 其他元数据。画面输入支持 `click`、`input`、`key`、`scroll`，分别对应 HTTP 的 `click_at`、`input`、`key`、`scroll`；模型工具不开放用户坐标点击和焦点输入。`seq` 是当前连接内递增的正整数，重复或倒序直接拒绝；它不是跨连接幂等凭据，禁止断线后沿用旧动作重发。成功返回 `ack`；失败返回 `error`，含 `code`、`seq`。`seq=0` 为连接级故障，客户端停止自动重连并要求检查。页面读取中发生导航时发送 `loading`，最多重试三次画面读取，不重放任何输入。

画面以 `Page.captureScreenshot` 定时采样，每连接 1–5 FPS、JPEG 质量 1–80，默认 5 FPS／60；实际速率受渲染和发送耗时限制。全局最多 8 个画面连接，发送队列只保留一个帧，另有在途采集与传输，发送慢时等待而非积累历史画面。单张 JPEG 最多 8 MiB。截图、元数据和页面版本在同一运行时命令锁中读取，文档中途变化则丢弃结果。该采样方案与页面命令共享浏览器锁，多画面会增加 CPU、编码和带宽开销，应按部署资源评估；未宣称达到 8 路满速的性能基准。

连接沿用设备认证、同源升级检查、根上下文取消；每次动作和每张画面发送前重新验证设备。写超时 5 秒，心跳 15 秒，页面命令含排队最多 30 秒。连接关闭只释放画面资源，不关闭标签、不改变控制权。设备撤销阻止后续画面和输入，不影响已经发送到设备的内容。

Flutter 的独立浏览器页和电脑分区支持新建、选择、访问地址、接管／交还、恢复和关闭标签。画面来源常显；坐标按实际显示尺寸换算到 1280×720。电脑分区首次进入才连接，浏览器／终端页签切换和详情收起保留现有组件状态。宽度小于 720 时只提供用户主动读取截图，不建立画面 WebSocket，不显示操作入口；截图来源使用本次响应头，避免与旧列表地址混淆。

图像使用 `RawImage` 显示，先校验 JPEG 字节数和编码尺寸，再解码；最多一个解码任务与一个待处理帧，旧图像及时释放，参见 [Flutter RawImage 资源约定](https://api.flutter.dev/flutter/widgets/RawImage-class.html)。导航、换连接或切换 Bot 后的迟到结果丢弃。重连后必须收到新画面才能输入，超过 5 秒没有新画面也会暂停输入。单个动作待确认期间暂停后续输入，确认期限 35 秒；断线或未知结果须用户查看画面后恢复，不自动重发。输入对话框另外绑定打开时的页面与控制版本，避免在输入文字期间跳转后误发到新页面。访问地址和关闭确认也绑定原标签与控制版本，新建对话框绑定原 Bot，目标变化时取消本次操作并提示。输入控件管理自身资源，关闭动画结束后再释放，避免提前销毁。

## 模型工具与审批

工具提供 `tabs/open/snapshot/screenshot/click/type/key/scroll/download/close_tab`。`open` 接收 URL，带 `id` 时导航已有标签；其余单标签操作必须指定 `id`。`download` 要求 `url` 和当前快照 `ref` 二选一。Bot 只能访问自己的标签，变更页面、下载或关闭标签还要求 Bot 控制权。失败标签允许所属 Bot 显式关闭，以释放容量。

- 新来源使用 `net.new_domain` 高风险审批，已有许可降为低风险，严格度与显式规则照常生效。许可只在通过审批／策略检查的执行事务内保存，事务失败不产生许可。
- `click/type/key/download` 均按 `browser.interact` 高风险逐次确认，因为网页事件可能发送输入或提交操作。即使存在 allow 规则，也必须单次批准；审批接口拒绝为此类动作记忆规则，客户端展示来源、页面、引用、输入内容、按键或下载地址与保存范围。
- 快照、截图、标签列表及滚动为低风险；关闭为中风险。审批绑定控制版本与页面版本，执行前重新检查规则、许可和风险；接管、页面变化、撤回许可或新增拒绝规则都会使旧许可失效。
- `screenshot` 将 JPEG 保存为工作区图片产物并发布 `artifact.created`。工具结果携带文件摘要和图像尺寸。视觉模型在下一步收到核对过摘要的 JPEG，其他模型收到文件路径和文字说明。详见[聊天附件与视觉输入](attachments.md)。

用户接管时不受 Bot 来源规则限制。交还 Bot 前先同步运行时元数据，再在同一事务中批准当前记录的页面来源；这不会批准用户之前访问的其他来源，也不能覆盖显式拒绝规则。

## 原生下载

下载使用 Chromium 原有 profile 和会话，地址方式发起一次导航，引用方式触发一次主文档元素点击，支持需要已有登录态的附件和表单生成文件。下载动作开始前保存意图、双版本及审计；模型下载始终单次审批，URL 的来源许可在执行事务中保存，显式拒绝仍优先。重定向沿用文档导航保护，未知来源不会因下载而自动放行。普通点击没有下载接收权限，模型应使用 `download` 操作下载按钮或表单，避免误以为附件已保存。

接收窗口使用 [CDP Browser 下载协议](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Browser.pdl) 的 `allowAndName`，临时文件按协议 GUID 命名；窗口结束恢复 `deny`。同一命令只接收所选主文档的一个文件，其他文档或多个下载同时出现时整次失败，不发布任何文件。协议事件状态最多跟踪 8 个标识，进度通知合并，页面命令等待期间仍检查容量和冲突；保护协议异常或不能确认取消时停止浏览器，必须显式恢复。

单个文件接收及发布上限为 32 MiB，命令含排队最多 30 秒，导航完成确认、取消回收和页面元数据同步各有独立的 5 秒期限，业务结果保存另有 5 秒期限。超过已报告总量或接收量上限即进入取消流程；完成后再核对普通文件类型、实际字节数与协议计数，并通过目录句柄拒绝链接替换。Chromium 在两次进度通知之间可能继续写入暂存，因此此限制不等同磁盘硬配额；部署需要为浏览器临时写入预留空间。请求尚未产生下载标识时，取消会停止页面加载；已结束的非下载导航不再向失效的旧页面会话发送停止命令。超限取消前等待协议 GUID 对应的临时文件真实出现，确认 Chromium 文件初始化已经执行，避免迟到的建目录任务在清理后重建目录；等待有截止时间和退避，无法确认则停止进程再清理。失败、取消和崩溃不重放 GET、点击或 POST。

临时目录位于私有 profile 的 `tom-downloads/job-<唯一ID>/`，成功或失败返回前清理；旧进程退出后启动清理已知格式的中断目录，不恢复未完成下载。只有完整文件会发布到 Bot 的 `inbox/<唯一ID>/`；独立用户标签发布到 `shared/inbox/<唯一ID>/`。统一复用文件上传层的名称校验、临时文件、原子发布、摘要、权限与审计，禁止覆盖同名文件，服务端不执行下载内容。下载文件名无效或存储失败则报错。完成事件 `artifact.created` 刷新工作区；文件已经发布后状态或事件保存失败会明确返回失败，不能自动重试。

Flutter 桌面和平板在接管后可填写下载地址，下载对话框绑定原 Bot、标签与页面版本，切换目标后不发送；结果显示工作区路径。手机保持只读，文件可从工作区查看或保存。下载请求使用 60 秒响应等待期限，断线显示结果未确认，刷新标签和文件列表，不自动重复请求。尚未实现任意 iframe 或新弹窗的下载归属转移，也不提供跨重启续传。

## 截图导出

“保存截图”保存当前显示帧的原始 JPEG，不重新访问网页，也不要求接管。手机需先点击“查看截图”；桌面可保存已显示的实时帧，断线后仍可保存最后显示的画面。截图已经过 8 MiB 字节上限与 1280×720 尺寸校验；保存期间固定字节与来源，后续画面更新不会替换正在保存的内容。客户端额外保留当前帧的编码数据，每个面板最多 8 MiB；另有一个正在保存的帧，完成后释放。

平台差异由 `PlatformCapabilities` 决定，与窗口断点无关。桌面使用 [path_provider](https://pub.dev/packages/path_provider) 返回的系统下载目录，原子创建 `tom-screenshot-<随机后缀>/`，写入并刷盘后将 `.part` 重命名为 `截图.jpg`，不覆盖已有文件；网页标题和 URL 不参与本地路径。失败会清理本次专用目录，清理失败明确报告。成功提示含实际路径和截图来源。

iOS／Android 使用 [gal](https://pub.dev/packages/gal) 写入系统相册，只有用户点击后才申请授权，不创建自定义相簿。拒绝权限、空间不足、格式不支持及原生错误均显示中文提示，不自动重试。原生保存等待最多 60 秒；超时显示结果未确认，保持互斥直到原生调用结束。尚在等待权限或目录创建的操作在迟到返回后停止发布；已经交给系统的相册写入无法撤回，用户需先检查结果。切换 Bot 或关闭面板后，旧操作的结果不会冒充新面板的操作结果。

## 文档导航保护

使用浏览器级 CDP `Fetch` 在 Request 阶段拦截 Document 请求，覆盖主文档、重定向、弹窗和 iframe；未知归属一律拒绝。请求线程只访问授权数据库，不获取服务／浏览器命令锁。每次决策最多 5 秒，待处理队列最多 128 项，文档身份最多 2048 项；越界、授权存储异常或非取消类协议错误均停止浏览器并锁定失败状态，需显式 `recover`。

未经批准的跳转在请求发出前终止，`blocked_navigation` 提供 `{url, method, code}`，不保存请求正文和头部。错误页仍可能异步变化，因此重新提案前应先查看当前快照；旧页面版本不能沿用。被阻断的 POST 不会自动重放；模型只能重新提案，获得批准后打开目标地址，或等待用户接管处理。异步点击造成的阻断可能通过后续标签查询或事件显示。

这是文档导航保护，不是全部浏览器流量的防火墙：页面脚本的 XHR、静态资源、WebSocket 等不在此过滤器范围内。页面与共享登录态仍需按既定信任边界使用。协议依据为 [Chromium 浏览器级 Fetch 注册](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/devtools/browser_devtools_agent_host.cc) 与 [Fetch 协议定义](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Fetch.pdl)，具体行为由固定版本 Chromium 回归测试验证。

## 失败与恢复

创建、页面动作和关闭都先提交操作意图及审计，再执行一次。原始输入、页面正文和完整 URL 不写入动作审计。完成状态或审计保存失败时返回 `BROWSER_STATE_FAILED`，停止后续页面动作；读取持久列表和显式关闭仍可用于检查与清理。

进程内崩溃可限次退避恢复，最多连续失败三次；恢复只打开标签地址，不重放输入或点击。服务整体重启时，仅自动装载 `active` 标签；`opening`、`acting` 标为失败并返回 `BROWSER_INTERRUPTED`，`closing` 记录删除，防止重开已确认要关闭的标签。失败标签需用户显式恢复或关闭。

导航保护自身失败时不走自动重启，状态为 `failed`，后续页面操作返回 `BROWSER_NAVIGATION_GUARD_FAILED`。只有浏览器已取消的拦截任务（固定协议错误 `Invalid InterceptionId.`）被视为取消完成；其他协议失败不得静默忽略。

页面跳转到内部错误页等不受支持地址时保留最后已验证地址，并显示 `BROWSER_URL_UNSUPPORTED`，此时保存的 URL 不代表当前页面地址。输入会被拒绝，可查看截图后选择显式恢复或关闭。单标签恢复失败不会阻断其他业务；状态查询与标签错误码用于展示降级。

导航事件和地址元数据可能分批到达。运行时重新确认有效 Web 地址后，即使页面版本没有再次变化，也会清除过渡期的地址错误；仍为无效地址时继续拒绝输入。快照读取期间文档变化则返回 `BROWSER_DOCUMENT_CHANGED`，可以重新读取快照，不能据此自动重放输入或提交。

`recover` 不确认先前的动作成功，也不重放它们。无法确定结果的操作仍标记为失败，随后可以单独恢复标签。服务关闭时停止同步，再让 Chromium 有序刷写 profile；升级或备份前应等待正常退出。

## 迁移与回滚

迁移 0008 只创建空表和索引，没有历史数据回填，短暂取得 SQLite 写锁；对大库没有全表扫描。升级后额外常驻一个 Chromium，标签上限限制了数量但不保证任意网页的内存用量，需要按部署资源预留浏览器开销。

迁移 0009 创建空许可表，并给最多 32 条标签记录增加三个带空默认值的有界字段；SQLite 在添加 CHECK 约束时可能检查标签记录，工作量由标签容量限制。迁移在写事务内完成，无来源许可回填。升级前已有 Bot 标签可能因没有许可而恢复失败；用户可接管并重新交还，或由 Bot 明确提案访问地址并审批，不能自动把历史地址视为已经批准。新增 IDNA 依赖为 `golang.org/x/net v0.56.0`，同时使用其所需的 `x/text v0.38.0` 与 `x/crypto v0.53.0`；不改变已存密码散列格式。

实时画面增量无数据库迁移，继续使用版本 9；新增用户动作、WebSocket 和截图来源响应头，服务与客户端应同步升级，不提供旧协议兼容层。反向代理必须支持 WebSocket 升级，并允许至少 15 秒心跳间隔及最大约 11 MiB 的 JSON 画面。回滚该增量应停止活动操作并备份后，恢复匹配的旧服务和客户端；版本 9 的数据结构不需反向修改。

原生下载增量同样没有数据库迁移，复用标签 `acting` 状态、文件工作区与审计表。服务和客户端应同步升级；下载期间浏览器命令串行，画面可能暂停，客户端会暂停对旧画面的输入。回滚前停止活动下载、等待服务正常退出并备份，然后恢复匹配的旧二进制与客户端。已发布文件仍是普通工作区文件；不要把临时下载目录当作已交付产物，也不要手工修改迁移账本。

截图导出仅修改客户端，无接口或数据库迁移。增加 `path_provider 2.1.6`、`gal 2.3.3`；macOS 的 Debug／Release 沙箱增加下载目录读写授权，iOS 增加相册写入及旧版授权说明，Android 仅为 API ≤29 声明外部存储写权限。客户端需重新构建和签名，当前 iOS 构建最低支持 15，保存截图使用相册添加权限。回滚时等待保存结束、退出客户端并安装匹配的旧客户端；用户已保存的图片保持不变，不要求回滚服务或数据库。相册权限配置依据插件官方说明，移动实机授权仍需独立验收。

升级前停止活动任务并备份完整数据目录与工作区，升级后二进制自动执行迁移。回滚应停机恢复迁移前完整快照及匹配的旧二进制，包含 profile；旧程序会拒绝更高迁移版本。历史迁移不可修改，不提供删表或修改账本的降级方法。
