# DeepSeek 快速接入

模型设置只提供 DeepSeek 快速接入。客户端选择供应商并输入 API Key，服务端调用真实模型发现接口，再保存加密密钥、供应商和模型；没有内置型号列表，也不会将失败请求替换为演示模型。通用供应商和模型 CRUD API 仍供服务能力与已有配置管理使用。

## 官方契约与模型规格

- [模型发现接口](https://api-docs.deepseek.com/api/list-models/)：对配置的基础地址发起 `GET /models`，使用 Bearer 认证。响应包含 `object: list` 和 `data`，每个模型有真实 `id`；名称、上下文、最大输出、输入及输出模态是可选元数据。
- [基础地址和认证](https://api-docs.deepseek.com/)：默认基础地址为 `https://api.deepseek.com`，可通过部署配置覆盖。
- [聊天协议](https://api-docs.deepseek.com/api/create-chat-completion/)：采用 `max_tokens` 与工具调用格式。当前运行器未持久化并回传完整推理内容，因此 DeepSeek 明确使用 `thinking.type=disabled`，保证多轮工具调用契约完整；其他供应商编码不变。

有规格时采用上游实际值。缺少上下文或输出上限时，以应用运行限额接入：默认上下文 8192、默认输出 4096，可通过环境变量修改；这些数值不代表厂商宣称的模型规格。输出始终不超过有效上下文；仅有输出规格但没有上下文时，新模型仍受应用输出限额约束。已有模型缺失的规格保留已保存限额。

响应与供应商元数据中的 `model_limit_defaults` 列出采用应用限额的模型键，客户端持续提示可在模型设置调整。用户显式提交上下文与输出限额后清除此标记。视觉能力仅在输入模态包含 `image` 时开启；工具能力按 DeepSeek 聊天协议设置。发现接口不提供价格，新模型保留“价格估算”标记，不宣称免费；重新同步保留已有显式价格。

## HTTP API

两个入口都要求设备认证，位于 `/api/v1` 下。

- `GET /provider-presets` 返回数组 `[{"id":"deepseek","display_name":"DeepSeek"}]`。
- `POST /providers/connect` 接收 `preset`、`api_key` 和可选 `provider_id`，成功返回 HTTP 200，正文为 `{provider, models, model_limit_defaults}`。新建需要密钥；已有供应商省略或清空 `api_key` 表示使用当前加密密钥重新同步，非空表示验证成功后替换。密钥永不进入成功响应。

供应商响应包含 `preset: deepseek`，前端按此字段判断可编辑能力，无需复制服务器 URL 规则。重复连接复用已有 DeepSeek 供应商以及相同模型键对应的模型 ID。首次创建使用 `deepseek` 供应商 ID；显式更新已有记录保留其 ID 和显示名称。

首次同步只有在没有全局默认模型时，才选择上游返回的首个模型，并在同一事务内绑定尚未配置模型的 Tom。后续刷新保留用户的全局默认和 Bot 选择；刷新规格不重新绑定用户已清空的 Tom 模型。上游不再提供的模型若无 Bot 或审查配置引用，会被删除；仍有引用则整次同步返回 409，要求先调整引用。

## 失败与一致性

模型发现默认限时 15 秒，不重试，不跟随重定向，响应最多 1 MiB、模型最多 200 个。空列表、重复或非法模型标识、非法已提供规格都会显式失败。上游认证失败返回 400 `PROVIDER_AUTH_FAILED`，不会把本地设备会话误判为过期；超时返回 504 `PROVIDER_TIMEOUT`。错误不包含上游响应正文或提交的密钥。

上游调用在数据库事务外执行。确认有效后，在单个写事务中提交密钥创建或轮换、供应商、模型、默认模型绑定和审计。任一写入失败全部回滚。共享给其他供应商的密钥不会被原位轮换，而为本供应商创建独立密钥。数据库事务前后核对供应商快照及密钥 nonce；发现期间其他设备修改配置或轮换密钥时，返回 409 `PROVIDER_CONNECTION_CHANGED`，拒绝保存过时结果。正常重同步只记录受控密钥使用审计，不读取或保存明文到客户端。

## 部署、迁移与回滚

更新服务端二进制后必须重启 `tomd`，运行中的旧进程不会自动加载新接口。若添加提供商时提示“当前服务器不支持模型提供商接入”，表示提供商列表接口返回了 `NOT_FOUND`；请更新并重启服务端，再点击“重新读取提供商”。重复读取或仅重启客户端不会修复旧服务缺失的接口，表单会保留已输入内容且禁止提交。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `TOM_DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 基础地址；允许 HTTPS 或本机环回 HTTP，禁止用户信息、查询参数及片段 |
| `TOM_DEEPSEEK_CONTEXT_LIMIT` | `8192` | 缺失上下文规格时的应用运行限额，范围 256–10000000 |
| `TOM_DEEPSEEK_OUTPUT_LIMIT` | `4096` | 缺失输出规格时的应用运行限额，至少 1 且不超过应用上下文限额 |

本次没有数据库结构或基础数据迁移。预设身份与限额来源保存在已有 `providers.extra_json`，实际模型来自用户主动接入后的业务写入。网络调用不占用数据库写锁；事务最多处理 200 个模型并保留原有唯一索引约束。

回滚需同时回滚服务端和客户端版本；已有供应商、模型及加密密钥记录仍是原表结构。旧版本不会识别快速接入入口或 DeepSeek 专用请求参数，回滚后应停用该供应商，或使用已验证的通用模型调用方式；不添加旧界面兼容层。若要撤销本次业务接入数据，使用正常配置删除流程或恢复升级前的数据目录及对应主密钥备份。
