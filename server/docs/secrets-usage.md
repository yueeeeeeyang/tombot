# 密钥管理、用量与月度预算

## 客户端入口

工作室底部的“用量、密钥与设备”菜单提供“密钥管理”和“用量与预算”，避免小窗口内导航按钮挤占会话列表。密钥页支持分页、添加、轮换和确认删除；只读取名称、引用标识、末尾脱敏提示及创建／轮换时间。密钥输入隐藏字符，保存或关闭弹窗后清理控制器，不保存到客户端文件，也不提供读取原值的接口。Dart 字符串不能保证立即物理清零，因此不能将清空输入框描述为进程内存的安全擦除。

模型供应商仍可在原配置页创建／轮换密钥。供应商引用中的密钥不能删除；已发出的请求可能继续使用轮换前的值。Shell 沿用已有的 `env_secrets: [{name, secret_id}]` 契约：`name` 是环境变量名称，`secret_id` 是密钥页的引用标识。模型仅接触引用元数据，执行时解密，使用审计记录名称与 Run ID，不记录值。

用量页按日期、Bot 或模型查看费用、调用数、输入／输出／缓存读取 token 和估算调用数；支持日期选择和分页。预算编辑与汇总刷新分离，统计筛选不会覆盖草稿。保存失败不自动重发；版本冲突保留草稿，重新读取或离开未保存页面需确认。输入美元最多六位小数，以整数换算微美元，避免浮点舍入。

## 费用与日期口径

- 用量唯一来源是 `usage_events`。父子 Run／Turn 累计字段用于执行预算，不能再相加作为账单，否则会重复计算委派和私信。摘要、协调计划和工具审查也进入实际调用账本。
- 供应商“测试连接”计入“系统”用量：已配置模型使用价格快照，未知模型按零金额标注估算，并按供应商归入“未配置模型的连通性测试”。测试取消或失败仍保存已返回的用量，尚未实际调用则不计。测试不创建 Turn，不受新回合准入限制，但其费用参与月度累计；恢复配置时仍可显式测试连接。
- 费用单位是微美元，1 美元等于 1000000 微美元；未知价格仍按已有计价规则标为估算。报表不是供应商最终账单。
- 日期分组、月度重置统一使用 UTC 自然日／自然月，不随主机或客户端时区改变。区间为左闭右开：`from <= created_at < to`。账本时间为调用返回后的结算记录时间，不拆分跨月的单次调用。
- 删除 Bot、模型、会话不会删除历史调用费用；报表保留原引用标识，名称显示“已删除的 Bot／模型”。无 Bot 的记录归为“系统”。
- 每次查询最多 366 天，分组默认 50、最多 200 项。分页只影响分组列表，总计仍覆盖完整区间。客户端后续页固定首屏的日期范围，跨月翻页不会混入新月份。

## 月度预算

默认不限额，预设提醒阈值 80%、上限策略 `stop`。启用时额度范围为 1–1000000000000 微美元；提醒阈值为 1–99 的整数百分比。阈值金额向上取整到微美元。

`stop` 在当前月已结算费用达到额度后拒绝新 Turn，包括用户单聊／私信介入、群组、例程、Bot 私信和委派。检查与 Turn 创建在同一个 SQLite 写事务内完成；被拒绝时不留下用户消息或新 Turn。例程保留失败触发记录，错误码为 `MONTHLY_BUDGET_EXCEEDED`，不自动重复发起已失败的触发。

`warn` 只提醒，继续接受新任务。关闭额度、增加额度或下月费用归零后，新任务按新状态重新判断。预算不预占费用，已经接受的回合继续执行；并发调用、单次调用和排队任务可能造成超额。Run／Turn 原有预算仍各自生效，不能把月度预算视作绝对扣费硬上限。

实际调用结算及预算修改都会检查提醒。每个 UTC 月份的“阈值”和“上限”各持久化提醒一次，改变额度或重启不会再次发送同一阶段。提醒状态、审计及 `system.notice` 在同一事务中提交；任何一步失败都会返回错误并回滚。工作室通过事件显示提醒，用量页始终按当前费用显示状态。事件流仍遵循已有的有限保留策略；历史审计和提醒去重表持续保存。

## 接口

所有接口要求设备授权。密钥接口不增加明文读取能力：

| 路径 | 行为 |
| --- | --- |
| `GET /secrets?cursor=&limit=` | ID 倒序的元数据分页 |
| `POST /secrets` | 写入 `{name,value}`；名称最多 120 字节，值为 8–16384 字节 |
| `POST /secrets/{id}/rotate` | 替换 `{value}`，不返回值 |
| `DELETE /secrets/{id}` | 删除未被供应商引用的密钥 |
| `GET /usage?from=&to=&group_by=&cursor=&limit=` | `from/to` 同时省略时取本 UTC 月；提供时必须均为 RFC3339；`group_by` 为 `bot/model/day` |
| `GET/PATCH /settings` | 原审查配置之外增加 `monthly_budget` |

用量响应为 `{from,to,group_by,total,groups,next_cursor,monthly}`。`total` 和各分组包含 `calls,input_tokens,output_tokens,cache_read_tokens,cost_micro,estimated_calls`；分组另有 `id,name`。`monthly` 始终指当前 UTC 月，包含 `month`、相同累计字段、`budget` 与 `status: unlimited|normal|warning|limit`，不跟随历史报表范围。

月度设置字段为 `{limit_micro,warn_percent,action,revision}`。`limit_micro:null` 表示关闭额度；`action` 为 `stop|warn`。PATCH 必须带读取到的 `revision` 并提供至少一个业务字段，未提供字段保留；成功后版本递增，过时版本返回 409 `MONTHLY_BUDGET_CHANGED`。多个配置分区同一请求原子保存，不能出现只改了一半的结果。损坏的持久配置显式失败，不默认放行。

## 升级、性能与回滚

新增迁移 `0013_monthly_budget_alerts.sql`，0001–0012 未修改。只新增以 `(month,level)` 为主键的提醒表，不复制或修复历史费用。建表使用短写事务；运行时每次启用预算的结算／准入读取当月调用费用，报表使用现有时间索引和 SQL 聚合，最多返回 201 个分组用于分页判断，不在应用内无界加载调用记录。报表限时 15 秒，与现有单写连接共享数据库；大体量账本需要按实际规模观察聚合延迟和锁等待。

升级前正常停止任务及服务，完整备份数据目录和工作区（包含 SQLite WAL），再同步部署服务和客户端。文件主密钥必须与密文一同备份并妥善加密保管；环境变量主密钥需另行安全保管。本增量没有实现备份／还原命令，该项仍在 M8。

旧服务不认识迁移 0013，会拒绝打开新数据库。回滚需要停机、恢复升级前完整快照和匹配版本的服务／客户端，不能删表、改历史迁移或只替换二进制。仅关闭预算时应通过设置将额度置空，不改数据库结构。

## 验证范围

回归覆盖并发结算与父子任务不重复统计、跨时区与闰年月份边界、上限准入、已接受任务收尾、阈值去重、通知／审计失败回滚、版本冲突与局部更新、历史引用缺失、分页与区间校验、HTTP 鉴权和密钥元数据脱敏。客户端覆盖三种宽度、写入与轮换、防重复提交、引用删除失败、预算读取失败、微美元精度、冲突草稿及固定日期分页。真实供应商账单对账与跨平台人工交互仍属于最终验收。
