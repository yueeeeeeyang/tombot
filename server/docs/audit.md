# 鉴权与审计

在客户端打开“已授权设备 → 审计记录”。默认每页 50 条，按追加顺序从新到旧排列。展开一条记录可查看动作标识、对象和详情。浏览期间新增的记录在刷新首页时出现。“导出全部记录”会保存整个实例的审计记录。

## 鉴权事件

| 事件 | 记录时机 | 详情 |
| --- | --- | --- |
| `auth.setup` | 初始化提交 | 对象为本次初始化标识 |
| `auth.login` | 设备签发成功 | 设备标识、平台、是否同时登记推送 |
| `auth.login.denied` | 校验管理员口令失败 | 是否进入退避，退避期间直接限流 |
| `auth.device.push` | 更新或移除设备推送凭据 | 是否登记 |
| `auth.device.revoke` | 首次撤销设备授权 | 操作设备、目标设备、是否撤销自身 |
| `audit.export` | 服务器接受导出请求 | 操作设备。实际文件保存结果由客户端显示 |

设备签发、推送变更、撤销与对应审计共用一个 SQLite 事务。写入失败则业务操作失败。鉴权审计只保留定位事件所需的标识及状态。写入和读取均递归处理结构化详情中的凭据字段，对可识别的鉴权串和个人号码文本脱敏。接口排除历史 IP 字段。单条详情最多 64 KiB、嵌套深度最多 24 层，损坏或超限记录会使读取失败。

## 查询和导出

- `GET /api/v1/audit?cursor=&limit=` 需要有效设备授权，返回 `records` 数组及可选的 `next_cursor`。每条包含 `id`、`actor`、`action`、可选的 `target`、`details` 和 UTC 时间 `created_at`。每页 1–200 条，查询限时 15 秒。
- 将服务端返回的游标原样用于下一页。查询依据 SQLite 行号向前定位，追加新记录和系统时钟回拨均不会移动后续页边界。还原或离线重建数据库后从首页重新浏览。
- `GET /api/v1/audit/export` 返回 UTF-8 JSON 数组，建议文件名为 `tom-audit.json`。每批最多 100 条，释放数据库连接后写网络，读取下一批前复查设备授权。总时限五分钟。遇到撤销、超时、存储或网络故障时中断响应，调用方应丢弃未完整接收的文件。
- 桌面用户选择保存目录后，客户端将数据分块写入唯一子目录中的临时文件，校验长度（若服务端提供）和导出数组的首尾边界，刷新文件并改名后才显示保存成功。网络传输及写盘发生错误时清理该目录。若系统强制终止客户端，可能留下仅含临时文件的下载子目录，可在应用退出后删除。工作区下载复用相同的保存流程。手机通过系统保存插件写入，单次最多 64 MiB。

## 初始化、升级与回滚

初始化先把新凭据写入私有暂存文件并同步目录，再在同一事务中写入 `system_state` 的初始化标识和审计记录。事务提交后才把凭据改名为 `auth.json`。启动时会清理未提交的暂存文件，或发布与已提交标识匹配的凭据。标识冲突、已提交凭据缺失或损坏会阻止启动。遇到此类故障，应从同一份停机备份恢复数据库与凭据。备份校验以只读方式识别已提交的暂存状态。

本次沿用迁移 0014 及已有审计表。升级前先停机备份，再同时替换服务和客户端。已有实例的原认证文件可直接使用，新增鉴权事件从升级后开始记录。每次设备变更增加一次事务内审计写入，导出速度受历史记录量与网络带宽影响。为回退，先完成或取消下载并停机，再恢复配套的旧服务和客户端。若新初始化在文件发布前中断，应先用当前版恢复至就绪，或恢复升级前的完整备份，再回退。

## macOS 实机复验

在仓库根目录运行以下命令。测试使用临时数据库和仅监听环回地址的服务。客户端翻页、导出 JSON，再下载 65 MiB 加 1 字节的文件，校验长度和最后一个字节。

```sh
TOM_TEST_NATIVE_AUDIT=1 go test -race ./internal/httpapi -run '^TestNativeAuditAndLargeDownload$' -count=1 -v -timeout 5m
```

另加 `TOM_TEST_NATIVE_PICKER=1` 可单独验证系统目录授权。看到“验收应用已构建”后，打开 `client/build/macos/Build/Products/Debug/tom.app`，点击审计页的导出按钮，选择命令输出的专用临时目录。服务读回保存后的文件并核对记录数、最新事件及脱敏结果。验收程序退出后，在 `client` 下运行 `flutter build macos --debug` 可重新构建工作台入口。
