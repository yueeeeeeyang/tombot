# 节点独立电脑验收与镜像准入

`tomd` 现在同时监督控制心跳和 `nodecatalog.Verifier`。登记节点与镜像后，验收工作者自动创建节点专用临时电脑，使用正式 `Inspect`、`Ensure`、`Remove` 通道；不创建业务用户、凭据或可登录账户，不复用任何用户电脑。API 不持有 Docker socket，所有实际操作仍由受信节点执行。

验收流程已经接通，但生产 `capabilityProbe` 尚未确认共享浏览器能力，因此当前正式节点不能通过完整验收。这不是可通过配置关闭的检查项；共享浏览器阶段接通真实证据后才能开放开户。公开远程电脑交互仍不在本期范围。

## 执行与恢复

1. 从数据库确认控制租约有效，锁定节点及该节点唯一验收记录。未登记、离线、排空或已有工作者持租约时不新建资源。
2. 先检查同一资源，再决定是否供给。只有终端、浏览器、文件、配额、网络隔离和进程回收全部通过，才保存证据并进入 `cleaning`；此时仍不能开户。
3. 清理前再次检查原资源，调用幂等 `Remove` 并核验同一身份的 `absent` 回执。物理不存在也必须确认持久关闭屏障，不能跳过关闭后进入下一代。
4. 清理确认后再次读取实际节点心跳，并在短事务中核对运行实例、节点代次、控制租约、验收有效性、镜像启用状态和证据时限。全部满足才原子发布节点 `ready`、验收镜像与到期时间，并记录审计。

每节点最多一台验收电脑。逻辑电脑、合成所有者和操作身份持久不变；确认上一代清理后，才按正式节点约定同时增加电脑代次、尝试号及 fencing token。合成所有者只用于节点资源命名与隔离，不写 `users`，也不占用用户的 `reserved` 名额。受保护节点账本与数据库验收记录共同保存这些身份；不得删记录、换 ID 来绕过清理失败。

创建或删除结果未知时，保留阶段并先重新检查实际状态；没有确认不存在时不创建替代电脑。每阶段核实次数有上限，持续未知或身份不符进入 `quarantined`，保留资源账本并发出带节点、操作标识的错误日志，不再自动创建下一代。数据库或通道暂时失败不退出 API，现有有效证据到期后门禁自动关闭。进程退出保留未完成租约，下一实例只能在到期后接管。

数据库事务不跨越节点调用；固定锁顺序为节点行、验收行、必要时镜像行，取得相关锁后重新读数据库时钟。状态提交再次比较租约时限和控制令牌，迟到回包不能覆盖接管者。证据时限从检查调用前的数据库时刻起算，不因清理、排队或提交延迟重新计时。

## 开户门禁与诊断

迁移 `0046_node_capability_verification.sql` 新增每节点一行的 `node_verifications`，节点目录新增 `verified_image_id` 和 `capability_expires_at`。控制连接拥有验收表的读取与写入权限，身份、租户和分发角色没有该权限。验收记录保存固定资源规格、阶段、租约、能力证据和固定错误码，不保存业务内容或凭据。

`reserve_computer_node(node_id,image_id)` 在行锁内检查有效控制租约、有效能力证据、镜像匹配、镜像启用及剩余容量；开户和失败重试使用同一个函数。目录登记为全局启用的镜像不代表本机已经验收它。当前单节点部署一次验收配置中的一个镜像；切换配置后先清理旧验收，再检查新的固定镜像，旧用户电脑继续保留原引用。

节点重启或控制租约中断后恢复时，数据库触发器使正在执行的旧验收失效并清除已发布证据。排空状态不会被验收解除。能力证据到期、控制租约仍有效时，节点显示 `bootstrapping`；控制租约到期显示 `offline`。`tomnode-register` 的 `status` 查询补充验收阶段、错误码、已验收镜像和证据期限，用于诊断，不提供手工就绪动作。

## 配置与资源影响

服务配置新增必填 `node.verification.image_id`，必须对应本机已登记、准备完成的固定镜像。其余字段有有界默认值：

```json
{
  "image_id": "实际登记的镜像 ULID",
  "resources": {"cpu_millis": 1000, "memory_bytes": 2147483648, "disk_bytes": 1073741824, "process_limit": 512},
  "lease_duration": "3m",
  "interval": "5m",
  "lifetime": "15m",
  "retry_delay": "5s",
  "max_attempts": 5
}
```

单次调用使用 `node.call_timeout`，默认 30 秒。验收租约至少覆盖五次调用预算，最大 10 分钟；周期 1–30 分钟，证据期限须覆盖周期和租约且不超过 1 小时。重试间隔 1–60 秒，每阶段最多 1–20 次状态核实。工作者参数不能关闭验收或无限重试。

首次启动与周期复验均会真正创建、检查、删除临时容器及磁盘。开始新一轮时撤销上一轮准入，检查期间暂不接纳新电脑，既有用户查询不受影响。发布容量必须额外预留一台验收电脑的 CPU、内存、磁盘、进程及出网服务名额；`capacity` 是业务用户数量，不能把全部物理余量分满后再期待验收成功。实际调用耗时和周期成本仍须在部署验收中测量。

数据库验收表每节点一行，宿主磁盘记录现按逻辑用户保留一份最高代次及一把稳定锁；代理控制目录只保留当前代次，进入下一代前必须先确认旧实例与会话关闭、实际资源不存在，再回收旧目录。最高代次、宿主探针版本和桌面关闭屏障继续保留。删除中断会持久记录旧目录 inode 和待进入代次的规格及控制版本，重启不能接纳旧请求或替代目录。未知文件、链接、挂载和未释放的代理锁阻止换代，不做递归删除，详见[控制元数据保留规则](../internal/dockernode/README.md#控制元数据保留与代次回收)。

## 迁移与回滚

先停止接单并排空控制调用，执行新增 `0046`，再发布匹配的 API 与配置。历史 `0001`–`0045` 不变。迁移撤销没有本次能力证据的旧 `ready`，保留控制绑定、容量、预留量和用户电脑；不制造成功验收记录。DDL 取得节点表结构锁，状态更新只扫描节点目录，新增表起初为空，不扫描用户业务历史；执行前评估节点数、在途事务及锁等待。

旧三参数状态函数和单参数预留函数已移除，没有兼容入口。回滚只能使用理解同一验收表、双租约及镜像门禁的版本；保留验收规格、代次、控制令牌、节点关闭记录及用户卷。禁止通过删除验收记录、回退迁移或恢复旧 API 绕过未知资源或能力缺失。

## 验证边界

真实临时 PostgreSQL 测试覆盖并发领取、清理前不发布、未知创建/删除结果对账、持久关闭、下一代身份、过期和旧回包、行锁等待、重启与失联恢复、排空、镜像停用/不匹配、配置改变、未来/过期证据、有限核实、取消及前向迁移；账户测试确认新建与重试的镜像能力门禁。运行时成功路径是明确的接口替身，不是生产验收证据。

真实 Ubuntu systemd 首次安装、真实 Docker 专用验收电脑、loop 挂载、配额、cgroup 入组与回收、共享 Chrome 联合探针及完整同步开户仍须实测。不能将数据库回归通过、API 就绪或节点控制通知当作这些条件已经满足。
