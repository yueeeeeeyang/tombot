# 例程调度与恢复

例程支持 Bot 和群组两种目标、时区 cron、每次新建或固定会话、跳过或排队、错过补跑，以及手动触发。客户端关闭后由服务端继续调度。创建和修改都先进入“审批待办”，批准配置后才生效，不能记忆为自动放行规则。

## 配置与审批

`target` 必须且只能指定 `bot_id` 或 `group_id`。Bot 必须未归档，目标的主会话必须可用。固定模式指定的会话必须属于同一目标；省略或清空固定会话时使用目标的主会话。服务执行时重新校验目标与配置版本，不向已删除、已归档或被替换的目标派发旧任务。

cron 采用锁定的 `robfig/cron/v3 v3.0.1`，只接受“分 时 日 月 星期”五字段格式，最短粒度为一分钟，不接受秒字段、`@every` 或表达式内的时区覆盖。时区采用 IANA 名称，默认 `Asia/Shanghai`，拒绝依赖机器配置的 `Local`。二进制包含时区数据；夏令时由目标时区规则计算，跳过不存在的墙钟时刻，回拨后的重复时刻按各自绝对时间触发。没有未来触发点的表达式直接拒绝。

默认 `overlap_policy=skip`、`catch_up=once`、`target_mode=new`、`is_enabled=true`。名称最多 200 UTF-8 字节，指令为 1–65536 UTF-8 字节。全局最多 1000 个例程、1000 个未决配置审批、1024 个尚未入队的触发。

创建和修改返回审批标识，不提前写入生效配置。审批属于 `routine.create`，有效期 24 小时，显示目标、指令、时区、重叠与补跑策略、会话模式和启停状态。修改提案绑定 `revision`；其他设备先批准了新版本时，旧提案不能覆盖它。批准、配置写入、审计与事件在同一事务中完成，审计失败时审批仍待处理且配置不变。拒绝、过期或目标删除均不会启用提案。

停用也属于配置修改，批准后取消未来调度，并将该例程尚未入队的旧触发标为 `ROUTINE_CHANGED`。已入队回合使用既有快照继续运行，用户可在会话中停止。停用后仍可明确选择“立即运行”。删除例程需版本确认，若已有活动回合则先停止；删除配置和触发列表，保留已完成会话转录。

## 时间与一致性

服务在开放管理接口前恢复旧入队意图，引导达到 ready 后开始调度。启动检查后每分钟一轮，每轮最多处理 1000 个到期例程，按每页 100 条读取；每轮有 45 秒时限。单次模型执行继续受全局队列、Bot 互斥、群组路由、步骤、费用、墙钟和审批限制。

到期抢占使用 `UPDATE … WHERE id=? AND next_run_at=?`，在同一 SQLite 事务内推进到严格晚于当前时间的下一次时间，并保存本次触发记录、配置快照、审计和事件。非手动触发另以 `(routine_id, scheduled_at)` 唯一索引防重。抢占失败回滚时间、记录以及新会话，不留下时间已推进但没有触发意图的窗口。

启动发现错过一次或多次时，`once` 只补一次，记录原定时间并将未来计划推进至当前时间之后；`skip` 记录 `skipped_missed`。正常运行因延迟错过多个点时，也只领取一个当前到期记录，不补成无限队列。墙钟回拨不会重放已经推进的时间点。

`skip` 会检查目标全部会话中的活动 Turn：Bot 参与尚未产生成员 Run 的群回合时也视为忙碌；群目标检查该群所有主会话与例程会话。忙碌时记录 `skipped_overlap`。领取和入队事务内分别检查，覆盖两个阶段之间出现的新任务。

`queue` 保存待入队意图。新会话可进入既有全局队列；固定会话若仍有活动回合，则留在例程队列，由下一分钟检查继续处理。同一例程按领取顺序入队。队列满时继续等待；不自动取消正在执行的回合。尚未入队的意图数量有上限，达到上限时新的触发明确记录失败。

入队时重新检查触发状态、配置版本、目标与重叠条件，并在创建 Turn 的同一事务内关联触发、写入 `source=routine` 和事件。事务提交后才启动模型，因此重复派发不会生成第二个回合。群组例程沿用实际触发会话，成员发言与最终汇总不会误入主群聊；成员先结束也不会提前结束整个群回合。

这不是跨崩溃的“恰好执行一次”承诺。服务重启将已入队但未完成的 Run／Turn 标记中断；旧进程尚未入队的 `pending` 意图标记 `ROUTINE_INTERRUPTED`，发出系统通知，不重放潜在副作用。之后仍按未来计划与启动补跑规则调度。恢复清理只成功执行一次，不会在启动检查重试时误清理新进程刚接收的手动触发。

手动运行建立独立触发，不改变 `next_run_at`。客户端确认后只提交一次，网络失败不自动重发；再次手动点击代表新的触发。入队失败、无模型、目标不可用等错误保存在触发记录中并发出通知，不能把“已触发”当作“已执行成功”。

## 接口与客户端

所有接口均需设备鉴权，前缀为 `/api/v1`。

| 方法与路径 | 契约 |
| --- | --- |
| `GET /routines?bot_id=&group_id=&cursor=&limit=` | 按一种目标过滤，ID 倒序分页；默认 50，最大 200 |
| `POST /routines` | 提交完整创建配置，返回 202 与 `{approval_id,routine_id}` |
| `GET /routines/{id}` | 获取已批准配置、版本和下次／上次触发时间 |
| `PATCH /routines/{id}` | 必须提供 `revision`；合并提供的字段，提交配置审批并返回 202 |
| `DELETE /routines/{id}?revision=…` | 条件删除；活动回合阻止删除 |
| `POST /routines/{id}/run-now` | 请求体 `{revision}`；返回触发记录，可能为已入队、等待、跳过或失败 |
| `GET /routines/{id}/runs?cursor=&limit=` | 分页触发历史，包含关联会话、Turn 实际状态和错误码 |

配置字段为 `name`、`cron`、`timezone`、`prompt`、`target`、`overlap_policy`、`catch_up`、`target_mode`、`pinned_conversation_id`、`is_enabled`。局部修改保留未提供的字段；更换目标时不复用原目标的固定会话。模式改为 `new` 时清除固定会话。过时版本返回 409，客户端保留草稿；重新读取会覆盖草稿，需用户确认。

Flutter 工作室提供例程入口，Bot 详情展示例程及下次触发时间，群组顶栏提供过滤后的例程列表。管理页支持创建、修改、启停提案、立即运行、删除和运行记录。审批后的 `routine.updated` 会刷新列表；编辑页不监听覆盖事件。运行记录可跳到实际触发会话，侧栏的例程会话也使用独立路由，主 Bot／群组入口始终选择主会话。

## 迁移、性能与回滚

新增迁移 `0012_routine_dispatch.sql`，历史 0001–0011 保持不变。迁移调整主会话唯一索引以排除 `source=routine`；增加例程版本、到期索引、触发快照和去重索引；重建审批表以允许只有 `routine.create` 使用无 Run 审批，并保留全部原有字段与记录，新增配置提案表。

升级需暂停任务、正常停机并整体备份数据目录与工作区，再同步升级服务与客户端。审批表复制与索引建立在单个 SQLite 写事务内进行，写锁持续时间取决于历史审批和会话量；大库需要维护窗口和足够临时磁盘空间。启动前备份不能只复制主数据库文件而遗漏未合并的 WAL，应采用停止服务后的完整目录快照。

单用户单进程仍由数据目录排他锁保护；条件抢占、唯一索引和事务提供额外防重，不宣称支持多机部署。时区数据增加二进制体积；运行记录持续保留，管理读取有分页，定期备份仍需覆盖增长后的数据库。例程使用既有模型和工具能力，并会产生与手动会话相同的模型费用。

旧二进制会拒绝打开版本 12 数据库。回滚必须停止新服务，恢复升级前完整数据／工作区快照以及匹配的旧服务和客户端；不能只换二进制、删表或篡改迁移账本。回滚不会重放已经中断的回合。

## 验证边界

自动化验证包括真实版本 11 历史审批升级、时区与夏令时、无效计划、并发抢占、推进失败回滚、补跑和跳过、目标隔离、配置审批与过期、审计回滚、局部修改保留、目标删除、重启不重放、新进程恢复隔离，以及实际 Agent 的独立 Bot 会话、群成员完整收尾、公开群工具与固定会话排队。

本地真实 HTTP 模型上游完成鉴权配置 → 审批 → Bot／群组例程 → SSE／消息持久化 → 费用 → 历史查询；客户端组件覆盖 390／900／1440 宽度的提案、审批、手动触发、历史跳转、编辑冲突、删除确认与失败不重发。外部真实模型账号、跨平台人工交互和长时间运行验收仍属于项目最终验收范围。
