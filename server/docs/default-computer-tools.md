# 默认启用浏览器和桌面操作

桌面客户端创建猫咪时默认授予 `computer_shell`、`computer_browser`、`computer_screenshot`、`computer_input`。用户开户已要求可用电脑，后续运行仍会重新取得桌面授权并检查节点状态。浏览器动作由容器内 Agent 执行，桌面截图和键鼠操作使用既有节点链路；不新增工具执行通道或扩大宿主权限。

已有默认猫咪由新增迁移 `0075_default_computer_tools.sql` 补齐权限：仅匹配旧版默认系统提示词且工具集合恰好为 `computer_shell` 的记录，包括归档猫咪，以便重新启用后保持一致。自定义提示词、空权限及其他工具集合不修改。每条命中记录修订号加一；重复启动不会重复更新。已保存的运行快照不改写，新增权限从升级后新受理的运行生效。

## 模型与运行条件

浏览器、桌面工具要求模型同时支持工具调用和图片输入。现有路由会从已分配策略中选择满足条件及上下文预算的候选，没有合适候选时明确失败，不静默退回纯文本模型或去掉工具。上线前须确认用户策略包含已启用的视觉工具模型，并如实配置能力。工具定义增加模型输入用量；长历史仍受原上下文、费用、步骤和时间上限约束。

节点可用不代表模型能力已经配置。普通聊天同样携带这些工具，因此默认猫咪的新运行均需要合适的视觉模型。各桌面分别登录网站。模型在本桌面打开 Chrome，再使用桌面截图和输入操作网页。节点暂不可用、权限撤销及未知操作结果沿用明确失败与恢复机制。

## 升级、迁移和回滚

先确认模型策略，再暂停接单、等待在途运行结束并备份数据库，更新 `tomd` 并执行 `tomd upgrade` 应用 0075，随后更新并重启桌面客户端。部署独立桌面浏览器须同时更新节点与电脑镜像，详见[升级与回滚](browser-readiness.md)。仍在运行的旧客户端会继续按旧规则招聘，因此应一并更新客户端。

迁移扫描机器人表，临时策略 DDL 和命中行更新会持锁；不扫描聊天正文，不创建索引、不改写历史迁移。执行受既有 10 秒锁等待、45 秒语句及一分钟迁移事务上限约束，大目录或长事务可能导致失败，失败会整体回滚，安排维护窗口重试。迁移临时权限只授予结构所有者，成功或失败均不遗留跨租户权限。

回滚优先发布新的前向修复迁移，依据升级前备份恢复命中猫咪的权限，不能修改或删除 0075，也不能覆盖升级后用户主动修改的权限。完整回退旧程序须停单、保全升级后内容、恢复升级前数据库和对应客户端、服务端；旧程序会拒绝较新的迁移账本。节点身份、文件、桌面数据及模型策略不因本迁移改变。

## 验证范围

客户端创建测试检查完整默认权限；PostgreSQL 测试验证旧目录前向迁移、跨用户覆盖、限制条件、修订号、重复执行、失败事务回滚及临时权限回收。Worker 测试验证完整工具集合交给 Agent、浏览器动作走本地授权通道、桌面截图与输入结果进入模型，以及无视觉模型时拒绝执行。测试使用受控模型和节点，不等同于目标 Linux 主机与真实供应商的端到端验收。
