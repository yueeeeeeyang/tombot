# TomBot Web 管理平台

管理平台使用 React、TypeScript 和 Vite，访问同源 `/api/v2/admin`。已实现管理员验证器登记、账户激活、登录、身份复验、退出及自动会话续期，用户目录、同步开户、进度查询、失败重试、隔离对账与一次性激活材料展示，以及供应商、模型、凭据版本、策略版本、启用前能力测试、启停和默认策略操作。

这些页面调用真实管理协议，没有产品内演示数据或认证旁路。当前 `tomd` 已挂接管理接口及静态资源，部署配置见[应用组合说明](../server/internal/serverapp/README.md)；首位管理员的[本机引导命令与网页激活](../server/docs/admin-bootstrap.md)已接通，节点部署与真实能力探针仍待完成。账户禁用、角色与限额管理、策略按用户和机器人分配、价格编辑、用量、审计、任务、电脑运维和总览页面仍待补齐。

## 本地构建与检查

在本目录执行：

```sh
npm ci
npm run check
npm run test:e2e
```

`check` 包含格式、ESLint、TypeScript、Vitest 和生产构建。浏览器测试需要 Go 和匹配版本的 Playwright Chromium；通过 `npx playwright install chromium` 安装，也可用 `PLAYWRIGHT_BROWSERS_PATH` 指定隔离测试目录。测试启动正式 Go 静态处理器，在实际 CSP 下检查用户目录、深浅色、窄屏、模态焦点及模型版本启停流程，并要求没有 CSP 违规；业务 API 仅在测试代码中拦截，不连接公网模型或真实用户容器。

`npm run dev` 启动本地开发服务；`npm run preview` 查看生成的内置资源目录。单独运行前端无法提供账户和 API，不会自动创建测试管理员。正式联调必须与真实管理 API 同源部署在 HTTPS 下，不能通过关闭 Cookie、CSRF 或来源校验解决跨源问题。

## 认证与结果一致性

- 平台尚无管理员时，登录页展示首位管理员创建入口：设置用户名、显示名称和密码，成功后展示一次性的验证器设置材料，再返回登录。首建请求不发送管理 Cookie 或 CSRF，只接受明确的完成响应。
- 登记材料只保留在当前页面内存，默认隐藏，返回或离开页面时清除并取消在途请求；历史页面恢复也不保留输入。未知创建结果转到登录核实，不自动重放；明确拒绝的输入可以更正后提交。
- 访问与续期凭据仅由服务端 HttpOnly Cookie 管理。页面只把 CSRF 值保存在内存；本地存储只记录主题偏好，不保存账户、激活材料、模型凭据或业务缓存。
- 管理请求设置同源凭据、禁止重定向和缓存，并验证响应结构及大小。登录失效会取消在途请求、清空业务界面；旧会话响应不能重新写入新会话。
- 页面根据服务端返回的真实到期时间，在访问凭据到期前 60 秒自动续期；刷新页面、恢复前台、历史页面恢复和网络恢复时重新检查。访问 Cookie 过期后通过只读 `/auth/refresh-context` 获取当前续期校验值，续期 Cookie 仍有效即可恢复，不延长会话的绝对有效期。
- 同标签页合并续期，多标签页通过 Web Locks 的独占锁串行检查与轮换；业务请求持共享锁，写入前同步当前 CSRF，避免轮换废弃在途请求。每次管理写入增加一次有索引的会话查询。需要支持 Web Locks 的现代浏览器，缺少该能力明确报错。
- 临时断网显示续期错误并保留工作页面；网络恢复或点击重新连接后重新检查。续期 POST 不盲目重试：只读校验拒绝已消费、过期或撤销的续期 Cookie。会话真正失效才返回登录，二次验证输错密码不会退出。鉴权失效的只读业务请求最多恢复后重读一次，写操作不自动重放。
- 写请求不自动重放。`504 CREATE_PENDING` 读取原操作；创建回包丢失时冻结原参数，只允许显式复用原幂等键核对。关闭弹窗后可通过用户目录的创建进度继续查询。
- 创建状态来自服务端。`pending`、`running`、`reconciling` 和 `compensating` 均不代表成功；查询有界轮询，达到上限或连接失败后显示当前状态并提供刷新。
- 模型修订冲突或写入结果未知时，关闭弹窗并重新读取后再决定下一步，不推算修订或覆盖他人修改。创建版本也会改变策略修订，界面重新读取后才允许启用。首次启用前明确提示实际能力测试及供应商调用。
- 激活材料只在专用弹窗中短暂显示，关闭即卸载；再次签发会废止旧材料。密码、动态码和供应商凭据提交后立即清空输入控件。

## 样式与部署

[ui/theme.css](../ui/theme.css) 与 [ui/controls.css](../ui/controls.css) 是客户端和管理平台共享的主题、按钮、表单及弹窗样式来源。管理端只增加网页布局与业务样式，不依赖 Electron IPC、窗口拖拽区或客户端品牌组件。

构建基路径固定为 `/admin/`，Vite 输出到 `server/web/admin/bundle/dist/`，由 Go `embed` 编入 `tomd`。构建机需要 Node.js/npm，部署机只需配套 `tomd` 与服务配置、数据库及证书，不再复制前端目录或运行前端进程。`make -C server build` 会安装锁定依赖、构建前端并编译服务；缺少产物时直接编译 `tomd` 会失败，不能发布空页面。电脑节点不导入嵌入资源包。

[Go 静态处理器](../server/web/admin/page.go)在启动时校验内置资源，仅为已定义的页面路由返回 HTML，保持 CSP、禁止缓存、禁止目录列表及未知资源回退等边界。更新管理平台需重新构建并替换 `tomd` 后重启，运行时不读取外部静态文件。浏览器测试也使用同一嵌入入口。

### 页面地址与刷新恢复

管理平台使用 React Router 的浏览器路由：`/admin/users`、`/admin/administrators`、`/admin/computer-nodes`、`/admin/model-providers`、`/admin/model-policies`。供应商详情为 `/admin/model-providers/:providerID`，策略版本为 `/admin/model-policies/:policyID/versions`；`/admin/` 进入用户目录。导航、前进、后退和刷新以 URL 为准，详情通过单条查询读取，不依赖列表第一页或浏览器内存。未登录访问详情时保留原地址，登录后再读取业务数据；凭据及表单内容不写入地址。

本次新增只读 `GET /api/v2/admin/model-providers/:providerID` 和 `GET /api/v2/admin/model-policies/:policyID`，沿用管理员权限，无数据库变更。部署需替换内置页面的 `tomd` 并重启，使深层页面地址与详情接口一起生效。回滚时恢复匹配版本的二进制与配置并重启，原数据保留；旧版需从 `/admin/` 进入。外部反向代理必须将这些页面转发给 `tomd`，不能把未知静态资源或 API 请求回退为 HTML。

空目录统一显示虚线提示面板，不显示零条计数、空表头或分页分隔线；翻到空页时保留返回首页。弹窗底部按钮按内容宽度靠右排列，下载链接沿用相同按钮样式。

纯界面变更不导入旧数据；涉及目录约束时按对应迁移说明升级。回滚应成套回退理解相同 v2 协议的前端和 API；保留服务端开户操作、模型版本与审计，不用回滚重发未知写入。共享样式移动后，客户端也需要从同一仓库根布局构建。

## 模型导入与选择控件

“从供应商拉取”点击即发起一次读取，按钮显示加载状态并阻止重复点击；失败在目录显示原因，可显式重试，离开供应商取消在途请求。成功后展示导入弹窗，各模型默认收起，只显示名称、标识和必要的已登记状态。选择与展开分别控制，展开/收起不清空已填参数；提交遇到缺失或越界规格时先展开对应模型并定位字段，禁止跳过校验写入。

表单选择控件共用 `ui/Select.tsx` 的主题外观和键盘行为，包括登录页外观、协议、模型、凭据、节点及镜像。管理端浏览器需支持 Popover API；以真实浏览器测试检查顶层弹出、窄屏定位、焦点和 CSP。此变更不新增接口或迁移，部署替换内置页面的 `tomd` 并重启；回滚恢复匹配二进制及配置并重启，保留已登记目录及策略数据。

### 会话恢复与品牌图标发布

管理端登录、首位管理员设置、侧栏及 favicon 共用客户端 `desktop/src/renderer/src/assets/cats/frames/bombay.png`，不复制图片或依赖桌面运行时。

本次会话修复要求服务端与内置前端同批编译：`GET /auth/session` 必须返回 `access_expires_at` 和 `expires_at`，另新增管理专属只读 `GET /auth/refresh-context`。无数据库结构变更，无需数据迁移；部署时替换内置前端的二进制并重启服务。回滚时成套恢复上一个二进制及匹配配置后重启，避免前后端协议不一致；现有会话数据保留。

### 模型维护与账户菜单

模型停用后显示编辑、删除入口；编辑表单独立校验长度上限、媒体类型和思考级别，保存后保持停用。删除前确认模型名称，被任意策略版本引用时显示明确原因且不删除。写入携带修订号，竞争或结果不明时重新读取，不盲目重发。

侧栏底部显示当前管理员的猫咪头像、名称和用户名。账户菜单包含跟随系统、浅色、深色和退出登录，支持方向键、Home/End、Escape、Tab、外部点击关闭及焦点返回。名称与用户名由服务端会话的 `principal.display_name` 和 `principal.username` 提供，登录、恢复及续期均取数据库当前值；仅主题偏好持久化到本地。

此功能需成套发布服务端与前端，并由 `tomd` 自动执行迁移 0056。索引创建的锁影响和回滚见 [模型目录说明](../server/internal/modelregistry/README.md)；升级前备份数据库与部署文件，旧二进制不能直接连接 0056 数据库。恢复到旧版本时需完整恢复升级前数据库与程序，不能只替换前端或删除迁移记录。

## 多模型策略配置

策略版本页面可跨供应商添加最多 16 个候选，支持优先级主备、加权分配与轮询。自动按任务的工具、图像及上下文需求筛选候选；参数设置默认收起，输出上限、思考级别及凭据默认继承，只有显式覆盖才发送覆盖值。模型不可重复添加，停用模型不可选。页面使用统一自定义下拉组件，提交结果不明时禁止自动重发。

版本列表显示路由方式、候选参数和“已启用 / 已停用”状态。新版本默认停用，首次启用会测试全部候选；已验证版本可随时重新启用，同一策略只能启用一个版本。切换和停用版本仅影响新任务，停用后可以再次启用，不再使用发布、激活或撤销版本的概念。状态直接读取版本接口，避免策略指针和版本列表先后返回产生矛盾标签。模型选择区域在桌面端保留下拉框空间，添加按钮按内容宽度显示，窄屏下独立换行。选择器不复用表格分页页脚；仅在确有多页时显示对应的翻页操作，不显示条数与分隔线。

该功能需与服务端及数据库迁移 0058 同步更新；应停止接单、排空操作并备份数据库，回滚必须恢复整套数据库与程序。具体锁影响、并发和计量边界见 [多模型策略说明](../server/internal/modelregistry/README.md#多模型路由与版本启停)。

策略整体停用时，版本页显示停用原因及“启用策略”入口，携带当前修订号确认后刷新策略和版本；失败保留停用状态，不自动恢复策略。添加候选模型时可直接选择思考级别，默认继承，仅列出模型声明的级别；切换模型、供应商或分页时重置选择，添加后仍可在参数设置中调整。本次为管理端改动，无接口或数据库迁移；替换内置前端的二进制并重启生效，回滚恢复匹配二进制及配置后重启。

## 节点自动接入

“电脑节点”保留分页目录，原手动登记表单改为“生成接入凭据”。管理员近期验证后签发一份有效期 24 小时的一次性凭据，在当前弹窗显示只读接入码并支持复制，完整解压离线包后运行 `sudo ./tomnode install` 并粘贴即可。凭据仅保留在页面内存，不写入浏览器存储或日志；关闭弹窗、离开页面即清除，无法再次查看。每台新节点使用独立凭据，重启不重新签发。主服务按节点 ID 路由并独立验收。部署需与新接口和 `0059_node_enrollment.sql` 同步发布，升级回滚见[节点接入说明](../server/docs/node-registration.md)。

管理身份验证的授权成功、操作成功和取消授权通过页面顶部消息展示，五秒后自动消失；取消会终止原请求，不在业务表单显示错误，也不重放写入。只有业务响应成功后才提示操作成功；真实业务错误仍保留在原表单。

节点接入码封装服务地址、HTTPS 证书指纹和一次性授权（最大 2048 字符）；首次安装无需手填服务参数，API 客户端信任由已鉴权引导接口提供。离线电脑镜像由配套节点安装包交付，详见节点安装文档。

### 从外部前端目录升级

本次不修改数据库。升级前备份 `tomd`、`server.json` 和原前端目录，从配置中删除 `admin_directory` 后替换内置页面的新二进制并重启；旧字段会被拒绝，不保留外部目录回退。确认页面、资源和深层地址均正常后可归档原前端目录。回滚到旧版须同时恢复旧配置、旧二进制和旧前端目录；已经采用内置页面的版本之间回滚只需匹配二进制及配置。
